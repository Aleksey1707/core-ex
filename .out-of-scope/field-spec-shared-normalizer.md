# Общий нормализатор спеки полей для View и Codec-плагина

Спеку полей `use Core.View` (`fields:` / `forms:`) и спеку полей Codec-плагина (`Core.Codec.Field`:
`fields:` плагина, `variants:`, нагрузка события, `Core.Es.ValueChanged`, подписи) разбирают две
грамматики. Один нормализатор синтаксиса, которому каждая декларация задаёт свой набор kind'ов
(View — `view` / `form` / `jsonb`, плагин — `entity` / `union` / `default`), библиотека не заводит.

## Почему это вне рамок

Синтаксически совпадает немного: keyword-форма, ровно один kind-ключ, `prim:` / `enum:` / `type:` /
`list:`, `optional:` boolean и не внутри `list:`, набор значений `type:`. В разборе опций View это
около 40 строк из 100. Остальное — семантика kind'ов, и у двух сторон она разная:

- `prim:` у View — тройка `{:prim, Mod, kind}`: kind только приводимый, sensitive запрещён, по kind
  строится typespec голого значения. У плагина `{:prim, Mod}` — kind любой, sensitive обязан проходить.
- `form:` у View проверяется по контексту — именам `forms:` той же декларации; `jsonb:` различает
  тип плагина и `{Модуль, :функция}`. У плагина свои `entity:` и `union:`.
- Режимные ключи — `wire:`, `default:`, `subject:` — есть только у плагина и нагрузки.
- `list:` устроен по-разному: у View элемент разбирается как поле и `optional:` отсекается потом,
  у плагина элемент — спека без доп. ключей.

Общему нормализатору пришлось бы принимать набор kind'ов, обработчик на каждый kind, допустимые
доп. ключи и политику `list:`. Interface вышел бы почти равен реализации — shallow module.

Пятый режим `Core.Codec.Field` вместо отдельного нормализатора перевернул бы зависимость: Codec
узнал бы `view:` / `form:` / `jsonb:`, хотя View зависит от Codec, а не наоборот.

Решение по семантике уже записано в ADR-0056 («Общая спека с `Core.View`» отвергнута). Там же и
граница общего: «общие — имена ключей и элементарные проверки». Её держит `Core.Helper.FieldCheck`,
и уточнять ADR не нужно. ADR-0057 называет общим имя опции `fields:`, а не грамматику, — это верно и
без общего кода.

Общие правила, которые всё же стоит держать в одном месте (проверка повторов, предикат «Prim
годен для read-пути»), вынесены отдельным тикетом, без общего нормализатора.

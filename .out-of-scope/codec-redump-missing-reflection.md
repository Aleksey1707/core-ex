# Рефлексия `__codec_redump_missing__/0` у Codec-плагина

Плагин генерирует `__codec_redump_missing__/0` — список типов без спеки пере-дампа, а фасад по нему
генерирует три группы клауз `__codec_redump__/1` и выбирает `@spec` через `Core.Codec.Facade.redump?/1`.
Убрать эту рефлексию и бросать отказ из клаузы самого плагина библиотека не будет.

## Почему это вне рамок

Обход вынужденный — из-за success typing Dialyzer:

- клауза плагина, которая только бросает, даёт функции success typing `none()`, и `@spec` со спекой
  redump расходится с ним, а вызов из фасада Dialyzer помечает «will not succeed»;
- поэтому плагин клаузу на тип без спеки не генерирует, а отказ бросает фасад
  (`Core.Codec.Plugin.Redump.missing!/2`);
- фасад без единого типа со спекой получает `@spec … :: no_return()` — иначе та же рассинхронизация
  на уровне фасада. Для этого и нужен `redump?/1`.

Объяснение записано в `@moduledoc` `Core.Codec.Facade`, `Core.Codec.Plugin.Redump` и `@doc` `redump?/1`.

Сходство с `Es.Event.Codec` (тоже читает `Module.get_definition`) поверхностное: там ручные клаузы
нагрузки только находятся, чтобы запретить их, а цели клауз не разбираются.

Вынос AST-разбора ручных клауз из `Core.Codec.Plugin.Opts` в свой module — отдельный тикет,
рефлексию он не трогает.

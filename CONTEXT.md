# Core

Core — библиотека-фундамент, подключаемая git-зависимостью к нескольким Elixir-приложениям.
Её предметная область — не бизнес-домен, а язык, на котором приложение-потребитель строит свой:
что считать значением, агрегатом, представлением и событием, и как это попадает в базу и в брокер.

Здесь — значения терминов. Нормы (`MUST` / `SHOULD`) живут в `docs/rules/**`; адрес нормы указан
у каждой группы. Часть терминов называет то, что даёт библиотека, часть — то, что по её правилам
строит потребитель; это сказано в самом определении.

## Значения

**Prim (доменный примитив)**:
Обёртка над примитивным значением — строкой, целым, decimal, UUID, датой: `%Mod{value:}`, где
значение проверено при создании и дальше живёт уже проверенным. Принадлежит агрегату-владельцу и
именуется внутри него (`User.ID`), значение без владельца принадлежит общей части контекста; задаёт
формат значения для кодека.
_Avoid_: валидатор, тип, VO; «примитив» без уточнения — это raw-значение внутри обёртки

**Prim.Compose (композитный примитив)**:
Доменный примитив поверх другого доменного примитива, а не поверх raw-значения:
`%Approver.ID{value: %User.ID{value: raw_id}}`. Даёт роли или смыслу собственный тип, сохраняя
проверки базового; на wire уходит в формате базового примитива.
_Avoid_: алиас типа, подтип, наследование, обёртка

**Enum (перечисление)**:
Закрытое множество атомов с описанием каждого значения и, при необходимости, с кодами внешнего
источника. Значение — голый атом, а не структура: этим Enum и отличается от Prim.
_Avoid_: справочник, словарь, константы

**Version (версия агрегата)**:
Целое ≥ 1, помечающее состояние агрегата. Расхождение ожидаемой версии с действительной означает,
что вызывающий видел не то состояние, которое есть: его изменили конкурентно либо агрегат ещё не
заведён. Ожидаемая версия — либо явная (та, чьё состояние вызывающий видел), либо `:current` —
«последняя, какая есть».
_Avoid_: ревизия, номер изменения, timestamp

**Сверка ожидаемой версии**:
Проверка того, что действительная версия агрегата равна названной вызывающим. Не сошлась —
вызывающий видел устаревшее состояние, и повтор этого не исправит. Код ошибки общий с отказом
хранилища, различает их ключ `source:` в detail: у сверки — `:expected`, у отказа — `:storage`.
_Avoid_: конфликт версии, optimistic lock, проверка If-Match

**Context (контекст вызова)**:
Обстоятельства вызова, а не его данные: текущий пользователь, эталонные копии агрегатов.
Передаётся сквозь usecase- и repo-функции; порядок аргументов задаёт `20-agreements.md`.
_Avoid_: scope, session, окружение, состояние

Результат и опциональное значение — сквозные формы, в которых по библиотеке ходят исходы операций
и значения, которых может не быть. Нормы — `11-domain.md`.

**Результат**:
Исход операции в одной из трёх форм: успех со значением (`{:ok, v}`), успех без значения (`:ok`)
или ошибка (`{:error, reason}`). Форм три, а не две: успех без значения — это `:ok`, а не
`{:ok, nil}`. Причина ошибки — `%Error{}` там, где отказ доменный или прикладной, и произвольный
терм там, где он остаётся внутри модуля. Имена формам даёт библиотека: `Core.Result.t/0,1,2` и
`Core.Result.unit/0,1`.
_Avoid_: ответ, статус, either, монада, тапл

**Опциональное значение**:
Значение, которого может не быть, — `a | nil` (`Core.Option.t/1`). Отсутствие здесь не отказ:
отказом оно становится на границе, где вызывающему нужен результат, — это и делают
`Option.to_result/1` и `Option.to_unit/1`.
_Avoid_: maybe, nullable, пустое значение, опция

Слово «кодек» покрывает четыре разных модуля: профиль задаёт формат примитивов, плагин — правила
одной сущности, фасад — единственную точку вызова, а `<Aggregate>.Codec` — это плагин конкретного
агрегата. Первые три даёт библиотека, последний пишет потребитель. Нормы — `11-domain.md`.

**Codec (кодек)**:
Преобразование доменного значения в wire-форму (`dump`) и обратно (`load`), где wire — то, что
уходит в базу, в брокер и в HTTP-ответ.
_Avoid_: сериализатор, маппер, конвертер

**Codec-профиль**:
Набор правил формата для примитивов: как выглядят uuid, datetime, date и decimal. Internal — формат
хранения, External — формат наружу.
_Avoid_: формат, сериализатор, схема

**Codec-плагин**:
Правила `dump` / `load` для одной сущности. Регистрируется в фасаде и вызывается только через него,
а не по имени модуля.
_Avoid_: entity-codec, маппер сущности

**Codec-плагин по полям**:
Codec-плагин, чьи `dump` / `load` выведены из объявленного списка полей сущности, а не написаны
руками: wire-форма повторяет поля один к одному. Если wire расходится с полями сильнее, чем
переименованием ключа, плагин пишется руками.
_Avoid_: автокодек, auto-codec, derive, декларативный кодек

**Спека полей**:
Объявленный список полей типа: у каждого — вид значения, необязательность и wire-ключ. Язык один
для плагина по полям, нагрузки события и подписей.
_Avoid_: схема полей, field DSL

**Семейство (union)**:
Модуль, которым называют набор вариантов одного полиморфного значения: загрузка по семейству сама
выбирает вариант по адресу в данных. Варианты — обычные типы; семейство struct не имеет.
_Avoid_: базовый тип, интерфейс, sum type

**Адрес варианта**:
То, по чему вариант семейства узнаётся в wire: тег тегированной формы, тег вместе с дискриминатором
внутри полей или один дискриминатор среди полей. Адрес неизменяем, как wire-тег события: по нему
читается записанная история.
_Avoid_: тег (о всём адресе), ключ варианта, type

**Тегированная форма**:
Wire-форма варианта union, в которой тег варианта лежит рядом с его полями, а не среди них:
`type` — тег, `fields` — поля варианта. Вариант по тегу выбирает семейство при загрузке.
_Avoid_: конверт, envelope, tagged union, самотегированная map

**Дискриминатор**:
Поле среди данных варианта с постоянным для этого варианта значением: по нему выбирается вариант,
когда тега нет или один тег разделяют несколько вариантов.
_Avoid_: variant_by, подтип, kind

**Codec-фасад**:
Единственная точка вызова `dump` / `load` в приложении (`InCodec` / `OutCodec`), выбирающая плагин
по модулю значения.
_Avoid_: сериализатор, реестр кодеков, диспетчер

**Пере-дамп (redump)**:
Перевод jsonb-нагрузки read-пути из формата, в котором её записал внутренний профиль, в формат
внешнего — по спеке формы, без разбора в домен. Спеку формы описывает тот, кто эту форму пишет:
плагин по полям выводит её из своей спеки, ручной плагин объявляет сам.
_Avoid_: перекодирование, конвертация jsonb, wire_prims

**Доменное время**:
Текущее время, которое видит домен: «сейчас» значений даты и времени. В тестах его останавливают
и сдвигают, не дожидаясь срока. Инфраструктура библиотеки (аренды, уборка, метрики) живёт по
реальному времени и остановку не видит.
_Avoid_: системное время, now, часы сервера

## Агрегаты и представления

Одну и ту же строку таблицы описывают четыре термина, и путают их постоянно: `Aggregate` живёт на
write-пути и держит инварианты, `View` живёт на read-пути и не держит ничего, `Schema` знает
колонки (определена ниже, в «Хранении»), а `Entity` — не пятая сущность, а роль в API мапперов.
Нормы — `13-repos.md`.

**Bounded context (ограниченный контекст, `<BC>`)**:
Раздел домена потребителя со своим языком и своими агрегатами. У потребителя каждый контекст —
граница Boundary верхнего уровня: другие видят его только через её экспорт. Библиотека контексты
не знает и знать не может — их заводит потребитель.
_Avoid_: модуль, подсистема, домен, слой

**Граница контекста**:
Граница Boundary верхнего уровня, которой является bounded context: `deps` — от чего он зависит,
`exports` — его интерфейс для остальных. Ссылку мимо экспорта и цикл между контекстами ловит сборка.
_Avoid_: API контекста, фасад контекста, публичный слой

**Common (общая часть контекста, `<BC>.Common`)**:
Часть контекста, общая для всех его срезов, в раскладке до вертикали по агрегату. Её больше нет:
всё об агрегате лежит в каталоге агрегата, значение без владельца — в `values/`, а другие контексты
видят контекст через его экспорт. `Common` в коде — признак раскладки до вертикали.
_Avoid_: shared, core, база

**Каталог агрегата (`<bc>/<aggregate>/`)**:
Единица раскладки контекста — вертикаль по агрегату: агрегат и всё о нём в одном каталоге, включая
подкаталоги акторов. То, что не принадлежит одному агрегату, лежит в каталогах уровня контекста.
_Avoid_: модуль агрегата, папка, срез

**Значение без владельца (`<BC>.Values.<Value>`)**:
Prim, который делят несколько агрегатов контекста и ни один из них не вводит. Лежит в каталоге
`values/` уровня контекста; значение одного агрегата вложено в него по имени.
_Avoid_: общий тип, shared-примитив, `Common`

**Понятие контекста (`<BC>.<Concept>`)**:
Модель, которую делят несколько агрегатов контекста и которая не сводится к одному значению:
правила и шаблоны расчёта с их реестром, кодеками и ошибками. Лежит своим каталогом уровня
контекста; usecases, проекций и репозиториев в нём нет — появились, и это агрегат или read-модель.
_Avoid_: общая модель, подмодель, `Common`, `Process`

**Композиционный корень (`MyAppApp`)**:
Граница приложения-потребителя, которая собирает его целиком: список контекстов, дерево процессов,
очередь, метрики, задачи релиза и mix-таски. Единственная граница, которой видны и контексты, и
web; от неё не зависит ни одна. Проекции, процессы и компоненты контекстов корень не перечисляет, а
собирает из объявлений контекстов.
_Avoid_: Application как имя корня, bootstrap, main, ядро

**Граница-сток (`MyApp.Infra`)**:
Граница приложения-потребителя без зависимостей на домен: `DAO` и namespace идентификаторов из
ключа. От неё зависят контексты, подсистемы и корень; web и граница входа — нет.
_Avoid_: инфраструктурный слой, shared, utils, common

**Граница входа (`MyAppIngest`)**:
Граница приложения-потребителя рядом с web, через которую входит внешняя система: подписчики её
брокера, разбор её формата, DLQ отклонённого. Точка входа, как web: зовёт usecases контекстов, а
её не зовёт никто. Есть только у приложения с таким входом.
_Avoid_: подсистема, интеграция, адаптер, consumer

**Подсистема приложения (`MyApp.<Subsystem>`)**:
Часть приложения вне доменных контекстов без собственных агрегатов — своя граница верхнего уровня:
хранилище файлов, интеграция с внешним сервисом. Контексты видит, как чужой контекст, — только
через их экспорт. Появился агрегат — это уже bounded context. От корня отличается тем, что
приложение не собирает, от стока — тем, что видит домен, от порта — тем, что свою работу делает
сама. Тип, который вводит модель контекста и который хранит его агрегат, — часть модели контекста,
а не подсистемы: подсистеме остаются её собственные типы.
_Avoid_: контекст, BC, модуль, сток

**Граница аксессора**:
Граница, в которой лежит аксессор текущего пользователя: контекст агрегата учётной записи, а без
такого агрегата — подсистема `MyApp.Auth`.
_Avoid_: контекст пользователей, Auth-граница, граница учётной записи

**Фабрика контекста (`MyApp.ContextFactory`)**:
Подсистема приложения-потребителя, в которой собирается контекст вызова единицы работы: эталонные
копии и учётная запись, от имени которой идёт вызов. Лежит над границей аксессора и под всеми,
кто её зовёт.
_Avoid_: ContextBuilder, хелпер контекста, Auth

**Механизм (механизм над моделью)**:
Работа над моделью одного контекста, которую зовут usecases всех контекстов, включая его
собственные: проверка доступа над моделью прав. В коде — порт и его реализация в контексте модели;
usecases называют механизму свой ключ — пространство разрешений, — а модель о них не знает.
_Avoid_: сервис, движок, каталог, подсистема

**Порт**:
Граница приложения-потребителя без `deps` на контексты: behaviour, который зовут контексты, а
реализует другая граница — контекст, который владеет моделью, или заглушка. Какую реализацию
получит вызов, решает композиционный корень. Пример — порт проверки доступа `MyApp.Authz` с
макросом декларации.
_Avoid_: адаптер, интерфейс, фасад, подсистема

**Модуль-оглавление (`MyApp.Domain.<BC>`)**:
Модуль с именем контекста рядом с его каталогом — корень границы контекста: `use Boundary` с
`deps` и `exports`, плагины кодека и ключи пространств разрешений, а `@moduledoc` — карта
контекста (агрегаты, акторы, read-модели, компоненты, связи с другими контекстами). Предметного кода
не держит.
_Avoid_: index, фасад контекста

**Объявления контекста (`<BC>.Supervision`)**:
Модуль контекста, который отдаёт корню приложения то, что тот поднимает и наблюдает: проекции,
процессы агрегатов, корни компонентов, их `watch_list` и списки для провайдеров метрик. Сам
процессов не поднимает и лежит отдельно от оглавления: от оглавления фасад кодека зависит на
компиляции.
_Avoid_: супервизор контекста, корень контекста, реестр контекста

**Поверхность (`MyAppWeb.<Api>`)**:
HTTP-API приложения со своим префиксом и пайплайном: у каждой свои версии со своими `ApiSpec` и
ресурсы.
_Avoid_: API, endpoint, фронт

**Метка процесса (`component`)**:
Стабильная строка, по которой метрики и алерты называют наблюдаемый процесс. Не выводится из имени
модуля и уникальна в списке наблюдаемых процессов приложения.
_Avoid_: имя процесса, тег

**Компонент**:
Набор процессов приложения с одним назначением под одним корневым супервизором: включается,
выключается и наблюдается целиком. Тумблер у него может быть и один; часть, без которой он
работает в ослабленном режиме, может иметь подчинённый тумблер внутри того же корня. Понятие времени выполнения, а не namespace: компонент
лежит у исполнителя — рядом с usecases, которые зовёт, а не у того, чьё событие его запускает.
_Avoid_: подсистема, сервис, воркер, поддерево

**Реакция**:
Компонент контекста, который в ответ на доменное событие своего или чужого агрегата зовёт usecases
своего контекста. Принадлежит реагирующему контексту, а не производителю события: производитель о
ней не знает.
_Avoid_: handler, listener, подписчик производителя, process manager

**Задача-следствие**:
Фоновая задача, которая завершает решение, уже закоммиченное вызывающим: аннулировать счёт
отменённого заказа. Исполняется от системной учётной записи; пользователь, чьё решение её
породило, — данные операции, а не её автор.
_Avoid_: задача пользователя, отложенная команда, джоба

**Отложенная команда пользователя**:
Фоновая задача, которая исполняет собственную операцию пользователя позже — от его имени и с
проверкой его прав в момент исполнения: отправка от его имени по расписанию, выгрузка его данных.
_Avoid_: задача-следствие, системная задача

**Actor (актор, `<Actor>`)**:
Инициатор операций в контексте — роль пользователя или системный процесс (фоновые задачи, импорт).
В коде — подкаталог в каталоге агрегата с модулем usecases актора; свои ReadRepo и представление —
только когда у актора свой доступ или своя форма данных. Актор, который действует от имени
учётной записи, носит её имя.
_Avoid_: роль, права, пользователь, срез

**Модуль usecases актора (`<Aggregate>.<Actor>.Usecases`)**:
Модуль с usecases одного актора над одним агрегатом в подкаталоге актора. Чтение, общее нескольким
акторам, — общий модуль чтения агрегата `<Aggregate>.Usecases`. Оба контекст экспортирует: чужой
контекст, web и точки входа зовут контекст через них.
_Avoid_: сервис, слой usecases, `Usecases.<Usecase>`

**Query (`<Aggregate>.Query`, `<ReadModel>.Query`)**:
Чтение без проверки доступа: его зовут usecases, которые доступ уже проверили, — свои или другого
контекста, для шага решения или чтобы дополнить свой ответ; тому, что читают другие контексты,
место в `exports`. Точки входа на него не ссылаются.
_Avoid_: запрос usecase, общий модуль чтения, `<ReadModel>.Usecases` для других контекстов,
обогащение, enrichment

**Aggregate (агрегат)**:
Единица изменения на write-пути: структура из Prim, которая держит инварианты, версионируется и
порождает события. Сама в базу и в брокер не пишет — это делает репозиторий.
_Avoid_: модель, entity, объект, сущность

**State-stored агрегат**:
Агрегат, чьё состояние хранится строкой таблицы, а случившиеся с ним события записываются рядом, в
той же транзакции. Источник истины — строка. События копятся в самом агрегате при мутации.
_Avoid_: облегчённый ES, audit-log, журнал аудита

**Event-sourced агрегат**:
Агрегат, чьё состояние восстанавливается из его событий. Источник истины — события, а не строка.
Новые события он не копит, а возвращает решением по команде.
_Avoid_: полноценный ES, ES-агрегат

**Незаведённый агрегат**:
Event-sourced агрегат, в потоке которого ещё нет событий: идентификатор есть, версии нет. Существует
ли он для команды, решает сам агрегат — создающую принимает, прочие отклоняет доменной ошибкой.
_Avoid_: blank, пустое состояние, пустой агрегат, новый агрегат

**Процесс агрегата**:
OTP-процесс, который держит в памяти состояние одного event-sourced агрегата и исполняет его команды по
одной. Состояние в нём — кеш: источник истины остаётся в хранилище событий, и процессов одного агрегата может
оказаться несколько.
_Avoid_: актор, aggregate server, GenServer агрегата, агрегат-процесс

**Команда**:
Данные с намерением изменить агрегат. Агрегат по ней меняется или отказывает доменной ошибкой:
event-sourced решает, какие события случатся, state-stored применяет мутацию. Сама команда логики не содержит
и ничего не меняет.
_Avoid_: command handler, message, request, изменяющий usecase

**Черновик события**:
То, что event-sourced агрегат возвращает решением по команде: какое событие случится и с какой нагрузкой.
Идентификатор, версию, автора и момент библиотека назначает при исполнении команды — до этого черновик ещё не
событие.
_Avoid_: событие, заготовка, результат decide

**Entity (сущность)**:
Роль в API мапперов Schema — то, что `to_entity` поднимает из строки, а `to_model` кладёт обратно.
В этой роли выступает агрегат или его дочерняя сущность.
_Avoid_: View, модель, DTO

**Read-модель**:
Именованный по назначению набор данных для чтения: его таблицы, репозиторий чтения и представление.
Может собирать данные нескольких агрегатов; у event-sourced агрегатов её таблицы пишет одна проекция.
Когда её строка — один агрегат, называется по нему и лежит в его каталоге, иначе — по назначению, в
своём каталоге уровня контекста. Таблицы у неё может и не быть: значение собирается на чтении.
_Avoid_: view-модель, отчёт, запрос

**View (представление)**:
Структура, в которой read-модель отдаётся: из примитивных значений, а не из Prim. Инвариантов не
держит, мутаций не имеет, обратного пути в агрегат у неё нет.
_Avoid_: DTO, модель, presenter, entity

**Usecase**:
Функция прикладного слоя, которую зовёт контроллер или воркер: изменяющий меняет состояние и
возвращает `:ok` или результат собственного выполнения (id созданного, версию после записи),
читающий — читает и возвращает `{:ok, T}`. Изменяющий usecase event-sourced агрегата, дождавшись
проекции по `wait:`, может отдать представление. Нормы — `20-agreements.md`.
_Avoid_: сервис, handler, interactor, экшен, команда, сценарий (слово домена потребителя)

## Хранение

Слово «репозиторий» значит здесь четыре разных вещи: `Repo` — контракт доступа к агрегату,
`Repo.Pg` — его реализация на Postgres, `ReadRepo` — отдельный модуль чтения со своей схемой,
`DAO` — единственный `Ecto.Repo`, который заводит у себя потребитель. Первые три оперируют доменом,
`DAO` — соединением и транзакцией. Нормы — `13-repos.md`.

**write-путь**:
Поток записи целиком: usecase → агрегат на Prim → `Schema.to_model!` → строка в базе, вместе с
записью событий в той же транзакции. Здесь значения проверены и инварианты действуют.
_Avoid_: Repo, командный репозиторий, запись

**read-путь**:
Поток чтения целиком: строка из базы → `Schema.to_view` → `View` → wire (у read-модели без таблицы
вместо строки — свёртка потоков write-репозиторием). Валидации на нём нет:
значение уже прошло запись, и поднимать на нём доменную ошибку было бы негде.
_Avoid_: ReadRepo, query-слой, чтение

**Repo (репозиторий записи)**:
Контракт доступа к агрегату: чтение перед мутацией и запись её результата — у state-stored строки
вместе с событиями, у event-sourced только событий. Знает домен и `Version`, не знает SQL.
_Avoid_: репо, DAO, сторадж, хранилище

**Repo.Pg**:
Реализация этого контракта на PostgreSQL: generic CRUD, синхронизация дочерних строк, запись
накопленных агрегатом событий.
_Avoid_: адаптер, драйвер, имплементация

**Хранилище событий (event store)**:
Место, куда пишутся события агрегатов с проверкой ожидаемой версии и откуда читается история
агрегата. Одно на приложение и общее для обоих видов агрегатов: у event-sourced это источник истины,
у state-stored — запись рядом со строкой.
_Avoid_: Repo, журнал, event log

**Поток событий**:
События одного агрегата в хранилище событий, упорядоченные по его версии. Адрес потока — тип агрегата
и идентификатор агрегата.
_Avoid_: stream, история, журнал агрегата

**Отказ хранилища (отказ записи событий)**:
Хранилище событий не приняло пачку: версия потока занята, сработал страж `xid` или нарушена
непрерывность. Не означает, что вызывающий видел устаревшее состояние: голова потока бывает ровно
там, где он её видел. Снимается повтором команды новой транзакцией — в отличие от сверки ожидаемой
версии.
_Avoid_: конфликт версии, гонка, расхождение версий

**Тип агрегата**:
Wire-имя вида агрегата в хранилище событий — первая часть адреса потока. Неизменяемо, как wire-тег
события.
_Avoid_: категория, stream type, имя таблицы

**Идентификатор из ключа**:
Идентификатор event-sourced агрегата, вычисленный из неизменяемого естественного ключа в области ключа и
namespace приложения, а не сгенерированный. Один ключ всегда даёт один поток, поэтому уникальность ключа
держит сам поток. Из персональных данных не вычисляется: идентификатор открыт, не уничтожается, и ключ по
нему перебором восстановим — такой ключ держит резерв ключа.
_Avoid_: детерминированный id, вычисляемый id, UUIDv5-id, stream id

**Внешний идентификатор**:
Идентификатор event-sourced агрегата, равный UUID внешнего источника, когда этот UUID и есть
неизменяемый естественный ключ. Не генерируется и не вычисляется: приходит от источника, и
уникальность между видами держит источник. Решение — ADR-0036.
_Avoid_: чужой id, external id, импортированный id

**Область ключа**:
Wire-имя, в пределах которого естественный ключ уникален, — оно разводит ключи разных видов: одинаковый ключ
в разных областях даёт разные идентификаторы из ключа и разные резервы ключа. Принадлежит ключу, а не типу
агрегата — один идентификатор из ключа бывает общим у нескольких агрегатов. Неизменяема, как тип агрегата.
_Avoid_: категория, префикс ключа, тип агрегата

**Резерв ключа**:
Запись о том, что изменяемый естественный ключ в своей области занят event-sourced агрегатом; в одной области
у агрегата не больше одного ключа. Ставится, переносится на новое значение и снимается в транзакции команды,
которая меняет ключ, поэтому две команды за один ключ не проходят обе. Принадлежит write-пути, а не
read-модели: проекция его не пишет, и пересборка его не трогает. Это не бронь с истечением — резерв держится,
пока агрегат владеет ключом. Занятость ключа — про его владельца; невозможность выяснить владельца при
конкурентной записи — другой исход, и с занятостью он не смешивается. Резерв ключа из персональных данных
значения ключа не хранит и снимается в транзакции, которая уничтожает ключ субъекта: ключ свободен снова.
_Avoid_: бронь, lock, claim, уникальный индекс, `unique_keys`

**Глобальная позиция**:
Место события в сквозном порядке всех потоков хранилища событий. Читатель по ней не пропускает событие
конкурентной записи, а внутри потока её порядок совпадает с порядком версий.
_Avoid_: offset, sequence, номер события, `$all`

**Проекция**:
Асинхронный обработчик событий хранилища событий, который строит read-модель в порядке глобальной
позиции. Побочных эффектов вне своей read-модели не имеет, а саму read-модель никто, кроме неё, не пишет,
поэтому историю можно прогнать через неё заново; реакция на событие с внешним эффектом — дело подписчика
брокера, а не проекции.
_Avoid_: подписчик, handler, consumer, reactor, синхронная проекция

**Чекпоинт**:
Глобальная позиция, до которой проекция обработала события, включительно. Меняется только вместе с
read-моделью проекции, поэтому уже обработанное событие в неё повторно не попадает.
_Avoid_: offset, last_seen, progress, закладка

**Отставание проекции**:
Время от самого раннего события хранилища событий, которое проекция ещё не обработала, до текущего момента.
Пока проекция успевает за записью, оно близко к нулю; при пересборке равно возрасту ещё не пройденной части
истории и убывает по мере прогона.
_Avoid_: лаг, lag, backlog, задержка проекции

**Ожидание проекции**:
Ожидание usecase'ом, пока проекция обработает последнее событие потока агрегата на момент вызова или
событие заданной версии, в том числе ещё не записанное, — чтобы чтение увидело уже записанное или
итог реакции другого контекста, версия которого известна заранее. Изменяющий usecase ждёт после
commit, вне транзакции, читающий — до чтения; оба — только по `wait:` вызывающего. У HTTP его задаёт
`Prefer` клиента, у реакции другого контекста — сама реакция.
_Avoid_: синхронная проекция, read-after-write (как имя действия), подтверждение записи

**Пересборка проекции**:
Повторный прогон всей истории хранилища событий через проекцию: её read-модель очищается, а чекпоинт
возвращается в начало. Пока пересборка идёт, read-модель неполна. Построить read-модель заново без
неполного окна можно только новой проекцией под новым именем — это уже не пересборка.
_Avoid_: replay, reset, rebuild, перепроигрывание, миграция проекции

**Снапшот**:
Сохранённое состояние event-sourced агрегата на известной версии его потока: свёртка начинается с него, а не
с начала потока. Источником истины не является — удалить его можно в любой момент.
_Avoid_: кеш состояния, shadow copy, эталонная копия, memento, состояние процесса агрегата

**ReadRepo (репозиторий чтения)**:
Отдельный модуль чтения со своей Ecto-схемой и своими Specs, отдающий представление, а не агрегат.
Кеш read-модели бывает только у него.
_Avoid_: Repo, query-репозиторий, read-путь

**Repo.Sc (shadow copy, эталонная копия)**:
Копия агрегата на момент последнего чтения или успешной записи в рамках контекста: по ней на
записи видно, изменилось что-нибудь или нет. Обновляет её тот, кто читает или пишет.
_Avoid_: снапшот, кеш, дифф, оригинал

**DAO**:
Единственный `Ecto.Repo` приложения-потребителя, обёрнутый под after-commit хуки; лежит в
границе-стоке (`MyApp.Infra.DAO`). Библиотека получает его из конфигурации, а не объявляет сама.
_Avoid_: Repo, репозиторий, коннекшн, пул

**Schema (Ecto-схема)**:
Модель строки таблицы вместе с мапперами между строкой и доменом: `to_entity` / `to_model` на
записи, `to_view` на чтении.
_Avoid_: модель, таблица, entity, маппер

## События и доставка

Одно событие существует в четырёх формах, и в разговоре все четыре зовут «событием»: `Es.Event` в
памяти агрегата, конверт после `dump`, запись в таблице outbox, сообщение в брокере. Форму стоит
называть, потому что правила у них разные: конверт неизменяем, запись имеет статус доставки,
сообщение переживает код, который его написал. Нормы — `14-events-outbox.md`.

**Es.Event (доменное событие)**:
Факт, случившийся с агрегатом: идентификатор и версия агрегата, время, автор и нагрузка. Порождает
его агрегат, записывает репозиторий.
_Avoid_: ивент, message, команда, уведомление

**Семейство событий агрегата**:
Семейство (union) всех событий одного агрегата. Оно называет, чей идентификатор несут его события
и кто бывает их автором; событие принадлежит ровно одному семейству, а кодек событий агрегата
читает и пишет события одного семейства.
_Avoid_: базовое событие, тип событий, `Event`-модуль

**Событие-контракт**:
Доменное событие, экспортированное контекстом-производителем: другой контекст того же приложения
читает его модули, семейство и топик производителя, а не отдельное сообщение. Интеграционное
событие — другая форма, для системы вне приложения, а не синоним.
_Avoid_: публичное событие, DTO, внешний контракт

**Интеграционное событие**:
Сообщение для системы вне приложения, форму которого задаёт потребитель, а не кодек событий агрегата.
Персональные данные в нём уходят открытыми — это их передача третьему лицу, и уничтожение ключа
субъекта до получателя не доходит.
_Avoid_: событие-контракт, внешнее событие, публичное событие

**Конверт (wire-конверт события)**:
Результат `dump` события: `event_id`, `type`, `aggregate_id`, `aggregate_version`, `at`, `by`,
операция, сеанс инициатора, основание и нагрузка. Формат неизменяем — историю читает сегодняшний
код; ключа, которого не было при записи, у старого конверта нет, и он читается пустым.
_Avoid_: envelope, payload, JSON, тело

**Операция**:
Одно изменение, сделанное за одну транзакцию записи: все события этой транзакции, в том числе
нескольких агрегатов, принадлежат одной операции. Отвергнутая и повторённая транзакция — новая
операция.
_Avoid_: команда (это намерение, а не случившееся изменение), запрос, correlation id

**Основание**:
Операция, на событие которой реагирует текущая операция: связь реакции с причиной, звено к звену.
Корня цепочки у операций нет. У операции по запросу пользователя основания нет.
_Avoid_: causation id (он указывает на событие), причина (это поле нагрузки), родитель

**Сеанс инициатора**:
Сеанс пользователя, из которого пришёл запрос, вызвавший операцию. Что считать сеансом, решает
потребитель; у операции Системы сеанса нет.
_Avoid_: сессия, session cookie, токен

**Апкаст**:
Приведение записанного события к текущей схеме при чтении: старый тег и форма нагрузки становятся
текущими, а сама запись в хранилище событий не меняется.
_Avoid_: миграция событий, upgrade, конвертер, переписывание истории

**Запись outbox**:
Строка в таблице outbox, поставленная в одной транзакции с состоянием агрегата: topic, ключ, имя,
конверт, заголовки и статус доставки (`:new → :in_work → :published | :failed`).
_Avoid_: очередь, задача, job, событие

**Сообщение брокера**:
Запись в топике брокера: ключ, заголовки и тело — байты, формат которых библиотеке не известен; у
удаления в компактном топике тела нет. Публикует его поллер из записи outbox (тогда тело — JSON
конверта) или внешний источник, чей формат знает только потребитель. Подписчик обязан пережить
сообщение, чей тип он больше не знает.
_Avoid_: событие, payload, пакет, письмо

**Позиция источника**:
Место сообщения брокера в топике, из которого его прочитали: партиция и смещение. Есть только у
прочитанного сообщения; по ней оператор находит сообщение у источника.
_Avoid_: offset, cursor, чекпоинт, глобальная позиция

**Заявка на готовность**:
Разовая просьба подписчика к читателю брокера: сообщить, когда появится что читать. Подписчик
оставляет её, прочитав всё; читатель отвечает один раз и забывает её. У читателя одна заявка —
новая заменяет прежнюю. Инициатива у получателя, а не у отправителя: этим заявка и отличается от
пробуждения поллера и читателя проекции, адресата которого находит записавший.
_Avoid_: wake, пробуждение, подписка, callback

## Подписи

Событие — факт для кода; человеку его показывают названием и сведениями, тексты которых объявлены
в домене рядом с тем, что они называют. Страница событий агрегата для человека («история») —
понятие потребителя: библиотека даёт ей событие страницы событий, название, сведения и словарь ссылок. Нормы —
`11-domain.md` и `app/11-domain.md`, «Подписи», решение — ADR-0063.

**Подпись**:
Текст для человека, объявленный рядом с тем, что он называет: полем struct'а, значением Enum.
Описание значения в `@moduledoc` Enum подписью не служит: оно объясняет смысл разработчику.
_Avoid_: label, лейбл, заголовок, описание

**Название события**:
Подпись вида события: одна на модуль события и без подстановок — переменное живёт в сведениях.
_Avoid_: title, тип события, имя события, тег

**Сведения события**:
Дерево подписанных значений нагрузки события, у каждого значения — его вид: текст, число, дата,
ссылка, группа, список, изменение «было → стало». Id в сведениях — ещё не ссылки.
_Avoid_: details, детали, описание, payload

**Ссылка на запись**:
Id записи, упомянутой в сведениях, с видом записи и её текущим именем; имени может не быть.
_Avoid_: ref, EntityRef, внешний ключ

**Ссылка на учётную запись**:
Id учётной записи — автора события или упомянутой в нагрузке — с её текущим именем для человека.
Чем это имя служит (логин, ФИО), решает потребитель.
_Avoid_: UserRef, ссылка на пользователя

**Словарь ссылок**:
Текущие имена всех id, упомянутых на странице событий, собранные пачкой по типу id.
_Avoid_: refs, кеш имён

**Событие страницы событий**:
Форма события для клиента страницы событий: идентификатор, агрегат, версия агрегата, тег, машинная
нагрузка, момент и автор, а при подписях — название и сведения. Это не конверт: его форма — контракт
API приложения, а не неизменяемая запись истории.
_Avoid_: конверт, запись истории, EventDTO, history item

## Персональные данные

История событий неизменяема, поэтому персональные данные в ней не стираются, а делаются
невосстановимыми. Это не скрытие значения в логах и ошибках (чувствительный Prim) и не
конфиденциальность одним общим ключом (`Core.Security.Secret`): ни то, ни другое данные не
уничтожает.

**Субъект данных**:
Физическое лицо, чьи персональные данные встречаются в событиях — в потоке любого агрегата, не только
своего. Единица уничтожения: данные уничтожаются по субъекту, а не по агрегату или полю; агрегат
совпадает с субъектом лишь в частном случае.
_Avoid_: владелец данных, пользователь, data subject, поток

**Идентификатор субъекта**:
UUID, которым событие называет субъекта своих персональных данных: id агрегата или поле нагрузки, но
не автор события. Лежит в событии открыто и сам персональными данными не является. Одно лицо под
двумя несвязанными идентификаторами — два субъекта.
_Avoid_: subject id, владелец, автор, `by`

**ПДн-значение**:
Значение поля нагрузки события, которое целиком — персональные данные одного субъекта и потому лежит
в истории и в сообщениях о событии только зашифрованным под его ключом. Субъект у значения ровно один;
значение с данными нескольких лиц не делится, субъекта выбирает автор события.
_Avoid_: зашифрованное поле, чувствительное поле, sensitive

**Ключ субъекта**:
Единственный ключ, под которым лежат все персональные данные одного субъекта, в каком бы потоке они
ни встретились. Уничтожается только целиком: частичного уничтожения, по цели или по полю, нет.
_Avoid_: ключ агрегата, ключ потока, ключ поля, DEK

**Хранилище ключей**:
Держит ключи субъектов и само зашифровывает и расшифровывает ПДн-значения: ключ субъекта его не
покидает. Оно же скрывает значение в резерве ключа из персональных данных своим секретом, который
тоже его не покидает. Отвечает, уничтожен ли ключ, и отличает уничтоженный ключ от ключа, которого не знает.
Подменяется целиком — например, сертифицированным средством шифрования.
_Avoid_: KMS, vault, keyring, кеш ключей

**Уничтожение ключа субъекта**:
Действие, после которого содержание персональных данных субъекта нельзя восстановить ни в одной
форме, которую хранит или передаёт библиотека: шифротекст остаётся, ключа к нему нет. Окончательно:
новые персональные данные субъекта после него не записываются, данные того же лица по новому
согласию — под новым идентификатором субъекта. Слово — из 152-ФЗ; «удаление» закон называет другой
операцией.
_Avoid_: удаление, стирание, забвение, shred

**Уничтоженное ПДн-значение**:
ПДн-значение, ключ субъекта которого уничтожен: поле в событии на месте, содержания нет. Событие с
ним остаётся читаемым, а само значение отличимо и от настоящего, и от отсутствующего. Ключ, который
хранилище не нашло или не смогло выдать, значение уничтоженным не делает: это сбой, а не уничтожение.
_Avoid_: забытое значение, стёртое значение, пустое значение, redacted, masked

**Событие уничтожения ключа**:
Запись в истории событий о том, что ключ субъекта уничтожен; её делает само уничтожение. По ней read-модель
перестаёт держать персональные данные субъекта, сохранённые раньше: иначе о таких строках проекция не узнаёт.
Это не событие агрегата и не акт об уничтожении.
_Avoid_: tombstone, forget event, сигнал уничтожения

## Ошибки

Отказ описывают два разных понятия, и оба в разговоре зовут «ошибкой»: одна ошибка может
объяснять другую («почему»), а может стоять рядом с другой («что ещё не так»). Первое линейно,
второе плоско; смешение даёт дерево, которого не несут ни обёртка ответа, ни обработчики на
границе. Нормы — `12-errors.md`, решение о форме — ADR-0021.

**Цепочка причин**:
Последовательность ошибок «почему»: отказ на границе, под ним — отказ, который его вызвал.
Линейна, читается от внешней к корневой; клиенту уходит только внешняя, целиком — в лог.
_Avoid_: стек, трассировка, история, вложенные ошибки

**Множество ошибок**:
Несколько независимых отказов одной операции, собранных в одну ошибку: невалидные поля формы,
провалившиеся элементы пачки. Элементы друг друга не объясняют — этим отличается от цепочки
причин; порядок входа сохраняется для читаемости, вложенности нет.
_Avoid_: список ошибок, агрегированная ошибка, batch-ошибка

**Обёртка ответа**:
Общая форма JSON-тела HTTP-ответа: признак исхода (успех или ошибка) и данные; у ошибки — ещё
код и текст для человека. Одна на все ответы с телом, включая ошибки, не дошедшие до контроллера.
_Avoid_: конверт, envelope, схема ответа

**Константа границы**:
Код ошибки в обёртке ответа, который задаёт сама граница HTTP, а не каталог ошибок домена: отказ
аутентификации, непредвиденный сбой, ошибка до контроллера, нарушение спеки запроса. Не несёт
пространства имён — этим отличается от кода доменной ошибки.
_Avoid_: системный код, служебный код, код статуса

## Сбои

**Критическая ошибка**:
Отказ приложения выполнить запрос по его собственной вине — не из-за неверного запроса, прав или
временной перегрузки. Пользователь получает общий текст без подробностей и, если запись о ней
создана, идентификатор ошибки.
_Avoid_: ошибка сервера, падение, исключение, внутренняя ошибка

**Идентификатор ошибки**:
Номер записи о критической ошибке в службе учёта ошибок, который пользователь получает в ответе и
передаёт, чтобы по нему нашли запись. Без записи в службе идентификатора нет.
_Avoid_: код ошибки (это вид отказа), номер ошибки, event id

**Служба учёта ошибок**:
Внешняя система, которая собирает записи о критических ошибках и сбоях фоновой работы и ищет их
по идентификатору ошибки. Развёрнута вне приложения.
_Avoid_: трекер ошибок, Sentry, мониторинг

**Падение процесса**:
Сбой фоновой работы: процесс (GenServer, Task, подписчик) завершился из-за исключения. Запись о
нём уходит в службу учёта ошибок со stacktrace, без идентификатора ошибки — его некому показать.
_Avoid_: краш, crash-репорт, критическая ошибка (это отказ на запрос)

**Внешний вызов**:
Обращение приложения к системе вне его границ (платёжный шлюз, касса, служба доставки, SMS) с
закрытым множеством исходов: выполнен, таймаут, система недоступна, система отказала. Исход
определяет вызывающий: смысл ответов конкретной системы библиотеке не известен.
_Avoid_: порт (это граница внутри приложения), подсистема, интеграция, HTTP-запрос

## Жизненный цикл приложения

Нормы совместимости защищают то, что уже выкачено; до выката защищать нечего. Нормы —
`app/00-index.md`, решение — ADR-0035.

**Первый релиз**:
Момент, когда у приложения появилась база, которую нельзя пересоздать, или потребитель любого его
контракта (API, топик, wire событий) вне команды — что раньше. Один на приложение, а не на контракт;
с него действуют нормы совместимости. Состояние записано строкой локального свода приложения.
_Avoid_: первый выкат, первый деплой, go-live, прод

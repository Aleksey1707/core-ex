# 03: Корень и сток — границы и имена

**What to build:** приложение-потребитель собирается из корня `MyAppApp` — одной границы с `Application`, списком
контекстов, outbox, PromEx, сервером метрик, задачами релиза и mix-тасками. Инфраструктура — граница-сток
`MyApp.Infra` с `DAO` и `StreamID`, недоступная web. Проекции, процессы агрегатов, плагины кодека и `watch_list`
корень собирает из объявлений контекстов; `MyApp.Projections` и `MyApp.Processes` исчезают.

## Comments

- Уточнено с мейнтейнером: обвязка `test/support/` — `MyAppTest.DataCase`, `MyAppTest.ConnCase` (ConnCase
  уходит из `MyAppWeb`: в границе web фикстуры контекстов ей недоступны); список контекстов —
  `MyAppApp.contexts/0`, сборка — `MyAppApp.Application` (`projection_opts/0`, `processes/0`,
  `process_opts/1`, `watch_list/0` — он же провайдер `Core.Workers.PromEx`); опции дерева проекций — ключ
  `Core.Es.Projection.Supervisor`; дети контекстов стартуют после разделяемой инфраструктуры, включая
  планировщик задач, `contexts/0` — в порядке зависимостей; `MyAppWeb` — MUST `check: [aliases: true]`.
- `boundary` без `check: [aliases: true]` не видит `Transact.run(DAO, …)` в web (замечание тикета 01) —
  проверено сценарием фикстуры `ConsumerWeb`: без опции маркер остаётся без предупреждения, с ней —
  `forbidden reference to Consumer.Infra.DAO`; вызов экспортированного usecase и паттерн `%Account.ID{}`
  ложных срабатываний не дают.
- Фикстура: граница сценариев `Consumer.S` → `ConsumerTest` (строка `MyAppTest`), `Consumer.Foreign` —
  подсистема, `ConsumerWeb` — web. Сценарий C1l держит имя `.beam` ровно на пределе 255 байт: `+2` символа
  `ConsumerTest` компенсированы снятием добивки `X` с двух сегментов длинного имени.
- Рантайм-объявления — модуль `MyApp.Domain.<BC>.Supervision`, а не оглавление (уточнено с мейнтейнером после
  ревью): фасад зависит от оглавления на компиляции (`codec_plugins/0`), и ссылки оглавления на проекции и
  корни компонентов, которые зовут фасад, давали compile-connected цикл — на проекте-пробнике правка воркера
  пересобирала фасад, после выноса объявлений цикла нет. `contexts/0` перечисляет модули `Supervision`; кодек
  склеивает плагины своим литеральным списком оглавлений: вызов через переменную компилятор не отслеживает.
- Списки для провайдеров метрик названы: `readers/0`, `kafka_readers/0`, `caches/0` — обязательны в каждом
  контексте, если приложение подключает соответствующий плагин.
- Префикс telemetry репозитория Ecto выводится из имени модуля: `MyApp.Infra.DAO` даёт
  `[:my_app, :infra, :dao]` и метку `repo` `MyApp.Infra.DAO` — записано в пункт тикета 01 в CHANGELOG.
- Не решено: `MyApp.ContextFactory` остался строкой таблицы namespaces, но `MyApp` не граница — модуль вне
  границ. Своя граница-подсистема даёт цикл с контекстом учётной записи (его воркеры берут актора у
  фабрики); у потребителя A решение Q18 — экспорт контекста учётной записи рядом с аксессором
  `CurrentUser`. Для всех потребителей место не решено — тикет 09.
- Модуля `Sales.Supervision` у фикстуры нет: корня у фикстуры нет, склеивать объявления некому (как и
  `codec_plugins/0` после тикета 02).
- Нового ADR о корне и стоке тикет не заводит (только пометка в ADR-0024); «Цена» ADR-0037 о модуле,
  переданном значением, для web снята `check: [aliases: true]` — ADR не правится, норма в `app/10`.

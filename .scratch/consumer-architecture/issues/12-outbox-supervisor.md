## Agent Brief

**Category:** enhancement
**Summary:** готовое дерево очереди `Core.Outbox.Supervisor` вместо корня очереди, который пишет каждый потребитель;
wake — по отметке дерева.

**Current behavior:**
Библиотека даёт процессы `Core.Outbox.Poller`, `Core.Outbox.Cleaner`, доставку `Core.Outbox.Delivery.Mq` и две
публичные проверки старта — `Core.Outbox.check_singleton!/1` и `Core.Outbox.validate_partition!/1`. Супервизор
очереди (writer → поллер(ы) → cleaner, `rest_for_one`) пишет приложение; свод требует звать из него обе проверки,
вызов `check_singleton!/1` держит ратчет `app/19`. После вставки в очередь `Core.Outbox.Repo.Pg` будит поллеры,
на каждый вызов читая `poller_name` / `pollers` из `config :core, Core.Outbox`; `Poller.wake/1` на отсутствующий
процесс отдаёт `:ok`.

**Desired behavior:**
Всё, что ниже, — ADR-0045, «Решение»; при расхождении брифа с ADR прав ADR.

- `Core.Outbox.Supervisor` — супервизор `rest_for_one`, одно дерево на ноду. Дети по порядку: необязательное
  соединение `connection: {mod, opts}` → для каждого элемента `pollers:` в его порядке — writer-процесс (если
  элемент задан через `writer:`) и поллер → один cleaner.
- Опции. Обязательные: `enabled:` (boolean), `cluster_query:` (без дефолта; `nil`, `:ignore`, `""` —
  кластеризации нет), `repo:`, `pollers:`, `poll_interval_ms:`, `idle_min_ms:`, `batch_size:`,
  `lock_duration_seconds:`, `max_attempts:`, `published_ttl_seconds:`, `cleaner_interval_ms:`. Tunables —
  положительные целые; в Prim (`BatchSize`, `LockDuration`, `Attempts`, `PublishedTTL`) их оборачивает дерево.
  Необязательные: `allow_cluster:` (по умолчанию `false`), `context_factory:` (по умолчанию `&Context.new/0`, одна
  на поллеры и cleaner), `connection:`. Неизвестная опция, отсутствие обязательной, недопустимое значение —
  `ArgumentError` (по образцу `Core.Helper.StartOpts` и `Core.Es.Projection.Supervisor`). Config и env дерево не
  читает.
- Элемент `pollers:` — keyword: `name:` (атом, обязательная), `topics:` (`Core.Outbox.topics_filter()`, по
  умолчанию `:all`), `label:` (непустая строка, обязательная, уникальна в списке) и ровно один из двух ключей:
  - `writer: {mod, opts}` — writer-процесс, который дерево поднимает своим ребёнком перед этим поллером; доставка
    поллера — `Delivery.Mq.new(mod, Keyword.fetch!(opts, :name))`;
  - `via: {mod, name}` — процесс, которым владеет приложение (Kafka-клиент); ребёнка нет, доставка —
    `Delivery.Mq.new(mod, name)`.

  Оба ключа или ни одного, дубль `name:` или `label:` — `ArgumentError`. Опций `delivery_module:` / `delivery:`
  у дерева нет.
- `start_link/1` проверяет опции при любом `enabled:`, затем единственность на кластере (логика нынешнего
  `check_singleton!/1`: `enabled:`, `cluster_query:`, `allow_cluster:`) и непересечение фильтров поллеров (логика
  `validate_partition!/1`). Полнота разбиения не проверяется. `enabled: true` при `pollers: []` — `ArgumentError`.
  `enabled: false` — `:ignore` с `info` «отключён»; старт — `info` «запущен».
- До подъёма детей, в том числе при `:ignore`, дерево пишет в `:persistent_term` отметку: имена и фильтры
  топиков поднимаемых поллеров (при `:ignore` — пусто). Wake после вставки в `Core.Outbox.Repo.Pg` читает только
  отметку; без отметки не будит никого. `config :core, Core.Outbox` библиотека не читает нигде.
- `Core.Outbox.Poller.init/1`, не найдя своего `name` в отметке дерева, отказывает `ArgumentError` с текстом, что
  поллер стартует только из `Core.Outbox.Supervisor`.
- `Core.Outbox.Supervisor.watch_list/1` принимает те же опции, что `start_link/1`, и отдаёт элементы в форме
  `watch_list/1` дерева подписчика: `outbox_connection` (если задан `connection:`), `outbox_writer:<label>` (только
  для `writer:`), `outbox_poller:<label>`, `outbox_cleaner`; при `enabled: false` — `[]`.
- `check_singleton!/1` и `validate_partition!/1` уходят из публичного API `Core.Outbox` (приватные детали дерева
  или его внутренний модуль с `@moduledoc false`). `topics_match?/2` и `topics_overlap?/2` — как есть.
- Нормы:
  - `14-events-outbox.md` (библиотечный свод): lifecycle очереди — дерево, wake по отметке, ключ `:core` не
    читается; «Единственность поллера» — проверки внутри дерева;
  - `app/14`, «Единственность поллера»: проверки делает дерево, ратчета нет; топики вне фильтров поллеров ждут
    в `pending` — так выключается транспорт, цена видна метриками `Core.Outbox.PromEx`; «Конфигурация»: ключ
    `config :my_app, Core.Outbox.Supervisor`, библиотека из него ничего не читает, тестовый overlay —
    `enabled: false` без `poller_name`;
  - `app/17`: свой супервизор очереди — `MUST NOT`; очередь — пример «Готового дерева без корня» рядом с деревом
    проекций; опции собирает одна функция `MyAppApp.Application.outbox_opts/0` из
    `config :my_app, Core.Outbox.Supervisor`, её же принимает `watch_list/1`; «Тумблер компонента» — фраза
    «тумблер очереди — под `:core`» уходит; соединение с одним пользователем у очереди — опция `connection:`;
    тумблер транспорта поллера учитывает сборка списка `pollers:`; пример «поддерево с внутренним порядком
    (writer → поллер → cleaner)» — заменить;
  - `app/19`, «Ратчеты»: строка «корень очереди зовёт `check_singleton!/1`» уходит;
  - прочие упоминания `MyAppApp.Outbox`, `check_singleton!`, `validate_partition!`, `poller_name`,
    `config :core, Core.Outbox` в `docs/rules/**`, `README.md`, `@moduledoc` библиотеки — привести к ADR-0045;
    `app/00-index.md` — таблица устаревших форм, если в ней есть строки об очереди.
- CHANGELOG, «Не выпущено» → «Ломающие изменения контракта»: один пункт — что изменилось, почему (ADR-0045) и
  перевод потребителя «было → стало»: рукописный корень очереди → `{Core.Outbox.Supervisor, outbox_opts()}` в
  `Application`; `config :core, Core.Outbox` → `config :my_app, Core.Outbox.Supervisor` с новыми именами опций
  (`poller_name` / `pollers` → элементы `pollers:` с `writer:` / `via:` и `label:`, `reference_prefix` → в опции
  writer'а); `check_singleton!/1` / `validate_partition!/1` удалены; имена компонентов `watch_list`.

**Key interfaces:**
- `Core.Outbox.Supervisor.start_link/1`, `child_spec/1`, `watch_list/1` — новые, с `@doc` / `@spec`; `@moduledoc`
  с разделами «Opts» и «Старт» по образцу `Core.Es.Projection.Supervisor`
- `Core.Outbox.Poller.init/1` — новый отказ вне дерева
- `Core.Outbox.Repo.Pg` — источник целей wake: отметка дерева вместо Application env
- `Core.Outbox.check_singleton!/1`, `Core.Outbox.validate_partition!/1` — уходят из публичного API

**Acceptance criteria:**
- [ ] при `enabled: true` дерево поднимает детей в порядке connection → (writer, поллер) по элементам → cleaner;
      падение writer'а перезапускает его поллер и всё ниже (`rest_for_one`)
- [ ] элемент с `via:` не поднимает ребёнка, его поллер пишет через указанный процесс
- [ ] `enabled: false` — `:ignore`, детей нет, `watch_list/1` — `[]`, wake после вставки — no-op
- [ ] каждый отказ старта даёт `ArgumentError`: неизвестная / отсутствующая опция, отсутствие `cluster_query:`,
      оба или ни одного из `writer:` / `via:`, дубль `name:` или `label:`, пересечение фильтров, `enabled: true`
      с `pollers: []`, включённая очередь в кластере без `allow_cluster: true`; проверки опций — и при
      `enabled: false`
- [ ] `allow_cluster: true` в кластере — старт с `warning`, как у нынешней проверки
- [ ] вставка записи будит только поллер, чей фильтр совпал с топиком, по отметке дерева; при выставленном
      `config :core, Core.Outbox, poller_name: …` без дерева wake ничего не делает
- [ ] `Core.Outbox.Poller` вне дерева не стартует: `ArgumentError`
- [ ] `watch_list/1` отдаёт элементы с метками `outbox_connection`, `outbox_writer:<label>`,
      `outbox_poller:<label>`, `outbox_cleaner`, без элементов для `via:`
- [ ] тесты библиотеки и сценарий очереди фикстуры-потребителя (`make consumer-check`) поднимают поллер через
      дерево; тесты нынешних `check_singleton!/1` / `validate_partition!/1` перенесены на дерево
- [ ] в `lib/` нет чтения `Application.get_env(:core, Core.Outbox …)`
- [ ] нормы и CHANGELOG — как в «Desired behavior»; `make` зелёный

**Out of scope:**
- лидер-элекция поллеров между нодами
- проверка полноты разбиения топиков
- проверка единственности для компонента, который не очередь (ADR-0043, «Цена»)
- переезд потребителей на дерево — их собственная работа после выпуска
- `Core.Outbox.PromEx` и `Core.Workers.PromEx` — без изменений, кроме имён компонентов, которые отдаёт `watch_list/1`

# 06: Авторизация — порт, ключи пространств у контекста

**What to build:** проверка доступа — порт `MyApp.Authz` (behaviour и макрос декларации) в своей границе без
зависимостей на контексты. Реализация — контекст прав или заглушка, выбор — в корне. Контекст объявляет ключи своих
пространств; макрос проверяет ключ при компиляции; корень собирает реестр для реализации. Контрактный набор тестов
обязателен для боевых реализаций, тестовая реализация порта — вне него.

**Blocked by:** 01, 03

**Status:** done

## Comments

- Уточнено с мейнтейнером: реализацию и реестр называет ключ `config :my_app, MyApp.Authz`
  (`impl:`, `namespaces:` — MFA корня `{MyAppApp, :authz_namespaces, []}`) в `config.exs`, порт
  читает его в рантайме; тестовая реализация — мок Mox `MyAppTest.Authz` (тест usecase —
  `async: true`), интеграционный тест операции — `Mox.stub_with/2` на боевую (`async:` — по модели
  прав); оглавление контекста макрос выводит из имени модуля актора, а не из опции `context:`.
- Проверено на копии `fixtures/consumer` (в репозиторий не вошла): `compile_env` в порте —
  `forbidden reference` порта на модуль реализации; `Application.fetch_env!/2` — без предупреждений.
  Сверка ключа из тела макроса при правке оглавления не пересобирается (`require` даёт только
  зависимость по экспорту), сверка в теле модуля актора — пересобирается и даёт `CompileError` на
  удалённый ключ. Отсюда нормы «рантайм-резолв» и «сверка в теле модуля» в `app/10`.
- Выведено из норм свода без отдельного вопроса: `MyAppApp.Application.start/2` зовёт
  `MyApp.Authz.validate!/0` («Старт проверяет конфигурацию до подъёма дерева»); каталог отказа
  `MyApp.Authz.Errors` — в порте и в его `exports` (ошибку строит реализация в контексте прав,
  `app/12`, «Словарь `ns`»); заглушка `MyApp.Authz.Stub` — в порте (контекст без агрегатов
  запрещён); реализация — `MyApp.Domain.<BC>.Authz` в каталоге уровня контекста, вне `exports`.
- `rules/19`: MUST общего набора — на боевые реализации; тестовая реализация (мок порта, дублёр
  внешней системы) — вне него, расхождение мока с боевой ловит интеграционный тест операции.
- `app/13`, «Read-модель»: «механизм проверки прав» → «реализация порта проверки доступа»;
  `app/10`, «Состав контекста», и `CONTEXT.md`, «Подсистема приложения»: «реестр прав» убран из
  примеров подсистемы.
- Фикстура не менялась: порт — код потребителя, библиотека его не поставляет; Boundary-сценарий
  «контекст ссылается на реализацию» повторил бы `scenarios/foreign.ex`.
- ADR — новый `0042-authz-port.md`, в ADR-0025 — пометка о замене пунктов.
- После ревью: `app/13`, «DI» — исключение из `compile_env` для порта; `app/17`, «Дерево
  процессов» — `MyApp.Authz.validate!/0` в закрытом списке `start/2`, `MyApp.Authz` в `deps` корня
  примера; порт — не подсистема (`app/10`, «Состав контекста»; `CONTEXT.md`); интеграционный тест
  операции — MUST только при реализации в контексте прав; разбор отвергнутых вариантов из
  «Проверки доступа» ушёл в ADR-0042, у норм — ссылка; пример порта — опции через
  `Core.Helper.Opts`, `@doc`/`@spec`, `# ---`; `rules/19` ↔ `app/19` — без дубля, `app/19`
  ссылается; `CONTEXT.md` — определения без норм, оглавление несёт ключи пространств.

берёт топик из неё, литерала топика у него нет. Функция следует нормам генерируемых функций.

## Comments

- `topic/0` → `String.t()`: строкой топик берут `topic:` подписчика и `topics:` поллера, читателю брокера —
  `Core.Mq.Topic.new!/1` над ней; так же кодек событий отдаёт `type/1`. Результат — литерал из опции, поэтому
  граница типов (`rules/20`, «Генерируемые функции») выполнена без `generated: true`.
- Порядок с `es-type-safety/11`: тикеты независимы. `topic/0` без аргументов и с литеральным результатом
  сужения не требует; открытые головы и несуженный результат `from_event/1` / `from_events/1` остаются тикету 11,
  запись `DEBT.md` о `Core.Es.Outbox` верна для них.
- Фикстура: сценарий `scenarios/outbox.ex` — топик, принятый за Prim (`Core.Mq.Topic.value/1` над результатом),
  ловится сборкой; `Account.Outbox` и `Order.Outbox` — в `exports` контекста `Sales`.
- Сверх тикета: `app/10` — модули outbox в составе `exports` и в примере оглавления; `rules/14` — `topic/0` в API
  `<Aggregate>.Outbox`; `app/00` — строка устаревшей формы «литерал топика у подписчика».
- После ревью: норма подписчика в `app/14` — последним пунктом, сразу над примером; `CONTEXT.md` — определение
  без нормы, «интеграционное событие» — отдельная форма, а не синоним; CHANGELOG — занятое имя `topic/0`.

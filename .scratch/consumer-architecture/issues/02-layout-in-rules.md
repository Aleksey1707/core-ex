# 02: Раскладка контекста по всему своду

**What to build:** свод библиотеки и ярус потребителя описывают вертикаль целиком: read-модель агрегата и по
назначению, подкаталог актора со своим ReadRepo и View, `values/`, `errors.ex`, операцию над равноправными агрегатами,
запись двух контекстов и join между контекстами. Примеров с `Common` и срезами в своде, README и документации модулей
не остаётся.

**Blocked by:** 01

**Status:** done

**Spec:** [Контекст — граница Boundary, раскладка — вертикаль по агрегату](../spec.md) — «Раскладка», «Направления»,
«Объявления контекста»

## Comments

- Уточнено с мейнтейнером: запись в главный и подчинённый лежит в каталоге того агрегата, чей id
  пришёл командой (селектор `app/10` прежний, Q25 «в каталоге главного» — его частный случай);
  репозиторий записи актора state-stored агрегата остаётся (`<Aggregate>.<Actor>.Repo`, `get` под
  ACL-фильтром) — `app/10` после тикета 01 его умалчивал; реестр плагинов — MUST через
  `codec_plugins/0` оглавления; аксессор `CurrentUser` — в каталоге агрегата учётной записи.
- Q26 и Q30 записаны ADR-0038 (`docs/adr/0038-one-context-per-transaction.md`); пометка ADR-0025 о
  типе модели стояла с тикета 01.
- Актор-домен (`<Actor>.<Aggregate>` с ролевыми операциями среза) места в вертикали не получил:
  пример `Actor.Agg.mutate` и диаграмма слоёв в `app/10`, строка `rules/20` — без него.
- Остаются для тикета 05: `app/17`, «Место компонента» (срез инициатора, `Common`), «Фоновые
  задания», пример `<BC>.System.Subscribe`, термин «Компонент» в `CONTEXT.md` — на них уже
  ссылается «Usecases» `app/10` (реакция второго контекста). Для тикета 04 — `app/15`, «Ожидание
  проекции»: вызовы переведены на `Agg.Client.Usecases`, норма не тронута.
- Фикстура не правилась: её `Consumer.Codec` держит центральный список плагинов, оглавления без
  `codec_plugins/0`.

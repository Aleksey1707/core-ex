# 11: Готовое дерево очереди outbox в библиотеке

**What to build:** решение, нужно ли библиотеке готовое дерево очереди — writer → поллер → cleaner под `rest_for_one`
с `enabled:`, проверкой единственности и разбиения поллеров при старте и `watch_list/1`, — вместо корня очереди,
который каждый потребитель пишет сам. Если нужно — его опции и место корня `MyAppApp.Outbox` после него.

**Blocked by:** None (can start immediately)

**Status:** needs-triage

**Spec:** [Контекст — граница Boundary, раскладка — вертикаль по агрегату](../spec.md) — «`use Core.Component`»;
ADR-0043, «Решение»

- [ ] форма дерева: опции, `watch_list/1`, отказы старта; что остаётся корню приложения
- [ ] варианты, которые есть у потребителей: второй поллер с доставкой Kafka, соединение с одним пользователем
      внутри корня, несколько поллеров с разбиением топиков
- [ ] ADR, норма `app/17` и `app/14`, CHANGELOG — если решение «да»

## Факты

Обзор — `research/03-component-roots.md`, «Корень очереди у пяти потребителей»:

- корень очереди есть у всех пяти потребителей с компонентами: один состав детей в одном порядке и одни ключи
  `Core.Outbox` в опциях, 31–63 строки опций на корень;
- `rest_for_one` по порядку детей — `MUST` свода (`docs/rules/17-otp-concurrency.md`, «Дерево процессов»; очередь —
  пример в `app/17`, «Дерево процессов»), проверка единственности — `MUST` в корне очереди (`app/14`,
  «Единственность поллера»), её вызов держит ратчет;
- деревья библиотеки config и env не читают: опции собирает приложение, как у
  `Core.Es.Projection.Supervisor` (`app/17`, «Готовое дерево без корня»).

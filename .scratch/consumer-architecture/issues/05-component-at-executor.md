# 05: Компонент у исполнителя и граница входа

**What to build:** свод кладёт реакцию на доменное событие в реагирующий контекст, к агрегату, чей usecase она зовёт
(при нескольких — `reactions/`), а Oban-воркер — к агрегату-исполнителю, который экспортирует функцию постановки
задачи. Вход внешней системы — граница `MyAppIngest` рядом с `MyAppWeb` с `deps` только на контексты.

## Comments

- Уточнено с мейнтейнером: `deps` у `MyAppIngest` — контексты и подсистемы (тумблер соединения с
  брокером — функция её владельца-подсистемы); сток, кодек, корень и web — MUST NOT.
  `MyAppIngest` несёт `check: [aliases: true]`, как web: `DAO` недоступен входу и значением;
  `repo:` у `Core.Mq.Dlq.Writer`, `Core.Mq.Dlq.Reader`, `Core.Mq.Kafka.Reader` — опция компонента
  из `config/runtime.exs`, как у `Oban`. Пример DLQ в `app/14` переехал под `MyAppIngest`.
- ADR — новый `0040-component-at-executor.md`, в ADR-0024 — пометка со ссылкой на него.
- «MAY» у `MyAppIngest` прочитано как «граница есть только при входе внешней системы»: разбор её
  формата при таком входе — MUST во входе, а не в контексте (`app/17`, `app/14`).
- Вывод из «компонент у исполнителя»: компонент контекста MUST NOT звать изменяющие usecases
  другого контекста; воркер у операции над равноправными агрегатами — в каталоге операции;
  сборка задачи чужого воркера (`new/1`, `Oban.insert/2`) — MUST NOT, постановка — `enqueue/N`
  модуля воркера (форма из примера `app/10`, «Usecases», тикет 02).
- Дерево каталога в `app/10`: `reactions/<name>.ex` → `reactions/<component>/` (компонент —
  каталог с корнем); в каталоге агрегата — строки воркера и реакции. Пункт «реакция на события
  нескольких агрегатов» исправлен на «зовёт usecases нескольких агрегатов» (Q28).
- Плейсхолдеры `MyAppIngest` и `<Source>` — в `docs/rules/00-index.md`; `MyAppIngest` — в корнях
  `scripts/rules_lint.exs`. Линтер `boundary_lint --consumer` правки не требует: закрытого состава
  корней в нём нет.
- В CHANGELOG — перенос реакции и входа без правки строк `subscriber_name:` и `component:`: по ним
  живут смещения Stream и Kafka (`offset_reference = subscriber_name`), записи `mq_dlq` и метрики.
- Фикстура не менялась: тикет нормирует место, сборкой проверяемых форм не добавляет.
- После ревью: дубли норм `app/14` ↔ `app/17` сведены к ссылке из `app/14`; обоснование ушло в
  ADR-0040, у норм — ссылка на него и примеры «плохо / хорошо» (раскладка компонента, воркер у
  исполнителя); в оглавлении фоновая задача — не компонент; `watch_list/0` корня — с корнем входа;
  пример DLQ — `MyAppIngest.<Source>.*`; из `CONTEXT.md` убраны нормы; в CHANGELOG — оговорка про
  имя воркера в `oban_jobs`, «было» без невыпущенных имён. Уточнено с мейнтейнером: модуль воркера
  экспортируется целиком (`enqueue/N`), обход через `new/1` держит ревью — вариант с функцией в
  usecases или отдельным модулем записан отвергнутым в ADR-0040.
- Не правились: пример `Core.Mq.Kafka.Reader` в README (опции читателя, не место компонента);
  расхождение `spec.md` / `decisions.md` («`deps` только на контексты») с уточнением — запись здесь;
  доступ входа к `ContextFactory` — заметка в тикете 09.

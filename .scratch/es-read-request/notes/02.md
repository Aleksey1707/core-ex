# 02 — заметки

## План

`Core.Es.Aggregate.Load.Plan` (`lib/core/es/aggregate/load/plan.ex`), `@moduledoc false`.
Поля: `marker`, `sealed?`, `every`, `write_snapshots?`, `streams`. `Plan.new/3` считает маркер
один раз (`Snapshot.marker/1`) и строит потоки с границами `aggregate_id`, `after_version`,
`to_version`, `snapshot_to`, `snapshot?`; без `snapshot:` маркер `nil`, потоки без снапшота.
`Plan.refold/2` оставляет маркер и запрещает снапшот отвергнутым потокам. `Plan.snapshot/2` —
выбор последнего снапшота по границам потока: им пользуется тестовый источник, SQL берёт строку
join'ом (снапшот один на поток).

## Источник

`Core.Es.Aggregate.Load.Source` — behaviour с одним колбэком
`fetch(cfg, plan, opts) :: [Source.entry()]`, запись — `{stream, stored_snapshot | nil, rows}`.
`Load` передаёт готовый план и парит ответ по `aggregate_id`, а не по позиции. Адаптеры:

- `Core.Es.Aggregate.Repo.Pg` (`@behaviour`, `fetch/3`) — SQL в репозитории агрегата, маркер
  из плана;
- `Core.Es.Store.Rows` (`test/support/es_store_rows.ex`) — литература в опциях
  `rows:` / `snapshots:` / `order: :reverse`, границы и выбор снапшота из плана.

`cfg.source` — модуль `Core.Es.Aggregate.Repo.Pg`; в заявке `source` — модуль, замыканий нет.

## Расшифровка

`Snapshot.sealed/4` и `Snapshot.opened/4` принимают план; хвост и снапшот открываются одним
вызовом `Store.load_fold_rows/4` на поток, поэтому исходы не общий позиционный список.
`Snapshot.write/3` пишет с маркером плана. `Snapshot.marker/1` оставлен публичным для теста
зависимости от `sealed`.

## Тесты

`test/core/es/aggregate/load_test.exs` использует `Rows` как модуль-источник. Новое без базы:
маркер считается один раз (трассировка `Snapshot.marker/1` через отдельный tracer-процесс),
снапшот приходит вместе со своим потоком при обратном порядке потоков, отвергнутый снапшот
перечитывается без него. Teлеметрия `[:es, :aggregate, :load|:fold]`, исходы и detail не менялись.

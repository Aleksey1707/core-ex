# 03: Исправления по ревью тикетов 01–02

**What to build:** привести оформление и швы плана чтения к сводам: `@impl` рядом с функцией,
нижняя граница хвоста считается планом, тест раскладки снапшотов ловит подмену, маркер считается
один раз на пути записи, `Snapshot.opened/3` без неиспользуемого `cfg`, doc репозитория не
приписывает ему чтение на версии. Публичное поведение, исходы, телеметрия и снапшоты не меняются.

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] `@impl true` стоит после `@spec` через пустую строку перед `def` — `fetch/3` в `Core.Es.Aggregate.Repo.Pg` и в тестовом источнике строк.
- [x] Нижняя граница хвоста считается планом (`Plan.tail_from/2`), тестовый источник её не пересчитывает; в SQL остаётся `coalesce` как выражение той же политики.
- [x] Тест «расшифрованный снапшот приходит вместе со своим потоком» проверяет два `snapshot: :hit` и `snapshot_hit: 2` при обратном порядке потоков; подмена снапшотов местами его роняет.
- [x] На реальной базе чтение с записью снапшота считает маркер ровно один раз, записанный снапшот несёт маркер плана.
- [x] `Snapshot.opened/3` без неиспользуемого `cfg`; тип плана в `@spec` широкий, взаимного цикла `Plan ↔ Snapshot` нет.
- [x] Moduledoc `Core.Es.Aggregate.Repo.Pg` не приписывает модулю `get_at` / `get_many_at`, но описывает их метки `op:` в телеметрии чтения через read-репозиторий.

# 03: Сигнал чекпоинта внутри ноды

**What to build:** на ноде, где прошла пачка, `Core.Es.Projection.await/4` отвечает сразу после её commit, а не на
следующем шаге опроса. Читатель после пачки рассылает сигнал чекпоинта своей проекции, ожидающий подписан на него на
время ожидания. Mailbox вызывающего — GenServer, LiveView — после ожидания остаётся чистым. На одной ноде этого
достаточно для полного быстрого пути.

**Blocked by:** [02: Ожидание будит читателя проекции](02-await-wakes-reader.md)

**Status:** resolved

**Spec:** [Сигнал чекпоинта: ожидание проекции без задержки опроса](../spec.md) — «Сигналы внутри ноды», «Ожидание»,
«Читатель»

- [x] Сигнал чекпоинта — ключ Registry по имени проекции; читатель после пачки с исходом `:processed`, включая старт
      пересборки, рассылает его после commit.
- [x] Режим `:poll`: подписка через alias процесса (`Process.alias/1`) значением записи Registry — до чтения цели и
      чекпоинта; рассылка шлёт на alias. По сигналу своей проекции — перечитать чекпоинт тем же разбором исходов.
- [x] Шаги идут по расписанию от начала ожидания и сигналами не сдвигаются; `timeout` ограничивает всё ожидание.
- [x] После ожидания при любом исходе — снятие регистрации, `Process.unalias/1`, вычерпывание доставленных сигналов;
      сигнал чужой проекции ожидание не будит.
- [x] Registry не запущен — регистрация пропускается, ожидание идёт шагами.
- [x] Тесты в sandbox (`Core.Es.Projection.AwaitTest`), шаги ожидания 60 000 мс при таймауте в секунды: живое дерево,
      запись через репозиторий → `:ok`; пачка, начавшая пересборку, → `:projection_rebuilding`; после `:ok`, таймаута
      и пересборки в mailbox теста нет сигналов.
- [x] Регресс: тесты `await: :poll`, `:inline`, пересборки, ошибок программиста, span и telemetry проходят.
- [x] `17-otp-concurrency.md`, «Имена процессов»: исключение для получателей, которые регистрируются в Registry сами,
      распространяется на ожидающего, которого порождает не дерево; подписка — через alias, чтобы поздний сигнал не
      попал в mailbox вызывающего. `make rules-check`.
- [x] moduledoc `Core.Es.Projection` («Ожидание» — сигнал чекпоинта), `Core.Es.Projection.Reader` (сигнал после
      пачки), `Core.Es.Projection.Registry`.
- [x] `CHANGELOG.md`, «Не выпущено» / «Новое»: пункт «Read-after-write» дополнен.
- [x] `make` зелёный.

## Comments

- 2026-09-15 — реализация:
  - ключ — `{:checkpoint, <имя проекции>}`, значение записи — alias ожидающего; сообщение
    `{alias, :checkpoint}` шлёт и принимает только `Core.Es.Projection.Registry`:
    `subscribe_checkpoint/1`, `receive_checkpoint/2`, `unsubscribe_checkpoint/2`, `signal_checkpoint/1`;
  - шаг — пара «когда наступает, длина» от начала ожидания; дедлайн читателя не будит и чекпоинт не
    перечитывает: прежний код будил читателя на дедлайне, и тест сигнала при шагах 60 000 проходил и без
    сигнала. Шаг, просроченный долгим чтением, срабатывает сразу;
  - сигнал читателя — в `apply_outcome/2` на `:processed`, до telemetry цикла;
  - тесты: порядок «ожидание застало чекпоинт отстающим → пачка» задан без времени — `:sys.suspend/1`
    читателя до записи и `:sys.resume/1` по telemetry первого чтения `es_checkpoints` процессом теста
    (`after_checkpoint_read/1`); пересборка — на `Failing`: пачка старта сигналит, следующая отказывает, и
    `:ok` исключён; поздний сигнал — пачка после ожидания, mailbox без telemetry пуст. Мутация «сигнал
    читателя убран» роняет тесты записи и пересборки таймаутом;
  - `Registry.register/3` линкует ожидающего с разделом Registry на время ожидания: остановка дерева
    (`:shutdown`) или падение Registry посреди ожидания завершает и вызывающего.

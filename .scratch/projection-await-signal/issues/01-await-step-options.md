# 01: Шаг ожидания — опции дерева

**What to build:** разработчик приложения задаёт шаг страховки `Core.Es.Projection.await/4` опциями дерева
`Core.Es.Projection.Supervisor` — `await_min_ms:` (первый шаг) и `await_max_ms:` (предел удвоения) — вместо констант
модуля ожидания. Без опций ожидание ведёт себя как сейчас: удвоение 10 → 100 мс. Опции шага не смешиваются с
интервалами читателя. Это подготовка: следующие тикеты доказывают сигнал детерминированно шагами 60 000 мс.

**Blocked by:** None (can start immediately)

**Status:** resolved

**Spec:** [Сигнал чекпоинта: ожидание проекции без задержки опроса](../spec.md) — «Ожидание», «Дерево»

- [x] `await_min_ms:` (по умолчанию 10) и `await_max_ms:` (по умолчанию 100) — положительные целые; недопустимое
      значение — `ArgumentError` при любом `enabled:`; пара не сверяется, как `idle_min_ms` / `poll_interval_ms`.
- [x] Значения попадают в отметку дерева и в опции читателей не передаются.
- [x] Режим `:poll` берёт первый шаг и предел удвоения из отметки; константы шага из модуля ожидания уходят. `:inline`
      не меняется.
- [x] Контракт `await/4` — исходы, ошибки программиста, span, telemetry — не меняется; существующие тесты ожидания
      проходят, меняются только опиравшиеся на константы шага.
- [x] Тесты: `Core.Es.Projection.SupervisorTest` — `ArgumentError` на недопустимые значения при `enabled: true` и
      `false`, умолчания и заданные значения в отметке; `Core.Es.Projection.AwaitTest` — ожидание с заданными шагами
      (например, шаг больше таймаута → `:projection_timeout` без промежуточного опроса).
- [x] moduledoc `Core.Es.Projection.Supervisor` (опции) и `Core.Es.Projection` («Ожидание» — шаг из опций дерева).
- [x] README и `22-projections.md`: env `ES_PROJECTIONS_AWAIT_MIN` / `ES_PROJECTIONS_AWAIT_MAX` в примере
      `config/runtime.exs`, длительности — через `Core.DurationParser`.
- [x] `CHANGELOG.md`, «Не выпущено» / «Новое»: пункты «Дерево проекций» и «Read-after-write» дополнены, новых нет.
- [x] `make` зелёный.

## Comments

- 2026-09-15 — реализация:
  - шаг проверяется не временем, а числом чтений строки чекпоинта процессом теста (Ecto telemetry
    `[:core, :test_repo, :query]`, образец — `Core.EsAggregateRepoContract`). Первый шаг — верхней границей:
    `await_min_ms: 50`, `timeout` 500 — проверки на 0, 50, 150, 350 и 500 мс, не больше 5, а прежние константы
    дают 9; сон дольше заказанного число только сокращает. Предел удвоения — нижней границей с запасом:
    `await_min_ms: 10`, `await_max_ms: 10` — до 51 проверки за 500 мс, с пределом 100 мс их не больше 9;
  - счётчик чтений — своя копия в тесте, а не новый вид запроса в `Core.EsAggregateRepoContract`: тест ожидания не
    завязывается на контракт репозитория агрегата;
  - опции читателей — `Map.take` ключей читателя, а не `Map.drop` опций дерева: опции дерева из следующих тикетов
    (`notifications:`) читателям не утекут;
  - `poll` / `wait` получили `max_interval` отдельным аргументом.
- 2026-09-15 — по ревью: добавлены тест предела удвоения и тест заданных значений в отметке; пример `22-projections.md`
  дополнен env шага; «почему» в CHANGELOG; таймаут теста первого шага — 500 мс.

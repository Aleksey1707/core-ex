# 01: лист для Prim-варианта семейства

## Что добавлено

- `Core.Labels.Walk`: у узла видимого значения подменяется спека — `variant_spec/2`. Вариант-Prim даёт
  лист со спекой `{:prim, variant}`, вариант-struct с `Core.Labels.Fields` остаётся группой, прочий
  struct — `ArgumentError` с именем модуля. `%Core.Es.Personal.Destroyed{}` и `nil` отсекаются по
  значению до разбора варианта и сохраняют прежнее поведение.
- `Core.Labels.Details`: `prim_shape/1` для `{:custom, leaf}` даёт `ArgumentError` по образцу
  `:unkinded` (раньше — `FunctionClauseError`).
- Moduledoc `Core.Labels.Details`: строка таблицы видов про `union:` и абзац о листе по варианту.
- Тесты: `details_test` — describe «семейство Prim-вариантов» (текст, plain, `ref`, `user`, `id`,
  композит, destroyed, `nil`, неподдерживаемый вариант, custom-вид); `refs_test` — id вариантов
  `ref`/`user` в словаре, `text:`/`id`/destroyed не попадают; `fields_test` — `paths/1` для `union:`
  отдаёт только подпись поля.

Wire сведений, скрытые поля, OpenAPI-схемы и `Fields.paths/1` не менялись.

## Фикстуры

- `Core.LabelsFixture.Contact` — семейство Prim-вариантов: `Contact.Phone` (`Core.Labels.Text`),
  `Contact.Code` (plain, число), `Contact.Item` (`Labels.ID kind: :ref, entity: :stock_item`,
  резолвер `ItemQuery`), `Contact.User` (`Labels.ID kind: :user`, резолвер `UserQuery`),
  `Contact.Snapshot` (`kind: :id`), `Contact.Alias` (`Core.Prim.Compose` над `Contact.Phone`).
- `Core.LabelsFixture.Contact.Codec` — плагин семейства (`use Core.Codec.Plugin, union: Contact`).
- `Core.LabelsFixture.Event.ContactFamily` и `Core.LabelsFixture.Event.Reachable` — событие с видимым
  полем `contact: [union: Contact, personal: true, optional: true]` (ПДн-место с субъектом
  `:aggregate_id`, поэтому `Personal.Test.destroyed/1` заменяет значение целиком).
- `Core.LabelsFixture.Event.ContactFamily.Codec` — тег `labels_contact.reachable`.
- `Core.LabelsFixture.Texts.phone/1` — текст варианта `Phone`.
- Ни `Contact.Codec`, ни `Event.ContactFamily.Codec` не зарегистрированы в
  `Core.CodecFixture.plugins/0`; кодек события не входит в `@full` ратчета полноты.

## Как включить в полный набор (тикет 02)

1. `test/core/labels/completeness_case_test.exs`: добавить `LabelsFixture.Event.ContactFamily.Codec`
   в `@full`; при проверке плагинов — `LabelsFixture.Contact.Codec`.
2. `test/support/codec_fixture.ex`: добавить `Event.ContactFamily.Codec` и `Contact.Codec` в
   `plugins/0`, если событие должно дампиться фасадами.
3. `Core.Labels.Walk.declarations/1`: маршрутизировать Prim-варианты поля `union:` как места
   `{:prim, owner, field, variant}`. Сейчас `visit/5` для `{:union, family}` идёт через
   `{:entity, variant}`, и `descend/3` пропускает не-labelled Prim — ложного пробела «struct без
   решения по полям» нет, но и вид варианта ратчет не проверяет.
4. `test/core/labels/kind_table_test.exs`: добавить новый плагин/кодек в набор «вид × подписи ×
   ссылки × полнота».
5. Сломанная фикстура (`Core.LabelsBrokenFixture`): добавить в семейство `Mark` Prim-вариант без вида
   и Prim-вариант с custom-видом для пробелов `check_ids/1` (вариант-struct без полей `Mark.Bare`
   уже есть).

## Открытые вопросы

- `make` падает только на шаге `audit`: `idna 7.1.0` — advisory `EEF-CVE-2026-117678` (MEDIUM).
  Изменение не связано с тикетом, `mix.lock` не трогался; коммит идёт с `SKIP=mix-audit`.
- Событие `Reachable` не входит ни в один фасад, поэтому dump/load поля `union:` с Prim-вариантами
  через фасад не exercised; round-trip — в тикете 02 при регистрации плагина.

# 01: Сведения и словарь ссылок — лист для Prim-варианта семейства

**What to build:** видимое поле `union:`, вариант которого — Prim, выходит в сведениях события одним
сведением-листом, а не падает на странице событий. Вид и значение листа — по варианту: `Core.Labels.Text` →
текст функции, без объявления — plain-вид Prim (`text` / `number` / `date` / `datetime`), `Core.Labels.ID` →
`ref` с видом записи / `user` / `text` для `id`. Объявления вида и текста действуют на вариант, включая
цепочку композита: эффективная спека листа — модуль варианта, не семейство. Id варианта с резолвером
попадает в словарь ссылок и резолвится пачкой; `text:`-вариант и уничтоженное значение в словарь не
попадают. Уничтоженное ПДн-значение остаётся `kind: :destroyed` без `value`; поле без значения — группа с
`value: nil`, как сегодня; вариант-struct с объявлением полей — группа, как сегодня. Неподдерживаемый
вариант (struct без `Core.Labels.Fields`, не Prim) даёт понятный `ArgumentError` с именем модуля, а не
`UndefinedFunctionError`; custom-вид Prim — тоже понятная ошибка, а не `FunctionClauseError`. Wire сведений,
скрытые поля и `Core.Labels.Fields.paths/1` не меняются.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Видимое поле `union:` с вариантом-Prim выходит листом; вид и значение — по варианту (`Labels.Text` — текст функции, plain-вид, `ref` с видом записи, `user`, `text` для `id`)
- [ ] Эффективная спека листа — модуль варианта: объявления вида и текста, включая цепочку композита, применяются к варианту
- [ ] Id варианта `ref`/`user` с резолвером попадает в словарь ссылок и резолвится пачкой; `text:`-вариант и уничтоженное значение в словарь не попадают
- [ ] `%Core.Es.Personal.Destroyed{}` в поле-семействе — `kind: :destroyed` без `value`; `nil` — группа с `value: nil`, как сегодня
- [ ] Вариант-struct с `Core.Labels.Fields` — группа, как сегодня; скрытое поле-семейство не меняется; `Fields.paths/1` для `union:` отдаёт только подпись поля
- [ ] Неподдерживаемый вариант (struct без объявления полей, не Prim) — `ArgumentError` с именем модуля варианта; Prim с custom-видом — `ArgumentError`, не `FunctionClauseError`
- [ ] Фикстура семейства на Prim-модулях, выделенных под семейство (текст, plain, `ref` с видом записи, `user`); событие с видимым полем ещё не входит в полный набор ратчета, чтобы тикет оставался зелёным

- [ ] Wire сведений и OpenAPI-схемы события страницы событий не меняются

# Предпосылки MVP потребителя F: конверт операции, доменное время, дублёр доставки, эксплуатация

Type: spec
Status: ready-for-agent

## Problem Statement

Потребитель F строит MVP на `:core`, и его спека держит тикеты реализации заблокированными до шести
возможностей библиотеки. Без них приложение либо не выполнит своё нефункциональное требование, либо
повторит механизм библиотеки своим кодом:

- **Журнал операций.** Аудит потребителя пишет строку на каждое событие всех топиков и группирует их
  по операции: кто, из какого сеанса, в ответ на что. Конверт события несёт только `by` и `at`;
  операции, сеанса инициатора и основания в нём нет, а `Store.append` получает `%Context{}`, но ничего
  из него не берёт. Добавить их позже нельзя: событие неизменяемо, история без них останется без них.
- **Истечение сроков в тестах через API.** Срок кода входа, срок оплаты, срок сеанса, сутки чека
  коррекции и уборка просроченного проверяются HTTP-тестами историй. «Сейчас» значений даты и времени
  берётся из системных часов, шва для подмены нет, и такие истории через API не закрыть.
- **Приёмка без брокера.** Тест истории проходит путь «команда → outbox → подписчик другого контекста →
  команда → read-модель». Живого брокера в `make test` нет, а дублёры `Core.MqFake.*` лежат в
  `test/support` библиотеки и к потребителю не приезжают. In-memory брокер когда-то был в `lib/` и
  оттуда убран. Обработка сообщения (`filter` → `from_message` → `on_message`) зашита в цикл
  GenServer `MqSubscriberReliable`, и вызвать её вне процесса подписчика нельзя.
- **Выборка страницами с фильтром.** Поиск товаров и списки сотрудников — `limit` / `offset` с
  фильтром. `Repo.Pg.list_by/4` фильтрует без страниц, `page` пагинирует без фильтра.
- **Эксплуатация.** Релизу нужны миграции всех репозиториев и повтор `:failed` записей outbox без Mix.
  После восстановления базы на момент T нужно переопубликовать события окна из хранилища событий:
  топики удаляются, потому что их позиции впереди базы. Compose-проверке нужен `/ready`. Алерту
  отставания подписчика Аудита нужен возраст самого старого неподтверждённого сообщения Stream, а
  `kafka_reader_lag_seconds` есть только у Kafka и растёт на пустом топике.
- **Внешние вызовы.** Платёжный шлюз, касса, служба доставки и SMS вызываются из адаптеров
  приложения. Словаря span'ов и метрик внешнего вызова (система, операция, исход) нет, и каждый
  адаптер придумал бы свой.

Раздел «Вид агрегата», который спека потребителя тоже относила к предпосылкам, уже есть в app-ярусе
свода. Ссылка на него из `app/11-domain.md` рабочая, поэтому пункт снят.

## Solution

Каждая возможность — отдельная поставка библиотеки:

- **Конверт операции.** Конверт события получает три необязательных поля: операцию, сеанс инициатора
  и основание (ADR-0081).
  - Значения берутся из `%Context{}` и проставляются на любом пути записи до outbox и хранилища.
  - Если операции в контексте нет, библиотека создаёт одну на внешнюю транзакцию.
  - Основание — операция события, на которое реагирует подписчик. Оно приезжает заголовком
    сообщения и попадает в контекст обработчика само.
  - Пустые ключи в wire не пишутся: у событий без операции wire не меняется.
- **Доменное время.** «Сейчас» значений даты и времени идёт через `Core.Clock` (ADR-0083).
  - В тестах `Core.Clock.Test` останавливает и сдвигает время процесса-владельца и тех, кто его
    видит: `$callers` и `allow/2`. Поэтому `async: true` сохраняется.
  - Инфраструктура библиотеки остаётся на реальном времени.
- **Дублёр доставки.** `Core.Outbox.Test` доставляет записи outbox подписчикам приложения без брокера,
  в sandbox теста (ADR-0082).
  - Шаг обработки сообщения вынесен из `MqSubscriberReliable` и один для настоящего подписчика и
    дублёра.
  - Синхронный `drain` подходит детерминированным тестам, реактор — тестам через HTTP, где цепочку
    реакций должен кто-то гнать, пока запрос ждёт проекцию.
  - `settle` ждёт тишины с пределом.
- **`page_by`.** Страница с фильтром рядом с `list_by`.
- **Эксплуатация:**
  - задачи релиза `Core.Release.migrate` и `rollback`;
  - `Core.Outbox.Release.requeue` и `republish_since` — переопубликация окна из хранилища событий;
  - `Core.Web.HealthPlug` с `/health` и `/ready`;
  - gauge возраста неподтверждённого сообщения Stream в `Core.Mq.PromEx`.
- **Внешний вызов.** `Core.External.call/4` оборачивает вызов внешней системы:
  - span со словарём `Core.Otel.External` и telemetry;
  - метрики `Core.External.PromEx` по системе, операции и исходу;
  - исход определяет классификатор вызывающего.

## User Stories

### Конверт операции

1. As an автор журнала операций, I want чтобы у каждого события была операция, so that строки
   журнала одной изменяющей команды группировались без моих эвристик.
2. As an автор журнала операций, I want чтобы события нескольких агрегатов одной транзакции несли
   одну операцию, so that операция «оформить заказ» читалась одним действием, а не россыпью.
3. As an автор usecase, I want не создавать операцию руками, so that полнота журнала держалась
   устройством библиотеки, а не моей дисциплиной.
4. As an автор usecase, I want задать операцию явно через `Core.Context.Operation`, so that
   несколько транзакций одного действия, если они мне нужны, были одной операцией.
5. As an автор usecase, I want чтобы повтор отвергнутой транзакции (`Es.Transact`) давал новую
   операцию, so that откатанная попытка не делила id с записанной.
6. As an автор web-слоя приложения, I want положить сеанс инициатора в `Core.Context.Session`
   своим плагом, so that события запроса несли сеанс, а библиотеке не нужно было знать, что такое
   сеанс в моём приложении.
7. As an автор подписчика, I want получить основание в контексте `on_message` без своего кода, so
   that забытый хелпер не рвал связь реакции с причиной молча.
8. As an автор подписчика, I want чтобы сообщение без заголовка операции давало пустое основание,
   so that сообщения внешних источников и старые записи outbox обрабатывались как раньше.
9. As an автор журнала операций, I want читать операцию, сеанс и основание из сообщения топика, so
   that журнал строился из топиков, а не из чужой таблицы `es_events`.
10. As an автор проекции, I want видеть операцию, сеанс и основание у событий пачки и страницы потока,
    so that read-модель, которой они нужны, не читала их отдельно.
11. As a разработчик приложения на прежней версии `:core`, I want читать конверт новой версии без
    сбоя, so that соседние приложения обновлялись независимо.
12. As a разработчик приложения с выкаченной базой, I want получить колонки аддитивной миграцией,
    so that существующие строки `es_events` остались как есть и читались с пустыми полями.
13. As a разработчик приложения, I want чтобы golden-фикстуры событий без новых ключей продолжали
    грузиться, so that обновление библиотеки не заставляло перегенерировать фикстуры.
14. As a разработчик приложения без журнала операций, I want не менять ничего в своём коде, so that
    новые поля были возможностью, а не обязанностью.
15. As a разработчик state-stored агрегата с событиями, I want тех же полей у его событий, so that
    журнал покрывал оба вида агрегатов одинаково.
16. As a разработчик приложения, I want чтобы событие уничтожения ключа субъекта тоже несло операцию,
    so that обезличивание было видно журналу как любое изменение.

### Доменное время

17. As an автор приёмочного теста, I want остановить доменное время своего теста (`freeze`), so that
    исход, зависящий от «сейчас», был детерминированным.
18. As an автор приёмочного теста, I want сдвинуть остановленное время (`advance`), so that проверить
    истечение срока за миллисекунды, а не за час.
19. As an автор приёмочного теста, I want чтобы процессы, порождённые тестом через `Task`, видели моё
    время без настройки, so that usecase с параллельными шагами не расходился во времени.
20. As an автор приёмочного теста, I want разрешить своё время процессу, которого нет в `$callers`
    (`allow/2`), so that реактор, подписчик или GenServer видели то же «сейчас».
21. As an автор теста с `async: false`, I want глобальный режим, so that время видели все процессы
    VM.
22. As an автор теста, I want чтобы параллельные тесты не видели время друг друга, so that
    `async: true` оставался безопасным.
23. As an автор теста, I want реальное время там, где время не остановлено, so that тесты, которым
    часы не нужны, ничего не настраивали.
24. As a разработчик приложения, I want включить тестовые часы одной строкой конфигурации и одним
    стартом в `test_helper`, so that в prod шов ничего не стоил и не требовал моей конфигурации на
    сборке.
25. As a разработчик приложения, I want чтобы `now/0` и `now!/0` всех моих Prim даты и времени шли
    через шов, so that не переписывать вызовы в домене.
26. As a разработчик приложения, I want звать `Core.Clock.now/0` напрямую там, где Prim не нужен,
    so that и такой код видел доменное время.
27. As a разработчик приложения, I want чтобы аренды outbox, уборка, чекпоинты и метрики библиотеки
    шли по реальному времени, so that остановленное время теста не ломало доставку и уборку.

### Дублёр доставки

28. As an автор приёмочного теста, I want доставить записи outbox подписчикам приложения без брокера,

29. As an автор приёмочного теста, I want передать дублёру тот же список подписчиков, что получает

30. As an автор приёмочного теста, I want чтобы дублёр звал тот же шаг обработки, что настоящий

31. As an автор приёмочного теста, I want синхронный `drain`, so that детерминированный тест сам

33. As an автор приёмочного теста, I want `settle` с пределом, so that перед проверкой всё

38. As an автор приёмочного теста, I want чтобы реактор работал в sandbox моего теста и видел моё

## Implementation Decisions

### Конверт операции (ADR-0081)

- **Поля.**
  - Три поля, все UUID: `operation_id`, `session_id`, `basis_id`.
  - Prim-типы — `Es.Event.OperationID` и `Es.Event.SessionID`, по образцу `Es.Event.ID`; основание
    типизировано как `OperationID`.
  - У `%Es.Event{}` поля необязательные, вне `@enforce_keys`, по умолчанию `nil`.
- **Хранилище.**
  - Три nullable-колонки `binary_id` в `es_events`, без индексов.
  - Миграция аддитивная: отдельная функция модуля миграции хранилища событий, идемпотентная.
    Выкаченная база добавляет её вызов своей миграцией.
  - Ecto-схема строки хранилища получает поля, чтение потока, страницы и пачки проекции отдаёт их в
    событии.
- **Wire.**
  - `dump_envelope` пишет ключи `operation_id`, `session_id`, `basis_id` только непустыми.
  - Загрузка читает отсутствующий ключ как `nil`.
  - `to_fields` / `from_fields` получают поля.
  - Прежний читатель берёт свои ключи и игнорирует лишние: новый конверт читается старой версией
    библиотеки.
- **Аксессоры контекста.**
  - `Core.Context.Operation`, `Core.Context.Session`, `Core.Context.Basis` на
    `use Core.Context.Accessor` с типами из Prim.
  - Своего web-плага у библиотеки нет: сеанс — модель приложения.
- **Простановка.**
  - Одна функция проставляет поля событиям до построения записей outbox и до `Store.append`.
  - Через неё проходят все пути записи: репозиторий event-sourced агрегата, state-stored с событиями,
    событие уничтожения ключа субъекта. Запись outbox и строка хранилища поэтому совпадают.
  - Значение из контекста имеет приоритет.
- **Генерация операции.**
  - Если в контексте операции нет, создаётся UUID v7, один на внешнюю транзакцию DAO.
  - Хранится в состоянии процесса под тем же счётчиком глубины, что `Core.Helper.AfterCommit`, и
    сбрасывается на commit и rollback внешней транзакции.
  - Вне транзакции — одна операция на вызов записи.
  - Наружу сгенерированный id не отдаётся.
- **Заголовок.** Outbox кладёт `operation_id` в заголовки записи рядом с `name`, `aggr_id`,
  `event_id`, если операция есть.
- **Основание у подписчика.**
  - Шаг обработки сообщения (см. «Дублёр доставки») кладёт значение заголовка `operation_id` в
    контекст от `context_factory` как `Core.Context.Basis`. Делает это до `on_message`, рядом с
    продолжением трейса.
  - Нет заголовка — основания нет.
- **Чего нет.** Контекста трейса в `es_events` по-прежнему нет: операция — не трейс.

### Доменное время (ADR-0083)

- **`Core.Clock`.**
  - Behaviour с `now/0` → UTC `DateTime` с микросекундами.
  - Реализации — системная (по умолчанию) и `Core.Clock.Test`.
  - Выбор — ключ `clock:` в `Core.Config`, читается в рантайме на каждый вызов; compile-time
    конфигурации нет.
- **Prim.**
  - Генерируемые `now/0` и `now!/0` у `use Core.Prim.DateTime` и `use Core.Prim.Date` берут время у
    `Core.Clock`, затем приводят к поясу и точности Prim, как сейчас.
  - Это генерируемый код потребителя, поэтому `make consumer-check` проверяет его вывод типов.
- **Инфраструктура.**
  - Внутренние места библиотеки явно берут реальное время, Prim-ами outbox через `new`:
    - время записей outbox (`created_at`, `updated_at`, `published_at`);
    - поллер, cleaner, аренды;
    - хранилище ключей субъектов;
    - читатель проекции;
    - метрики PromEx.
  - Время события уничтожения ключа субъекта — доменное.
- **`Core.Clock.Test`** на `nimble_ownership` (обычная зависимость):
  - `start/0` — старт сервера владения, зовётся в `test_helper.exs` потребителя;
  - `freeze/1` — остановить время владельца на заданном `DateTime`;
  - `advance/1` — сдвинуть остановленное время на длительность (`Duration` или keyword
    `DateTime.shift/2`); без `freeze` — ошибка программиста;
  - `allow/2` — разрешить время владельца другому процессу;
  - глобальный режим для `async: false`;
  - поиск: `self()` → `$callers` → разрешения; не найдено — реальное время;
  - владение снимается при выходе процесса-владельца.

### Дублёр доставки (ADR-0082)

- **Шаг обработки.**
  - Внутренний модуль рядом с подписчиком.
  - На вход — сырое `Mq.Message`, опции обработки подписчика и номер попытки.
  - Делает: `filter`, span `process` с родителем из заголовков, `from_message`, контекст от
    `context_factory` с основанием, `on_message`, перехват исключения в `{:error, %Error{}}`.
  - Возвращает исход: обработано, отфильтровано, повтор с ошибкой, отказ без повторов.
  - `MqSubscriberReliable` оставляет за собой чтение, `commit`, счёт попыток, backoff, DLQ-writer и
    telemetry цикла.
- **`Core.Outbox.Test`** — модуль в `lib/`, по образцу `Core.Es.Projection.Test` и
  `Core.Es.Store.Test`.
- **Подписчики.**
  - Список keyword в той же форме, что приложение отдаёт `MqSubscriberReliable`.
  - Работают `topic`, `filter`, `from_message`, `on_message`, `context_factory`, `max_attempts`.
  - Сетевые ключи (`reader_module`, `reader`, `dlq_*`, `subscribe*`, `name`, `shutdown`,
    `poll_interval_ms`, `retry_max_ms`) игнорируются.
- **`drain/2`.**
  - Синхронный проход в вызывающем процессе.
  - Записи outbox резервируются и сохраняются тем же `Core.Outbox.Repo`, что у поллера.
  - Запись превращается в `Mq.Message` той же функцией, что у `Delivery.Mq`, поэтому wire, заголовки
    и запечатанные ПДн совпадают.
  - Сообщение попадает в журнал своего топика; у каждого подписчика свой курсор.
  - Состояние журналов, курсоров и мёртвых писем живёт в процессе, который зовёт `drain`.
- **Доставка.**
  - Подписчик получает сообщения своего топика по порядку.
  - Повтор с ошибкой оставляет его на сообщении до следующего прохода, без backoff; остальные идут
    дальше.
  - Исчерпание `max_attempts` или отказ без повторов кладёт сообщение в мёртвые письма дублёра и
    сдвигает курсор.
  - Топик без подписчиков просто публикуется.
- **Реактор.**
  - Процесс, который крутит `drain` раз в 10 мс.
  - Стартует через `start_supervised` в тесте и ставит себе `$callers = [владелец]`: sandbox Ecto и
    `Core.Clock.Test` видят его без `allow`.
  - Подписки на commit нет.
- **`settle/2`.**
  - Ждёт пустого outbox (нет `:new`), всех курсоров в конце журналов и отсутствия подписчика,
    застрявшего на ошибке.
  - Предел по умолчанию — 5 с. По пределу — провал теста со списком застрявших сообщений (топик,
    тег, `event_id`, подписчик, попытки, последняя ошибка).
  - Мёртвое письмо — провал, если не передано `dead_letters: :allow`.
- **`dead_letters/1`** отдаёт мёртвые письма для проверки.
- **Своё дерево outbox.** Потребитель держит его выключенным в тестах (`OUTBOX_ENABLED`). Дублёр его
  не трогает.

### Страница с фильтром

- `Repo.Pg.page_by(pg, filter, limit, offset, context, opts \\ [])` рядом с `list_by/4`.
- Фильтр — `Ecto.Query.dynamic_expr()`, как у `list_by`; `limit` / `offset` — Prim `Core.Pagination`.
- Возврат — `Pagination.Result` с `total` по тому же фильтру; опции — те же, что у `page`.

### Эксплуатация

- **`Core.Release`** — задачи релиза без Mix:
  - `migrate(app)` — все `up`-миграции каждого репозитория из `:ecto_repos` приложения;
  - `rollback(app, repo, version)` — откат до версии.
  - Вывод оператору — по норме задач релиза в `20-agreements.md`.
- **`Core.Outbox.Release`:**
  - `requeue/1` — обёртка над `requeue_failed` (`:all` или список id) с итогом числом записей, по
    образцу `Core.Mq.Dlq.Release.requeue/2`;
  - `republish_since(app, since)` — переопубликация окна.
- **`republish_since`.**
  - Outbox-модули (`use Core.Es.Outbox`) находятся среди модулей приложения; у каждого — топик, а
    через кодек — тип агрегата. Агрегаты с `outbox: :none` модуля не имеют и пропускаются.
  - Выбираются строки `es_events` найденных типов с `at >= since` в порядке commit (`xid`, `number`).
  - Записи outbox собираются механически, без декодирования: конверт из колонок с новыми ключами,
    ключ — `aggregate_id`, имя — тег, заголовки `name`, `aggr_id`, `event_id`, `operation_id`, без
    `traceparent`, статус `:new`.
  - Одна транзакция. Итог — число записей по топикам.
- **`Core.Web.HealthPlug`:**
  - опции: `repos:` (обязательная), `health_path:` (`/health`), `ready_path:` (`/ready`), `timeout:`
    (1000 мс);
  - `/health` — `200` `ok` без проверок;
  - `/ready` — `SELECT 1` по каждому репозиторию с таймаутом: `200` `ok` либо `503` `unavailable` с
    `warning` в лог;
  - после ответа `halt`, прочие пути проходят дальше.
- **Gauge отставания Stream.**
  - Новая polling-метрика `Core.Mq.PromEx` `<prefix>_mq_reader_pending_age_seconds` с метками, как у
    `reader_pending`.
  - Значение — «сейчас минус время сообщения в `pending`», 0 при пустом `pending`.
  - Stream reader хранит время вместе с `pending`: timestamp чанка, если клиент `rabbitmq_stream` его
    отдаёт, иначе момент получения чанка. Тогда gauge измеряет застревание обработки, а не отставание
    чтения, и это сказано в moduledoc и `21-observability.md`.
  - Проверка клиента — первый шаг тикета.

### Внешний вызов

- **Вход.** `Core.External.call(system, operation, fun, opts)`.
  - `system` и `operation` — атомы; `fun` — нуль-арная; результат `fun` возвращается без изменений.
  - Обязательная опция `outcome:` — функция «результат → `:ok | :timeout | :down | :rejected`».
  - Иное значение классификатора — ошибка программиста.
- **Span** через словарь `Core.Otel.External`:
  - имя `"<system> <operation>"`, `kind: :client`;
  - атрибуты `core.external.system`, `core.external.operation`, `core.external.outcome`,
    `peer.service = system`;
  - статус error у `timeout`, `down` и исключения; у `rejected` статус не ставится: отказ системы по
    существу — не сбой.
- **Исключение в `fun`** — `record_error`, исход `exception` в telemetry и метрике, повторный
  `raise`.
- **Telemetry** — `:telemetry.span` с префиксом `[:external, :call]`, метаданные `system`,
  `operation`, `outcome`.
- **`Core.External.PromEx`:**
  - гистограмма `<prefix>_external_call_duration_milliseconds` и счётчик
    `<prefix>_external_call_total`;
  - метки `system`, `operation`, `outcome`.
- **Алерты.** `21-observability.md` получает рекомендованные `ExternalCallFailing` (доля не-`ok` выше
  порога 5 мин) и `ExternalCallSlow` (p95 выше порога). Пороги задаёт потребитель.

## Testing Decisions

- **Что такое хороший тест.** Проверяется внешнее поведение через публичный вход библиотеки: что
  записалось, что получил обработчик, что вернула функция, какие span и метрика появились. Не
  проверяются внутреннее состояние процесса и порядок приватных вызовов. Шов один на пункт, самый
  высокий.
- **Конверт.**
  - Запись через репозитории фикстурных агрегатов (event-sourced и state-stored) на `DataCase`. Затем
    проверяются три места:
    - события из `Core.Es.Store.Test.events!` и страницы потока;
    - запись outbox: ключи wire и заголовок `operation_id`;
    - контекст, который получил `on_message` из шага обработки.
  - Случаи:
    - два агрегата одной транзакции — одна операция;
    - явная операция из контекста;
    - повтор `Es.Transact` — новая операция;
    - сеанс из контекста;
    - сообщение без заголовка — пустое основание;
    - старый конверт без ключей грузится;
    - dump без операции побайтно совпадает с прежним.
  - Образцы: тесты хранилища событий, outbox событий, контрактный тест репозитория event-sourced
    агрегата.
- **Доменное время.**
  - `now/0` фикстурного Prim при конфигурации `Core.Clock.Test`:
    - `freeze` / `advance`;
    - `Task` видит время через `$callers`;
    - чужой процесс видит его после `allow/2`;
    - глобальный режим;
    - параллельный тест не видит чужое время;
    - без `freeze` — реальное время.
  - Отдельно: время записей outbox при остановленных часах реальное.
  - Образцы: тесты Prim.
- **Дублёр доставки.**
  - Публичный API `Core.Outbox.Test`: запись фикстурного агрегата → подписчики-keyword. Случаи:
    - доставка и `:published`;
    - `filter` и `{:skip, _}`;
    - ошибка, повтор на следующем проходе, а другой подписчик того же топика идёт дальше;
    - исчерпание попыток и отказ без повторов → мёртвые письма;
    - `settle` валит тест на мёртвом письме и пропускает его с `dead_letters: :allow`;
    - `settle` по пределу даёт список застрявших;
    - реактор доставляет запись, сделанную после его старта, в sandbox теста.
  - Тесты `MqSubscriberReliable` на `MqFake` не меняются и страхуют вынос шага.
  - Образцы: тесты `MqSubscriberReliable`, тестовые хелперы проекций.
- **`page_by`.** Над таблицей фикстуры `TestRepo`: фильтр, страница и `total` по фильтру. Образцы —
  тесты `list_by` и `page`.
- **Эксплуатация.**
  - `republish_since`: запись фикстурных агрегатов → очистка outbox → переопубликация. Пересобранные
    записи равны исходным с точностью до id, статуса, `created_at` и `traceparent`. Граница окна по
    `at`, пропуск агрегата без outbox, итог по топикам.
  - Задачи релиза: `migrate` / `rollback` на миграции с отдельной тестовой версией; номера вида
    `20_261_…`, чтобы не путать с файлами.
  - `requeue` — по образцу тестов `Core.Mq.Dlq.Release`.
  - `HealthPlug` через `Plug.Test`: `/health`, `/ready` при живом и недоступном репозитории, чужой
    путь проходит дальше. Образец — тест `MetricsPlug`.
  - Gauge — опрос плагина по состоянию reader. Живой брокер — только под тегом `:rabbit_stream`.
    Образец — тесты `Core.Mq.PromEx`.
- **Внешний вызов.**
  - Тестовый экспортёр OTel SDK (он уже `only: :test`) и telemetry-обработчик. Проверяются:
    - имя, kind, атрибуты и статус span'а по каждому исходу;
    - исключение: `record_error`, исход `exception`, повторный `raise`;
    - результат `fun` без изменений.
  - Описание метрик `Core.External.PromEx` — по образцу тестов PromEx-плагинов outbox.
- **Вывод типов.** `make consumer-check`: генерируемые `now/0` / `now!/0` у Prim фикстуры-потребителя
  не дают предупреждений.

## Out of Scope

- Раздел «Вид агрегата» — уже есть в app-ярусе.
- Работа на стороне потребителя:
  - web-плаг сеанса;
  - журнал операций;
  - `AcceptanceCase` и реактор приёмки;
  - задачи релиза приложения;
  - стенд;
  - миграция колонок в его базе.

- Режим часов «смещение при текущем ходе».
- In-memory брокер в `lib/` и сетевой путь в дублёре (поллер, reader, `commit`, backoff).
- Gauge возраста неподтверждённого сообщения у Kafka-reader.
- Circuit breaker и повторы во `Core.External.call`.
- Правки спеки потребителя F по итогам этой спеки: имена `Core.Outbox.Test` и `Core.External`,
  снапшоты агрегатов с ПДн (в `:core` разрешены и запечатаны), отсутствие `es_events.inserted_at` в
  учении восстановления. Их вносит пользователь.

## Further Notes

- ADR: 0081 (конверт операции), 0082 (дублёр доставки), 0083 (доменное время).
- Термины «Операция», «Основание», «Сеанс инициатора», «Доменное время», «Внешний вызов» и новые ключи
  «Конверта» уже в `CONTEXT.md`.
- **Зависимости тикетов.**
  - Конверт и дублёр связаны шагом обработки: основание кладёт шаг. Шаг выносится в тикете дублёра
    или раньше, отдельным тикетом.
  - `republish_since` пишет новые ключи и заголовок, поэтому идёт после конверта.
  - Остальные пункты независимы.
- **Допущения.**
  - Статус span'а у исхода `rejected` не ставится. Риск низкий.
  - Время сообщения Stream — время получения чанка, если клиент не отдаёт timestamp. Риск низкий,
    проверка — первый шаг тикета.

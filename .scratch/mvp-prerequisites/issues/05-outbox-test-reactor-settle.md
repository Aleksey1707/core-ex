# 05: Дублёр доставки — реактор и `settle`

**What to build:** приёмочный тест через HTTP поднимает реактор, который в фоне гонит доставку. Так запрос, ждущий
проекцию реакции, получает итог в своём бюджете ожидания. Перед проверками тест зовёт `settle`. Он ждёт тишины или
валит тест понятным списком застрявших сообщений и мёртвых писем.

Спека — «Дублёр доставки»; ADR-0082.

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] Реактор стартует через `start_supervised` и зовёт `drain` раз в 10 мс. Он ставит себе `$callers = [владелец]`,
      поэтому sandbox Ecto видит его без `allow`.
- [ ] `settle/2` ждёт трёх условий: пустой outbox (нет `:new`), курсоры в конце журналов, нет подписчика,
      застрявшего на ошибке. Предел по умолчанию — 5 с.
- [ ] По пределу `settle` валит тест списком: топик, тег, `event_id`, подписчик, попытки, последняя ошибка.
- [ ] Мёртвое письмо валит `settle`, если не передано `dead_letters: :allow`. `dead_letters/1` работает и с реактором.
- [ ] Тесты:
      - реактор доставляет запись, сделанную после его старта;
      - `settle` проходит после цепочки из двух реакций;
      - `settle` по пределу даёт список застрявших;
      - мёртвое письмо валит `settle` и проходит с `:allow`.
- [ ] Свод `19-testing.md` и app-ярус тестов: дублёр вместо брокера, список подписчиков одной функцией для дерева и
      теста, выключенное дерево outbox в тестах.
- [ ] CHANGELOG «Новое».
- [ ] `make` зелёный.

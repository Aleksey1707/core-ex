# 02: Заявка чтения — один дискриминант и политика снапшота у источника

**What to build:** операция чтения задаётся одной меткой, конструктор сам строит адреса потоков,
движок имеет один вход. Политика записи снапшота выводится из операции, а возможность записи
объявляет источник строк. Тесты перестают мутировать заявку.

**Blocked by:** 01.

**Status:** ready-for-agent

- [ ] В заявке одна метка операции с прежними именами (`get`, `get_decision`, `get_many`, `refresh`, `get_at`, `get_many_at`); отдельная метка `kind` в адресе движка удалена, ветвление и телеметрия идут по операции.
- [ ] Конструкторы операции строят адреса потоков сами; точки входа репозиториев зовут один вход движка; внутренние `head/at/many_at` удалены.
- [ ] Политика записи снапшота выводится из операции (`get`, `get_decision`, `get_many`, `refresh` пишут; чтение на версии — нет); флаг записи в заявке удалён.
- [ ] `Source` объявляет колбэк «источник умеет писать снапшоты»: SQL-адаптер — да, тестовый источник строк — нет; тесты больше не правят заявку.
- [ ] Тест «признак не писать снапшоты» переписан в правило «чтение на версии не пишет снапшот».
- [ ] Исходы, detail отказов и телеметрия чтения прежние; `make` зелёный. CHANGELOG не пополняется.

# 01: Типизированная конфигурация event-sourced репозитория

**What to build:** конфигурация чтения write-репозитория event-sourced агрегата становится
структурой с обязательными полями и вложенной настройкой снапшота. Движок чтения, план и
read-репозиторий читают поля структуры; резолв `dao`, `codec` и источника строк — в одной точке.
Публичное поведение, исходы и телеметрия не меняются.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Модуль конфигурации — структура с `@enforce_keys`; поля: поведение, агрегат, модуль id, кодек событий, тип, каталог ошибок, настройка снапшота, резервы ключей, `dao`, `codec`, источник строк.
- [ ] Настройка снапшота — вложенная структура (`every`, `version`, `sealed`); `nil` — снапшоты выключены.
- [ ] Базовая структура собирается на компиляции; вызов конфигурации делает struct update и резолвит зависимости через `Core.Config` в одной точке; `Map.merge` на каждый вызов уходит.
- [ ] `Snapshot.marker/1`, `Snapshot.sealed/4`, `Snapshot.opts!`, `Plan.new/3`, движок чтения и read-репозиторий читают поля структуры, а не ключи map'ы.
- [ ] Служебная функция read-репозитория сохраняет имя и возвращает структуру; на компиляции read-репозитория она не вызывается, проверка — наличие экспорта.
- [ ] Тесты правят конфигурацию по полям структуры; `make` зелёный, dialyzer без новых предупреждений.
- [ ] CHANGELOG не пополняется: всё внутреннее.

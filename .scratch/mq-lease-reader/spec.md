# Один порт аренды и один цикл ожидания в MQ

Внутренний рефакторинг читателей брокеров и DLQ. Термины — `CONTEXT.md`, «Сообщение брокера»,
«Позиция источника», «Заявка на готовность»; нормы — `docs/rules/10-architecture.md`,
`docs/rules/21-observability.md`, `docs/adr/0093-topic-without-poller-is-misconfiguration.md`.

## Problem Statement

Три читателя — `Core.Mq.Stream.Reader`, `Core.Mq.Kafka.Reader` и `Core.Mq.Dlq.Reader` — реализуют один
behaviour `Core.Mq.ReaderReliable`, но общую часть держат копиями. Аренда описана трижды: тип токена и
`new_lease/0` в `Kafka.Reader.Store` и `Dlq.Store`, а срок считается в Postgres (`clock_timestamp()`);
потеря аренды выходит тремя разными фактами (`:kafka_lease_lost`, `:dlq_lease_lost` и `Logger.warning`
в outbox). Цикл ожидания (`poll/2`, `idle_or_poll/2`, `deadline/1`, `timed_out?/1`, `Process.sleep(10)`)
скопирован в трёх адаптерах, как и `:nothing_to_commit`. Плагин метрик `Core.Mq.PromEx` знает конкретные
адаптеры по именам и зовёт `Reader.info/1`/`Kafka.Reader.info/1`; у DLQ-читателя `info/1` нет, и новый
адаптер обязан править плагин, иначе метрики молча пропадут.

## Solution

Появляется внутренний `Core.Mq.Lease` — один порт аренды: новый токен, срок, нормализованный отказ
«аренда потеряна». Хранение остаётся у адаптеров (Kafka и DLQ), outbox не трогается. Цикл ожидания
сводится в `Core.Mq.Reader.Poll`: deadline, заявка на готовность и исход `:nothing_to_commit` по
таймауту. `ReaderReliable` получает необязательный `metrics/0`; `PromEx` предпочитает его и перестаёт
знать адаптеры по именам. Появляется контрактный набор тестов читателя — как у writer'а.

## User Stories

1. As мейнтейнер библиотеки, I want одно определение токена аренды, so that Kafka и DLQ не расходились в типе и способе создания.
2. As мейнтейнер библиотеки, I want один код отказа «аренда потеряна», so that метрика и лог не зависели от адаптера.
3. As мейнтейнер библиотеки, I want срок аренды считался в одном месте, so that сравнение часов Postgres и Elixir не расползалось.
4. As мейнтейнер библиотеки, I want один цикл ожидания, so that `deadline`, `sleep` и `:nothing_to_commit` не копировались в третий адаптер.
5. As мейнтейнер библиотеки, I want адаптер сохранял свои особенности (буфер и chunk у stream, партиции и аренда у Kafka), so that общий цикл не стирал различия.
6. As мейнтейнер библиотеки, I want новый читатель получал ожидание и заявку на готовность бесплатно, so that реализация behaviour не начиналась с копипасты.
7. As мейнтейнер библиотеки, I want `PromEx` не знал имён адаптеров, so that новый читатель давал метрики без правки плагина.
8. As мейнтейнер библиотеки, I want контрактный набор тестов читателя, so that «без commit то же сообщение» и «commit двигает» проверялись одинаково у всех адаптеров.
9. As мейнтейнер библиотеки, I want DLQ-читатель проверялся в обычном `mix test`, so that основные гарантии не ждали брокера.
10. As мейнтейнер библиотеки, I want брокерные адаптеры проверялись под тегами, so that инфраструктура не требовалась для обычного прогона.
11. As разработчик приложения, I want `ReaderReliable` остался совместимым, so that свой читатель не переписывался.
12. As разработчик приложения, I want `metrics/0` был необязательным, so that свой читатель без метрик продолжал компилироваться.
13. As разработчик приложения, I want `info/1` у существующих читателей сохранился, so that код, звавший его, не сломался.
14. As разработчик приложения, I want поведение подписчика не изменилось, so that backoff и решение «опрашивать или ждать заявку» остались прежними.
15. As разработчик приложения, I want wire-формат сообщений не изменился, so that совместимость с уже отправленными сообщениями сохранилась.
16. As разработчик приложения, I want outbox не затронут, so that его аренда и часы остались как есть.
17. As оператор приложения, I want метрики DLQ-читателя появились, so that мёртвые письма были видны без отдельного дашборда.
18. As оператор приложения, I want потеря аренды логировалась одинаково, so that поиск по инциденту не зависел от брокера.
19. As оператор приложения, I want существующие gauges Kafka и stream не изменили имена, so that дашборды остались рабочими.
20. As мейнтейнер библиотеки, I want `Mq.Lease` внутренним, so that у потребителя не появился контракт, которого библиотека не обещает.

## Implementation Decisions

- **`Core.Mq.Lease` — внутренний модуль** (`@doc false`), не behaviour: `new_token/0`, `deadline(ttl)`,
  `lost_error(scope, detail)`. Хранение и SQL остаются у адаптеров: `Kafka.Reader.Store` и `Dlq.Store`
  продолжают писать `locked_until` и токен, срок по-прежнему считает Postgres. Outbox не переводится на
  `Mq.Lease`: у него свои часы (`DateTime.utc_now`), свой Prim `LeaseID` и своя семантика лога.
- **`Core.Mq.Reader.Poll` — модуль функций**, не макрос и не behaviour. Основная функция `await/4`
  принимает `fetch` (функцию чтения), `ready?`/`ready_request` (заявку на готовность, если адаптер её
  поддерживает), таймаут и интервал; владеет deadline, `Process.sleep`, `timed_out?` и исходом
  `{:error, :nothing_to_commit}` по таймауту. Backoff, интервал опроса по умолчанию и решение
  «опрашивать или ждать `{:mq_ready, ref}`» остаются у `Core.PubSub.MqSubscriberReliable`.
- **Адаптеры сохраняют свои исходы.** Stream и Kafka переводят свой `:nothing_to_commit` в общий вид;
  DLQ — тоже. Ошибки брокера, отказ `commit` и `exit` процесса-читателя не переупаковываются: контракт
  `ReaderReliable` остаётся про отказ брокера, а не читателя.
- **`metrics/0` — необязательный колбэк** `Core.Mq.ReaderReliable`, возвращает карту значений для gauges.
  `PromEx` зовёт `metrics/0`, если модуль его экспортирует, иначе падает на существующий `info/1`.
  `info/1` у `Stream.Reader` и `Kafka.Reader` сохраняется как есть; `Dlq.Reader` получает `metrics/0`
  (по `info/1` он не обязан).
- **Имена метрик не меняются.** `PromEx` продолжает отдавать те же gauges; меняется только способ
  получения значений.
- **Wire-формат не меняется.** `Stream.Codec`, `Stream.Buffer`, `Mq.Position` не трогаются; DLQ
  round-trip остаётся.
- **Контрактный набор читателя** — `test/support/mq_reader_contract.ex` по образцу
  `mq_writer_contract.ex`: без `commit` то же сообщение, `commit` двигает позицию, `notify_when_ready`
  приходит один раз, `metrics/0` возвращает карту нужной формы, `get` после закрытия/пустоты даёт
  `:empty`. DLQ гоняется в обычном прогоне, stream и Kafka — под тегами `:rabbit_stream` и `:kafka`.
- **CHANGELOG.** «Новое»: необязательный `metrics/0` в `ReaderReliable`, `metrics/0` у DLQ-читателя.
  Ломающих изменений нет; `Mq.Lease` и `Reader.Poll` внутренние и в CHANGELOG не попадают.
- **Порядок работ (тикеты).** 01 — `Mq.Lease`, перевод Kafka и DLQ; 02 — `Reader.Poll` и три читателя;
  03 — `metrics/0`, `PromEx`, контрактный набор. Каждый шаг — зелёный `make`; 02 и 03 дополнительно
  `make test-stream` и `make test-kafka`.

## Testing Decisions

- Хороший тест проверяет наблюдаемое поведение: что вернул `get`, сдвинулся ли курсор после `commit`,
  пришла ли заявка на готовность, какие значения отдаёт `metrics/0`. Приватные функции и SQL не
  проверяются.
- **Высший шов — контракт `Core.Mq.ReaderReliable`**, общий для трёх адаптеров: новый
  `MqReaderContract` прогоняется на DLQ всегда, на stream и Kafka — под тегами. Приоритет — существующий
  writer-контракт как образец.
- **Шов цикла — `Reader.Poll` с фейковым `fetch`:** таймаут без сообщений даёт `:nothing_to_commit`,
  сообщение до таймаута возвращается как есть, заявка на готовность вызывает `fetch` один раз, интервал
  не превращается в busy-loop. Тест без процессов и брокера.
- **Аренда** проверяется через store-тесты Kafka и DLQ: потерянная аренда даёт один и тот же отказ и не
  даёт записать `commit`. Существующие тесты, которые руками портят `locked_until` или спят на
  миллисекундном TTL, сохраняются как есть.
- **Метрики** — тест `PromEx` на фейковом читателе: `metrics/0` используется, `info/1` — запасной путь,
  отсутствие обоих не роняет сбор метрик.
- **Subscriber** — существующие тесты `MqSubscriberReliable` должны пройти без правок: поведение
  подписчика не меняется.

## Out of Scope

- Аренда outbox и её часы; `Outbox.Repo.Pg` и `Outbox.Record` — спека `outbox-record`.
- Новые брокеры и новые адаптеры; wire-формат, партиционирование, DLQ-миграции.
- Поведение `MqSubscriberReliable` (backoff, DLQ-writer, порядок партиций) — не меняется.
- Read-движок ES и спека поля — соседние спеки.
- Публичный контракт `Mq.Writer` и `Mq.Client.ensure_available!` — не трогаются.

## Further Notes

- Шов аренды реальный: два адаптера хранения уже есть (Kafka, DLQ), третий (outbox) сознательно не
  втягивается.
- ADR-0093 (topic без poller — миссконфигурация) не пересматривается: спека не трогает сборку дерева
  outbox и `Mark`.
- Риск: `metrics/0` не должен требовать от читателя живой процесс — у DLQ `info/1` строится по ETS/базе;
  форма карты фиксируется контрактным тестом, а не `@spec` без реализации.

# 05: Дашборды `mq` и `kafka`

**What to build:** приложение выгружает дашборды подсистем библиотеки RabbitMQ Stream с
подписчиками (`mq`) и Kafka с DLQ (`kafka`). Набор по умолчанию учитывает опции
`Core.Mq.PromEx`: без `kafka_readers:` нет дашборда `kafka`, без `stream_readers:` и `readers:` —
нет `mq`. Основа — дашборды потребителя A без панели собственного плагина приложения
(`research.md`, раздел 1). Спека: `.scratch/consumer-tooling/spec.md`.

Отступления от дашбордов A:
- переменная `topic` у `mq` — по `deliver_entries_total`, а не по регулярке
  `{__name__=~"<префикс>_mq_.*"}`: самопроверка имён метрик сочла бы `mq_` необъявленной метрикой;
- у `kafka` добавлена сводка «Messages to DLQ, 5m» по `reason` — двойник графика `topic × reason`
  по норме «Форма панелей»; панели ряда DLQ сдвинуты вниз;
- параметр порога — только «Max backlog» (`kafka_backlog_critical`, 1000): пороги `1` у сводок
  ошибок, аренды и мёртвых записей значат «любое срабатывание» и от приложения не зависят;
- в описании панели алерт `MqKafkaDecodeDrops` → `MqDecodeDrops` (имя рекомендованного алерта
  библиотеки); порядок ключей верхнего уровня — как у `outbox`;
- единица оси «Publish duration p95» — параметр `mq_duration_axis_unit` по `duration_unit:` плагина
  (у A — литерал `ms`).

`readers:` включает `mq`, как требует спека, хотя плагин этот ключ больше не читает (переименован в
`stream_readers:`): приложение со старым ключом получит `mq` с пустыми панелями читателей.

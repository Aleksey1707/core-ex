# 04: Проверка свежести выгрузки и нормы обращения с дашбордами

**What to build:** тест приложения падает, когда выгрузка дашборда подсистемы библиотеки или
штатного PromEx в его каталоге разошлась с текущим рендером — ручная правка, старый порог,
обновлённая core: после обновления зависимости забытый переэкспорт ловит тест, а не пустая панель
в проде. Свод говорит, как обращаться со штатными дашбордами и дашбордами подсистем библиотеки и
где проходит граница ярусов. Спека: `.scratch/consumer-tooling/spec.md`; решение: ADR-0089,
ADR-0099.

**Blocked by:** 01

**Status:** resolved

- [x] Публичная проверка свежести в `Core.PromEx.Dashboards`: каждая выгрузка дашборда подсистемы библиотеки и штатного PromEx совпадает с рендером для модуля PromEx приложения; расхождение — нарушение с именем файла; вариант для теста
- [x] Доменные дашборды проверка свежести не трогает; штатные выгрузки PromEx проверяет наравне с подсистемными — `stale/2` и `surplus/2` смотрят `names/0` и `standard/0`
- [x] Тесты: совпадающая выгрузка проходит; ручная правка, старый порог, другой `otp_app` — нарушение
- [x] `app/21-observability.md`, «Дашборды и алерты»: штатные дашборды и дашборды подсистем библиотеки — выгрузка `mix core.dashboards.export` без ручных правок, переэкспорт после обновления core; доработка — только в доменном дашборде; `dashboards/0` не регулируется

- [x] Пункт в CHANGELOG с переходом «своя копия → выгрузка»

# 04: Проверка свежести выгрузки и нормы обращения с дашбордами

**What to build:** тест приложения падает, когда выгрузка дашборда подсистемы библиотеки в его
каталоге разошлась с текущим рендером — ручная правка, старый порог, обновлённая core: после
обновления зависимости забытый переэкспорт ловит тест, а не пустая панель в проде. Свод говорит,
как обращаться со штатными дашбордами и дашбордами подсистем библиотеки и где проходит граница
ярусов. Спека: `.scratch/consumer-tooling/spec.md`; решение: ADR-0089.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] Публичная проверка свежести в `Core.PromEx.Dashboards`: каждая выгрузка дашборда подсистемы библиотеки совпадает с рендером для модуля PromEx приложения; расхождение — нарушение с именем файла; вариант для теста
- [ ] Доменные и штатные дашборды проверка свежести не трогает
- [ ] Тесты: совпадающая выгрузка проходит; ручная правка, старый порог, другой `otp_app` — нарушение
- [ ] `app/21-observability.md`, «Дашборды и алерты»: штатные дашборды — выгрузка `mix prom_ex.dashboard.export` без ручных правок; дашборды подсистем библиотеки — выгрузка `mix core.dashboards.export` без ручных правок, переэкспорт после обновления core; доработка — только в доменном дашборде; `dashboards/0` не регулируется
- [ ] `app/00-index.md`: строка «дашборды» в таблице ярусов разделена — выгрузки и нормы обращения с ними в ярусе потребителя, доменные дашборды и пороги в локальном своде
- [ ] Пункт в CHANGELOG с переходом «своя копия → выгрузка»
- [ ] `make` зелёный

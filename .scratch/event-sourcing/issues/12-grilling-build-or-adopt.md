# Своя реализация или готовая библиотека

Type: grilling
Status: resolved
Blocked by: 11, 13
Map: [Event-sourced агрегат в :core](../map.md)

## Question

На чём строится event-sourced агрегат `:core`:

- своя реализация на `Repo.Pg` / `DAO`;
- EventStore (commanded/eventstore) как хранилище, подписки и снапшоты + адаптеры `:core`;
- другое, если research «Готовые ES-библиотеки на Elixir и их совместимость с принципами core» или task
  «Проверить EventStore на Elixir 1.20 и append в `Transact.run`» откроют новый вариант.

Что взвесить:

- что адаптер обязан добавить поверх библиотеки: кодек `:core` как сериализатор и провайдер типа,
  `Context` → метаданные (автор, момент), доменные ошибки вместо ошибок библиотеки, telemetry / OTel;
- цена зависимости: сопровождение, совместимость с Elixir 1.20, свои процессы и пул соединений, свои
  миграции и схема БД, блокировка `$all`;
- что библиотека закрывает из тикетов карты (модель потока, подписки с чекпоинтом, снапшоты) и что всё
  равно пишется в `:core` (decide / evolve, репозиторий, агрегат-процесс, эволюция событий);
- граница: optional-зависимость, модуль хранилища объявляет потребитель (решение раунда 3 тикета
  «Контракт event-sourced агрегата»).

## Answer

- Своя реализация на `Repo.Pg` / `DAO`, без новых зависимостей: хранилище событий, глобальная позиция, подписки,
  чекпоинты и снапшоты — в `:core`; Commanded, EventStore, Marten, Emmett, Message DB — образцы устройства.
- EventStore отвергнут:
  - блокировка `$all` сериализует все append store на длину транзакции usecase, отключить нельзя;
  - в `Transact.run` встаёт только через приватный ключ ecto_sql, требует запущенного supervisor store, при
    гонке переводит транзакцию в aborted;
  - экономит лишь SQL глобального порядка и таблицу снапшотов: чекпоинт вместе с read-моделью и telemetry
    пишутся в `:core` в любом случае;
  - сопровождение (релиз 2025-03, `fsm` 2018) приемлемо и само по себе не решающее.
- Ariadne Flow (DCB без версии агрегата) и копия внутреннего `EventStore.Streams.Stream` исключены; Commanded и
  Maestro исключены раньше — путём команды.
- Ограничение тикету «Модель потока и таблица событий»: глобальный порядок не заставляет запись в разные потоки
  ждать commit чужой транзакции — остаются `xid8 < pg_snapshot_xmin` и high-water mark; не проверено на нагрузке.
- Ограничения тикету «Контракт репозитория event-sourced агрегата»: конфликт версии — `:version_mismatch` без
  aborted-транзакции; без приватных API Ecto / ecto_sql.
- Источник событий проекций (хранилище или outbox → брокер) не решён — вопрос тикета «Проекции: источник
  событий, чекпоинт, порядок».
- Термин «Хранилище событий (event store)» — в `CONTEXT.md`, раздел «Хранение».

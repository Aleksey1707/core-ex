# Эволюция событий: где апкастится история

Type: grilling
Status: resolved
Blocked by: 03, 12
Map: [Event-sourced агрегат в :core](../map.md)

## Question

Как история событий читается кодом, который её не писал:

- где выполняется апкаст: в `Es.Event.Codec` при `load`, в event store при чтении, отдельной цепочкой;
  что на входе — конверт (map) или структура;
- как определяется версия схемы события: новое поле конверта, новый тег, `aggregate_version` (текущее
  правило `docs/rules/14-events-outbox.md`);
- что делать с `:unknown_event_type` при восстановлении event-sourced агрегата и в проекции;
- распространяется ли механизм на state-stored агрегаты (кодек общий);
- апкаст на лету против переписывания истории.

## Answer

- **Место апкаста** — кодек агрегата: `use Core.Es.Event.Codec` с `upcasts: %{"старый тег" => "новый тег"}` и колбэком
  `upcast(old_tag, envelope)` → нагрузка; срабатывает в `load_by_tag` до выбора модуля. Его видят все, кто грузит через
  фасад: `get`, проекция, подписчик брокера, экран истории, golden-фикстуры — у event-sourced и state-stored агрегатов,
  без флага. Апкаст в `Core.Es.Store`, struct → struct и отказ от механизма отвергнуты.
- **Границы.** Меняются только тег и нагрузка, заголовок (`event_id`, `aggregate_id`, `aggregate_version`, `at`, `by`)
  колбэк только читает; одно записанное событие — ровно одно прочитанное. Цепочка v1 → v2 → v3 по шагам. На
  компиляции: источник не в `tags:`, цель — в `tags:` или сама источник, циклов нет, колбэк обязателен при непустых
  `upcasts:`; переименование тега — клауза с нагрузкой как есть.
- **Версия схемы — тег.** Новое опциональное поле тег не меняет, любое другое изменение — новый тег
  (`delivery.registered.v2`) и апкаст со старого. Поле `schema_version` отвергнуто; правило «upcast по
  `aggregate_version`» уходит — версия агрегата не разделяет потоки, начатые до и после выкладки.
- **Удаление типа без замены** — тип остаётся в `tags:`, клауза `evolve` не меняет состояние, писать перестают.
- **История не переписывается** (MUST NOT), инструмента нет: брокер уже получил старую форму, `event_id` — ключ
  идемпотентности, копия получает новый `xid`. Исключение — перенос таблиц state-stored в `es_events` без
  преобразования.
- **Неизвестный тег.** Агрегат — `raise` в `get`. Проекция: тег проходит цепочку `upcasts:`, «объявлен ли» — по
  текущему тегу, апкаст нагрузки и `load` — только объявленному; известный кодеку (`tags:` или источник `upcasts:`),
  но не объявленный — пропуск; неизвестный кодеку — ошибка `load`, retry без пропуска (пересмотр
  [«Проекции: источник событий, чекпоинт, порядок»](08-grilling-projections.md) ради поэтапной выкладки). Подписчик
  брокера — `:unknown_event_type`, как сейчас.
- **Prim в событии** (нагрузка и заголовок) не ужесточается, ослаблять можно; новое ограничение — новый Prim и новый
  тег. `load` истории без проверок и обрезание значения в апкасте отвергнуты.
- **Golden-фикстуры:** (1) у каждого тега `types/0` есть фикстура; (2) каждая грузится через
  `InCodec.load(Agg.Event, _)`; (3) у каждого источника `upcasts:` есть фикстура; (4) фикстура источника грузится в
  модуль конца цепочки. Имена интроспекции и место `EventCompatCase` — «Тестовая поддержка» в карте.
- **Снапшоты** апкаст не покрывает — [«Снапшоты: хранение, политика, инвалидация»](10-grilling-snapshots.md).
- **Свод** — таблица «Совместимость событий» в `14-events-outbox.md` (правка — «Своды» в карте):

  | Изменение | Статус |
  |---|---|
  | новое событие (новый тег) | разрешено |
  | новое **опциональное** поле нагрузки | разрешено, тег прежний; `load_payload` читает нагрузку без него |
  | новое обязательное поле, переименование или удаление поля, смена типа значения | новый тег + апкаст со старого |
  | переименование тега | новый тег + апкаст со старого, нагрузка как есть |
  | удаление типа события | тег остаётся в `tags:`, клауза `evolve` не меняет состояние, писать перестают |
  | ужесточение проверок Prim в нагрузке или заголовке | **запрещено**; новый Prim + новый тег |
  | ослабление проверок Prim | разрешено |
  | изменение записанных строк `es_events` | **запрещено** |

  Норма «тег и clause `load_payload` остаются навсегда» → «тег остаётся в кодеке навсегда — в `tags:` или в
  `upcasts:`».
- Термин «Апкаст» — в `CONTEXT.md`, раздел «События и доставка».

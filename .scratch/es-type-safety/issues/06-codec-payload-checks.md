# 06: Проверки кодека событий — `dump_payload`, `load_payload`, модуль нагрузки

**What to build:** автор кодека событий получает предупреждение при сборке, указывающее на строку
`use Core.Es.Event.Codec`, если у `dump_payload/2` или `load_payload/3` нет clause для события с нагрузкой или если
`load_payload/3` отдаёт нагрузку другого события — литералом или через `Payload.new`.

**Blocked by:** 01, 04

**Status:** resolved

**Spec:** [Типобезопасность потребителя `Core.Es`](../spec.md) — «Функции-проверки полноты»

- [x] `__before_compile__` кодека генерирует по событиям `tags:` с нагрузкой, по механике тикета 04:
  - проверку `dump_payload/2` на событии, суженном по `payload:` — имя `"dump_payload/2 принимает <Event>"`;
  - проверку `load_payload/3` с литеральным модулем события и сопоставлением результата с
    `{:ok, %<Payload>{}}` — имя `"load_payload/3 отдаёт нагрузку <Payload>"`; clause `{:error, _}` размечена
    `generated: true` в meta, остальная проверка — нет.
- [x] Кодек без событий с нагрузкой проверок нагрузки не получает.
- [x] Фикстура: маркеры H1 (`dump_payload`), H1 (`load_payload`), H2 литералом, H2 через `Payload.new`. Корректные:
      кодек с `upcasts:`, `load_payload`, который никогда не возвращает ошибку, модуль нагрузки, общий у двух событий,
      — ноль предупреждений.
- [x] moduledoc `Core.Es.Event.Codec` (проверки и их имена); `11-domain.md` / `14-events-outbox.md` — где описаны
      колбэки нагрузки.
- [x] `CHANGELOG.md`, «Не выпущено»: пункт кодека событий дополнен.
- [x] `make` зелёный.

Prior art: `.scratch/es-type-safety/prototype/lib.diff` (`event/codec.ex`), раздел P2 в `RESULTS.md` (H1, H2, находка
про `Payload.new` на проходе проверки).

## Comments

- 2026-09-17 — реализация:
  - `__before_compile__` `use Core.Es.Event.Codec` после `draft` генерирует через `Es.Check.define/5`
    проверки `dump_payload` и `load_payload` на каждое событие с нагрузкой; строка `use` —
    `@es_use_line` из `__using__`. Clause `{:error, _}` собрана `quote generated: true`, а `put_line`
    в `define/5` meta не затирает;
  - имя проверки `load_payload` называет модуль нагрузки, поэтому у нагрузки, общей у нескольких
    событий (`Grants`), функция одна — с clause на событие (литерал модуля события в голове, как в
    прототипе); clauses идут подряд: сначала все проверки `dump`, затем `load`, отсортированные по
    нагрузке. Проверено вручную: у `Ping` функций-проверок нет;
  - мутация «без `generated: true`» даёт 4 лишних предупреждения, в том числе на корректном
    `Consumer.Parcel.Event.Codec`;
  - фикстура: события посылки переехали из `lib/scenarios/codec.ex` в `lib/consumer/parcel/**` с
    корректным кодеком, чей `load_payload/3` не ошибается (`Payload.new` у `Sent`, литерал у `Lost`).
    В сценариях — кодеки `BadCodec` (H1 ×2, на него же переведены H1d), `BadCodecPayload` (H2),
    `BadCodecPayloadNew` (H2n) и `BadCodecSharedPayload` (H2g ×2). Маркеров 86 (было 80);
  - сверх перечня: moduledoc `Core.Es.Check` — разметка clause в meta (снята при ревью 04 до этого
    тикета); `11-domain.md` колбэки нагрузки не описывает — правился только `14-events-outbox.md`.
    Проверка `dump_payload` ловит и опечатку в поле нагрузки без паттерна `%Payload{}` (проверено
    вручную), но в тикете такого сценария нет — маркер не заведён, в документации не заявлено.
- 2026-09-17 — по ревью: первая версия делила одну функцию на модуль нагрузки с `case` на событие в
  теле — вывод типов после первого предупреждения в теле функции остальные не сообщает
  (`context.failed` сбрасывается только на новой clause), и у общей нагрузки с двумя сломанными
  событиями было видно одно. Переделано на clause на событие, закреплено сценарием H2g с двумя
  маркерами. Убран неиспользуемый `Lost.Payload.new/1` фикстуры, заголовок пункта CHANGELOG о занятых
  именах назван полностью. Не принято: вынос пары `@es_use_line` / `Module.get_attribute` в
  `Es.Check` — место строки `use` задано спекой, у проекции и кодека разные `__using__`; перенос
  `payload_checks` к `__before_compile__` блоками — `draft_ast` уже живёт в хвосте, минимальный
  diff; общий хелпер выборки событий с нагрузкой — три короткие формы с разным результатом;
  `generated: true` в CHANGELOG — так же описано сужение `execute/2`; разметка clause в moduledoc
  `Core.Es.Check` — её туда и отложили при ревью 04; H1 dump и load в одном модуле — как C1 ×2 у
  `BadEvolve.Repo`.

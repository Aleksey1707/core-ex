# 01: Храповик — фикстура-потребитель и `make consumer-check`

**What to build:** мейнтейнер `Core` запускает `make consumer-check`: собирается фикстура-потребитель — приложение на
`Core`, которое видит библиотеку зависимостью, — и её предупреждения компилятора сверяются с маркерами над ошибочными
строками. Корректная часть фикстуры собирается без предупреждений, сценарии, которые компилятор ловит уже сейчас,
размечены. Пропавшее ожидание или лишнее предупреждение валит шаг. Это основа задачи: каждый следующий тикет доказывает
свою проверку маркером здесь.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Spec:** [Типобезопасность потребителя `Core.Es`](../spec.md) — «Храповик — фикстура-потребитель», «Testing Decisions»
(шов 1)

- [ ] Фикстура — Mix-проект в core-ex вне `config|lib|test`: зависимость `:core` по пути на корень репозитория,
      `lockfile:` — `mix.lock` библиотеки (он не меняется), свой `_build`. `_build` и `deps` фикстуры не отслеживаются;
      formatter, Credo, `layout_lint`, `boundary_lint` библиотеки её не обходят.
- [ ] Корректный потребитель собирается с нулём предупреждений: два агрегата с ID, командами, событиями с нагрузкой и
      без, кодеками (один с `upcasts:`, один только из событий без нагрузки, у одного — модуль нагрузки, общий у двух
      событий), `Errors`, `Outbox`, репозиториями и их `Pg`, процессом, проекцией на события двух агрегатов, фасадом и
      usecase'ами в типовых вызовах (`@repo` через `Core.Config.repo!/1`, `execute`, `append`, `Process.execute`).
- [ ] Сценарии карты `research/02-core-es-blind-spots.md` со статусом «ловится» — по функции или модулю на ошибку, с
      маркером `# expect: <начало заголовка предупреждения>` строкой над ошибочной строкой.
- [ ] Скрипт-сверка живёт при фикстуре: предупреждения — из диагностик Mix API (`compile --force --return-errors`), а не
      разбором текста; перед сборкой пересобирается изменённая path-зависимость (`deps.loadpaths`). Падает, если
      ожидание без предупреждения или предупреждение без ожидания, и печатает файл, строку и заголовок; сдвиг строк
      переживает.
- [ ] Три исхода скрипта — пропавшее ожидание, лишнее предупреждение, сдвиг строк — воспроизводимы (скрипт
      самопроверки или процедура в README фикстуры).
- [ ] Dialyzer на фикстуре не запускается.
- [ ] Цель `make consumer-check` после `compile-no-optional`, в `make` по умолчанию; хук в `.pre-commit-config.yaml`
      на том же месте; порядок шагов обновлён в `20-agreements.md` («Linters & Formatters»), в комментарии
      pre-commit и в `AGENTS.md` («Команды»).
- [ ] README фикстуры: что это, как запустить, как добавить сценарий, что маркер сверяет начало заголовка.
- [ ] CHANGELOG не правится: шаг — инструмент мейнтейнера.
- [ ] `make` зелёный.

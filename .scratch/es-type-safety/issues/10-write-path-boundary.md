# 10: Граница генерируемых функций write-пути — `Core.Repo.Pg`, `StateStored`, `Schema`

**What to build:** автор state-stored агрегата получает предупреждение при сборке на типовые ошибки вызовов, которые
генерируют `Core.Repo.Pg`, `Core.Repo.Pg.StateStored` и `Core.Repo.Pg.Schema`: ID или сущность другого агрегата,
неверная версия, опечатка в поле результата, невозможная clause. Поведение write-пути при исполнении прежнее.

**Blocked by:** 01

**Status:** ready-for-agent

**Spec:** [Типобезопасность потребителя `Core.Es`](../spec.md) — «Остальные генерируемые функции `Core`», «Граница типов
генерируемых функций»

- [ ] Фикстура получает state-stored агрегат с событиями, репозиторием, `Pg` и `Schema`, и сценарии типовых ошибок для
      каждой публичной генерируемой функции; сначала фиксируется, какие из них ловятся сейчас (маркеры).
- [ ] Молчащие сценарии становятся видимыми: закрытые головы — вариант головы выбирается при раскрытии макроса вместо
      `(@id_type == nil or is_struct(id, @id_type))` и `(@entity_type == nil or is_struct(entity, @entity_type))`;
      результаты сужены в `generated: true`.
- [ ] Правка без сценария, который она делает видимым, не вносится. Сценарий, который видимым не сделать, записан в
      комментарии тикета с причиной — он уходит в таблицу пределов компилятора (тикет 13).
- [ ] Корректный state-stored потребитель — ноль предупреждений.
- [ ] ExUnit write-пути (`Repo.Pg`, `StateStored`, `Schema`, гонки) — прежние исходы.
- [ ] `13-repos.md` и moduledoc — если меняются типы результатов или занятые имена.
- [ ] `CHANGELOG.md` — по правилам CHANGELOG, если изменение видно потребителю.
- [ ] `make` зелёный.

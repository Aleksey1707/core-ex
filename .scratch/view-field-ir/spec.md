# Одна таблица видов и один IR поля

Внутренний рефакторинг языка спеки полей: `Core.Codec.Field`, `Core.View`, `Core.View.Opts`,
`Core.View.Dumper`, `Core.Codec.Plugin.Fields`, `Core.Es.Event.Payload`, `Core.Labels.*`.
Термины — `CONTEXT.md`, «Спека полей», «Структура по полям», «Codec-плагин по полям», «View»;
нормы — `docs/rules/11-domain.md`, `docs/adr/0090-struct-by-fields.md`,
`docs/adr/0091-set-and-map-fields.md`.

## Problem Statement

Один и тот же язык «спека поля» разбирается в двух независимых таблицах видов: `Core.Codec.Field`
(`prim`, `enum`, `entity`, `union`, `list`, `set`, `map`, `type`) и `Core.View.Opts` (`prim`, `enum`,
`type`, `view`, `form`, `list`, `set`, `map`, `jsonb`). Пересечение поддерживается дважды, расхождение
(`entity`/`union` против `view`/`form`/`jsonb`) нигде не сверяется. Дальше одна спека поля разбирается
заново в каждой проекции: тип (`View.type_ast`), рантайм-форма (`View.shape` + `Opts.shaped?`), код дампа
(`View.Dumper.dump_ast`), необходимость codec (`Opts.needs_codec?`), нормализация (`Opts.spec!`).
Добавление вида `jsonb` прошло по пяти местам, `set:`/`map:` — по пяти в `View` плюс шесть switch'ей в
плагине и по одному в `Payload` и подписях. Правки синхронные, а забытая проекция проявляется не ошибкой
сборки, а неверным значением в `new/1` или в wire-форме.

## Solution

Спека поля нормализуется один раз. Виды собираются в одну таблицу с allowlist по хосту (структура,
плагин, нагрузка события, View, подписи), поэтому «этот вид здесь запрещён» — одна запись, а не две
таблицы. Для `View` появляется внутренний IR `%Core.View.Field{}`: он несёт AST типа, AST формы, AST
дампа и два boolean'а, посчитанных один раз в `Opts`. `View` и `Dumper` только собирают из готовых
кусков. Срезы: View (1), плагин по полям (2), `Payload`/подписи (3). Публичный контракт `use Core.View`
не меняется, поведение `new/1`, дампа и загрузки — тоже.

## User Stories

1. As мейнтейнер библиотеки, I want одну таблицу видов поля, so that расхождение `Codec.Field` и `View.Opts` стало невозможным.
2. As мейнтейнер библиотеки, I want allowlist по хосту, so that «этот вид запрещён в структуре/нагрузке/View» читалось в одном месте.
3. As мейнтейнер библиотеки, I want добавить новый вид одной правкой таблицы и одного адаптера, so that не искать пять switch'ей.
4. As мейнтейнер библиотеки, I want IR `%View.Field{}` с посчитанными проекциями, so that `View` и `Dumper` не разбирали спеку заново.
5. As мейнтейнер библиотеки, I want `shaped?` и `needs_codec?` выводились из IR, so that добавление вида не забывало флаг.
6. As мейнтейнер библиотеки, I want ошибку «у вида нет обязательной проекции» получать на сборке, so that неполный вид не доходил до рантайма.
7. As мейнтейнер библиотеки, I want срез 1 не трогал плагин, so that ревью было обозримым и падение не смешивало две причины.
8. As мейнтейнер библиотеки, I want срез 2 перевёл плагин на ту же таблицу, so that `set:`/`map:` перестали быть шестью switch'ами в одном файле.
9. As мейнтейнер библиотеки, I want срез 3 свёл `Payload` и подписи к общей таблице, so that нагрузка события и подписи не заводили свои списки видов.
10. As разработчик приложения, I want `use Core.View` не изменился, so that объявления View в приложении не переписывались.
11. As разработчик приложения, I want `new/1` давал те же значения, so that поведение конструктора не поехало.
12. As разработчик приложения, I want `dump`/`load` давали ту же wire-форму, so that записи в `jsonb` и брокере остались совместимыми.
13. As разработчик приложения, I want прежние `CompileError` на неверную спеку, so that диагностика сборки не ухудшилась.
14. As разработчик приложения, I want `default:` и `optional:` сохранили своё разное значение по режимам, so that принятая цена ADR-0090 не превратилась в ломающее изменение.
15. As разработчик приложения, I want `set:`/`map:` продолжали работать в структуре, плагине, View и нагрузке, so that недавняя фича не откатилась.
16. As разработчик приложения, I want `Core.Struct` не менял выведенные ключи и `@enforce_keys`, so that структуры остались прежними.
17. As разработчик приложения, I want `consumer-check` ловил сужение типов, so that опечатка в поле View по-прежнему давала предупреждение.
18. As оператор приложения, I want wire-формат не изменился, so that старые записи читались без миграции.
19. As мейнтейнер библиотеки, I want тест «вид × проекция» таблицей, so that новый вид проверялся по всем обязательным проекциям.
20. As мейнтейнер библиотеки, I want внутренний IR не попал в публичную документацию, so that потребитель не начал на него опираться.

## Implementation Decisions

- **Одна таблица видов.** `Core.Codec.Field` владеет объединением видов и функцией `kinds/0`; каждый хост
  объявляет allowlist (структура, плагин по полям, нагрузка события, View, подписи). Отдельная таблица
  `View.Opts.@kind_keys` исчезает; попытка вида вне allowlist — `CompileError` с именем хоста.
- **Общие правила ключей остаются в `Field`.** `map_opts!/2`, `check_map_key!/2` и `string_prim?/1`
  переиспользуются View через существующий адаптер (`field_key/1`); правило «ключ словаря — Prim с
  wire-строкой» не дублируется.
- **`%Core.View.Field{}` — внутренний IR** (`@doc false`): `name`, `spec`, `optional?`, `type_ast`,
  `shape_ast`, `dump_ast`, `shape?`, `needs_codec?`. Строится один раз в `View.Opts.field!/4`.
- **AST, не замыкания.** `new/1` генерируется на сборке и вызывает AST-фрагменты напрямую; замыкание в
  IR убило бы оптимизацию конструктора. `dump_ast` собирается так же, как сейчас.
- **`View.Opts.shaped?/1` и `needs_codec?/1` уходят как отдельные вычисления**: значения читаются из IR.
  Публичная функция `View.shape/2` сохраняется — её зовёт сгенерированный `new/1`.
- **`use Core.View` не меняется**: те же опции, те же проверки, те же `CompileError`. Внутренний IR не
  попадает в `@type t` View и в документацию.
- **Срез 2 — плагин.** Шесть switch'ей `Codec.Plugin.Fields` (`dump_pattern`, `field_guard`,
  `value_guard`, `dump_value`, `as_is?`, `load_*`) сводятся к адаптеру вида с четырьмя операциями
  (`pattern/1`, `guard/1`, `dump/2`, `load/3`). `Payload` продолжает декорировать `subject:` поверх
  готового адаптера, а не переписывать switch.
- **Срез 3 — `Payload` и подписи.** `Payload` и три обхода подписей (`Details`, `Refs`,
  `CompletenessCase`) читают общую таблицу; объединение самих обходов в один walker — **не** эта спека
  (см. Out of Scope).
- **Семантика не меняется.** Два смысла `default:` (wire-литерал у плагина против значения поля у
  структуры) и разное `optional:` по режимам сохраняются как принятая цена ADR-0090. `set:`/`map:`
  сохраняют канонический порядок и форму wire (`Codec.Helper.set_wire/1`, `enum_key/1`).
- **Порядок работ (тикеты).** 01 — общая таблица + `%View.Field{}`, allowlist всех хостов, `View` и
  `Dumper` на IR; 02 — плагин по kind; 03 — `Payload` и подписи. Срез 1 не трогает плагин и `Payload`
  по существу, только переводит их таблицу на общую.
- **CHANGELOG.** Изменение внутреннее: публичная поверхность, wire-форма и значения не меняются, поэтому
  пункт не заводится (AGENTS, «CHANGELOG» — внутренние изменения не попадают). Это уточняет раннюю
  договорённость о разделе «Новое»: видимой поверхности в срезах нет.

## Testing Decisions

- Хороший тест проверяет объявление и наблюдаемое поведение: `new/1` возвращает ожидаемое значение,
  `dump`/`load` через фасад дают ожидаемую wire-форму, неверная спека даёт `CompileError` с ожидаемым
  текстом. Внутренние имена и форма IR не проверяются.
- **Существующий (высший) шов — `use Core.View`** (`test/core/view_test.exs`, 69 тестов): объявление,
  `new/1`, дамп, `CompileError`. После среза 1 проходит без смысловых правок.
- **Шов плагина — фасад кодека** (`test/core/codec/**`, round-trip `dump`/`load` по всем видам):
  срез 2 не меняет ожиданий тестов, только реализацию.
- **Новый табличный тест «вид × обязательная проекция»**: для каждого вида из `kinds/0` проверяется,
  что хост получает все свои проекции (тип, форма/дамп, `needs_codec?`) или явный `CompileError`.
  Тест защищает от «добавили вид, забыли проекцию».
- **`consumer-check`** (`fixtures/consumer`, ADR-0014) — маркеры `# expect:`: опечатка в поле View и
  невозможная clause по результату дают предупреждение; храповик вывода типов не растёт.
- **Golden/round-trip** для `set:`/`map:`/`jsonb:` — существующие тесты, ожидания не меняются.

## Out of Scope

- Объединение трёх обходов подписей в один `Labels.Walk` и host-контракт вместо пробы модулей — отдельный
  кандидат, в эту спеку не входит.
- Унификация двух смыслов `default:` и разного `optional:` по режимам (ADR-0090).
- Новые виды поля и новые wire-форматы.
- `Core.Struct` (выведенные ключи, `@enforce_keys`), `Core.Codec.Redump`, `Core.Es.ValueChanged` —
  меняются только там, где переходят на общую таблицу, без изменения поведения.
- Публичный контракт `use Core.View` и опции `use Core.Struct`.

## Further Notes

- Мотивация по истории коммитов: `set:`/`map:` (ADR-0091) и структура по полям (ADR-0090) — последние
  крупные изменения языка; следующая фича языка заплатит ту же цену пяти правок, если таблицу не свести.
- Риск средний: срез 1 затрагивает сборку всех View у потребителей, поэтому `make consumer-check`
  обязателен, а `CompileError`-тексты считаются частью контракта.
- При конфликте «свести таблицу» и «не менять поведение» побеждает поведение: allowlist хоста может
  повторять сегодняшний набор видов, даже если он выглядит несимметричным.

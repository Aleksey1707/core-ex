# 03: 422 на составной схеме отдаёт нарушения чужих ветвей

**What to build:** `Core.Web.ErrorMapper.cast_errors/2` на неудавшейся составной схеме (`anyOf` /
`oneOf`) отдаёт в `data.errors` элемент составной схемы с перечнем `Schema(title: …)` всех ветвей и
нарушения каждой ветви. Нагрузка элемента пачки, выбираемая полем кода, у потребителя A собрана
`anyOf` без discriminator: из 11 элементов ответа настоящий — один, девять — одинаковые нарушения
чужих ветвей, допустимые в своей нагрузке.

**Решение:**

- нарушения строго под путём элемента составной схемы отбрасываются; на одном пути остаётся один
  элемент составной схемы — внешний, первый в списке; остальное — в порядке OpenApiSpex;
- `code` элемента — `reason` (`"any_of"` / `"one_of"`), текст — свой, с путём в форме
  OpenApiSpex и без названий схем: `"Value matches none of the allowed schemas"`, у `one_of` с
  непустым `meta.valid_schemas` — `"Value matches more than one of the allowed schemas"`;
- точная раскладка — у потребителя: discriminator на объекте-владельце поля, которое выбирает
  ветвь (`app/15-web-api.md`, SHOULD);
- записывается дополнением ADR-0068, его пункта в CHANGELOG и норм `10-architecture.md`,
  `app/15-web-api.md`.

**Status:** done

**Spec:** этот файл.

## Готово, когда

- `anyOf` и `oneOf` (оба исхода) дают по одному элементу на путь без нарушений ветвей и без
  названий схем;
- составная схема внутри ветви составной на том же пути даёт один элемент;
- элементы массива разбираются независимо, соседние нарушения сохраняются;
- ADR-0068, CHANGELOG, `10-architecture.md`, `app/15-web-api.md` описывают новую форму;
- `make` зелёный.

## Comments

`scripts/layout_lint.exs` принимал отступ маркера только как у определений модуля, а приватные
`cast_errors/2` матчат `%Cast.Error{}` и обязаны лежать внутри `if Code.ensure_loaded?(…)`:
`# ---` там допускается с отступом определения под ним, правило в `20-agreements.md` уточнено.

Не закрыто — `required` рядом с `anyOf` у самой составной схемы: при подошедшей ветви OpenApiSpex
отдаёт `missing_field` вместе с нарушениями упавших ветвей без элемента составной схемы. Отличить
исход можно только по самой схеме; записано в «Цене» ADR-0068.

Пример «хорошо» нормы discriminator в `app/15-web-api.md` проверен живым кастом: из нагрузки с
допустимым и лишним полем приходит одно нарушение — лишнего.

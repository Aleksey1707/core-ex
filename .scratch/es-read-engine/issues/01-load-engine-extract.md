# 01: Вынести read-движок и порт источника

**What to build:** чтение event-sourced агрегата идёт через один внутренний движок: он владеет свёрткой,
выбором снапшота, нарезкой версий и телеметрией, а SQL-запрос приходит через узкий порт «источник
строк». Мета потока и строки ходят парой, поэтому позиционной склейки в движке нет. Все шесть публичных
входов (`get`, `get_many`, `get_decision`, `refresh`, `get_at`, `get_many_at`) дают прежние исходы,
detail, снапшоты, обработку ПДн и исключения. Спека — `.scratch/es-read-engine/spec.md`.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Внутренний движок: `head/2`, `at/3`, `many_at/3` поверх приватного общего прогона; `@doc false`, публичных конструкторов адреса нет.
- [ ] Источник — функция, а не behaviour: получает конфигурацию, мету потоков и опции, возвращает пары «мета + шифротекст снапшота + строки»; политика версий и расшифровка остаются в движке.
- [ ] `Enum.zip_with` и склейка меты со строками по позиции в движке отсутствуют: каждая тройка сворачивается отдельно.
- [ ] Поведение сохранено: те же коды ошибок и detail (`source: :address` / `:expected`), те же события `[:es, :aggregate, :load]` и `[:es, :aggregate, :fold]` с прежними `op`, снапшот не выше границы, чтение на версии снапшоты не пишет, уничтоженное ПДн-значение остаётся уничтоженным.
- [ ] Тестовая поддержка строк без базы (`Core.Es.Store.Rows` в `test/support`) и unit-тесты движка: нарезка по границе, снапшот ≤ границы, снапшот новее границы, отказ адреса.
- [ ] Контрактные тесты read-репозитория и write-репозитория проходят без смысловых правок; `make` зелёный.
- [ ] CHANGELOG не меняется: видимой поверхности нет.

# Тикет 03 — что сделано и что это даёт дальше

Ветка `fcp/03` (от `field-constructor-personal`).

## Сделано

- `Core.Union` (`lib/core/union.ex`) + `Core.Union.Variant` (`lib/core/union/variant.ex`):
  - `use Core.Union, variants:` — список `{Модуль, адрес}`, опция-выражение (модули вариантов можно
    объявлять выше в том же модуле, `__MODULE__.X` тоже работает);
  - порождает `__core_variants__/0` (`[%Core.Union.Variant{module, address, place, kind}]`),
    `types/0` (`MapSet.t(String.t())`: тег или значение дискриминатора) и `variant/1`
    (по struct или модулю → `{:ok, variant} | :error`);
  - `kind`: `:prim` (`Core.Prim.prim?/1`), `:domain` (экспортирует `__core_fields__/0`),
    `:manual` (остальной struct);
  - `Core.Union.variants/1` — публичное чтение реестра для обходчика (пустой список, если `use` не
    было).
- Проверки при объявлении (`CompileError`, префикс `Union: variants: …`) переиспользуют
  `Core.Codec.Plugin.Variants`: `address!/2` (нормализация трёх форм), `check_places!/2` (повтор
  адреса, общий тег без дискриминатора, две формы, разные ключи), `check_default!/3`
  (дискриминатор против значения по умолчанию struct'а), `check_wire_clash!/3` (wire-ключ
  дискриминатора занят другим полем). Проверки мест принимают `[{модуль, place}]`, поэтому
  вызываются и старым путём плагина, и новым.
- Codec-плагин: `union: Family` без `variants:` берёт состав из `Family.__core_variants__()`
  (`Variants.union_variants!/2`; явные `variants:` старше). Источник полей варианта в плагине
  теперь `source`: спека `variants:` (`[%Core.Codec.Field{}]`), `{:domain, [%Core.Field{}]}`,
  `:prim` или `:manual`.
  - декларативный вариант: поля из `__core_fields__/0`, поле-дискриминатор из них исключается —
    при загрузке его оставляет `defstruct`;
  - вариант-Prim: `"fields"` — дамп Prim, загрузка `codec.load(Prim, fields)`; дамп идёт через
    новый служебный `codec.__codec_prim__()` (Prim-профиль фасада), иначе клоуза варианта ушла бы в
    рекурсию;
  - ручной вариант — прежние `dump_variant/2` / `load_variant/3`.
- `Core.Codec.Plugin.Fields`: путь по общему IR — `dump_args_ir/2`, `dump_guard_ir/1`,
  `dump_pairs_ir/1`, `load_body_ir/2`. Проекция IR→грамматика (`grammar/1`) живёт здесь, а не в
  `Core.Field`: иначе `Field → Union → Variants → Fields → Field` давал второй цикл xref.
- `Core.Codec.Plugin.Redump`: спека выводится и для новых источников — домен как `{:map, поля}`,
  Prim-вариант как спека самого Prim (`{:tagged, %{тег => {:prim, Prim}}}`); невыводимая спека
  Prim уходит в `__codec_redump_missing__/0`, как ручной вариант.
- `Core.Field`: `union_variants/1` (реестр семейства) и рабочий тип записи `union:`: варианты из
  `__core_variants__/0`, у семейства-плагина без реестра — из `types/0`; Prim-вариант — `t()`,
  домен — `write_t()` (иначе `t()`), ручной struct — `%Мод{}`. Тип чтения `union:` остался
  `struct()` (как и было; менялся только тип записи, см. notes/02 п.4).
- `Core.Codec.Facade.Behaviour`: служебный `__codec_prim__/0` — Prim-профиль фасада; реализуется
  макросом фасада.
- Тесты: `test/core/union_test.exs` (объявление, адреса, `types/0`, `variant/1`, интроспекция,
  тип записи, round-trip через фасад по всем видам, отказы) и фикстура
  `test/support/union_fixture.ex` (тег/общий тег/форма без обёртки, домен/Prim/ручной вариант,
  поле `union:`).

## Отличия от design note и допущения

1. **Вариант-Prim — только тегированная форма.** В форме без обёртки класть дамп Prim некуда
   (wire Prim.String — строка), дискриминатор наложить нечем; `CompileError`
   `Prim-вариант — только тегированная форма`. В design note этого ограничения не было.
2. **`__codec_variants__/0`** у вариантов из реестра отдаёт маркер `:union` вместо списка полей
   (форма внутренняя): настоящая интроспекция — `Core.Union.variants/1`. У старого пути форма
   прежняя (`[%Core.Codec.Field{}] | :manual`).
3. **`default:` декларативного варианта** — типизированное значение (spec, «`default:` — одно
   типизированное значение»): при отсутствующем ключе подставляется как есть, явный `null` не
   заменяет. У старого пути `variants:` `default:` — по-прежнему wire-литерал. Это осознанно:
   тикет 04/10 снимет старую форму.
4. **Prim-вариант занимает модуль в фасаде.** Диспетчеризация фасада — по модулю, поэтому тот же
   Prim нельзя объявить ещё и полем `prim:` в том же фасаде. Ограничение записано в moduledoc
   `Core.Union`.
5. **Тип чтения `union:`** оставлен `struct()`, тип записи — объединение вариантов (design note §5
   для чтения тоже предполагает варианты; это решение отложено до общего IR-этапа, чтобы не менять
   тип чтения у существующих `variants:`-семейств).
6. `Core.Codec.Plugin` не проверяет, что явные `variants:` совпадают с реестром семейства: явные
   побеждают молча (старый путь живёт до тикета 04).

## Грабли (важно следующим тикетам)

1. **Цикл xref.** `Core.Field → Core.Union → Variants → Fields → Core.Field` появлялся, если
   проекция IR→грамматика живёт в `Core.Field`. Держать её в `Fields` и не ссылаться на `Core.Field`
   типами/структурой (`%{name:, spec:, …}` вместо `%Core.Field{}`).
2. **Prim-вариант нельзя дампить `codec.dump/1`** — фасад отдаст его же плагину (рекурсия до
   таймаута). Только `codec.__codec_prim__().dump/1` и `.load/2`.
3. `Code.eval_quoted(quote do … end)` в тестах раскрывает алиасы из тестового модуля: модули внутри
   цитируемого кода нужно писать полным именем (иначе `Rect` уезжает в фикстуру).
4. Общая фикстура-фасад не допускает один модуль-вариант в двух плагинах: у `Shape` и `Drawing`
   разные доменные варианты (`Circle` / `Star`).
5. Инфраструктура общая: `mq/kafka` и `mq/stream` contract-тесты в полном прогоне иногда падают на
   чужом топике/сообщении — это не следствие правки, повторный прогон файла зелёный.

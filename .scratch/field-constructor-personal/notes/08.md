# Тикет 08 — уничтоженное значение, субъекты и эскалация границы

Ветка `fcp/08` (от `field-constructor-personal`).

## Сделано

- **Загрузка `{"$pd": null}` на любом месте.** `Core.Es.Personal.Plan.load/4` (и `under/2`):
  wire-значение поля → значение с `%Core.Es.Personal.Destroyed{}` на каждом ПДн-месте плана
  **до** разбора вида. Место задаётся путём плана (`{N, :each, :recipient}`), поэтому работает
  и в `list:`/значениях `map:`, и в глубине сущности; для `union:` с `personal: true` значение
  заменяется до выбора варианта — Codec варианта не вызывается. `nil` необязательного места
  остаётся `nil`.
- **Оставшийся маркер.** После замены любое `%{"$pd" => …}` в значении поля — отказ:
  `{"$pd": "<строка>"}` → `:sealed_personal_value`, иное → `:invalid_value` (`ns: :codec`,
  `detail: %{field: …}`). Ошибку строит `Plan.marker_error/3` (перенесена из `Payload`);
  `Core.Es.Event.Payload.marker_error/3` удалена (внутренняя, `@doc false`).
- **`Core.Codec.Plugin.Fields.Kind.load/3`** пропускает `%Destroyed{}` насквозь до разбора вида:
  одно место на все виды (включая `union:` и `set:`/`map:`-контейнеры).
- **Проводка.** `Payload.load_body/2` и `Core.Codec.Plugin.Fields.load_body_ir/2` на каждом поле
  зовут `Plan.load/4` (места поля — `Plan.under/2`), затем грузят значение; ошибка под ПДн-местом
  редактируется (`Payload.redacted_result/2`, тот же `Payload.redact/1`): путь ошибки
  (`field`, `index`, `key`) остаётся, значения в `detail`/cause-цепочке — нет. План плагина
  считается в теле `load/3` (не при раскрытии `use`): типы полей могут собираться параллельно.
- **Нагрузка-Prim (корневое место).** `Core.Es.Event.Codec.load_payload_clause/3` для `:prim` и
  `:plugin` прогоняет `Plan.load/4` по всему payload и отдаёт `%Destroyed{}` до разбора вида;
  загрузку значения вынес `Core.Es.Event.Codec.load_loaded_payload/3`. `Core.Es.Event.build/3`
  собирает событие с уничтоженной нагрузкой полями (`new/N` — тип записи и уничтоженное не
  принимает).
- **Тип чтения события.** `Core.Es.Event` порождает `@type t` в `@before_compile`: у нагрузки-Prim
  с `personal: true` в `payload` входит `Core.Es.Personal.Destroyed.t()`, `new/N` остаётся узким.
  Флаг (`personal_payload?/1`) считается в теле события — при раскрытии `use` нагрузка бывает не
  собрана (цикл `Account → Event.Codec → Event → Account.Holder` даёт `:unavailable`).
- **Уничтожение ключа.** После `destroy_key/3` свёртка/`page_stream` отдают `%Destroyed{}` на
  каждом вложенном месте, открытая часть (канал/статус/попытки, соседние элементы) читается;
  строка не `:unreadable`. Покрыто в `recursive_sealing_test` (свёртка, страница, нагрузка-Prim),
  `events_test` (строка `es_events`), `events_projection_test` (пачка проекции),
  `message_test` (сообщение брокера).
- **Снапшот.** `Core.Es.Aggregate.Load.Engine.destroyed_value?/2` обходит нагрузку рекурсивно
  (структуры/списки/словари): вложенное `%Destroyed{}` после `destroy_key/3` даёт полную свёртку,
  снапшот отвергается (`reason=destroyed`) и не пишется. Фикстура —
  `Core.EsFixture.Itinerary.Repo.{Snapshotted, Snapshotted.Pg}` (`snapshot: [every: 2]`).
- **Проекция.** `Core.Es.Projection` решает «есть ПДн» по `__es_personal__/0` (а не по
  `__es_subjects__/0`): событие только с вложенными местами тоже требует `KeyDestroyed` в
  `events:` или `personal: false`.
- **State-stored.** `Core.StateStoredFixture.Entity.holder` — `entity:` профиля с ПДн-полем
  `phone`, колонка `fixture_entities.holder` (`:map`). `to_model`/`to_entity` фикстуры кладут
  живое значение открытым wire-значением плагина, уничтоженное — `{"$pd": null}` (на вложенном
  месте и на всём контейнере); чтение не зовёт порт (telemetry `[:es, :personal, :call]` пуст),
  новый event с уничтоженным ПДн отвергается (`ArgumentError` из `Personal.Wire`).
- **Эскалация.** Тесты `payload_kind_test`: `set:` с ПДн-элементом и `map:` с ПДн-ключом —
  маркер и `%Destroyed{}` на контейнере; значения `map:` и элементы `list:` — по месту,
  уничтоженные элементы не схлопываются в `MapSet`.
- **Совместимость.** Строка, записанная открытой до разметки вложенных мест, читается
  (`recursive_sealing_test`).
- Тесты декларации: `plan_test` (непрозрачный тип в `list:`, `personal: true` у непрозрачного,
  отказ `assert_writable!` при `aggregate_id: nil`), `payload_personal_test` (`union:` с
  `personal: true` — Codec варианта не зовётся), `projection_test` (вложенное место требует
  разметки), `codec_personal_test` (уничтоженное значение словаря, шифротекст на глубине).

## Отличия от design note и допущения

1. **План плагина считается в рантайме.** `load_body_ir/2` строит `Plan.entries(@codec_declared)`
   в теле `load/3`: при раскрытии `use` типы полей могут ещё собираться, и пропущенное место
   ушло бы в открытое чтение молча. Цена — обход декларации на каждый `load` сущности.
2. **Замена до разбора вида — на уровне поля, а не глобальным проходом.** Один `Plan.load/4` на
   поле: `{:ok, value} | {:error, %Error{}}`. Ошибка «маркер не на месте» называет поле
   объявления (`detail: %{field: …}`), а не внутренний индекс/ключ: путь с `index`/`key`
   остаётся у ошибок загрузки *значения* места (редакция), а маркер вне места не несёт значения.
3. **Редакция шире поля.** Поле, в поддереве которого есть ПДн-место, редактирует все ошибки
   своей загрузки (включая открытые части, например `channel` шага). Путь ошибки сохраняется,
   значения — нет; для не-ПДн полей поведение прежнее.
4. **`@type t` события — в `@before_compile`.** Иначе тип не мог учесть `personal: true` у
   нагрузки-Prim, не внося compile-time зависимость от нагрузки (цикл `Account → Event.Codec →
   Event → Account.Holder`). `new/N` остаётся типом записи; уничтоженную нагрузку собирает
   `build/3` (клауза с `%Destroyed{}`).
5. **`__es_subjects__/0` остаётся** у `EventCompatCase`, `ProjectionCase` и
   `Personal.Test.subject_fields/1` — их переезд на `__es_personal__/0` в тикете 09. Из
   потребителей 08 переехали `projection.ex` и `engine.ex`.

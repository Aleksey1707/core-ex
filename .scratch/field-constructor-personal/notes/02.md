# Тикет 02 — что сделано и что это даёт дальше

Ветка `fcp/02` (от `field-constructor-personal`).

## Сделано

- `Core.Field` — типы по местам, а не через грамматику `destroyable:`:
  - `read_typespec/1` — на каждом ПДн-месте `| Core.Es.Personal.Destroyed.t()`, после него
    `| nil` от `optional:`;
  - `write_typespec/1` — проекция записи: `entity:` → `Mod.write_t()` (если он есть) иначе `Mod.t()`,
    `union:` → объединение типов записи вариантов, `list:`/`map:` поэлементно/по значению;
  - `personal_places?/1` — есть ли места (по нему `Core.Struct` решает `write_t :: t()`);
  - `inspect_places/1` — `%{поле => [путь]}`, пути только по `list:`/`map:` (в `entity:` не
    спускается — у сущности свой `Inspect`); `hide_personal/2` подставляет
    `%Core.Es.Personal.Hidden{}` на место, `nil` и `%Destroyed{}` оставляет;
  - `split!/3` + `normalize!/3` + `apply_personal!/2` — одна нормализация на два вида результата
    (`Core.Struct` держит и `%Core.Codec.Field{}`, и IR).
- `Core.Struct`:
  - `@core_fields` считается первым фрагментом тела, до `defstruct` и `@type`;
  - `@type t`/`@type write_t` порождаются условно **в теле модуля** (см. «Грабли»);
  - `Inspect` — `@before_compile Core.Struct` (это **макрос**) при непустых местах;
  - `__struct_fields__/0` остался `[%Core.Codec.Field{}]` (вложенные `{:personal, _}` в нём
    срезаны, IR их держит).
- `destroyable:` удалён из языка: `Core.Codec.Field` отвергает ключ в любом режиме и на любой
  глубине текстом `destroyable: удалён — ПДн-место объявляет personal: true, а уничтоженное
  значение даёт тип чтения`. `Core.Codec.Field.destroyable_places/1` и поле `%Field{destroyable:}`
  удалены.
- `wire:`/`subject:` разрешены роли `:struct`; `Core.Codec.Field.check_shapes!` сверяет ещё и
  wire-ключ структуры с плагином (`wire-ключ расходится со структурой …`).
- `Core.Es.Cmd`: `use` помечает модуль `@core_command`; `t()` — проекция записи, `write_t :: t()`;
  проверка `destroyable:` заменена на отказ `personal: true` (путь до поля как раньше:
  `recipients: list: phone`, `by_id: map: value: phone`); персональные Prim допустимы.
- `Core.View.Opts` отвергает `personal:`/`subject:` и (отдельным текстом) `destroyable:`.
- Фикстуры: `Core.StructFixture.Personal/Recipient/Inspectable/Command`, `PluginFieldsTest.Badge`
  получил `wire: "title"`, inline-фикстуры с `destroyable:` переведены на `personal: true`.

## Грабли (важно следующим тикетам)

1. **Тело модуля раскрывается целиком до исполнения.** Модульный атрибут, поставленный кодом
   `use Core.Es.Cmd` выше, не виден при раскрытии следующего `use Core.Struct`. Поэтому `t()` vs
   `write_t()` выбирается `if` в теле модуля (читает `Module.get_attribute(__MODULE__, :core_command)`),
   а не в `__using__`. То же правило для будущих пометок ролей.
2. **`@before_compile` — макрос**, не функция: `defmacro __before_compile__(env)`. Функция молча
   не инжектит код.
3. **`Code.Typespec.fetch_types/1` не работает на модуле, собранном в том же файле** (beam ещё не
   записан). Поэтому `write_t()` сущности определяется по наличию `__core_fields__/0` (декларативные
   структуры) с запасным вариантом по байткоду.
4. **`union:` записи** берёт варианты из `__core_variants__/0` (модуль или `{модуль, ...}`) либо
   `types/0` (список модулей). Тикет 03 MUST вернуть из одного из них модули вариантов; иначе тип
   записи останется `struct()`.
5. **`__struct_fields__/0` ≠ IR по спекам для вложенного `personal:`**: legacy-спека не держит
   `{:personal, _}` (иначе ломается `check_shapes!` плагина). Равенство проверяется по составу и
   метаданным (включая `personal`), а не по литералу спеки; тикет 10 убирает legacy-форму.
6. `Inspect` ставит плейсхолдер `%Core.Es.Personal.Hidden{}` (`lib/core/es/personal/hidden.ex`,
   `@moduledoc false`). `Payload` (05) SHOULD переиспользовать `Core.Field.inspect_places/1` и
   `hide_personal/2` вместо `@derive {Inspect, except: …}` — тогда скроется место, а не список.

# Тикет 07 — сквозной путь ПДн на любой глубине

Ветка `fcp/07` (от `field-constructor-personal`).

## Сделано

- `Core.Es.Personal.Plan.mark!/3`: по плану на уже dump'нутой wire-карте нагрузки заменяет
  открытое значение каждого места `%Core.Es.Personal.Marker{}` (субъект + wire-значение). Обход —
  по wire-путям (`:each` — элемент списка или значение словаря), `nil` необязательного места
  остаётся `nil`, готовый маркер уничтоженного верхнеуровневого поля не перезаписывается.
  Субъект `{:path, …}` резолвится по dumped wire-карте (ключи — строки) на том же `:each`, что и
  место.
- `Core.Es.Event.Payload.dump_body/1`: открытый дамп полей + маркеры по плану; маркер
  уничтоженного значения остаётся только у верхнеуровневого поля с `subject:`. Условие
  «нужен `aggregate_id`» и guard `dump` — по плану (любое место с `:aggregate_id`), а не по
  списку полей с `subject:`.
- `Core.Es.Event.Codec`: `__es_personal__/0` включает нагрузку-Prim (`personal: true` у Prim —
  корневое место `path: []`) и нагрузку-сущность (места `__core_fields__/0` от корня payload).
  Клаузы `dump` для `:prim`/`:plugin` ставят маркеры по тому же плану (`Payload.mark_payload/3`).
- `Core.Es.Personal.Wire` рекурсивен:
  - запись — один обход payload собирает маркеры с конкретным путём (wire-ключи, индексы,
    ключи словаря) и шифрует одним `Port.seal/1` на пачку строк/записей; подстановка
    `%{"$pd" => Base.encode64}` тем же порядком обхода;
  - AAD — `Port.address([event_id | path])`; у верхнеуровневого поля адрес совпадает с прежним;
  - чтение — один рекурсивный поиск `%{"$pd" => binary}` в payload и один `Port.open/1` вместе с
    `extra` (снапшоты); `:destroyed` → `%{"$pd" => nil}`, нечитаемый base64/JSON — прежний исход
    `:unreadable`; `%{"$pd": nil}` остаётся для `load`.
- Потребители плана: `Snapshot.opts!/3` принимает `__es_personal__/0` (снапшот — только когда все
  места, включая вложенные, под `:aggregate_id`), `Repo.Pg` передаёт план, `Process` считает
  `personal:` по непустому плану. `__es_subjects__/0` и остальные потребители — 08/09.
- `Core.Es.Personal.Test.fixtures/1` обходит маркеры рекурсивно: без этого golden-фикстуры
  вложенных мест падали на `Jason.encode!`.
- `Core.Web.Event.to_wire/5` снимает маркеры рекурсивно (нужно уже сейчас: у подписей есть
  `list:` с ПДн-элементами). Это забегает в 09, но без него ломается существующий read-путь.
- Сквозной тест `test/core/es/personal/recursive_sealing_test.exs` на синтетическом агрегате

## Отличия от design note и допущения

1. **`map:`-значения — по месту, не контейнер.** Так в спеке (user story 23) и в обходчике плана;
   прежние тесты ожидали один шифротекст на всё поле с `subject:`. Новый формат — следствие 07,
   в CHANGELOG.
2. **Резолв субъекта на записи — по dumped wire, а не по struct.** План места — wire-ключи;
   `assert_writable!` по-прежнему обходит struct (имена полей), а маркер ставит `mark!` по wire.
   Субъект `{:path, …}` ищется на том же `:each`-элементе.
3. **Вложенный `{"$pd": nil}` на чтении — 08.** Загрузка `%Destroyed{}` на вложенном месте пока
   даёт ошибку вида; сквозной тест после `destroy_key/3` проверяет read-путь хранилища
   (`Store.load_wires/2`): открытая часть на месте, строка не `:unreadable`. Это совпадает с
   границей 08 («уничтожение ключа даёт `%Destroyed{}` на каждом вложенном месте»).
4. **`Web.Event` обновлён раньше 09.** Иначе `LabelsFixture.Contacted` (`list:` с ПДн-элементами)
   падал на JSON-кодировании маркеров.
5. **Текст отказа снапшота сохранён** («субъект ПДн-поля — поле нагрузки, а не `:aggregate_id`»),
   хотя теперь называет путь места; тест `pg_test` сверяет текст.
6. **Нагрузка-сущность без `personal:`-разметки.** `__es_personal__/0` для `:plugin` читает
   `__core_fields__/0`; проверки `Plan.entries!` для неё не запускаются (это декларация структуры,
   а не нагрузки события).
7. **`Outbox.ReleaseTest` ждёт топик `itineraries`** — новая фикстура-агрегат регистрирует outbox
   в приложении `:core`, и `republish_since/2` обходит все топики.

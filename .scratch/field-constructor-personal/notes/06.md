# Тикет 06 — что сделано и что это даёт дальше

Ветка `fcp/06` (от `field-constructor-personal`).

## Сделано

- `Core.Field.declare!/4` (`declare!/3` остался через default): роль `:view` разбирает спеку
  `Core.View.Opts.fields!/3` (с именами `forms:` для проверки `form:`), минуя общий `check_keys!`:
  тексты отказа `personal:` / `subject:` / `destroyable:` остаются текстами View.
- `Core.Field.introspect/1` читает общую декларацию и у модуля, который ещё собирается: атрибут
  `@core_fields`, который ставят `Core.Struct` / `Core.Es.Event.Payload` / `Core.Es.ValueChanged`
  (в теле его читает `Core.Labels.Fields.host/1`). Функция `__core_fields__/0` — путь собранного
  модуля. Гонка параллельной сборки (модуль закрылся между проверкой и чтением) — `nil`.
- `Core.View` собирается из IR: `struct`, `@type t`, `new/1` и дампер — из
  `Core.Field.declare!(fields, :view, ...)`, порождается `__core_fields__/0` (`@doc false`).
  Вид IR не держит `kind` Prim — его восстанавливает `Core.View` (`Core.Prim.leaf/1`). `forms:`
  по-прежнему разбирает `Core.View.Opts`, их проекции — `Core.View.Field` (тип, форма, дамп).
- `Core.View` не принимает `personal:` / `subject:` (`CompileError` текстами роли), `%Destroyed{}`
  в `t()` не попадает (тест по байткоду).
- `Core.Labels.Fields`: хост — `{:declared, [Core.Field.t()]}` из `Core.Field.introspect/1`,
  `:struct` (ручной `defstruct`) или `:none`; ролевые атрибуты (`declared_fields/1`,
  `__es_payload_fields__/0`, `__es_value_changed__/0`) больше не читаются. Спека полей — прежняя
  грамматика `Core.Codec.Field` с снятым `{:personal, вид}`.
- `use Core.Labels.Fields, fields:` у ручного struct'а разбирается общим конструктором в роли
  `:labels` (`Core.Field.declare!`), вид `text:` остаётся своим (снимается до нормализатора).
- `Core.Labels.Check` / `Walk` / `Details` / `Refs` / `CompletenessCase` не менялись: они и раньше
  читали только `__label_*` и `Core.Field.introspect/1`.
- Тесты: `view_test` — IR и отсутствие `Destroyed` в типе; `labels/fields_test` — прямой
  `declare!/3` с `{:declared, ir}`, подписи декларативного типа с ПДн-местами без `fields:`,
  `fields:` ручного struct'а с `personal:`; фикстура `Core.LabelsFixture.PersonalPlace`.

## Отличия от design note и допущения

1. **Хост подписей — `{:declared, ir}` вместо ролевых кортежей.** В IR нельзя отличить нагрузку от
   структуры, а прежний код различал их только текстом `CompileError`; текст один:
   «спека поля и у декларативного типа — вид поля задаёт его `use`». Диагностика — контракт, пункт
   в CHANGELOG.
2. **`value:` рядом с `change:` у любого декларативного типа — `CompileError`.** Прежний
   fall-through принимал `value:` у нагрузки события (нагрузка «было → стало» размечалась как
   структура с `old_value`/`new_value`). Вид значения у декларативного изменения задаёт сама
   декларация (`old_value`/`new_value` или `type:`), поэтому `value:` избыточен. Фикстура
   `HolderChanged.Payload` потеряла `value:` — wire и сведения не изменились.
3. **`Core.Field.declare!/4`.** `forms:` не входит в `where` (строка адреса отказа); роль `:view`
   получила отдельный аргумент контекста. Design note называет `declare!/3`.
4. **`@core_fields` как источник in-flight интроспекции.** Во время сборки модуля функцию
   `__core_fields__/0` вызвать нельзя, а role-атрибуты запрещены; атрибут — та же общая
   декларация, не ролевой признак. `Module.get_attribute` без `rescue` ронял сборку потребителя:
   параллельный воркер успевал закрыть чужой модуль.

## Грабли (важно следующим тикетам)

1. `Module.open?/1` — про любой открытый модуль, а не про текущий процесс: `Module.get_attribute`
   для чужого модуля может упасть `ArgumentError` (ETS-таблица закрылась). Читать атрибут можно
   только с `rescue` (и только как `nil`, иначе `Codec.Plugin` увидит недописанную декларацию).
2. `Core.View` порождает `__core_fields__/0`, поэтому `Core.Labels.Fields` на View теперь
   принимает `labels:` без `fields:` (раньше — отказ). Комбинация не поддерживается: виды
   `view:`/`form:`/`jsonb:` в сведениях не раскрываются. Отдельного отказа нет.
3. `Core.Field.introspect/1` в `Codec.Plugin.Opts.declared!/1` теперь может вернуть IR модуля,
   который ещё собирается в другом процессе (если его тело уже поставило атрибут); порядок «тип
   выше `use` в одном модуле» не изменился — при раскрытии своего `use` атрибута ещё нет.
4. Тест с `personal:` на декларативном struct'е в `Code.eval_quoted` даёт предупреждение о
   консолидации `Inspect`; такие фикстуры — в `test/support`.

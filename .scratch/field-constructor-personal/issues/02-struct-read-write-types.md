# 02: Core.Struct — типы чтения/записи, типизированный default:, Inspect

**What to build:** структура по полям переходит на общий IR и порождает два типа: `t()` чтения
(включает `%Destroyed{}` на ПДн-местах) и `write_t()` записи (без `%Destroyed{}`). `personal: true`
у Prim или поля автоматически делает место ПДн-местом и расширяет тип чтения; отдельный
`destroyable:` удаляется. `default:` становится одним типизированным доменным значением: struct
использует его как значение поля, Codec подставляет при отсутствующем wire-ключе; явный `null`
`default:` не заменяет. `wire:` допустим в структуре (используется Codec). `Inspect` скрывает
каждое ПДн-место, а не весь содержащий его список.

**Blocked by:** 01

**Status:** resolved

- [x] Структура с `personal:`-полем порождает `t()` с `| Core.Es.Personal.Destroyed.t()` на этом месте и `write_t()` без него; без ПДн-мест типы совпадают.
- [x] `personal: true` у Prim делает каждое место с этим Prim ПДн-местом; `destroyable:` как отдельная опция удалён и даёт `CompileError`.
- [x] `default:` — одно типизированное значение; `optional: true, default: nil` допустимо; явный `null` не заменяется default (optional → nil, обязательное поле → ошибка загрузки).
- [x] `wire:` допустим в декларации структуры; расхождение wire-ключей по-прежнему `CompileError`.
- [x] `Inspect` структуры скрывает ПДн-места, оставляя открытые поля видимыми; составное поле с `personal: true` скрывается целиком.
- [x] Тесты структуры по полям обновлены под новые типы и `default:`; `consumer-check` не растит храповик вывода типов.

## CHANGELOG

Раздел «Ломающие изменения контракта»:

- `Core.Struct` порождает два типа: `t()` — чтение, на каждом ПДн-месте (`personal: true` у поля,
  элемента `list:` или значения `map:`, а также у каждого места с Prim `personal: true`) с
  `Core.Es.Personal.Destroyed.t()`; `write_t()` — запись, без уничтоженного значения. Поле
  `entity:` в типе записи ссылается на `write_t()` вложенной структуры, `union:` — на типы записи
  вариантов, `list:`/`map:` проецируются поэлементно и по значению; без ПДн-мест
  `@type write_t :: t()`. Было: единственный `t()`. Потребителю: читать `t()`, принимать и отдавать
  на запись `write_t()`.
- Опция `destroyable:` удалена из структуры по полям — `CompileError` с текстом `destroyable:
  удалён …`. Было: `holder: [prim: Holder, destroyable: true]`; стало: ПДн-место объявляет Prim
  `personal: true` или поле `personal: true`, а `%Destroyed{}` в `t()` появляется сам.
- `Core.Struct` принимает `wire:` и `subject:`; wire-ключ объявляет структура, и Codec-плагин
  обязан с ним совпадать — расхождение даёт `CompileError`. Было: `wire:` в структуре запрещён.
- `Inspect` структуры с ПДн-местами скрывает каждое место плейсхолдером
  `%Core.Es.Personal.Hidden{}`, а не всё поле: открытые поля и открытые элементы того же списка
  остаются в выводе; `%Core.Es.Personal.Destroyed{}` печатается обычным struct'ом.
- Команда `Core.Es.Cmd` по полям: `@type t` — проекция записи без `Destroyed`, даже если поле —
  персональный Prim, `write_t()` равен `t()`; вместо проверки `destroyable:` команда отвергает
  `personal: true` с путём до поля. Было: команда отвергала `destroyable:` и допускала его место в
  типе.
- `Core.View` отвергает `personal:` и `subject:`; `destroyable:` отвергается с текстом об удалении
  из языка.

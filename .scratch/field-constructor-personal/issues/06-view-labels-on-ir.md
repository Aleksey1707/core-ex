# 06: Core.View и Core.Labels.Fields на IR

**What to build:** View и подписи переходят на чтение общей декларации полей через единый IR и
интроспекцию, вместо независимого разбора. Поведение View не меняется: голые значения, свои виды
(`view`/`form`/`jsonb`), keyword `new/1`, тотальный dump. `Core.View` не принимает
`personal:`/`subject:` и не расширяет типы `%Destroyed{}`. Подписи читают общие поля и метаданные;
рекурсивная обработка уничтоженных значений в сведениях — отдельный тикет read-пути.

**Blocked by:** 04

**Status:** resolved

- [x] `Core.View` читает общую декларацию/IR; `new/1`, дамп и wire-форма не меняются; `personal:`/`subject:` в View — `CompileError`.
- [x] `Core.Labels.Fields` берёт поля из общей интроспекции, а не из ролевых атрибутов; повторная спека для декларативного типа по-прежнему запрещена.
- [x] View не порождает `%Destroyed{}` в своём типе; уничтоженное значение преобразует проекция.
- [x] Существующие тесты View и подписей проходят без смысловых правок; `consumer-check` не растит храповик.

## CHANGELOG

Раздел «Изменения контракта макросов».

- `use Core.View` разбирает поля общим конструктором (`Core.Field.declare!/4`, роль `:view`) и
  порождает внутреннюю декларацию `__core_fields__/0`; структура, `@type t`, `new/1` и дампер
  строятся из неё. Поведение не меняется: виды `view:` / `form:` / `jsonb:`, keyword `new/1`,
  тотальный dump. `personal:` / `subject:` по-прежнему `CompileError`.
- `use Core.Labels.Fields` берёт вид полей декларативного типа (структура по полям, нагрузка
  события, `Core.Es.ValueChanged`, View) из общей декларации `__core_fields__/0`
  (`Core.Field.introspect/1`), а не из ролевых атрибутов; `fields:` на языке `Core.Codec.Field`
  остаётся только для ручного `defstruct`.
- `value:` рядом с `change:` у декларативного типа — `CompileError`: вид значения задаёт сама
  декларация (`old_value` / `new_value` или `type:`). Было: у нагрузки события `value:` принимался
  и перекрывал спеку полей. Стало: уберите `value:` — декларация уже называет вид.
- `CompileError` повторной спеки `fields:` у декларативного типа теперь один для всех хостов:
  «спека поля и у декларативного типа — вид поля задаёт его `use`». Было: отдельные тексты у
  нагрузки события и структуры по полям. Стало: сверяйте префикс до списка полей.

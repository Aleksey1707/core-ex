# 09: Read-путь и case-модули

**What to build:** рекурсивная обработка уничтоженных ПДн на read-пути и в тестовых инвариантах.
`Core.Web.Event` отдаёт `{"$destroyed": true}` на вложенном месте; `Labels.Details` даёт деталь
`kind: :destroyed` по пути; OpenAPI-схема ПДн-места допускает обычное значение или признак
уничтожения. `EventCompatCase` и `ProjectionCase` работают по рекурсивному ПДн-плану: открытая
фикстура — wire после расшифровки, уничтоженный вариант — `{"$pd": null}` на каждом ПДн-месте;
генерация обеих форм — из плана. Проекция явно преобразует `%Destroyed{}` (View не расширяет типы).

**Blocked by:** 06, 08

**Status:** ready-for-agent

- [ ] `Core.Web.Event.to_wire` отдаёт `{"$destroyed": true}` на вложенных уничтоженных местах; живое ПДн — открытым wire-значением.
- [ ] `Labels.Details` даёт `kind: :destroyed` по пути вложенного места без значения; OpenAPI-схема ПДн-места допускает значение или признак уничтожения.
- [ ] `Core.Es.Personal.Test.fixtures/1` строит открытую и уничтоженную формы рекурсивно из ПДн-плана.
- [ ] `EventCompatCase`: открытая фикстура не содержит personal-значений вне ПДн-мест; уничтоженный вариант даёт `%Destroyed{}` на каждом ПДн-месте.
- [ ] `ProjectionCase` прогоняет `project/1` на уничтоженном варианте по всем ПДн-местам; забытая обработка уничтоженного значения — провал.
- [ ] Проекция преобразует `%Destroyed{}` явно; `Core.View` не получает `%Destroyed{}` в типе.

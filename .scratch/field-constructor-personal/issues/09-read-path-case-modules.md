# 09: Read-путь и case-модули

**What to build:** рекурсивная обработка уничтоженных ПДн на read-пути и в тестовых инвариантах.
`Core.Web.Event` отдаёт `{"$destroyed": true}` на вложенном месте; `Labels.Details` даёт деталь
`kind: :destroyed` по пути; OpenAPI-схема ПДн-места допускает обычное значение или признак
уничтожения. `EventCompatCase` и `ProjectionCase` работают по рекурсивному ПДн-плану: открытая
фикстура — wire после расшифровки, уничтоженный вариант — `{"$pd": null}` на каждом ПДн-месте;
генерация обеих форм — из плана. Проекция явно преобразует `%Destroyed{}` (View не расширяет типы).

**Blocked by:** 06, 08

**Status:** resolved

- [x] `Core.Web.Event.to_wire` отдаёт `{"$destroyed": true}` на вложенных уничтоженных местах; живое ПДн — открытым wire-значением.
- [x] `Labels.Details` даёт `kind: :destroyed` по пути вложенного места без значения; OpenAPI-схема ПДн-места допускает значение или признак уничтожения.
- [x] `Core.Es.Personal.Test.fixtures/1` строит открытую и уничтоженную формы рекурсивно из ПДн-плана.
- [x] `EventCompatCase`: открытая фикстура не содержит personal-значений вне ПДн-мест; уничтоженный вариант даёт `%Destroyed{}` на каждом ПДн-месте.
- [x] `ProjectionCase` прогоняет `project/1` на уничтоженном варианте по всем ПДн-местам; забытая обработка уничтоженного значения — провал.
- [x] Проекция преобразует `%Destroyed{}` явно; `Core.View` не получает `%Destroyed{}` в типе.

## CHANGELOG

### Ломающие изменения контракта

- Подписи и OpenAPI-схема события понимают уничтоженное ПДн-значение на вложенном месте: деталь
  сведения — `kind: :destroyed` без `value`, wire страницы — `{"$destroyed": true}` по пути
  (свойство вложенной сущности, элемент `list:`, значение словаря). Раньше `{"$destroyed": true}` и
  `:destroyed` были только у поля верхнего уровня с `subject:`; теперь живое ПДн-значение места
  выходит открытым wire, а уничтоженное — признаком. Схема `payload` описывает форму на любой
  глубине (тип её по-прежнему не задан — нагрузка описывается кодеком).
- `Core.Es.EventCompatCase` и `Core.Es.ProjectionCase` работают по рекурсивному ПДн-плану
  (`__es_personal__/0`), а `Core.Es.Personal.Test.fixtures/1` и `destroyed/2` строят обе формы по
  нему же: открытая фикстура не должна содержать personal-значений вне ПДн-мест на любой глубине,
  уничтоженный вариант — `{"$pd": null}` на каждом месте, `destroyed/2` ставит `%Destroyed{}` на
  каждом месте. Проекция, не обработавшая `%Destroyed{}` на вложенном месте, теперь валит
  `ProjectionCase` — обработайте место явно (уничтоженное значение — не ПДн: очистить, замаскировать
  или `NULL`).
- Удалён `__es_subjects__/0` кодека событий (временный адаптер мест верхнего уровня). Потребителю —
  `__es_personal__/0`: `%{Событие => [%{path: путь, subject: субъект}]}`, путь — атомы wire-ключей и
  `:each` для элемента `list:`/значения `map:`, субъект — `:aggregate_id` или `{:path, путь}`.

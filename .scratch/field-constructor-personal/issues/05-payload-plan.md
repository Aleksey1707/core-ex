# 05: Нагрузка события и ValueChanged на IR + ПДн-план

**What to build:** `Core.Es.Event.Payload` и `Core.Es.ValueChanged` переходят на общий IR и
порождают интроспекцию ПДн-плана `__es_personal__/0` (места и субъекты по модулям событий) вместо
`__es_subjects__/0`. План строится рекурсивным обходом декларации: `personal:` у Prim/поля,
`subject:` (`:aggregate_id`, `{:payload, field}`, локальное поле), эскалация границы для `set:` и
ключа `map:`. `Payload.new/N`, `draft/1` и guard `dump` отвергают `%Destroyed{}` на любом месте
записи по плану. Шифрование на этом шаге ещё не включается — только декларация, план и защита
записи.

**Blocked by:** 04

**Status:** resolved

- [x] `Payload`/`ValueChanged` на IR; `Core.Es.Event.Codec` порождает `__es_personal__/0` с путями и субъектами вместо `__es_subjects__/0`.
- [x] Обходчик находит ПДн-места рекурсивно: `personal:` у Prim/поля, `subject:`-ссылки трёх видов, default `:aggregate_id`.
- [x] `subject:` в поддереве без ПДн и переопределение `subject:` под `personal: true` — `CompileError`; непрозрачный тип требует `personal: true/false`.
- [x] `Payload.new/N`, `draft/1` и guard `dump` отвергают `%Destroyed{}` на любой глубине записи; `ValueChanged` применяет план к `old_value` и `new_value`.
- [x] Тесты нагрузки события и `ValueChanged` обновлены; план проверяется через поведение, а не как публичный контракт формы.

## CHANGELOG

### Ломающие изменения контракта

- **`subject:` у нагрузки события выбирает только субъекта.** ПДн-место объявляет `personal: true`
  у Prim, поля, элемента `list:`/значения `map:` или непрозрачного типа; по умолчанию субъект —
  `:aggregate_id`. Было — `subject:` на поле включал шифрование поля верхнего уровня и требовал
  `subject:` у персонального Prim; стало — `subject:` без ПДн-места в поддереве, переопределение
  `subject:` под `personal: true`, субъект не UUID-Prim или сам ПДн — `CompileError`, а
  персональный Prim без `subject:` допустим. Правка потребителя: поле, которое шифровалось только
  через `subject:` при не персональном значении, получает `personal: true` (шифруется так же) или
  теряет `subject:` (значение остаётся открытым); у поля персонального Prim `subject:` можно
  убрать, если субъект — агрегат.
- **Непрозрачный тип в нагрузке требует `personal: true/false`.** `entity:` без
  `__core_fields__/0`, `union:` и `type: :map` без флага — `CompileError` вместо открытого
  значения в истории. Правка потребителя: было `[entity: Opaque]` / `[union: Family]` /
  `[type: :map]`, стало `[entity: Opaque, personal: false]` (или `personal: true`, если значение
  шифруется) и так же для остальных.
- **`Payload.new/N`, `draft/1` и `dump` — защита записи по ПДн-плану.** `%Destroyed{}` на любом
  ПДн-месте, в том числе вложенном, и непустое ПДн-значение при `nil` субъекте отвергаются
  (`ArgumentError`; на верхнеуровневом поле с `subject:` по-прежнему `FunctionClauseError`).
  Команда, собиравшая событие из уничтоженного значения через `draft/1`, получает отказ — новый
  event с уничтоженным ПДн запрещён.
- **`Inspect` нагрузки по полям скрывает ПДн-место, а не поле.** Значение места — плейсхолдер
  `%Core.Es.Personal.Hidden{}`; открытые поля и открытая часть списка остаются в выводе. Было —
  поле исключалось целиком (`@derive Inspector, except:`).
- **Кодек события отдаёт `__es_personal__/0`; `__es_subjects__/0` — временный адаптер.** План —
  `%{Событие => [%{path: [wire-ключ | :each], subject: :aggregate_id | {:path, путь}}]}`; адаптер
  отдаёт только места верхнего уровня и уйдёт вместе с переездом потребителей. Правка потребителя
  не требуется, пока он читает `__es_subjects__/0`.
- **`Core.Es.ValueChanged` применяет ПДн-план к обеим сторонам.** `old_value`/`new_value` —
  отдельные места с субъектом `:aggregate_id`; тип чтения допускает `%Destroyed{}`, `new/2` —
  нет. Wire-форма не изменилась.

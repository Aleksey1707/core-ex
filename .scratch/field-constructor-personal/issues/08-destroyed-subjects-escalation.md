# 08: Уничтоженное значение, субъекты и эскалация границы

**What to build:** загрузка уничтоженного ПДн и полная защита записи. `{"$pd": nil}` на ПДн-месте
даёт `%Destroyed{}` до разбора вида/варианта (для `union:`-поля с `personal: true` — до выбора
варианта, ручной Codec не вызывается); вне ПДн-места — `:invalid_value`; `{"$pd": "<строка>"}` —
`:sealed_personal_value`; `null` необязательного ПДн-поля — `nil`. Резолв субъекта и гарды:
непустое ПДн при `nil` субъекта — отказ записи, обязательное ПДн при необязательном субъекте —
`CompileError`. Эскалация границы: ПДн-лист в `set:`/ключе `map:` шифрует контейнер целиком,
`%Destroyed{}` в типе чтения — на месте контейнера. Непрозрачный тип требует `personal: true/false`.

**Blocked by:** 07

**Status:** resolved

- [x] Уничтожение ключа субъекта даёт `%Destroyed{}` на каждом вложенном ПДн-месте; открытая часть (маршрут/статусы) читается; ни одно событие не становится нечитаемым.
- [x] `{"$pd": nil}` вне ПДн-места — `:invalid_value`; `{"$pd": "<строка>"}` — `:sealed_personal_value`; `null` optional-ПДн — `nil`.
- [x] Для `union:`-поля с `personal: true` уничтоженное значение возвращается до выбора варианта; адрес варианта не требуется.
- [x] Непустое ПДн при `nil` субъекта отвергается `new/N` и guard `dump`; обязательное ПДн при необязательном субъекте — `CompileError`; субъект — UUID-Prim, открытый, сам не ПДн.
- [x] `set:` с ПДн-элементами и `map:` с ПДн-ключом шифруются целиком; `%Destroyed{}` в типе чтения на месте контейнера; элементы не схлопываются.
- [x] Непрозрачный тип без `personal: true` требует `personal: false`; `personal: false` не понижает `personal: true` у известных Prim/полей.
- [x] State-stored строка хранит `%Destroyed{}` как `{"$pd": null}` и загружает без обращения к хранилищу ключей; новый event с уже уничтоженным ПДн запрещён.

## CHANGELOG

### Ломающие изменения контракта

- `{"$pd": null}` читается как `%Core.Es.Personal.Destroyed{}` на каждом ПДн-месте, включая
  вложенные места сущностей, элементы `list:`, значения `map:` и контейнеры `set:`/`map:` с ПДн
  в ключе; у `union:` с `personal: true` уничтоженное значение возвращается до выбора варианта,
  Codec варианта не вызывается. Раньше вложенное уничтоженное значение давало ошибку загрузки,
  и событие с ним было нечитаемым. Открытая часть нагрузки (соседние поля, открытые элементы
  списков) читается. Код потребителя не меняется: тип чтения уже допускал `Destroyed`, а
  `new/N`/`dump` уничтоженное по-прежнему отвергают.
- Нагрузка-Prim с `personal: true` (`personal: true` у Prim): после уничтожения ключа событие
  читается с `payload: %Destroyed{}`, тип чтения события дополнен
  `Core.Es.Personal.Destroyed.t()`. `new/N` события остаётся типом записи; клаузы `evolve/2`,
  разбирающие такую нагрузку, должны учитывать уничтоженное значение.
- Маркер ПДн-значения не на своём месте (`{"$pd": …}` вне ПДн-места, в том числе внутри
  вложенной сущности) — ошибка загрузки `:invalid_value` с `detail: %{field: …}` поля
  объявления; нерасшифрованный шифротекст — `:sealed_personal_value`. Раньше такой маркер
  во вложенном месте мог пройти как обычное значение.
- `Core.Es.Projection` считает событие персональным по ПДн-плану, а не по верхнеуровневым
  полям с `subject:`: проекция над событием только с вложенными ПДн-местами теперь требует
  `Core.Es.Personal.Event.KeyDestroyed` в `events:` или `personal: false`, иначе — `CompileError`
  при сборке.
- Снапшот не пишется и отвергается, если уничтоженное значение пришло на любом месте нагрузки,
  включая вложенные: чтение после уничтожения ключа — полная свёртка.

### Новое

- State-stored строка хранит `%Destroyed{}` как `{"$pd": null}` и читает его без обращения к
  хранилищу ключей; живое ПДн в mutable-строке остаётся открытым.

# 01: Общий IR поля, реестр метаданных и интроспекция (expand)

**What to build:** единый внутренний IR декларации полей и централизованный реестр обработчиков
метаданных, на которые затем перейдут все builder’ы. Новый IR и протокол интроспекции
`__core_fields__`/`__core_variants__` вводятся рядом со старым `%Core.Codec.Field{}`, ничего не
ломая. Каждый ключ поля (`optional`, `wire`, `default`, `personal`, `subject`) обрабатывается
своим модулем-обработчиком, объявляющим допустимые роли, нормализацию значения и вклад в
проекции. Неизвестный ключ — `CompileError`. Это expand-шаг wide-рефакторинга: старые пути
разбора остаются работать, CI зелёный.

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] Декларация полей нормализуется в единый IR с метаданными; старый `%Core.Codec.Field{}` не удалён и продолжает работать.
- [x] Реестр обработчиков метаданных: каждый ключ имеет модуль-обработчик с ключом, ролями, нормализацией и проекциями; неизвестный ключ даёт `CompileError` с именем хоста и поля.
- [x] Протокол интроспекции `__core_fields__/0` порождается для декларации и читается единообразно, без знания того, каким `use` собран модуль.
- [x] Внутренний IR и протокол не попадают в публичную документацию и `@type t` потребителя.
- [x] Существующие тесты структуры/плагина/нагрузки/View/подписей проходят без смысловых правок.

## CHANGELOG

Раздел «Новое»:

- Спека полей принимает `personal: true` / `personal: false` у структуры, нагрузки события и
  подписей, а у нагрузки — адрес субъекта `{:payload, поле}` и `{:local, поле}` помимо
  `:aggregate_id` и имени поля. Флаг пока только разбирается и попадает в декларацию: типам
  чтения/записи и шифрованию его придаёт смысл следующий шаг рефакторинга.
- Общая декларация полей отдаёт внутренний IR (модуль вне публичной документации) и протокол
  интроспекции `__core_fields__/0` у модулей, собранных по полям; читается он единой функцией,
  без знания того, каким `use` собран модуль. `@type t` и публичный API этими типами не
  расширяются.

# 03: Core.Union и реестр вариантов

**What to build:** новая роль `Core.Union`: семейство объявляет состав и адрес вариантов в своём
модуле, а не в Codec-плагине. Порождаются `__core_variants__/0`, `types/0`, `variant/1` и проверка
уникальности адресов. Адрес — прежние три формы (тег; тег + дискриминатор; адрес среди полей).
Вариант может быть Prim, декларативной структурой или типом с ручным Codec; полей от варианта не
требуется. Это даёт полиморфные поля (например, получатель телефон/email) одним видом `union:` и
интроспекцию графа вариантов для обходчика ПДн.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] `use Core.Union, variants:` объявляет варианты и адреса; порождает `__core_variants__/0`, `types/0`, `variant/1`.
- [ ] Поддержаны три формы адреса; повтор адреса и общий тег без дискриминатора — `CompileError`.
- [ ] Вариант-Prim, вариант-декларативная-структура и вариант с ручным Codec принимаются; поля варианта не обязательны.
- [ ] Загрузка семейства через фасад выбирает вариант по адресу; round-trip `dump`/`load` по каждому варианту проходит.
- [ ] Интроспекция вариантов доступна обходчику декларации без знания Codec-плагина.

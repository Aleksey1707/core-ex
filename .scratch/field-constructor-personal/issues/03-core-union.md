# 03: Core.Union и реестр вариантов

**What to build:** новая роль `Core.Union`: семейство объявляет состав и адрес вариантов в своём
модуле, а не в Codec-плагине. Порождаются `__core_variants__/0`, `types/0`, `variant/1` и проверка
уникальности адресов. Адрес — прежние три формы (тег; тег + дискриминатор; адрес среди полей).
Вариант может быть Prim, декларативной структурой или типом с ручным Codec; полей от варианта не
требуется. Это даёт полиморфные поля (например, получатель телефон/email) одним видом `union:` и
интроспекцию графа вариантов для обходчика ПДн.

**Blocked by:** 01

**Status:** resolved

- [x] `use Core.Union, variants:` объявляет варианты и адреса; порождает `__core_variants__/0`, `types/0`, `variant/1`.
- [x] Поддержаны три формы адреса; повтор адреса и общий тег без дискриминатора — `CompileError`.
- [x] Вариант-Prim, вариант-декларативная-структура и вариант с ручным Codec принимаются; поля варианта не обязательны.
- [x] Загрузка семейства через фасад выбирает вариант по адресу; round-trip `dump`/`load` по каждому варианту проходит.
- [x] Интроспекция вариантов доступна обходчику декларации без знания Codec-плагина.

## CHANGELOG

### Новое

- `Core.Union`: семейство вариантов объявляет состав и адреса в своём модуле —
  `use Core.Union, variants: [{Модуль, "тег"} | {Модуль, {"тег", ключ: значение}} | {Модуль, [ключ: значение]}]`.
  Поля варианта не объявляются: у декларативной структуры они берутся из её `__core_fields__/0`, у
  Prim — это значение Prim, у типа с ручным Codec — колбэки `dump_variant/2` / `load_variant/3`.
  Порождаются `__core_variants__/0`, `types/0` и `variant/1`; повтор адреса, общий тег без
  дискриминатора, две формы адреса, разные ключи дискриминатора и вариант-Prim не в тегированной
  форме — `CompileError` с префиксом `Union: variants:`.
- `Core.Codec.Plugin` обслуживает такое семейство без `variants:`: `union: Family` берёт варианты из
  `Family.__core_variants__()` и генерирует `dump/2` / `load/3` по каждому варианту и загрузку
  семейства по адресу. Явные `variants:` остаются рабочими и старше реестра семейства.
  Нужно было → стало: адреса и поля вариантов в модуле семейства (или по-прежнему в плагине).
- Вариант-Prim существует только в тегированной форме: `"fields"` — дамп Prim, наложить на него
  дискриминатор нечем.
- `Core.Codec.Plugin.Variants`: для декларативного варианта `default:` поля — типизированное
  значение: при отсутствующем wire-ключе загрузка подставляет его как есть, явный `null` не
  заменяет.

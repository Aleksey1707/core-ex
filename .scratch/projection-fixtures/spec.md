# Фикстуры проекций грузятся тем же шагом, что и поток

Маленькая волна. Термины — `CONTEXT.md`, «Проекция», «ПДн-значение», «Уничтоженное ПДн-значение»,
«Конверт события»; нормы — `docs/rules/22-projections.md`, «Тесты проекций»,
`docs/rules/23-personal-data.md`; решения — ADR-0074, ADR-0076.

## Problem Statement

Тест-модуль проекции грузит golden-фикстуры событий мимо шага загрузки, которым пользуются проекция и
подписчик брокера: он вызывает кодек события напрямую. Конверт с ПДн-значением в таком обходе не
расшифровывается, поэтому первая же рабочая фикстура с субъектом данных падает на
«значение запечатано», и обойти это можно только второй копией шага загрузки в тестовом helper'е.

Сейчас дефект спящий: рабочие фикстуры не содержат ПДн-значений. Он проснётся в момент, когда
проекцию с ПДн-полем начнут покрывать golden-фикстурой, то есть тогда, когда расхождение теста с
продакшеном будет стоить дороже всего.

## Solution

Тест-модуль проекции грузит фикстуру тем же шагом, что и путь чтения хранилища событий: расшифровка
всех ПДн-значений конверта одним вызовом и загрузка события кодеком семейства. Ошибки загрузки,
проверка тега и сообщения об отсутствующих фикстурах не меняются.

## User Stories

1. As мейнтейнер библиотеки, I want фикстура проекции с ПДн-значением расшифровывалась, so that проекцию с субъектом данных можно покрыть golden-фикстурой.
2. As мейнтейнер библиотеки, I want тест шёл тем же шагом, что прод, so that расхождение теста с путём чтения ловилось, а не маскировалось.
3. As мейнтейнер библиотеки, I want уничтоженный ключ субъекта давал уничтоженное значение в тесте, so that поведение проекции по `$pd: null` проверялось.
4. As мейнтейнер библиотеки, I want сбой хранилища ключей в тесте давал ту же ошибку, что в проде, so that отрицательный сценарий был воспроизводим.
5. As мейнтейнер библиотеки, I want проверку тега конверта сохранить до загрузки, so that фикстура не того события по-прежнему отвергалась с внятным текстом.
6. As мейнтейнер библиотеки, I want сообщения об отсутствующих и сломанных фикстурах не изменились, so that диагностика теста осталась прежней.
7. As разработчик приложения, I want поведение и API тест-модуля не изменились, so that существующие тесты проекций не правились.

## Implementation Decisions

- **Загрузка фикстуры идёт через общий шаг хранилища событий** — тот же, что у пути чтения и у
  `Core.Es.Event.Message`: расшифровка конверта, затем загрузка кодеком семейства.
- **Ключ загрузки — кодек события семейства**, а фасад передаётся для вложенных значений; так же
  грузит и проекция.
- **Проверка тега остаётся до загрузки**: фикстура с чужим тегом отвергается прежним исходом.
- **Исходы ошибок не меняются**: отсутствующая фикстура, сломанный JSON, неверный тег, отказ
  загрузки — те же элементы результата и те же тексты.
- **Тест-модуль проекции не получает новых опций** и не требует настройки хранилища ключей сверх
  обычной тестовой конфигурации.
- **Добавляется рабочая golden-фикстура события с субъектом данных** в набор фикстур событий (не в
  набор «сломанных»): она нужна, чтобы шаг расшифровки был покрыт, а не только объявлен.
- **CHANGELOG не пополняется**: тестовый helper не является контрактом потребителя.

## Testing Decisions

- Хороший тест проверяет наблюдаемое поведение: событие, полученное проекцией из фикстуры, и
  сведения/состояние read-модели. Внутренние имена шага загрузки не проверяются.
- **Шов — тест-модуль проекции** (`Core.Es.ProjectionCase`): прогон проекции по фикстуре через
  `run_until_idle` и проверка read-модели. Образец — существующие тесты проекций и ПДн-проекций.
- **Отдельный тест — уничтоженный ключ субъекта**: фикстура с `$pd: null` после уничтожения ключа
  даёт уничтоженное значение в read-модели. Образец — `Core.Es.Personal.Test` и тесты ПДн-проекций.
- **Регресс на обход шага**: фикстура с запечатанным значением без расшифровки в тесте больше не
  проходит — это проверяется тем, что рабочая фикстура с ПДн-значением грузится успешно.
- Существующие тесты проекций и совместимости событий должны остаться зелёными без правок.

## Out of Scope

- `Declaration` как структура и единый тип исхода пачки — отдельная волна.
- `Core.Es.EventCompatCase` и набор «сломанных» фикстур.
- Golden-фикстуры событий агрегатов (их формат и апкасты).
- Путь чтения хранилища событий и расшифровка `$pd` вне теста.
- Проекции без ПДн: их загрузка не меняется по существу.

## Further Notes

- Мотивация: тестовый helper — второй путь загрузки события; спека сводит его с продом, пока
  расхождение не проявилось в чужой волне.
- Риск низкий: меняется только тестовый helper и добавляется фикстура. Главное — не потерять
  прежние тексты ошибок, по которым ищут причину упавшего теста.
- Спека идёт параллельно `es-read-request` и ни от чего не зависит.

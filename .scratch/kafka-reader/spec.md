# Чтение из Kafka

Type: spec
Status: ready-for-agent

## Problem Statement

Потребитель переходит на загрузку данных внешней учётной системы из Kafka: несколько топиков
справочников и документов, тела в Avro и JSON, позже — фильтр по заголовкам до разбора тела.
Библиотека Kafka только пишет: `Mq.ReaderReliable` для Kafka нет, и `MqSubscriberReliable`,
`{:skip, _}` с commit и путь DLQ работают только поверх RabbitMQ Stream (`DEBT.md`, «Kafka —
адаптер только на запись»; ADR-0004).

Клиент `:klife` читать с кластера без KIP-848 может только прямым `fetch` поверх своих
внутренних модулей (ADR-0034).

Три свойства нынешнего подписчика мешают и поверх Stream, но у внешнего источника становятся
заметны:

- **Фильтра до разбора тела нет.** Решение «пропустить» принимает только `on_message` — после
  `from_message`, то есть после декодирования тела, которое фильтр по заголовкам и должен
  сэкономить.
- **Детерминированный отказ повторяется.** Тело, которое не разбирается, или запись, нарушающая
  инвариант, проходит `max_attempts` повторов с backoff до `retry_max_ms` и только потом уходит в
  DLQ — всё это время партиция стоит.
- **DLQ — топик брокера.** Топики внешнего источника принадлежат не потребителю: завести рядом
  `<topic>.dlq` он не может, а разбирать отклонённое удобнее запросом, чем чтением топика.

## Solution

- Адаптер Kafka переезжает с `:klife` на `:brod` целиком: `Kafka.Writer` публикует через
  `:brod` с партиционером murmur2, совместимым с Kafka (ADR-0034).
- `Core.Mq.Kafka.Reader` — `Mq.ReaderReliable` поверх `brod_consumer` каждой партиции, без
  consumer group: смещения в таблице БД потребителя, одна активная нода на топик по аренде,
  чтение с earliest при отсутствии смещения, ключ, заголовки и позиция источника (партиция,
  смещение) в сообщении (ADR-0033).
- `Mq.Message` моделирует запись чужого топика: байтовый ключ, заголовки с любыми именами,
  `nil`-тело у tombstone, позиция источника (ADR-0032).
- Опция фильтра `MqSubscriberReliable` по сообщению до `from_message`: отфильтрованное
  коммитится как пропуск.
- Исход обработчика «отказ без повторов»: сообщение сразу уходит в DLQ.
- DLQ в Postgres: `Mq.Writer` в таблицу и `Mq.ReaderReliable` из неё, команда оператора
  «перечитать».
- PromEx: отставание чтения Kafka по партициям — по времени и в сообщениях, сброс смещения на
  earliest, ошибки чтения и commit; строки в таблице рекомендованных алертов.

Тикеты — `issues/01`–`07`; `07` (writer на `:brod`) — первым.

## Out of Scope

- Декодеры Avro / JSON и Schema Registry — у потребителя: wire-формат тела принадлежит
  адаптеру, а формат данных внешнего источника — потребителю.
- Exactly-once и транзакционное чтение Kafka.
- Деление партиций топика между нодами. Читатель без consumer group — одна активная нода на
  топик; режим на классической группе `:brod` для кластеров с выданным ACL на `Group` —
  отдельная задача (ADR-0033).
- Kafka ниже 0.11: заголовки записи требуют формата сообщений v2.

## Further Notes

- Кластер потребителя KIP-848 не поддерживает (проверено `ApiVersions` каждого брокера), поэтому
  consumer group `:klife` на нём не работает, а ACL на `Group` для классической группы не
  гарантирован — отсюда путь без группы (ADR-0033) и смена клиента (ADR-0034).

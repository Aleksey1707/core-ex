# 03: Отказ без повторов — сразу в DLQ

**What to build:** обработчик подписчика может сказать «это сообщение не загрузить никогда» —
тело не разбирается, запись нарушает инвариант, — и сообщение сразу уходит в DLQ и коммитится,
без `max_attempts` повторов с backoff. Партиция не стоит минутами на заведомо плохом
сообщении; транзиентные сбои (`{:error, _}`) повторяются как раньше.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Spec:** [Чтение из Kafka](../spec.md)

- [ ] Новый исход `on_message` (например `{:reject, reason}`) и способ отказаться из
      `from_message` (ошибка разбора, помеченная детерминированной); обе формы — в `@type`
      исходов `PubSub`.
- [ ] Отказ пишет в DLQ сразу, с причиной в заголовке DLQ-сообщения (по образцу `@attr_attempt`),
      затем commit.
- [ ] Без настроенного `dlq_writer` отказ ведёт себя как сейчас после `max_attempts`: `error` в
      лог, без commit — поведение описано в `@moduledoc`.
- [ ] Метрики и telemetry отличают отказ от выброса после исчерпания повторов.
- [ ] Тест — на тестовом читателе и тестовом writer'е, без брокера.
- [ ] Норма подписчика и `CHANGELOG.md` обновлены.

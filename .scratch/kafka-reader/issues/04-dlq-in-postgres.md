# 04: DLQ в Postgres и команда «перечитать»

**What to build:** потребитель, который не владеет брокером источника, складывает отклонённые
сообщения в таблицу своей БД: топик, ключ, заголовки, тело, позиция источника, причина, время.
Оператор видит их запросом и возвращает в обработку командой (mix-таска и функция для
release), по образцу `mix outbox.requeue`. Перечитанное сообщение обрабатывается тем же
обработчиком, что и исходный топик.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Spec:** [Чтение из Kafka](../spec.md)

- [ ] `Mq.Writer` в таблицу (подключается как `dlq_writer` подписчика) и миграция таблицы —
      через хелпер библиотеки, как у outbox (`Core.Outbox.Migration`).
- [ ] `Mq.ReaderReliable` из таблицы: перечитывание — подписчик с тем же обработчиком поверх
      него; `commit` помечает запись обработанной, а не удаляет.
- [ ] Команда оператора: вернуть в очередь все или по топику / идентификатору; ответ оператору —
      `Mix.shell().info/1` в mix-таске и `IO.puts` в функции release (`20-agreements.md`).
- [ ] Позиция источника сохраняется, если адаптер её отдаёт (тикет `01`), иначе пусто.
- [ ] Tombstone (`body: nil`), байтовый ключ и `key: nil` переживают выброс и перечитывание без
      искажения (ADR-0032).
- [ ] PromEx: число записей DLQ по топику и статусу; строка алерта в `21-observability.md`.
- [ ] Тесты на Postgres, без брокера; ярус потребителя и `CHANGELOG.md` обновлены.

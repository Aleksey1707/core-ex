**Воспроизведение (03.10.2026).** Хук `mix-test` pre-commit упал на
`test/core/mq/kafka/writer_test.exs:97`:

```text
Unexpectedly received message {:publish, %{count: 1, duration: 187416496}, %{result: :ok, topic: "contract"}}
(which matched {:publish, _, _})
code: refute_received {:publish, _, _}
```

Перед этим `make` дважды проходил целиком, отдельный прогон файла — 3 из 3. Правка коммита
тестов и `lib/` не трогала.

**Причина.** `:telemetry.attach/4` — глобальный обработчик: он срабатывает на событие
`[:core, :mq, :kafka, :publish]` из любого процесса VM. `Core.Mq.Kafka.WriterContractTest` (тоже
`async: true`) публикует в топик `"contract"` через тот же `Writer` параллельно, и его событие
доходит до почтового ящика `WriterTest` между `Writer.put` с пустым телом и `refute_received`.
Событие эмитится синхронно в процессе, который зовёт `Writer.put` (`emit_publish/3` внутри
`put_one/2`), поэтому отличить своё событие можно по процессу.

**Остальные тесты с `:telemetry.attach/4`.** Из 22 мест `async: true` ещё только
`test/core/prom_ex/safe_test.exs`, и он не подвержен: событие отказа строится от своего плагина
`:safe_test`, которого больше никто не эмитит. Остальные модули — `async: false`.

- Реализация: проверка из `Task` добавлена отдельным `refute_received` после проверки пустого
  тела — у каждого инварианта своё падение (замечание ревью). До фильтра обработчика она падала с
  `{:publish, …, %{result: :ok, topic: "topic_a"}}`; после — 201 прогон обоих модулей подряд
  зелёный.

## Agent Brief

**Category:** bug
**Summary:** изолировать обработчик телеметрии в тесте `Core.Mq.Kafka.WriterTest` от событий
соседних async-модулей, не снимая `async: true`

**Current behavior:**
Тест «publish эмитит телеметрию с результатом и топиком» вешает глобальный обработчик на
`[:core, :mq, :kafka, :publish]`, который пересылает тесту каждое событие из любого процесса.
Последняя проверка теста — `refute_received {:publish, _, _}` после `Writer.put` с пустым телом.
Если параллельный модуль (`WriterContractTest`, топик `"contract"`) в это время публикует через
`Writer`, его событие попадает в ящик теста, и тест падает. Падение редкое и зависит от
расписания: локально файл проходит, полный прогон — иногда нет.

**Desired behavior:**
Обработчик пересылает событие, только если его эмитит процесс теста (обработчик выполняется в
процессе, вызвавшем `:telemetry.execute/3`, — у `Writer.put` это вызывающий). Все проверки теста
остаются прежними: событие `:ok` с топиком `"topic_a"`, событие `:error` с топиком `"missing"`,
отсутствие события для пустого тела. Модуль остаётся `async: true`: глобальное состояние здесь —
только регистрация обработчика, и её уже убирает `on_exit`.

**Key interfaces:**
- Функция-обработчик в `:telemetry.attach/4` теста: сравнение `self()` с pid теста из конфигурации
  обработчика; событие чужого процесса отбрасывается.
- `Core.Mq.Kafka.Writer`: не меняется — событие эмитится в процессе вызывающего синхронно.

**Acceptance criteria:**
- [x] Событие `[:core, :mq, :kafka, :publish]` из чужого процесса не доходит до теста — проверено
      в самом тесте: публикация через `Writer.put` из `Task` во время теста не даёт сообщения в
      ящике теста (или эквивалентной проверкой)
- [x] `mix test test/core/mq/kafka/writer_test.exs test/core/mq/kafka/writer_contract_test.exs
      --repeat-until-failure 200` не падает
- [x] Модули остаются `async: true`
- [x] `make` зелёный

**Out of scope:**
- `lib/core/mq/kafka/writer.ex` и состав метаданных события (добавлять `client` в метаданные не
  нужно)
- Остальные тесты с `:telemetry.attach/4`: подверженных среди `async: true` нет
- Норма о телеметрии в async-тестах в `docs/rules/19-testing.md`

# 05: Метрики чтения Kafka

**What to build:** оператор потребителя видит на дашборде, насколько чтение Kafka отстаёт по
каждой партиции — по времени и в сообщениях, — и получает алерт, когда отставание растёт, смещение
сброшено на earliest или чтение и commit отказывают.

**Blocked by:** 01

**Status:** ready-for-agent

**Spec:** [Чтение из Kafka](../spec.md)

- [ ] PromEx-плагин `Core.Mq`: отставание по времени по топику и партиции (`now` минус
      `timestamp` последнего закоммиченного сообщения), ошибки чтения и commit по топику. На
      пустом топике отставание по времени не информативно — в тексте нормы.
- [ ] Отставание в сообщениях по топику и партиции: latest из `ListOffsets` (модуль внутреннего
      API `:klife` из тикета 01) минус зафиксированное смещение; запрос раз в интервал и только у
      владельца аренды (ADR-0033).
- [ ] Счётчик сброса на earliest (`OFFSET_OUT_OF_RANGE`, тикет 01) — алерт на единичное событие
      (ADR-0029).
- [ ] Серии счётчиков засеваются по правилу первого события (`21-observability.md`).
- [ ] Строки рекомендованных алертов с условиями и тест `promtool` в тексте нормы.
- [ ] `CHANGELOG.md` обновлён.

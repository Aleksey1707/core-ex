# 02: Команда идёт одной транзакцией при `repo:`

**What to build:** команда event-sourced агрегата при заданных `repo:` и `codec:` использует `dao` и `codec` реализации репозитория во всех шагах — чтение состояния, `append`, guard и цикл повтора. Падение колбэка после `append` откатывает и события. Ручная реализация behaviour репозитория, не собранная штатным макросом, отвергается на компиляции процесса агрегата.

**Blocked by:** 01 — единый вход `Transact` с `dao:`.

**Status:** resolved

- [x] Конфигурация репозитория (dao, codec) — единственный источник для исполнения команды и для процесса агрегата; id агрегата в span и telemetry берётся оттуда же.
- [x] Guard «вызов внутри транзакции» проверяет `dao` команды, а не `Core.Config.dao/0`.
- [x] Проверка «репозиторий собран через `use Core.Es.Aggregate.Repo.Pg`» вынесена в одну функцию и вызывается и read-репозиторием, и процессом агрегата.
- [x] Ручная реализация behaviour без функции конфигурации — `CompileError` при объявлении процесса.
- [x] Второй тестовый репозиторий на ту же БД; тест: репозиторий с `repo:`, падающий колбэк после `append` — поток событий пуст.
- [x] ADR «владелец `dao` команды» заводится, `13-repos.md` и CHANGELOG (раздел ломающих) обновлены тем же коммитом.

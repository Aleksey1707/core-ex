# 03: Дедлайн — ожидаемый исход в обоих режимах

**What to build:** истёкший дедлайн команды и `timeout:` значат одно и то же при `enabled: true` и `enabled: false`: вызывающий получает `{:error, %Error{code: :deadline_exceeded, detail: %{phase: …}}}` вместо exit или молчаливого игнора. После дедлайна нет commit; просрочка в очереди процесса отвечает ошибкой, а не дропом. Внутренняя метка `:expired` и классификаторы исхода исчезают. Остановленное дерево даёт понятный `RuntimeError`, а не exit из старта дочернего процесса.

**Blocked by:** 02 — `dao`/`codec` команды из репозитория.

**Status:** resolved

- [x] `execute/6` при обоих значениях `enabled:` возвращает только `{:ok, version | nil} | {:error, %Error{}}`.
- [x] Ошибка дедлайна: `kind: :app`, `ns: :es`, `code: :deadline_exceeded`, detail `%{aggregate_id: <дамп>, phase: :queue | :read | :commit}`; без ПДн.
- [x] `timeout:` действует при `enabled: false`; проверки до чтения и перед commit сохраняются; после дедлайна нет ни чтения, ни записи, ни commit.
- [x] Просрочка в очереди процесса отвечает ошибкой `phase: :queue`; `GenServer.call` ждёт дедлайн плюс запас 1 000 мс.
- [x] Метка `:expired`, `outcome/1` и `result/1` удалены; ошибку строит один конструктор, его зовут исполнение и процесс.
- [x] Исключения в решении и колбэке документированы как «не исход команды»: при `enabled: false` — raise, при `enabled: true` — exit; тест: события не записаны, следующая команда работает.
- [x] Ошибка колбэка `{:error, reason}` возвращается как есть, без обёртки.
- [x] `result` в telemetry — `:ok`, `:version_mismatch`, `:error`; `:exit` остаётся только для смерти процесса.
- [x] После остановки дерева `enabled: true` даёт `RuntimeError` с текстом «дерево остановлено»; `enabled: false` продолжает работать.
- [x] ADR «ожидаемые исходы команды», `13-repos.md`, `21-observability.md` и CHANGELOG (раздел ломающих) обновлены тем же коммитом.

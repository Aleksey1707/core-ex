# 01: Проверка формы панелей по норме

**What to build:** тест потребителя на дашборде с явным `legendFormat: null` получает нарушение
формы, а не падение; панель с `operation` без `system` не проходит проверку; `barchart` и
`piechart` не получают ложное `:variable_filter`; растущая метка, видимая только в `by (...)`
запроса, ловится так же, как метка в легенде. Проверка формы `Core.PromEx.Dashboards`
(`form_violations/3`, `assert_form!/3`) совпадает с нормой «Форма панелей», документация модуля
описывает новое поведение, собственные шаблоны библиотеки проходят ужесточённую проверку.
Спека: `.scratch/dashboard-fixes/spec.md`.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Явный `legendFormat: null` даёт нарушение `:summary_legend`, а не исключение
- [ ] `operation` считается фиксированной только в запросе, задающем `system` (`=`, `!=`, `=~`, `!~`); без `system` — растущая
- [ ] `:variable_filter` проверяется только у `timeseries`; `barchart`/`piechart` с растущей меткой проходят
- [ ] Растущие метки складываются из `{{…}}` легенды и меток `by (...)`; `le` и метки окружения игнорируются; `without`/`on` не разбираются
- [ ] Таблица правил в `@moduledoc`/`form_violations/3` обновлена под новое поведение
- [ ] Тесты на каждый случай в существующем файле тестов дашбордов
- [ ] Собственные шаблоны библиотеки проходят `assert_form!`
- [ ] Существующий пункт CHANGELOG про `form_violations/3` дополнен; новый пункт не заведён
- [ ] `make` зелёный

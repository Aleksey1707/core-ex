# 01: Проверка формы панелей по норме

**What to build:** тест потребителя на дашборде с явным `legendFormat: null` получает нарушение
формы, а не падение; панель с `operation` без `system` не проходит проверку; `barchart` и
`piechart` не получают ложное `:variable_filter`; растущая метка, видимая только в `by (...)`
запроса, ловится так же, как метка в легенде; строковые литералы запроса не дают ложных матчеров
и группировок, а вложенную `by`-агрегацию подавляет внешняя — это осознанная обработка, нужная
шаблону `kafka`. Проверка формы `Core.PromEx.Dashboards` (`form_violations/3`, `assert_form!/3`)
совпадает с нормой «Форма панелей», документация модуля описывает новое поведение, собственные
шаблоны библиотеки проходят ужесточённую проверку. Спека: `.scratch/dashboard-fixes/spec.md`.

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] Явный `legendFormat: null` даёт нарушение `:summary_legend`, а не исключение
- [x] `operation` считается фиксированной только в запросе, задающем `system` (`=`, `!=`, `=~`, `!~`); без `system` — растущая
- [x] `:variable_filter` проверяется только у `timeseries`; `barchart`/`piechart` с растущей меткой проходят
- [x] Растущие метки складываются из `{{…}}` легенды и меток `by (...)`; `le`, `quantile`, `job`, `instance` игнорируются; `without`/`on` не разбираются
- [x] Вложенную `by`-агрегацию подавляет внешняя (`count(max by (…))`, `sum by (…)(max by (…))`) — нужна шаблону `kafka`
- [x] Строковые литералы запроса (`"…"`, `'…'`, `` `…` ``) маскируются: `system=`, `by (...)` и `)` внутри кавычек не задают матчер, группировку и вложенность, а фильтр переменной внутри литерала не считается заданным
- [x] Таблица правил в `@moduledoc`/`form_violations/3` обновлена под новое поведение
- [x] Тесты на каждый случай в существующем файле тестов дашбордов
- [x] Собственные шаблоны библиотеки проходят `assert_form!`
- [x] CHANGELOG: новый пункт в «Не выпущено» про ужесточение проверки формы; выпущенный 0.17.0 не переписан
- [x] `make` зелёный

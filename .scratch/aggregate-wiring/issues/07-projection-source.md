# 07: Агрегат и кодек проекции без соглашения об именах

Type: grilling
Status: resolved

Blocked by: 04

## Question

`Es.Projection` находит кодек события как `<Family>.Codec`, а агрегат для `await/3` — как
`Module.split(codec) -- 2`. Обе связи — соглашение об именах, запрещённое Notes карты. Событие называет своё
семейство (`__es_family__/0`), но семейство не знает ни кодек, ни агрегат, а кодек не знает агрегат.

Какой явной ссылкой проекция получает кодек и агрегат: опцией `use` проекции, ссылкой семейства на кодек
(атомом, без загрузки), ссылкой кодека на агрегат или иначе? Решение не создаёт взаимного ожидания (семейство
ждут события, кодек ждёт семейство).

## Answer

Решено в обсуждении 2026-10-23.

Владелец потока у проекции бывает трёх видов: event-sourced агрегат (`__es_event_codec__/0`), state-stored
сущность (кодек знает только `Repo.Pg.StateStored event_codec:`) и `Core.Es.Personal` (не агрегат). Ни ссылка
агрегат → кодек, ни кодек → агрегат не покрывает всех трёх. Поэтому проекция идёт от события к кодеку, а агрегат
из `await` уходит.

**Кодек — ссылкой семейства.** `use Core.Es.Event.Family, aggregate_id:, by:, codec:`. `codec:` — атом без
загрузки. Проекция берёт `event.__es_family__().__es_codec__()` и вызывает `ensure_compiled`. Кодек при сборке
сверяет `family.__es_codec__() == __MODULE__`, а иначе — `CompileError`. Связь кодек ↔ семейство теперь
объявлена с обеих сторон, расхождение ловит сверка, как у `event_codec:` агрегата (тикет 04). Взаимного ожидания
нет: семейство кодек не грузит, кодек ждёт семейство, события ждут семейство.

Отвергнуты:
- опция проекции `codecs:` — каждая проекция повторяла бы список кодеков;
- `events:` с группировкой по кодеку — форма `events:` тяжелее и ломается.

**Агрегат в `await` не нужен.** Первый аргумент был только литералом в голове clause, поток выбирает `type`
кодека. Новые формы:
- `await(%Agg.ID{} = id, timeout)`;
- `await(%Agg.ID{} = id, %Core.Version{} = version, timeout)`.

Голова закрыта литеральным struct ID (ADR-0014). Предупреждение у вызывающего теперь звучит как «ID не из
`events:`», а не «агрегат не из `events:`». Clause у `Personal` — `await(%Core.Es.Personal.SubjectID{}, timeout)`.

**Общий ID у двух кодеков из `events:`.** Встречается: у потребителя A один ID у трёх агрегатов. Проекции на
событиях двух из них пока нет, но первая же проекция, которая к своему агрегату добавит соседний, упала бы на
`CompileError`. Поэтому общий ID поддерживается сразу:
- `await(%ID{} = id, timeout)` ждёт все потоки с этим ID среди типов проекции. Цель — наибольшая позиция по
  этим типам (`Es.Store` — вариант `last_stream_position` по списку типов), ложного `:ok` нет. Цена — иногда
  лишнее ожидание соседнего потока.
- У `await/3` версия адресует один поток: объединение дало бы `:ok` по чужой версии. На общем ID clause с версией
  получает первым аргументом агрегат: `await(Agg, %ID{} = id, %Core.Version{} = version, timeout)`. Для ID одного
  кодека форма прежняя, без агрегата.

**Агрегат — ссылкой семейства** (решено 2026-10-23, после выбора формы). `use Core.Es.Event.Family, aggregate:,
aggregate_id:, by:, codec:`; `aggregate:` обязательна в каждом семействе, атом без загрузки, как `codec:` (вариант Б
тикета 09, runtime-ребро). Проекция берёт литерал головы как `event.__es_family__().__es_aggregate__()`. Владелец
потока: у event-sourced агрегата — сам агрегат, у state-stored — сущность, у `Personal` — `Core.Es.Personal`.
Ссылку сверяет билдер, который уже ждёт и агрегат, и кодек (`Es.Aggregate.Repo`, `Repo.Pg.StateStored`); место
сверки и текст `CompileError` — в спеке. Тикет 04 обратной ссылки не вводил («её требует только `Projection`»):
теперь она нужна, и требует её та же `Projection`.

Семейство первым аргументом отвергнуто: вызывающий думает агрегатом (`Agg`), а не семейством событий
(`Agg.Event`).

Отвергнуты:
- `aggregate:` у кодека — кодек семейства уже называет `codec:`, и владелец потока — свойство семейства, а не
  кодека. Довод «у state-stored и `Personal` агрегатом стал бы модуль-метка» не подтвердился: у state-stored
  владелец — сущность, у `Personal` — `Core.Es.Personal`, оба уже существуют;
- агрегат первым аргументом во всех формах — при уникальном ID он избыточен, ID и так выбирает поток;
- агрегат в рантайме (`agg.__es_event_codec__()` в теле clause) — чужой агрегат ловится вызовом, а не
  предупреждением компилятора (ADR-0014), и не работает у state-stored и `Personal`;
- `aggregates:` у проекции.

Ломка потребителя: `Projection.await(Agg, id, t)` → `Projection.await(id, t)`, с версией — так же, кроме общего
ID: там `await(Agg, id, version, t)` не меняется. Ломается и каждое семейство: обязательная `aggregate:`. Уточняются
ADR-0014, ADR-0027, ADR-0030, ADR-0039, ADR-0080 и `22-projections.md`, «Read-after-write».

| Билдер | Было | Стало |
|---|---|---|
| `Es.Event.Family` | `aggregate_id:`, `by:` | `aggregate:`, `aggregate_id:`, `by:`, `codec:` |
| `Es.Event.Codec` | — | сверка `family.__es_codec__()` |
| `Es.Projection` | кодек `<Family>.Codec`, агрегат `Module.split(codec) -- 2` | кодек из семейства; `await/2`, `await/3` без агрегата; общий ID — `await/2` по всем его потокам, `await/3` с агрегатом из `__es_aggregate__/0` семейства |

Новые рёбра (атом `codec:` в `use` семейства, вызов проекции через семейство) проверяет тикет 09. Атом
`aggregate:` раскрывается так же, как `codec:` варианта Б, — отдельной проверки xref не требует.

# 02: Где семейство объявляет `aggregate_id` и `by`

Type: grilling
Status: resolved

Blocked by: 01

## Question

Сейчас каждое событие повторяет `aggregate_id:` и `by:`, а кодек выводит их и сверяет (`derive!`). Где их
объявить один раз на семейство событий агрегата?

Кандидаты:
- модуль семейства `<Aggregate>.Event` с собственным `use`;
- кодек `<Aggregate>.Event.Codec`;
- агрегат.

Решение учитывает:
- литеральные головы `new/5,6` события (`%AggID{}`), которые требует ADR-0014;
- уже отвергнутые в ADR-0014 варианты: «`draft` на семействе» — семейство и кодек ждут компиляции друг
  друга; «агрегат грузит кодек»;
- как событие находит своё семейство — явной ссылкой, а не по имени (Notes карты).

Итог — выбранное место, форма объявления и путь, по которому событие и кодек получают `aggregate_id` / `by`.

## Answer

Решено в обсуждении 2026-10-23.

**Место — модуль семейства `<Aggregate>.Event`.** Событие при сборке ждёт модуль, из которого берёт
`aggregate_id` / `by`: голова `new` — `%AggID{}`.
- Кодек отпадает: он ждёт события (`tags:`), и событие, ждущее кодек, — взаимное ожидание.
- Агрегат отпадает: головы `evolve/2` (`%Event.X{}`) заставляют агрегат ждать события.
- Семейство ждёт только два Prim; `@type t` модули событий не ждёт. Довод ADR-0014 против «`draft` на
  семействе» здесь не действует: семейству не нужен кодек.

**Охват.** Все `use Core.Es.Event` одним выпуском — события event-sourced и state-stored агрегатов,
событие библиотеки `Core.Es.Personal.Event.KeyDestroyed` (семейство `Core.Es.Personal.Event` становится
объявленным).

**Форма объявления.**

```elixir
defmodule Agg.Event do
  use Core.Es.Event.Family,
    aggregate_id: Agg.ID,
    by: UserID

  @type t :: Agg.Event.A.t() | Agg.Event.B.t()
end
```

- Новый билдер `Core.Es.Event.Family`, обе опции обязательны. Генерирует `__es_aggregate_id__/0`,
  `__es_by__/0`; при раскрытии ждёт оба Prim.
- `@type t` пишет автор (иначе — третья копия `tags:`); `@before_compile` проверяет, что он объявлен.

**Событие → семейство.** `use Core.Es.Event, family: Agg.Event, payload: …`; `aggregate_id:` / `by:` из
`use` события уходят.
- При раскрытии событие ждёт семейство (`module!` с экспортом `__es_aggregate_id__/0`, `__es_by__/0`) и
  запекает значения в литеральные головы `new/5,6`, `@type t`, `@spec` (ADR-0014).
- Интроспекция события остаётся: `__es_aggregate_id__/0`, `__es_by__/0` (читают
  `Core.Labels.CompletenessCase`, `check_subject!`), плюс новая `__es_family__/0`.
- Имя опции `family:`, а не `event:`: у события `event:` читался бы как оно само. Имя опции у кодека,
  `Outbox`, ключа — тикет 04.

**Кодек.**
- `@es_aggregate_id` / `@es_by` берёт у семейства `event:`, а не выводит из событий.
- Новая сверка: у каждого события `tags:` `__es_family__() == event:`, иначе `CompileError`. Закрывает
  дыру из тикета 01: принадлежность событий кодека семейству не сверял никто.
- `derive!` и его тест на «разные `__es_aggregate_id__`» удаляются: двух значений в семействе нет.
- `__es_aggregate_id__/0` кодека остаётся (`Store.Opts`, `Projection`, `StateStored`); `__es_by__` наружу
  не отдаётся.
- Новых ожиданий нет: кодек уже ждёт семейство (`module!` на `event:`).

**Глоссарий.** В `CONTEXT.md` — термин «Семейство событий агрегата».

**Для тикета 03.** Прототип проверяет: семейство → Prim, событие → семейство, кодек → семейство и события;
ожидаемый граф без взаимного ожидания; новое xref-ребро событие → семейство.

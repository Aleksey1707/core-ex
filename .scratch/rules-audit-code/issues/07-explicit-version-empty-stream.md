# 07: Явная версия на пустом потоке

**Status:** done

**What to build:** поведение ADR-0016 (`docs/adr/0016-explicit-version-on-unborn-aggregate.md`): команда с
`%Version{}` над незаведённым агрегатом отдаёт ошибку решения, если `decide` отклоняет, и `:version_mismatch` с
`actual: nil`, если принимает (в том числе без событий).

- `get_decision(id, version, context, fun, opts \\ [])` — колбэк behaviour `use Core.Es.Aggregate.Repo` и
  генерируемая функция `use Core.Es.Aggregate.Repo.Pg`; читающая, `fun: state -> {:ok, t} | {:error, e}`:
  - версия сошлась или `:current` — `fun.(state)`; пустой поток при `:current` — от `%Agg{id: id, version: nil}`;
  - пустой поток и `%Version{}` — `fun.(незаведённый)`: `{:error, _}` как есть, `{:ok, _}` → `:version_mismatch`
    с detail `%{aggregate_id, expected, actual: nil}`;
  - непустой поток мимо версии — `:version_mismatch`, `fun` не вызывается;
  - закрытая голова и сужение результата — `20-agreements.md`, «Генерируемые функции» (ADR-0014).
- `Core.Es.Aggregate.Process.Execution` — то же правило при `get` и при `refresh` процесса на id (закэшированное
  состояние с `version: nil`); отказ на пустом потоке не повторяется.
- `get` / `refresh` / `get_many` — контракт прежний; `get_many` явную версию сверяет до решения.
- Нормы:
  - `13-repos.md`, «Write event-sourced агрегата»: строка `get_decision` в таблице; пункт «`:not_found` репозиторий
    не отдаёт» дополнить; команда с явной версией SHOULD через `get_decision` или `Agg.Process.execute`; свёртка
    `:version_mismatch` с `actual: nil` в незаведённый агрегат MUST NOT; `fun` MUST NOT писать; исключение
    `get_many`; пример usecase `Transact.run` → `get_decision` → `append`.
  - `13-repos.md`, «Процесс агрегата»: пункт про `%Version{}` мимо головы потока — пустой поток по правилу выше.
  - `app/10-architecture.md:143` и `app/15-web-api.md` (`If-Match`): явная версия на незаведённом агрегате — ошибка
    домена или отказ предусловия; номер статуса доменного отказа не писать (тикет 14).
  - moduledoc `Core.Es.Aggregate.Repo`, `Core.Es.Aggregate.Repo.Pg`, `Core.Es.Aggregate.Process`.
- `CHANGELOG.md`, «Не выпущено»: дополнить существующие пункты «Новое» о репозитории event-sourced агрегата и
  процессе агрегата (новых пунктов не заводить); перевод потребителя — свёртка `actual: nil` → `get_decision`.
- Тесты: контрактный тест репозитория — четыре исхода `get_decision`; тест процесса (`enabled: false` и `true`) —
  пустой поток с `%Version{}`: отказ `decide`, принятие с событиями, принятие без событий; маркеры `# expect:` в
  `fixtures/consumer` для `get_decision`.
- `make` целиком, включая `consumer-check` и `compile-no-optional`.

**Why:** `13-repos.md` говорит «существование агрегата решает домен», но репозиторий отказывает раньше; приложение
сворачивает этот отказ обратно в незаведённый агрегат своим хелпером, а процесс агрегата свернуть его не даёт.

## Triage Notes

**Established:**

- `get(id, %Version{}, context)` на пустом потоке → `:version_mismatch` с `actual: nil`; так же `refresh` и
  `get_many`. Записано в `13-repos.md`, закреплено контрактным тестом репозитория и тестом процесса.
- HTTP: `Core.Web.ErrorMapper` отображает `:version_mismatch` в 412, доменный `:not_found` — в 400 (клаузы 404 нет).
- Поток только дописывается, удаление — доменное событие: явная версия на пустом потоке — не гонка, а ссылка на
  состояние, которого не было.
- qc: хелпер `blank` — 13 вызовов в 11 модулях по 8 агрегатам; `UserRoles` сворачивает в `:not_found`, потому что
  `Grant` заводит поток. `get_many` в qc вызывается только с `:current`.
- RFC 9110 §13.2.1: предусловие не проверяется, если без него ответ не был бы 2xx / 412.

## Agent Brief

**Category:** enhancement
**Summary:** публичная `Core.Outbox.check_singleton!/1` — отказ старта включённого outbox в кластере без явного
разрешения

**Current behavior:**
Библиотека даёт только `Core.Outbox.validate_partition!/1` — разбиение топиков между поллерами внутри ноды.
Проверку «включённый outbox + кластеризация» каждое приложение пишет само: пять копий у четырёх потребителей,
у трёх есть тесты, логика одна (не кластер → `:ok`, разрешено → `warning`, иначе `ArgumentError`), но копии
расходятся: в одной пустой `DNS_CLUSTER_QUERY` считается кластером, в другой `allow_cluster?` не приводится к
boolean. Норма `docs/rules/app/14-events-outbox.md`, «Единственность поллера», сейчас говорит «проверку приложение
пишет само». Устаревшее имя `Outbox.Supervisor.check_singleton!/0` осталось в ADR-0009 и ADR-0013.

**Desired behavior:**
`Core.Outbox.check_singleton!(opts) :: :ok`:

- `enabled?:` — boolean, обязательная; `cluster_query:` — `String.t() | :ignore | nil`, обязательная;
  `allow_cluster?:` — boolean, по умолчанию `false`. Неизвестная опция или значение не той формы — ошибка разбора;
- `nil`, `:ignore` и `""` — кластеризации нет;
- outbox выключен или кластеризации нет → `:ok`;
- включён, кластер, `allow_cluster?: true` → `Logger.warning` с `cluster_query` и `:ok`. Функция не чистая:
  `warning` требует норма, и писать его должна библиотека, а не каждый вызывающий;
- включён, кластер, без разрешения → `ArgumentError` с инструкцией: выключить outbox на всех инстансах, кроме
  одного (`OUTBOX_ENABLED`), или осознанно разрешить (`OUTBOX_ALLOW_CLUSTER`), и ссылкой на норму.

Env функция не читает: значения передаёт приложение. Место вызова — `start/2` приложения до подъёма дерева, рядом
с `validate_partition!/1`, как уже требует норма (копии сейчас зовут из `start_link` супервизора — норма остаётся).

**Key interfaces:**
- `Core.Outbox.check_singleton!/1` — новая: `@spec`, `@doc` с примером вызова из `start/2`
- moduledoc `Core.Outbox` и `@doc` `validate_partition!/1` ссылаются на `check_singleton!/1`, а не на «проверку
  единственности поллера приложения»

# 08: UUIDv5 в `Core.Prim.UUID`

**Status:** done

**What to build:** идентификатор из ключа по ADR-0017 (`docs/adr/0017-stream-id-from-key.md`):
`use Core.Prim.UUID, version: 5, namespace: …, scope: "…"` и приватный конструктор `from_key/1`.

- `Core.Prim.UUID`:
  - опции `namespace:` / `scope:`; `validate_opts!/1` — версия 5 допустима; при `version: 5` обе опции обязательны,
    при других версиях запрещены; namespace — валидная UUID-строка (любой версии), scope — непустая строка;
    `check_version: false` при `version: 5` допустим;
  - при `version: 5` `new/0` не генерируется, `generate/1` версию 5 не получает;
  - при `version: 5` генерируется `defp from_key(String.t() | [String.t(), ...]) :: t()`:
    `Enum.reduce(parts, UUID.uuid5(namespace, scope), &UUID.uuid5(&2, &1))`, строка — как список из одной части;
    закрытая голова и сужение результата — `20-agreements.md`, «Генерируемые функции» (ADR-0014);
  - `@moduledoc` — версия 5, опции, отсутствие `new/0`, `from_key/1`.
- Тесты `test/core/prim/uuid_test.exs` (Prim-фикстура с публичным `from_<key>`, зовущим `from_key/1`):
  - эталон схемы, сверен с Python `uuid`: namespace `1b0f8f5e-8a54-4a7c-9a2b-3f6d2c8e5a11`, scope `"delivery"`,
    ключ `"DLV-1"` → `48729eb6-0c8a-5383-a0c4-e8b281bbda54`; scope `"item_inspection"`, ключ
    `["0190a0c0-0000-7000-8000-000000000001", "0190a0c0-0000-7000-8000-000000000002"]` →
    `c710c79e-cc22-5467-91c7-fd8cc95b5832`;
  - `from_key("x") == from_key(["x"])`; граница: scope `"delivery"` + `"x:y"` ≠ scope `"delivery:x"` + `"y"`;
  - `new/1` отвергает не-v5 при `check_version: true`, принимает при `false`; `new/0` не экспортируется;
  - `CompileError`: нет `namespace:` / `scope:` при `version: 5`; невалидный namespace; пустой scope; `namespace:`
    при `version: 7`.
- `fixtures/consumer`: Prim с `version: 5` и `from_<key>` — без предупреждений (маркеры `# expect:` при нужде).
- Нормы:
  - `docs/rules/app/13-repos.md`, «Уникальность без индекса состояния»: `from_<key>/1` → `from_<key>` любой
    арности, тело зовёт `from_key/1`; объявление Prim (`version: 5`, `namespace:`, `scope:`); область ключа MUST у
    каждого идентификатора из ключа, общий идентификатор нескольких агрегатов — одна область; namespace MUST из
    одной публичной функции модуля приложения (пример `MyApp.StreamID.namespace()`, имя не фиксируется), литерал в
    Prim MUST NOT; ссылка на ADR-0017. Отдельной нормы про пробы в тестах нет.
  - `docs/rules/11-domain.md:113`: версии 1 / 4 / 7 / 5, у версии 5 нет `new/0`, конструктор — `from_key/1`.
- `CHANGELOG.md`, «Не выпущено», «Изменения контракта макросов» (правка `app/**` — тем же коммитом): новые опции и

## Triage Notes

**Established:**

- `Core.Prim.UUID` допускает `version: 1 | 4 | 7`, генерации по имени нет. `:uuid` — прямая зависимость
  библиотеки, `UUID.uuid5/2` в ней есть; `Core.Validator.UUID` версию 5 распознал бы. `versions/0` вне модуля не
  используется, `generate/1` зовёт только `new/0`.
- Норма `app/13-repos.md`, «Уникальность без индекса состояния»: неизменяемый уникальный ключ — id потока в виде
  UUIDv5, один неизменяемый namespace на приложение, конструктор `<Aggregate>.ID.from_<key>/1` в Prim. Как
  считать составное имя — не сказано.
- qc (`QC.StreamID`): namespace-константа, `uuid5(ns, scope)`, затем свёртка `uuid5(acc, part)` по частям; четыре
  Prim (`Delivery`, `Acceptance`, `ItemInspection`, `ClaimAct`) с `version: 7, check_version: false`, составной
  ключ — у `ItemInspection.ID.from_item/2`. `:uuid` в зависимостях qc нет. `new/0` — пробы несуществующего
  агрегата (~38 вызовов в тестах). Схема на ветке `core-rc` (16.09.2026), в `master` нет, тегов нет.
- qc: `UserRoles.Repo.Pg` объявлен с `id: User.ID` — один Prim идентификатора у двух типов агрегатов.
- PK `es_events` — `(aggregate_type, aggregate_id, aggregate_version)`: одинаковый id у разных типов хранилище не
  ломает.
- Namespace нельзя читать из конфига при компиляции: компиляция библиотеки не требует конфигурации потребителя
  (главный инвариант, `10-architecture.md`).

## Grilling (17.09.2026)

**Decided:**

- Схема qc целиком: область ключа обязательна, составной ключ — вложенный `uuid5`, не склейка. Отвергнутые
  варианты — ADR-0017.
- `namespace:` и `scope:` — опции `use`; не аргумент конструктора и не `Core.Config`.
- `new/0` у версии 5 нет; пробы — `from_<key>` от уникального ключа.
- Конструктор — приватный `from_key/1`, только строки; Prim в строки переводит `from_<key>` потребителя.
- `check_version: false` при версии 5 разрешён (переход агрегата со случайных id).
- Область ключа принадлежит идентификатору, не типу агрегата.
- CHANGELOG — «Изменения контракта макросов», а не «Новое».
- `CONTEXT.md`: термины «Идентификатор из ключа» и «Область ключа».

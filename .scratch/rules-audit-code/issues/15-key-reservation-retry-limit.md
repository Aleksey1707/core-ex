# 15: Резерв ключа — убрать неограниченный повтор

**Status:** done

**What to build:** отказ вставки резерва (`lib/core/es/key_reservation.ex`) разбирается строками
области, а не чтением одного ключа; повтор ограничен единицей; второй отказ подряд —
`%Error{kind: :app, ns: :es, code: :reservation_unresolved}`.

**Why:** цикл `reserve/3` → `reserve_taken/3` → `reserve/3` не ограничен ничем — ни счётчиком, ни
паузой, — и крутится внутри уже открытой транзакции команды, которая держит записанные события и
блокировки строк. `owner/3` читал только `(scope, key)`, поэтому пустой ответ склеивал две разные
причины отказа, и ни одна из них не была видна в логе.

- [x] `reserve/4` с бюджетом попыток; `owner/3` → строки области; `outcome/3` как чистый разбор
- [x] `:reservation_unresolved` в реестре `12-errors.md`; норма в `13-repos.md`; moduledoc; фраза
      в `CONTEXT.md`; CHANGELOG

## Решение

Развилки разобраны в грилле 18.09.2026; принято:

| Развилка | Решение |
|---|---|
| Ограничить петлю или убрать состояние | Убрать: причина отказа выясняется, а не угадывается повтором |
| `conflict_target: [:scope, :key]` | **Нет.** Сузить — значит превратить конфликт по `(scope, aggregate_id)` в исключение там, где следующая попытка доводит запись до конца |
| Разбор отказа | Один запрос по строкам области: `r.key == ключ or r.aggregate_id == наш` |
| Предел | 1: обе причины снимает ровно одна следующая попытка |
| Исчерпание | `%Error{kind: :app, ns: :es, code: :reservation_unresolved}`, detail `%{scope, aggregate_id, reason}` |
| Тесты | Чистый разбор `outcome/3` без базы: обе ветки повтора и обе причины исчерпания |
| ADR | Не заводить: правка одной приватной функции, откатывается тривиально. Обоснование — moduledoc, ADR-0018 не трогается |
| `CONTEXT.md` | Фраза в «Резерв ключа» — занятость и неразрешённость это разные исходы; отдельного термина нет |
| Порядок `DELETE` → `INSERT` | Не трогать: ожидание конкурента здесь корректно и уже зафиксировано в moduledoc |

Три ветки разбора и почему повтор один — moduledoc `Core.Es.KeyReservation`, «Разбор отказа
вставки».

## Triage Notes

*Первая картина была неполной: она знала только про исчезнувший ключ и не отделяла вторую дорогу в
тот же цикл — конфликт по `(scope, aggregate_id)`. Сохранено как история разбора.*

**Что установлено:**

- Цикл: `reserve/3` при `{0, _rows}` от `insert_all(… on_conflict: :nothing)` зовёт
  `reserve_taken/3`; тот при `owner/3 == nil` зовёт `reserve/3` заново. Выхода по числу попыток
  нет.
- Каждый виток — `DELETE` прежних ключей агрегата + `INSERT`, внутри транзакции команды.
- Витку по причине «ключ исчез» нужен **commit** соперника (иначе `on_conflict: :nothing` дождался
  бы его и вставил: это путь `{1, _rows}`, он покрыт тестом «резерв одного ключа: откат первого —
  второй занимает ключ») и **commit удаления** той же строки между вставкой и чтением `owner/3`.
- Связь с `Core.Es.Transact` (тикет 06) **не подтверждена**: повтор команды идёт новой
  транзакцией после отката, а откат соперника ветку `nil` не порождает — вставка после него
  проходит.
- Вторая дорога, найденная при разборе `conflict_target`: `on_conflict: :nothing` **без**
  `conflict_target` глушит любое уникальное ограничение таблицы (`lib/core/repo/pg.ex:1026`), а их
  два — PK `(scope, key)` и unique `(scope, aggregate_id)`. Владелец резерва — `aggregate_id` без
  типа агрегата, а идентификатор из ключа (ADR-0017) бывает общим у агрегатов разных видов, и
  такая пара в одной области конфликтует независимо от ключа. Тогда `owner/3` по нашему ключу
  строки не находит и отдаёт `nil` — второй вход в тот же цикл.
- Цикл по второй причине самоисцелялся за один лишний виток: `DELETE` следующей попытки сносил уже
  закоммиченную чужую строку. Поэтому сужать `conflict_target` нельзя — корректный исход стал бы
  исключением.
- У потребителя `:release` только на `Deleted` (`user.login`, `role.name`, `perm.name`), так что
  первая причина вне состязательного теста практически недостижима.
- Обе ветки повтора без производственного шва детерминированно не воспроизводятся: нужны
  интерливинги внутри `reserve/3`. Поэтому тест — чистый разбор, а не гонка.

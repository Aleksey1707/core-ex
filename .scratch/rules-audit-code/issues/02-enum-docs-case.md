## Agent Brief

**Category:** enhancement
**Summary:** case-модуль проверки таблицы описаний значений в `@moduledoc` у `Core.Enum` приложения

**Current behavior:**
Норма `docs/rules/11-domain.md`, «Описание значений в `@moduledoc`» (таблица с описанием каждого значения),
в библиотеке не проверяется; `19-testing.md` отсылает к ратчету приложения. Ратчет скопирован у трёх
потребителей (две копии отличаются только именами модуля и приложения, третья иначе собирает ошибки); все
отбирают модули эвристикой по функциям (`values/0` + `cast_optional/1`), а не `Core.Enum.enum?/1`, как требует
`docs/rules/app/19-testing.md`. `Core.Enum.enum?/1` уже есть. Enum самой библиотеки (`Core.Outbox.Status`,
`Core.DurationParser.*`, `Core.Web.Response.Code`, enum тестовой фикстуры `Core.View`) таблицы несут полностью.

**Desired behavior:**
- `use Core.Enum.DocsCase, otp_app: :my_app` генерирует тест: у каждого модуля приложения, для которого
  `Core.Enum.enum?/1` истинно, множество значений первой колонки таблицы в `@moduledoc` совпадает с `values/0`.
  Провал печатает модуль и расхождение: недостающие значения, лишние строки, нет `@moduledoc` или таблицы.
- Логика — публичная `check_*` (`:ok | {:error, detail}`) над явным списком модулей; тест — `assert :ok = …`.
  Образец формы — `Core.Es.EventCompatCase` и case-модуль тикета 03.
- `otp_app:` — обязательная опция с проверкой на компиляции. Значение по умолчанию из `Core.Config.otp_app/0`
  брать нельзя: `make boundary-check` запрещает этот вызов вне `Core.Config`. `async:` — необязательная, как у
  соседних case-модулей.

**Key interfaces:**
- `Core.Enum.DocsCase` — новый: `__using__/1` с опциями `otp_app:` (обязательная), `async:`; публичная `check_*`
- `Core.Enum.enum?/1` — единственный критерий отбора модулей

## Реализация

- `Core.Enum.DocsCase` (`lib/core/enum/docs_case.ex`): `use` с `otp_app:` (обязательная, `Helper.Opts.atom!/3`) и
  `async:`; три теста — `check_table/1` (`%{no_moduledoc: [...], no_table: [...]}`), `check_undocumented/1`,
  `check_unknown/1`; enum — `enums!/1` в `setup_all`. Незагруженное приложение и приложение без enum — провал всех
  тестов модуля, как у `ConstraintErrorsCase`: `otp_app:` на чужое загруженное приложение иначе даёт холостой
  зелёный прогон.
- Разбирается только таблица с заголовком `| Значение |`: по ревью — вторая таблица moduledoc с атомами в первой
  колонке давала бы ложное «несуществующее значение». Ячейка сравнивается со строкой `` `#{inspect(value)}` ``,
  атомы из документации не создаются. Ячейка другой формы (`| off |`) — и «не описано», и «несуществующее».
  Форма ячейки записана в норму `11-domain.md`.
- Фикстуры сломанных enum — в тесте, не в `test/support` (иначе их видит самопроверка `otp_app: :core`).
  `Code.fetch_docs/1` читает документацию из `.beam` на пути кода, а `mix test` собирает с `docs: false`: фикстуры
  собираются `Code.compile_string/1` с временно включённой опцией `docs` во временный каталог, модуль —
  `async: false`, уборка (модули, путь, каталог) — в `on_exit`.
- Самопроверка — `Core.EnumDocsTest` на `otp_app: :core` (4 enum `lib` + `Core.ViewFixture.Status`); мутация
  (убрана строка `:failed` у `Core.Outbox.Status`) валит тест «каждое значение описано».
- Не сделано: `async!/1` — третья дословная копия (`EventCompatCase`, `ConstraintErrorsCase`, `DocsCase`);
  вынос в `Helper.Opts.boolean!/3` — отдельный рефакторинг.

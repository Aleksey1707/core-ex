## Agent Brief

**Category:** enhancement
**Summary:** опция `subscribe:` у `Core.PubSub.MqSubscriberReliable` — подписка при старте без
процесса-bootstrap в приложении

**Current behavior:**
Подписчик стартует неподписанным, `subscribe/3` зовётся снаружи. Подписка только переключает состояние и ставит
таймер опроса — во внешние системы не ходит; отказать может лишь `:already_subscribed`. Приложения пишут
процесс-bootstrap: четыре копии у двух потребителей, три семантики отказа (нормальный выход с `Logger.error`,
`{:stop, error}` на любой ошибке включая `:already_subscribed`, sleep и `exit`). Во всех копиях данные подписки —
`nil`. Норма порядка подъёма — `docs/rules/app/17-otp-concurrency.md`, «Дерево процессов».

**Desired behavior:**
- `subscribe:` — необязательная опция `start_link`, boolean, по умолчанию `false`: поведение текущих потребителей
  не меняется (при включённой опции их внешний `subscribe/3` получил бы `:already_subscribed`);
- `subscribe_data:` — необязательная, любой терм, по умолчанию `nil`; значение уходит в `on_message` так же, как
  `data` из `subscribe/3`. Без `subscribe: true` не задаётся;
- при `subscribe: true` процесс подписан сразу после `init/1`, первый опрос — через `poll_interval_ms`, как после
  `subscribe/3`; `handle_continue` и backoff не нужны — подписка не ходит во внешние системы
  (`docs/rules/17-otp-concurrency.md`, «`init/1`»);
- опции разбираются через `Core.Helper.StartOpts` — поэтому после тикета 12.

**Key interfaces:**
- `Core.PubSub.MqSubscriberReliable.start_link/1` — опции `subscribe:`, `subscribe_data:`; `@doc` дополнен
- `subscribe/3`, `unsubscribe/2` — без изменений

**Acceptance criteria:**
- [x] тест: `subscribe: true` — сообщения обрабатываются без вызова `subscribe/3`, `subscribe_data` доходит до
      `on_message`; повторный `subscribe/3` → `:already_subscribed`
- [x] тест: по умолчанию процесс не подписан; недопустимое значение `subscribe:` роняет старт
- [x] `docs/rules/app/17-otp-concurrency.md`, «Дерево процессов» — процесс-bootstrap заменён опцией
- [x] CHANGELOG: дополнить существующий пункт «Не выпущено» о подписке подписчика ребёнком дерева, а не
      заводить новый
- [x] `make` проходит

**Out of scope:**
- включение подписки по умолчанию
- переподписка после `unsubscribe/2`
- backoff подключения к брокеру (он у `Core.Mq.Stream.Reader`)

## Реализация

- Тикет 12 не сделан: нужная форма уже была — `StartOpts.boolean!/4` разбирает `subscribe:`, отказ на
  `subscribe_data:` — `StartOpts.raise_invalid!/4`. Остальные опции подписчика по-прежнему без `StartOpts`, запись
  `DEBT.md` остаётся тикету 12; ему — добавить `subscribe` / `subscribe_data` в список известных опций.
- «Без `subscribe: true` не задаётся» прочитано строго: `subscribe_data:` при `subscribe: false` (включая явные
  `subscribe: false, subscribe_data: nil`) — `ArgumentError` на старте, а не молчаливое игнорирование.
- `init/1` возвращает state через `subscribe_on_start!/2`; подписка — общий `mark_subscribed/2` с
  `handle_call({:subscribe, _})`: state и `schedule` на `poll_interval_ms`, в брокер не ходит (`17-otp-concurrency.md`,
  «`init/1`»).
- Тесты (describe «подписка при старте»): тик таймера после `init/1` доставляет сообщение с `subscribe_data` без
  `subscribe/3`, повтор → `:already_subscribed`; по умолчанию `run_once` → `:not_subscribed`; `subscribe: "yes"` и
  `subscribe_data:` без флага — `ArgumentError` на старте. В тестах вынесен `sub_opts/3`.
- `app/17`, «Дерево процессов»: третий ребёнок-подписка и нормы его отказа заменены MUST на опцию; пример —
  `Keyword.put/3`, а не `++` (`Keyword.get` берёт первое вхождение). CHANGELOG — дополнен подпункт о поддереве
  подписчиков в «Новом» (было → стало).

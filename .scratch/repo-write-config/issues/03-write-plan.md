# 03: Данные записи пачки событий — структура

**What to build:** данные, которыми отличаются write-builder'ы хранилища событий, задаются структурой:
резервы ключа и ошибка занятого ключа идут вместе, а опечатка в ключе — ошибка сборки, а не тихий
пропуск резервов. Порядок шагов записи и исходы отказа не меняются.

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] `Core.Es.Store.Write.append/4` принимает структуру плана; оба write-builder'а и тестовая фикстура собирают её, а не map.
- [x] Пустые объявления ключей — шаг резервов пропускается; непустые — резервы ставятся и отказ занятого ключа отдаётся прежним кодом и detail.
- [x] Непрерывность потока остаётся свойством только event-sourced builder'а; у state-stored её нет, и это видно по собранному плану.
- [x] Неизвестный ключ в плане — ошибка компиляции сборки builder'а; клауза «ключа нет в map» больше не нужна.
- [x] Тесты записи пачки событий (события, outbox, резервы ключей, `continuous?: true`) зелёные.
- [x] CHANGELOG: `append/4` принимает структуру плана (правка для того, кто собирал map).
- [x] `make` зелёный.

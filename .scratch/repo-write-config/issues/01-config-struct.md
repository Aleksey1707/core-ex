# 01: Конфигурация репозитория — структура

**What to build:** `@pg`, который макрос репозитория кладёт в модуль-потребитель, — типизированная
структура вместо map: одна форма для обоих write-builder'ов и для кастомных методов репозитория.
Поведение записи, головы behaviour и исходы не меняются.

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] `@pg` в модуле-потребителе — `%Core.Repo.Pg.Config{}` с обязательными полями; значения-выражения по-прежнему вычисляются при компиляции модуля.
- [x] Головы функций `Repo.Pg` матчат конфигурацию по ключам, спеки называют `Config.t()`; кастомный метод, получающий `@pg` и вызывающий `Repo.Pg.get_by/6`, работает без правок.
- [x] `StateStored` читает ту же структуру и не заводит своей формы конфигурации.
- [x] Фикстуры тестов, строившие конфигурацию руками, переведены на структуру; тесты `Repo.Pg` зелёные.
- [x] CHANGELOG: `@pg` — структура (правка `Map.put(@pg, …)` → `%{@pg | …}`); новый модуль конфигурации.
- [x] `make` зелёный.

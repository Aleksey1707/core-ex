# 02: Одна точка переопределения записи

**What to build:** `save` перестаёт быть разрезанным хуком: выбор «insert или update» живёт в одном
месте и вызывает **модульные** `insert`/`update`, а `StateStored` переопределяет только точку выбора,
оборачивая её транзакцией. Забытое переопределение больше не пишет строку мимо детей и событий, а
невозможный набор методов ломает сборку.

**Blocked by:** 01 (конфигурация репозитория — структура).

**Status:** resolved

- [x] Модуль-фикстура, переопределившая только `insert`/`update`, сохраняется через `save` и получает детей, события и записи outbox — без ручного переопределения `save`.
- [x] `StateStored` не переопределяет `save` и не держит второй копии решения «строка уже есть»; транзакция вокруг выбора сохраняется, эталон в `Repo.Sc` кладётся после commit, возвращается входной агрегат с очищенными событиями.
- [x] Внешний вызов `Repo.Pg.save/4` вне макроса сохраняет прежнюю семантику выбора между generic `insert`/`update`.
- [x] `save` остаётся переопределяемым: модуль, переопределивший его по прежней документации, продолжает работать.
- [x] `only:` с `save`, но без `insert` или `update`, — отказ сборки с текстом про `only:`; набор `[:get, :save]` из тестов дополнен.
- [x] Свод `13-repos.md` и `@moduledoc` обоих builder'ов называют точку переопределения и требование к набору методов.
- [x] CHANGELOG: изменение контракта макросов (требование к `only:`), новая точка переопределения.
- [x] `make` зелёный, `make consumer-check` проходит.

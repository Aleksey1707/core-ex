# 02: Канонический режим разбора и критерий исключения

Type: grilling
Status: resolved

Blocked by: 01

## Question

Какой режим разбора опций `use` канонический и по какому критерию допускается отступление?

Гипотеза для проверки: граница проходит по ключам и значениям. Ключи (обязательные / неизвестные) проверяются
всегда при раскрытии: они литеральны даже у `name: first_line(@moduledoc)`. Значение-литерал проверяется при
раскрытии, значение-выражение уходит AST-ом в тело и проверяется там валидатором.

Решить:

- критерий: что считается «значением-выражением» (не литерал после `Macro.expand_literals`? ссылка на атрибут?)
  и законно ли выражение у опции-модуля;
- форма валидатора тела: публичная `@doc false` функция builder'а, функция `Core.Helper.Opts`, атрибут с вызовом;
- остаётся ли `quote bind_quoted` законным где-нибудь, и где;
- что из этого правило `20-agreements.md`, а что — ADR.

## Answer

Режим выбирается **по опции**: builder заранее объявляет каждую опцию литералом или выражением. От формы вызова режим
не зависит, путь у опции один.

- **Ключи** — всегда при раскрытии: обязательные и неизвестные. Список опций MUST быть литеральным keyword-AST
  (вложенные `use` библиотеки — `unquote(pg_opts)`, `use_prim` — ему удовлетворяют). Список выражением целиком —
  `CompileError` «ожидается литеральный keyword»; тесты, где так, переписываются.
- **Литерал** — значение, для которого после `Macro.expand_literals` и раскрытия сигилов `Macro.quoted_literal?/1`
  истинно. Проверено на Elixir 1.20.4: `~w()a`, `~D[]`, `~U[]` литеральны после `Macro.expand`, но не после
  `expand_literals`. `~r//`, захват `&Mod.fun/n`, атрибут и вызов функции — выражения.
- **Захват — выражение**. Проверка формы при раскрытии потребовала бы `Code.ensure_compiled` модуля захвата
  (compile-зависимость), а `&__MODULE__.fun/1` указывает на модуль, который ещё собирается. Поэтому в теле —
  `is_function(f, n)`.
- **Опция-литерал** проверяется при раскрытии; нелитерал на её месте — `CompileError` «ожидается литерал».
- **Опция-модуль** (`event:`, `repo:`, `codec:`, `errors:`, `entity:` …) — только литерал (`module!` при раскрытии).
  Список модулей вызовом функции (`plugins: <App>.Codec.plugins()`) — это опция-выражение типа «список», модули
  проверяются в теле.
- **Опция-выражение** уходит AST-ом в атрибут тела через публичный `@doc false` валидатор builder'а `<key>!/n`:
  `@es_tag_by_mod Builder.tags!(unquote(ast))`. Примитивные проверки значения (строка, атом, `is_function/2`) —
  value-варианты в `Core.Helper.Opts`.
- **Объявление** — атрибут `@expression_keys` рядом с `@required_keys` / `@optional_keys`. Новая функция
  `Core.Helper.Opts` (рабочее имя `literal!/3`) при раскрытии требует литерал у всех прочих опций. `@moduledoc`
  builder'а называет опции-выражения.
- **`quote bind_quoted`** в `__using__` библиотеки — MUST NOT, исключений нет. `DAO` пересылает открытый список
  через `unquote(opts)`, ему `bind_quoted` не нужен.

Какая опция — выражение. Нелитерал должен быть санкционирован контрактом (свод `app/**`, `@moduledoc` builder'а)
или встречаться у реальных вызовов в `lib/` / `test/` / `fixtures/consumer/`. По `inventory.md` выражениями станут:

- `Es.Event.Codec`: `tags:`, `upcasts:`;
- `Enum`, `Prim.*`: `name:`;
- `Prim.*`: `cast:` / `mutate:` / `validate:`, `re:`, `max_len:`, `namespace:`;
- `Codec.Facade`: `plugins:`;
- `Codec.Plugin`: `types:`, `union:`;
- `Repo.Pg`: `query:`, `to_entity:` / `to_model:` / `to_view:` / `to_id:` / `default_filters:`;
- `Labels.Text`: `with:`;
- `Labels.Fields`: `fields:`, `value:`;
- `Web.Event`: `user_ref:`.

Остальные опции — литералы, в том числе опции, которые сейчас уходят в тело при литеральных вызовах:
`Es.Projection` `name:` / `events:` / `version:` / `personal:` и `Es.Event.TagsCase` `except_*`. Если потребитель
передаёт им атрибут, это ломка неописанного использования: она допустима и идёт в CHANGELOG пунктом «Ломающие
изменения контракта».

Где что записано:

- `20-agreements.md` — нормы: ключи при раскрытии, литерал / выражение по объявлению, определение литерала,
  валидатор `<key>!`, опция-модуль только литерал, `bind_quoted` MUST NOT;
- ADR — почему: отвергнуты «всё при раскрытии» (ломает каждый Prim) и «всё в теле» (поздние ошибки, проходные
  функции ключей); режим по опции, а не по вызову (у режима «по вызову» два пути и генерируемый код зависит от
  вызова); захват — выражение; критерий выражения и ломка неописанного использования;
- перечня опций-выражений по builder'ам нет ни в правиле, ни в ADR: он живёт в `@expression_keys` и
  `@moduledoc`.

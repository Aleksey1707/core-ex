# 09: Текст правила, форма ADR и спека

Type: grilling
Status: resolved

Blocked by: 08

## Question

Как оформить решения карты в три документа назначения и записать их?

- Новый ADR «Разбор опций `use`»: разделы и состав «почему» по ответам тикетов 02–07 (что отвергнуто и почему),
  связь с ADR-0014 и ADR-0084.
- `docs/rules/20-agreements.md`: замена пункта «Параметры `__using__`… проверка на этапе компиляции» в «Стиль
  кодирования» — раздел или подраздел, текст норм с модальностью, строка «Проверяется» (`CredoChecks.UseOpts`),
  ссылка на ADR; `make rules-check`.
- `.scratch/use-opts-parsing/spec.md` по срезам из «Нарезка срезов перевода и их порядок», готовый к `/to-tickets`.

Запись трёх документов — последний шаг карты.

## Comments

- Из «Нарезка срезов перевода и их порядок»: спека берёт таблицу срезов, зависимости от срезов aggregate-wiring и
  пять критериев приёмки из его ответа. CHANGELOG — один накопительный пункт «Ломающие изменения контракта» с таблицей
  «builder → опции-выражения», его заводит первый ломающий срез. В `docs/rules/DEBT.md` запись не идёт: расхождение
  свода и кода на время перевода — список `excluded` храповика.

## Answer

Записано 2026-10-24.

- `docs/adr/0085-use-opts-parsing.md` — «Разбор опций `use`: режим выбирается по опции». Разделы: контекст по
  инвентарю, рассмотренные варианты (режим разбора, захват, композиция ключей, проверки по другим модулям, чем
  проверять), решение, цена. Тексты ошибок занимают одну строку со ссылкой на свод. Метки «Уточнён ADR-0085» в
  ADR-0014 и ADR-0084 нет: их решения не меняются, связь описана в «Контексте».
- `.scratch/use-opts-parsing/spec.md` — по шаблону спеки aggregate-wiring. Implementation Decisions нарезаны по
  десяти срезам. Дальше идут «Порядок работ» и «Документация, свод, CHANGELOG»: дословный текст подраздела свода,
  итоговый пункт CHANGELOG, строка «Версии библиотеки». Ветка прототипа — в Further Notes.
- `docs/rules/20-agreements.md` картой **не правится**. Норма называет `Helper.Opts.expand!` / `literal!` /
  `reject!/2` и строку «Проверяется: `CredoChecks.UseOpts`», а их до S1 нет. Подраздел `### Опции `use`` вносит S1
  тем же коммитом, что API и проверку; его текст лежит в спеке. Форма черновика проверена `scripts/rules_lint.exs`
  на копии свода.
- `CONTEXT.md` без записей: «опция-литерал» и «опция-выражение» — термины свода.

Уточнения, которых не было в тикетах:

- **Раздел CHANGELOG** — «Изменения контракта макросов», а не «Ломающие изменения контракта», как было записано в
  тикете «Нарезка срезов перевода и их порядок». Опции `use` по `CLAUDE.md` идут в этот раздел, там же лежат пункты
  «Не выпущено» того же рода. Ломка от этого не исчезает: пункт несёт «было → стало».
- **«Версия библиотеки»** (`docs/rules/app/00-index.md`) получает одну строку. Её вносит первый ломающий срез тем же
  коммитом, что пункт CHANGELOG.
- **Ломают контракт** срезы Prim, Labels, Тело-мелкие, Codec, Repo.Pg, Es-событие, Es-кодек и Проекция. S1 и
  Es-репозиторий не ломают: их значения уже проверялись при раскрытии.
- **`Repo.Pg.StateStored` `own_keys/0`** (снаружи не читается) становится атрибутом в срезе Repo.Pg.
- **`Core.Repo`** держит `bind_quoted` только в комментарии: AST-проверка его не видит, S1 правит лишь пролог.

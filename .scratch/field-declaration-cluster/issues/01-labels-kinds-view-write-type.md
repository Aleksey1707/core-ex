# 01: Подписи: замкнуть виды и дать View тип записи

**What to build:** объявление подписей (`use Core.Labels.Fields`) у декларативного хоста с видом, который сведения не интерпретируют (`view:`, `form:`, `jsonb:`), отвергается на сборке с текстом, называющим хост, поле и вид; скрытое поле (`:hidden`) с таким видом сборку не ломает. Новый вид поля без клаузы в обходе значений и в виде значения подписей ломает сборку библиотеки (храповик полноты клауз). `Core.View` порождает тип записи, совпадающий с типом чтения: поле `entity: View` в спеке полей даёт тип записи, а не ссылку на несуществующий тип. Маркер хоста не вводится: allowlist грамматики подписей уже определяет, что подписи умеют интерпретировать. Wire сведений и публичные поверхности не меняются. Спека — `.scratch/field-declaration-cluster/spec.md`, «Тикет 01» и «Testing Decisions».

**Blocked by:** None (can start immediately)

- [ ] Новый вид поля без клаузы в обходе значений и в виде значения подписей ломает сборку библиотеки (храповик полноты клауз, механизм `Core.Field.Spec.check_kinds!`)

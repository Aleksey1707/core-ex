# 01: Подписи: замкнуть виды и дать View тип записи

**What to build:** объявление подписей (`use Core.Labels.Fields`) у декларативного хоста с видом, который сведения не интерпретируют (`view:`, `form:`, `jsonb:`), отвергается на сборке с текстом, называющим хост, поле и вид; скрытое поле (`:hidden`) с таким видом сборку не ломает. Новый вид поля без клаузы в обходе значений и в виде значения подписей ломает сборку библиотеки (храповик полноты клауз). `Core.View` порождает тип записи, совпадающий с типом чтения: поле `entity: View` в спеке полей даёт тип записи, а не ссылку на несуществующий тип. Маркер хоста не вводится: allowlist грамматики подписей уже определяет, что подписи умеют интерпретировать. Wire сведений и публичные поверхности не меняются. Спека — `.scratch/field-declaration-cluster/spec.md`, «Тикет 01» и «Testing Decisions».

## CHANGELOG

### Ломающие изменения контракта

- Подписи (`use Core.Labels.Fields`) у `Core.View` читают декларацию представления: достаточно
  `labels:`, а `fields:` рядом с `use Core.View` — `CompileError` «спека поля и у декларативного
  типа». Раньше единственным способом подписать View был `fields:` со спекой каждого видимого
  поля. Было: `use Core.Labels.Fields, fields: […], labels: […]` → стало: `use Core.Labels.Fields,
  labels: […]`, скрытое поле — `:hidden`.
- Вид поля, который сведения не интерпретируют (`view:`, `form:`, `jsonb:` на любой глубине), у
  видимого поля декларативного хоста — `CompileError` при `use`; текст называет хост, поле и
  вид. Скрытое поле (`:hidden`) с таким видом законно. Было: такой вид мог дойти до сведений и
  уронить страницу событий `FunctionClauseError` на первом значении → стало: отказ сборки;
  правка — снять объявление подписей с View или скрыть поле.

### Новое

- `Core.View` порождает `@type write_t :: t()`: тип записи read-модели совпадает с типом чтения —
  ПДн-мест у View нет. Поле `entity: View` в спеке полей получает тип записи
  `View.write_t()`, а не ссылку на несуществующий тип.

## Результат

- `Core.Labels.Fields`: в `__after_compile__` у декларативного хоста видимые поля проверяются
  против allowlist'а грамматики подписей; `view:` / `form:` / `jsonb:` (в том числе вложенные в
  `list:` / `set:` / `map:`) — `CompileError` через `Core.Field.kind_key!/3`, текст как у ручного
  пути. `:hidden` в `specs/1` не попадает и остаётся законным.
- `Core.View`: `@core_fields` (для `Core.Field.introspect/1` в теле модуля — иначе путь
  интроспекции у View не существовал) ставится после вложенного `Codec`; `@type write_t :: t()`.
- Храповик `Core.Field.Spec.check_kinds!` на `Core.Labels.Walk` (клаузы `data/3`) и
  `Core.Labels.Details` (клаузы `shape/1`); виды — литеральным списком.
- Тесты: `test/core/labels/fields_test.exs` (4 негативных и 2 позитивных случая),
  `test/core/view_test.exs` (`write_t` = `t()`), `test/core/field_test.exs` (`entity: View`).
- `docs/rules/11-domain.md` (виды подписей, `@type write_t` View) и `docs/rules/13-repos.md`
  (состав порождаемых типов View) дополнены нормой.
- `make` зелёный. Заметки — `notes/01.md`.

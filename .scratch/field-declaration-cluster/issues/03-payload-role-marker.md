# 03: Нагрузка: роль объявляет builder

**What to build:** builder нагрузки по полям и builder изменения «было → стало» объявляют роль нагрузки; деривация кодека событий и проверка `subject:` читают объявление, а не совпадение арности конструктора с числом полей. Структура по полям с ручным `new/N` в размер декларации кодируется своим плагином и получает проверку субъекта; однополевой View не признаётся нагрузкой по полям; вложенная в событие нагрузка по-прежнему узнаётся при сборке, когда её модуль ещё открыт. Wire событий не меняется. ADR-0097 не правится: снятие записанной цены фиксируется CHANGELOG. Спека — `.scratch/field-declaration-cluster/spec.md`, «Тикет 03» и «Testing Decisions».

**Blocked by:** None (can start immediately; параллелен 01)

## CHANGELOG

### Ломающие изменения контракта

- **Нагрузка события классифицируется ролью builder'а, а не конструктором `new/N`.**
  Было: структура по полям с ручным `new/N` в размер декларации считалась нагрузкой по полям —
  кодек событий выводил её wire из полей, а не плагином типа; однополевое представление
  (`new/1` у `Core.View`) проходило ту же эвристику. Стало: роль объявляет builder
  (`use Core.Es.Event.Payload` и `use Core.Es.ValueChanged`); структура по полям с ручным `new/N`
  кодируется плагином своего типа, представление — своим dump-only плагином (нагрузкой события
  его объявлять нельзя: загрузка события с ним — `ArgumentError`). Wire событий, у которых
  нагрузку выводят builder'ы, не меняется. Проверка `subject: :aggregate_id` идёт по декларации
  нагрузки, а не по роли: не-UUID `aggregate_id` у нагрузки-сущности с плагином — `CompileError`
  (было — молча пропускалось). Правка потребителя: если структура по полям с ручным `new/N` была
  нагрузкой и ожидалась wire-форма по полям — объявить нагрузку через
  `use Core.Es.Event.Payload`; представление (`Core.View`) нагрузкой события не объявлять.

### Изменения контракта макросов

- **`__core_payload_role__/0` — порождаемая интроспекция роли нагрузки.**
  `use Core.Es.Event.Payload` и `use Core.Es.ValueChanged` объявляют атрибут роли и порождают
  `__core_payload_role__/0` (`:fields`); `Core.Es.Event.Payload.wire_payload?/1` читает роль, а не
  арность `new/N`. Роль — внутренний контракт классификации нагрузки: читать её в приложении не
  нужно. Модуль нагрузки MAY быть ещё открыт, когда роль читают на сборке; чтение зеркалит
  `Core.Field.introspect/1` (собранная функция, иначе атрибут собирающегося модуля).

## Результат

Роль объявлена builder'ами `Core.Es.Event.Payload` и `Core.Es.ValueChanged`; `wire_payload?/1`
читает `__core_payload_role__/0` (с откатом на атрибут открытого модуля). Проверка `subject:`
в `use Core.Es.Event` переведена с роли на декларацию нагрузки — структура по полям с ручным
`new/N` сохраняет отказ при не-UUID `aggregate_id`. Новые фикстуры
`Core.PayloadRoleFixture`: структура по полям с ручным `new/2` и плагином (default поля применяет
загрузка плагина), однополевой `Core.View` (дамп плагином, load — отказ dump-only), вложенная
нагрузка (маркер читается при сборке кодека). Wire событий не изменился, golden-фикстуры не
затронуты; запись цены в `docs/rules/DEBT.md` снята. Заметки — `.scratch/field-declaration-cluster/notes/03.md`.

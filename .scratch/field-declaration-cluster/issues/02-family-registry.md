# 02: Семейство: один реестр состава

**What to build:** обход объявлений читает состав семейства из реестра семейства первым; семейство без реестра сохраняет сегодняшнее поведение — варианты находятся через типы Codec-плагина. Семейство с реестром проверяется ратчетом полноты и когда его плагин лежит в другом приложении; у смешанного плагина (`types:` + `union:`) чужие декларативные типы больше не получают владельца и поле варианта, а пробелы атрибутируются месту объявления; `unknown_family` — только когда нет ни реестра, ни плагина. Место семейства порождается на каждое видимое поле `union:`. Недостижимая ветка разбора состава по типам плагина в проекции типа записи удаляется; семейство без реестра по-прежнему проецируется в `struct()`. Публичный API семейства (`variant/1`, `types/0`) не меняется. Спека — `.scratch/field-declaration-cluster/spec.md`, «Тикет 02» и «Testing Decisions».

## CHANGELOG

### Ломающие изменения контракта

- Ратчет полноты (`Core.Labels.CompletenessCase`) читает состав семейства из его реестра
  (`use Core.Union`) независимо от Codec-плагина: семейство с реестром проверяется и когда плагин
  лежит в другом приложении. Было: поле `union:` без плагина среди модулей `otp_app:` — провал
  «семейство неизвестно», даже если варианты объявлены в реестре → стало: провал «семейство
  неизвестно» только когда нет ни реестра, ни плагина. Правка кода потребителя не требуется;
  ложный провал уходит.
- Варианты семейства — только из реестра: у смешанного Codec-плагина (`types:` рядом с `union:`)
  чужие декларативные типы больше не считаются вариантами и не получают владельца и поле варианта.
  Было: пробел необъявленного типа из `types:` указывал на поле `union:` → стало: пробел
  атрибутируется полю, где тип объявлен, а тип, не объявленный ни в одной нагрузке, ратчетом не
  проверяется. Текст провала прежний: владелец, поле и модуль без объявления.

## Результат

- `Core.Labels.Walk.declarations/1`: на каждое видимое поле `union:` — место `{:family, owner,
  field, family}`; состав берётся из `Core.Field.union_variants/1` (реестр), при пустом реестре —
  из `__codec_types__/0` плагина семейства среди модулей приложения. Обход не теряет прежний путь
  через плагин для семейства без реестра.
- `Core.Labels.CompletenessCase.check_variants/1`: `unknown_family` — нет реестра И нет плагина
  среди модулей; `diverged` — по реестру каждого достигнутого семейства. Проба «плагин →
  семейство → реестр» удалена. Moduledoc и `@type variants` переписаны.
- `Core.Field.union_write_type/1`: мёртвая ветка `types/0` (`plugin_write_variants/1`,
  `variant_kind/1`) удалена; семейство без реестра — `struct()`; `Union.variant/1` и `types/0` не
  тронуты.
- Фикстуры и тесты: `test/support/labels_family_fixture.ex`,
  `test/core/labels/completeness_case_family_test.exs`; `test/core/field_test.exs` — тип записи
  регистрового семейства (`Core.UnionFixture.Shape`) и семейства без реестра.
- `docs/rules/11-domain.md`, «Ратчет полноты»: норма о реестре, смешанном плагине и условии
  `unknown_family`; в «Проверяется» добавлен новый тест-файл.
- `make` зелёный (`MIX_TEST_PARTITION=1 make DOCKER=true`). Заметки — `notes/02.md`.

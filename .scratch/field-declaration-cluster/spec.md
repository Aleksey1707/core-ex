# Кластер декларации полей: один реестр, замкнутые виды, роль нагрузки, одно описание

Status: ready-for-agent

Направление: view / struct / union / field / labels / es_event — кластер, где одну декларацию
полей потребляют пять хостов. Предшествовал независимый архитектурный разбор (HTML-отчёт
2026-11-19) и сплошная сверка его кандидатов с кодом, ADR и историей; спека фиксирует
исправленные формы решений. Термины — `CONTEXT.md`: «Спека полей», «Структура по полям»,
«Декларативный тип», «Тип чтения», «Тип записи», «Семейство (union)», «Адрес варианта»,
«Сведения события», «Словарь ссылок», «Событие страницы событий», «ПДн-место»,
«Поле-множество», «Поле-словарь». Решения — ADR-0063, ADR-0090, ADR-0097, ADR-0098.

## Problem Statement

Мейнтейнер библиотеки и разработчик приложения-потребителя платят за то, что знание об одной
декларации полей продублировано в интерпретаторах пяти хостов, и ответы расходятся:

- Ратчет полноты подписей и обход объявлений отвечают на вопрос «что такое вариант семейства»
  по-разному: ратчет читает реестр семейства, обход идёт через типы Codec-плагина. У смешанного
  плагина (`types:` + `union:` с реестром) чужие декларативные типы получают владельца и поле
  варианта: пробелы ратчета указывают не на то место, где тип объявлен.
- Подписи принимают у декларативного хоста виды, которых не понимает ни один интерпретатор
  сведений: View проецирует в общий IR свои виды (`view:`, `form:`, `jsonb:`), объявление
  подписей на View собирается, а страница событий падает `FunctionClauseError` на первом
  значении. Дыра латентная: сборка молчит, рантайм падает.
- View не порождает тип записи, хотя общий IR обещает его у каждого декларативного типа:
  поле `entity: View` проходит грамматику, и тип записи структуры ссылается на несуществующий
  тип. Буква ADR-0097 («каждый декларативный тип порождает тип чтения и тип записи») нарушена.
- Роль нагрузки события угадывается по арности конструктора: структура по полям с ручным
  `new/N` в размер декларации считается нагрузкой по полям — кодек выводит клаузы по полям
  вместо плагина, а проверка `subject: :aggregate_id` молча пропускается. Однополевой View
  (у View есть `new/1`) проходит ту же эвристику. Цена записана в «Последствиях» ADR-0097.
- Сведения и словарь ссылок независимо интерпретируют одни и те же узлы обхода: новый вид
  значения оплачивается правками в нескольких модулях. Цена измерена: лист варианта-Prim
  (ADR-0098) стоил трёх коммитов и правок в четырёх модулях библиотеки. Инвариант «словарь не
  шире сведений» держится прозой и тестами, а не конструкцией.

## Solution

Две волны. Волна 1 — три малые правки, закрывающие подтверждённые дыры:

1. Виды подписей замыкаются allowlist'ом грамматики на пути интроспекции и храповиком полноты
   клауз на обходе и виде значения; View порождает тип записи. Маркер хоста не вводится.
2. Состав семейства читается из реестра первым; плагин остаётся fallback'ом для семейств без
   реестра. Ратчет проверяет семейства по местам обхода, а не пробой плагинов. Мёртвая ветка
   разбора состава по типам плагина удаляется.
3. Роль нагрузки объявляет builder маркером; кодек и событие читают объявление, а не арность
   конструктора.

Волна 2 — один проход описания значения: сведения и словарь ссылок становятся проекциями
описанного узла, правило вида Prim вызывается на лист один раз. Протокол установки декларации
(кандидат №3 отчёта) отложен: конвейер разбора уже общий, оставшиеся различия хостов
существенны, макро-риск средний.

Публичная wire-форма сведений, API события страницы событий и OpenAPI-схемы не меняются.

## Implementation Decisions

### Волна и порядок

- Четыре тикета: 01 — виды подписей и тип записи View; 02 — реестр семейства; 03 — маркер
  роли нагрузки; 04 — одно описание значения. Порядок: 01 ∥ 03 (файлы не пересекаются),
  затем 02 (пересечение с 01 в модуле обхода), затем 04. Волна 1 — по
  `docs/agents/parallel-implement.md` (субагенты в worktree, CHANGELOG волны).
- Кандидат №3 (протокол установки декларации, маркер хоста) отложен. Конвейер разбора уже
  общий (`declare!` = разбор → нормализация → ПДн-обёртка); структура по полям использует те
  же шаги с инъекцией значения по умолчанию между разбором и нормализацией — это
  документированный шов, а не случайность. Различия View (свой парсер, свой язык спеки,
  голые значения) и момент вычисления декларации у `ValueChanged` (при раскрытии макроса,
  а не в теле модуля) существенны. Возврат — только если тикеты 01/02/04 снова упрутся в шов
  установки.

### Тикет 01 — виды подписей и тип записи View

- Валидация видов на пути интроспекции в `Core.Labels.Fields`: спека, пришедшая из
  `__core_fields__/0` декларативного хоста, проверяется против allowlist'а грамматики
  подписей плюс вид `text:`. Неинтерпретируемый вид (`view:`, `form:`, `jsonb:`) —
  `CompileError` при `use` с именем хоста, поля и вида. Скрытые поля освобождены: в обход
  они не попадают. Ручной путь `fields:` уже валидируется грамматикой — оба пути дают один
  отказ.
- Храповик полноты `Core.Field.Spec.check_kinds!` ставится на обход значений и на вид
  значения в сведениях — механизм существует и уже используется проекцией типов, адаптером
  видов плагина, спекой пере-дампа и проекциями View; подписи — единственные потребители без
  него. Новый вид без клаузы — ошибка сборки библиотеки.
- `Core.View` порождает `write_t()` как совпадающий с `t()`: ПДн-мест у View нет, проекция
  записи равна типу чтения. Это чинит ссылку на несуществующий тип у `entity: View` и
  приводит View к букве ADR-0097.
- Маркер хоста не вводится: ADR-0097 требует, чтобы читатели не проверяли, каким `use` собран
  модуль. Allowlist грамматики уже определяет, что подписи умеют интерпретировать; View с
  полями только общих видов подписи получает законно. Судьба моста View (нужны ли подписи на
  View как продукт) — отдельный вопрос, дыра закрывается отказом, а не достройкой видов.

### Тикет 02 — реестр семейства

- Обход объявлений читает состав семейства существующим протокольным читателем реестра в
  `Core.Field` (обход уже ссылается на `Core.Field` — новых рёбер сборки не нужно; обратная
  ссылка `Core.Field → Core.Union` замкнула бы граф сборки и запрещена). Реестр есть —
  варианты берутся из него: вариант-Prim — местом Prim, декларативный и ручной варианты —
  как сегодня. Реестра нет — сегодняшний путь через типы плагина; нет и плагина — место
  неизвестного семейства.
- Решение отчёта «нет реестра — семейство неизвестно» отвергнуто: оно ломает легальную
  конфигурацию — семейство без реестра с ручным `load/3` (например, семейство событий),
  чьи варианты сегодня находятся через плагин и ратчет проходит.
- Место семейства порождается на каждое видимое поле `union:`, а не только на неизвестное;
  остальные проверки ратчета его игнорируют. `check_variants` читает семейства из мест:
  `unknown_family` ⟺ нет реестра И нет плагина среди модулей приложения; расхождение спеки
  варианта с его декларацией проверяется по реестру для каждого достигнутого семейства.
  Проба плагинов в ратчете удаляется.
- Мёртвая ветка разбора состава по `types/0` в проекции типа записи удаляется: все
  генераторы `types/0` возвращают множество wire-тегов (строк), ветка всегда даёт пустой
  список. Поведение сохраняется: семейство без реестра — `struct()` в типе записи.
- Вид варианта для кодирования (`:prim` / `:domain` / `:manual`) и вид варианта для видимости
  (Prim / объявленный struct / прочее) — разные вопросы; они не сливаются. Проверка
  объявления полей у варианта остаётся: реестр её не заменяет (ADR-0098).
- Двухстрочный дубль протокольного чтения реестра в `Core.Field` и `Core.Union` остаётся: он
  документирован и обусловлен графом сборки.

### Тикет 03 — маркер роли нагрузки

- Builder'ы нагрузки по полям и изменения «было → стало» пишут маркер роли: атрибут модуля
  плюс порождаемая функция интроспекции. Атрибут обязателен: оба читателя маркера —
  compile-time, нагрузка MAY быть вложена в событие и ещё открыта; чтение зеркалирует
  интроспекцию полей (собранная функция, иначе атрибут собирающегося модуля).
- `wire_payload?/1` читает маркер вместо совпадения арности конструктора с числом полей.
  Деривация кодека и проверка субъекта не меняются — меняется только внутренность предиката.
  Moduledoc builder'а нагрузки переписывается: роль объявляет builder, а не конструктор.
- Снимаются оба класса ложных срабатываний: структура по полям с ручным `new/N` в размер
  декларации и однополевой View (`new/1` у View существует).
- ADR-0097 не правится: «Последствия» — запись решения на момент принятия. Снятие цены
  фиксируется CHANGELOG; при желании — ссылка на запись CHANGELOG из свода, без правки ADR.

### Тикет 04 — одно описание значения

- Новый внутренний модуль описания значения (термин закрепить в `CONTEXT.md`): один проход
  по объявленной видимой форме отдаёт узел с подписью, видом, значением и ссылками —
  правило вида Prim вызывается на лист один раз, ссылки и вид считаются вместе. Подмена
  спеки варианта семейства остаётся в обходе значений (ADR-0098). Канонический порядок
  поля-множества и поля-словаря — в описании.
- `Core.Labels.Details` — проекция описания; форма выхода не меняется, wire события страницы
  событий и OpenAPI-схемы не трогаются. `Core.Labels.Refs` — сбор ссылок с описанных узлов.
- Асимметрия словаря сохраняется сознательно: обход struct'ов без объявления полей и автора
  события остаётся отдельным путём словаря. Единый проход их не покрывает: сведения на
  необъявленном struct'е падают, и это поведение ратчета, а не дефект. «Словарь не шире
  сведений» становится свойством конструкции для объявленной части; защитный суперсет
  словаря документирован.
- Дублированный свитч по внутреннему тегу узла исчезает из сведений и словаря.

### CHANGELOG и документация

- Тикет 01: «Ломающие изменения контракта» — новый `CompileError` на неинтерпретируемый вид

  объявление подписей с View или скрыть поле); «Новое» — тип записи View.

## Testing Decisions

- Хороший тест проверяет внешнее поведение хоста на его публичной границе, а не внутренности:
  внутренние модули (обход, описание, предикат роли) напрямую не тестируются. Новых швов
  нет — каждый тикет проверяется существующим швом самого верхнего уровня.
- Тикет 01: шов — компиляция `use Core.Labels.Fields` (негативные тесты `CompileError`,
  образец — существующие тесты объявления подписей) и проекция типов `Core.Field` (образец —
  существующие тесты типов чтения и записи, случай `entity: View`). Храповик полноты клауз
  проверяется самой сборкой библиотеки (`make compile`), отдельный тест не нужен.
- Тикет 02: шов — `Core.Labels.CompletenessCase.check_*` (чистые функции «список модулей →
  `:ok | {:error, пробелы}`»; образец — существующие тесты ратчета на фикстурах подписей и
  сломанных фикстурах). Обход объявлений через ратчет, напрямую не тестируется. Тип записи
  семейства после удаления мёртвой ветки — существующие тесты типов `Core.Field`.
- Тикет 03: шов — кодек событий (сборка и round-trip dump/load; классификация видна по
  wire-форме и пути загрузки) и отказ `subject:` при `use Core.Es.Event`; образец —
  существующие тесты кодека событий и событий с вложенной нагрузкой. Предикат роли напрямую
  не тестируется (сегодня прямых тестов у него нет — так и остаётся).
- Тикет 04: шов — `Core.Labels.Details.build/1` и `Core.Labels.Refs.get/2`. Существующие
  тесты сведений и словаря ссылок остаются зелёными БЕЗ правки ожиданий — это контракт
  сохранности поведения. Новые тесты описания идут через те же входы на малых фикстурах;
  фикстура на 1558 строк не удаляется: объявления требуют модулей, выигрыш в том, что тесты
  узлов не требуют событий целиком.
- Новые фикстуры: смешанный плагин (`types:` + `union:` с реестром) — атрибуция пробела;
  семейство с реестром без локального плагина — варианты проверены, `unknown_family` нет;
  семейство без реестра с плагином — поведение прежних тестов не меняется; структура по
  полям с ручным `new/N` как нагрузка — деривация через плагин; однополевой View как
  нагрузка — не нагрузка по полям; вложенная нагрузка — маркер читается при сборке.
- Golden-фикстуры событий и тесты совместимости не затрагиваются: wire не меняется.
- Каждый тикет: полный `make` зелёный; `make compile-no-optional` после правок в зоне
  optional-клиентов не требуется (кластер их не касается), но общий прогон обязателен.

## Out of Scope

- Протокол установки декларации и маркер хоста (кандидат №3 отчёта) — отложен; возврат по
  спросу от тикетов 01/02/04.
- Реестр метаданных поля (`Core.Field.Meta`): выбран ADR-0097 сознательно; заглушки
  обработчиков — цена реестра, не дефект.
- Два смысла `default:` и разный `optional:` по режимам — принятая цена ADR-0090.
- Публичный API семейства (`variant/1`, `types/0`) — не удаляется, это API потребителей.
- Новые виды поля и новые wire-формы; поддержка подписями видов View (`view:`, `form:`,
  `jsonb:`) — продуктовый вопрос, отдельно; дыра закрывается отказом, а не достройкой.
- API события страницы событий и OpenAPI-схемы; форма выхода сведений.
- Правка ADR-0097 и других ADR: история решений не переписывается; снятие цены — CHANGELOG.
- Косметика (дубль перевода wire-ключа в атом, повторная проба хоста в `@after_compile__`) —
  может ехать попутно в тикетах 01/02, отдельной ценности и отдельного тикета нет.
- Объединение обхода значений и обхода объявлений в один модуль — обход уже унифицирован
  предшествовавшей волной (architecture-deepening, тикеты 06–08, resolved); эта спека — про
  интерпретацию, не про обход.

## Further Notes

- Поправки к HTML-отчёту, найденные независимой сверкой (важны для реализатора):
  - решение «только реестр» ломает семейства без реестра — легальная конфигурация с ручным
    `load/3`, покрыта фикстурой; правильная форма — реестр первым, плагин fallback'ом;
  - у View есть `new/1`: однополевой View — дополнительный класс ложных срабатываний
    эвристики арности, в отчёте не назван;
  - View не порождает тип записи: `entity: View` ссылается на несуществующий тип — найдено
    вне отчёта, чинится тикетом 01;

    lib» отчёта вводит в заблуждение);

# 04 — одно описание значения

## Что сделано

- Новый внутренний модуль `Core.Labels.Description` (`@moduledoc false`): один проход по видимой
  форме `Core.Labels.Walk.values/2` отдаёт узел `%{label, kind, entity, value, refs}` — подпись,
  вид, значение и ссылки поддерева. Правило вида Prim (`Core.Labels.Kind.of/1`) вызывается на лист
  **один раз**: из его ответа выходят `kind`, `entity`, значение и ссылка (резолвер + id владельца
  объявления).
- `Core.Labels.Details` — проекция описания: `Description.describe/1` → `Description.detail/1`.
  Собственного свитча по внутреннему тегу узла обхода (`data: :leaf | {:group, _} | …`) в сведениях
  больше нет; таблица видов и сортировка ушли в описание.
- `Core.Labels.Refs` — сбор ссылок с описанных узлов (`node.refs`); свитч по тегу узла удалён.
  Защитный суперсет сохранён и вынесен отдельным путём: struct без объявления полей (`raw/2`) и
  автор события (`by`, Prim-путь).
- Канонический порядок поля-множества (`Core.Prim.unwrap/1` / `compare/2`) и пар словаря — в
  описании (`order/2`, `before?/2`), проекция берёт готовый порядок.
- Ратчет полноты «вид спеки → вид значения» переехал из `Details` в `Description`
  (`@shape_kinds` + `check_kinds!`); в `Walk` остались ратчет обхода (`data/3`) и подмена спеки
  варианта семейства (`variant_spec/2`, ADR-0098) — не тронуты.
- `CONTEXT.md`: термин «Описание значения» (внутренний проход; сведения и словарь — проекции;
  суперсет словаря). `docs/rules/11-domain.md`: норма «сведения и словарь — проекции одного описания,
  свой разбор узлов словарь MUST NOT нести», ссылка ратчета видов переведена на
  `Core.Labels.Description`.
- `CHANGELOG.md` не менялся: внутреннее изменение, публичная форма сведений и wire не тронуты.

## Швы и тесты

- Публичные швы прежние: `Core.Labels.Details.build/1`, `Core.Labels.Refs.get/2`. Внутренний модуль
  напрямую не тестируется.
- `test/core/labels/details_test.exs` и `test/core/labels/refs_test.exs` не правились — зелёные
  (контракт сохранности поведения), фикстура на 1558 строк не тронута.
- Новые тесты `test/core/labels/description_test.exs` на малом наборе
  `test/support/labels_description_fixture.ex` (лист, группа с видимой и скрытой ссылкой,
  множество, словарь, свободная map'а, изменение): форма сведений по каждому виду, словарь ссылок
  (id `:id`/`text:` ссылкой не выходят, скрытое — нет), канонический порядок множества и пар
  словаря, изменение с ссылками обеих сторон. Кодек набору не нужен — тесты идут через
  `Details.build/1` и `Refs.get/2`.
- Тесты описания — характеризационные: поведение сведений и словаря не меняется, поэтому они
  зелёные и до рефакторинга; их ценность — пин совместного поведения вида и ссылки на малом наборе.

## Решения и допущения

1. **Узел несёт готовую форму сведения.** `value` контейнера/изменения — уже проекция детей
   (`detail/1`), поэтому проекция сведений не рекурсирует и не свитчится: `detail/1` — один свитч по
   виду узла, только в модуле описания. Ссылки агрегируются по поддереву в `refs` при сборке узла.
2. **Отложенный отказ листа.** `{:unkinded, leaf}` и `{:custom, leaf}` сохраняются видом узла, а
   `ArgumentError` поднимает `detail/1` — сведения падают ровно как раньше, а словарь на том же
   узле остаётся прежним (молча пропускает). Это сохраняет существующую асимметрию отказов, но
   означает: если сведения падают на таком листе, падает и страница (отказ приходит из сведений).
3. **Порядок — в описании.** `sorted`/`sorted_pairs` переехали из `Details` без изменения правил:
   Prim — `Core.Prim.unwrap/1`, скаляры — `compare/2`, пары словаря — по ключу.
4. **Refs Prim-путь остаётся.** Нагрузка-Prim и автор события в описание не входят: у них нет
   видимой формы-объявления, и это тот же защитный суперсет (задокументирован в moduledoc).

## Не сделано

- Теста «Kind.of вызывается один раз» нет: наблюдать это через публичные швы можно только
  побочным эффектом (счётчик в фикстуре), что противоречит «тесты описания — через
  `Details.build/1`/`Refs.get/2`». Инвариант держится конструкцией: `prim/3` — единственный вызов
  `Kind.of/1` на лист в описании, потребители вид не пересчитывают.
- Правок `app/**` нет: контракт приложения не менялся.

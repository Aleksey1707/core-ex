# 03: `expect!/2` теряет `%Error{}`

**Status:** ready-for-agent

**Current behavior:** `lib/core/result.ex:166` — `def expect!({:error, _reason}, message), do: raise(message)`.
Причина отбрасывается целиком: `Result.expect!({:error, %Error{code: :not_found, …}}, "нет агрегата")`
поднимает `RuntimeError` с одним текстом — без `ns`, `code`, `detail` и cause-цепочки.

**Why:** `12-errors.md` требует на bang-границе `raise Exc, error` (в т.ч. через `Result.unwrap!`), и соседний
`unwrap!/1` так и делает (`lib/core/result.ex:156`). `expect!/2` — вторая bang-дверь того же модуля, и она
ведёт мимо `Exc`: `%Error{}` уничтожается, и тот, кто ловит исключение, уже не прочитает ни `ns`, ни `code`,
ни `detail`, ни цепочку `parent` — в `%RuntimeError{}` их нет. У `unwrap!/1` структура доезжает в поле
`error` исключения `Exc`.

**Варианты на триаж:**

1. дописать причину в текст: `raise "#{message}: #{inspect(reason)}"` — дёшево, цепочка всё равно теряется;
2. `%Error{}` → `raise Exc, Error.wrap(…)` с `message` как внешним звеном, иной reason → `RuntimeError`
   (симметрично `unwrap!/1`);
3. удалить `expect!/2` — вызовов ноль (см. тикет 05).

- [x] выбран вариант — **3, удалить** (триаж 21.09.2026, см. `## Comments`)
- [ ] тест: `expect!/2` с `%Error{}` причиной — сейчас покрыт только `{:error, :e}` (тикет 06) — отпадает
- [ ] CHANGELOG «Ломающие изменения контракта», если меняется класс исключения

### Agent Brief

**Category:** bug
**Summary:** удалить `expect!/2` из `Core.Result` и `Core.Option` — вторая bang-дверь ведёт мимо `Exc`

**Current behavior:**
У `Core.Result` две bang-двери. `unwrap!/1` поднимает `%Error{}` через `Exc` (структура доезжает в
поле `error` исключения), `expect!/2` на любой причине поднимает голый текст вызывающего — `%Error{}`
теряется. У `Core.Option` есть функция-близнец с тем же дефектом. Ни одна из двух не вызывается ни в
библиотеке, ни в её фикстурах, ни в сводах, ни в приложениях-потребителях.

**Desired behavior:**
`expect!/2` в библиотеке не существует. Единственная bang-дверь `Core.Result` — `unwrap!/1`, и она ведёт
через `Exc`. Потребитель, которому нужен свой текст на bang-границе, получает в `CHANGELOG.md` рецепт
замены; никакая другая функция обоих модулей поведения не меняет.

**Key interfaces:**
- `Core.Result`: публичная `expect!/2` (`{:ok, a} | {:error, term()}, String.t() -> a`) удаляется целиком
  вместе со своими `@doc` / `@spec`;
- `Core.Option`: одноимённая `expect!/2` (`a | nil, String.t() -> a`) удаляется симметрично — модули-близнецы
  не расходятся по набору;
- замена на call site потребителя: причина `%Error{}` — `map_error/2` + `unwrap!/1`
  (`res |> Result.map_error(&Error.wrap(outer, &1)) |> Result.unwrap!()`), иная причина —
  `Result.unwrap_or_else(res, fn -> raise "…" end)`.

**Acceptance criteria:**

      valued-операций на unit-результате (`FunctionClauseError`), — сам набор остаётся зелёным;
- [ ] `CHANGELOG.md`: заведён раздел «Не выпущено» (сейчас верхний заголовок — выпуск `0.3.4`), в нём
      «Ломающие изменения контракта» одним пунктом на обе функции: что удалено, почему (bang-граница

# 05: Двенадцать функций без единого вызова — решение об объёме интерфейса

**Status:** ready-for-agent

**Вопрос:** оставлять ли в `Core.Result` функции, которых не зовёт ни библиотека, ни её фикстуры,
ни свод, ни `CHANGELOG.md`:

`map/2`, `map_or/3`, `map_or_else/3`, `and_/2`, `or_/2`, `tap/2`, `expect!/2`, `unwrap_or/2`,
`unwrap_or_else/2`, `ok?/1`, `error?/1`, `to_option/1` — 12 из 21.

Зовутся: `unwrap!/1` (23), `traverse/2` (3), `ok/0,1` и `error/1` и `map_error/2` (по 2),
`traverse_all/2`, `or_else/2`, `and_then/2` (по 1). Набор не менялся с заведения модуля (`cc413d6 core`).

**Почему это вопрос, а не дефект:** модуль публичен для потребителя, которого библиотека знать не имеет
права (`10-architecture.md`), — ноль вызовов внутри `lib/` неиспользуемость у потребителя не доказывает.

**Против нынешнего объёма:** интерфейс почти равен реализации — каждая функция в две строки, учить надо
21 имя. Два предиката сверх того спорят с собственным сводом: `20-agreements.md`,
«Паттерн-матчинг и арность» предпочитает pattern matching предикатам, а `ok?/1` / `error?/1` — это
`match?({:ok, _}, res)` под именем. `expect!/2` вдобавок дефектен (тикет 03).

**За:** полнота Rust-подобного набора предсказуема — потребитель не гадает, есть ли `map_or_else`;
удаление публичной функции — ломающее изменение контракта для всех потребителей разом.

**Варианты:** (а) оставить как есть и закрепить сводом — примеры на `map/2` и `and_/2` в `11-domain.md`;
(б) ужать до используемых плюс `map/2` и `and_then/2`, остальное удалить одним ломающим выпуском;
(в) ужать точечно — только `ok?/1` / `error?/1` / `expect!/2`, у которых есть свой аргумент против.

- [x] выбран вариант; при (б)/(в) — CHANGELOG «Ломающие изменения контракта» с «было → стало» на каждую
- [x] решение отражено в `11-domain.md`, «Result / Option» (сейчас там одна строка про комбинаторы)

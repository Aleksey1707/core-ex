# 02: Catch-all клозы `map_error/2` и `tap/2` расширяют домен

**Status:** ready-for-agent

**What to build:** развернуть хвостовые клозы в явные формы.

    # было
    def map_error({:error, reason}, fun), do: {:error, fun.(reason)}
    def map_error(ok, _fun), do: ok

    # стало
    def map_error({:error, reason}, fun), do: {:error, fun.(reason)}
    def map_error({:ok, _value} = ok, _fun), do: ok
    def map_error(:ok, _fun), do: :ok

То же для `tap/2` (`lib/core/result.ex:44`): клозы `{:error, _} = err` и `:ok` вместо `def tap(other, _fun), do: other`.

**Why:** `20-agreements.md`, «Домен функции и инференс типов»: недопустимый ввод не перечисляется в
заголовках, домен задают clauses. Сейчас `Result.map_error(:whatever, fun)` и `Result.tap(%Foo{}, fun)`
молча возвращают аргумент — компилятор вызов пропускает, `FunctionClauseError` не наступает никогда.
Остальные 19 функций модуля закрыты явными клозами, и тест «value ops reject unit at runtime»
(`test/core/result_test.exs:182`) закрепляет это как намеренное поведение; `map_error/2` и `tap/2` —
две дырки в том же модуле.

Спеки обеих функций уже описывают ровно три формы (`{:ok, a} | :ok | {:error, e}`) — правка приводит
рантайм к спеке, а не наоборот.

- [ ] клозы развёрнуты в обеих функциях
- [ ] тесты: чужой терм → `FunctionClauseError`; `tap/2` на `:ok` — сейчас не покрыт вовсе
      (решение триажа: тесты здесь, не в тикете 06)
- [ ] CHANGELOG: «Не выпущено» → «Ломающие изменения контракта» (решение триажа)

**Верификация (21.09.2026, Elixir 1.20.3).** Клоны обеих функций собраны в изолированной фикстуре
и скомпилированы в двух вариантах — с хвостовым catch-all и с развёрнутыми клозами:

| Вызов | Сейчас | После правки |
|---|---|---|
| компиляция `map_error(:whatever, f)` | предупреждений нет | `incompatible types given to …map_error/2`, ожидаемые формы `{:error, _}` / `{:ok, _}` / `:ok` |
| рантайм `map_error(:whatever, f)` | `:whatever` | `FunctionClauseError` |
| рантайм `tap(%{foo: 1}, f)` | `%{foo: 1}` | `FunctionClauseError` |
| `tap(:ok, f)` | `:ok`, эффекта нет | `:ok`, эффекта нет |

Заявленное тикетом поведение подтверждено полностью: домен расширен, компилятор вызов пропускает,
а после правки ловит его на compile time.

**Зона правки свободна.** Вызовов `map_error/2` и `tap/2` в `lib/`, `fixtures/`, `test/support/` нет
ни одного: только пример в `@doc` (`lib/core/result.ex:102`) и тот же пример в `docs/rules/12-errors.md:203`
— обе формы (`{:ok, [b]} | {:error, [Error.t()]}`) остаются в домене. Отступления не зафиксированы:
`DEBT.md` про `Core.Result` говорит только об `unwrap!/1` в генерируемых функциях, ADR-0014 — о том же.

**Решения триажа (21.09.2026).**

1. **CHANGELOG — «Ломающие изменения контракта».** `@spec` и `@doc` не меняются, но рантайм у
   потребителя меняется: вызов вне трёх форм раньше молча возвращал аргумент, теперь падает
   `FunctionClauseError`, а при литеральном аргументе — валит сборку потребителя ещё на
   компиляции (`mix compile --warnings-as-errors`). Это видимое изменение поведения.
2. **Тесты — в этом тикете.** Правка самодостаточна: без теста «чужой терм → `FunctionClauseError`»
   сужение домена ничем не закреплено. Тикет 06 остаётся про остальные пробелы покрытия.
3. **Семантика `tap(:ok, _)` не трогается** — эффекта по-прежнему нет, колбэк арности 1 звать не от
   чего. Асимметрия unit/valued описывается тикетом 04.

## Agent Brief

**Category:** bug
**Summary:** развернуть хвостовые catch-all клозы `map_error/2` и `tap/2` в явные формы результата,
закрепив сужение домена тестами

**Current behavior:**
`lib/core/result.ex:29` — `def map_error(ok, _fun), do: ok`; `lib/core/result.ex:44` —
`def tap(other, _fun), do: other`. Любой терм проходит обе функции насквозь и возвращается как есть:
`Result.map_error(:whatever, fun) == :whatever`, `Result.tap(%Foo{}, fun) == %Foo{}`. Компилятор такой
вызов считает законным — домен, который он выводит из клоз, включает `term()`. Спеки обеих функций
при этом описывают ровно три формы (`{:ok, a} | :ok | {:error, e}`), и остальные 19 функций модуля
перечисляют формы явно; тест «value ops reject unit at runtime» (`test/core/result_test.exs:182`)
закрепляет строгость домена как намеренное свойство модуля.

**Desired behavior:**
Рантайм совпадает со спекой: три формы принимаются, всё остальное даёт `FunctionClauseError`, а при
известном компилятору типе аргумента — предупреждение инференса на call site.

**Key interfaces:**

```elixir
# lib/core/result.ex — map_error/2 (error-клоза остаётся первой: функция про ошибку)
def map_error({:error, reason}, fun), do: {:error, fun.(reason)}
def map_error({:ok, _value} = ok, _fun), do: ok
def map_error(:ok, _fun), do: :ok

# lib/core/result.ex — tap/2 (ok-клоза остаётся первой: порядок текущего кода)
def tap({:ok, value} = result, fun) do
  _ = fun.(value)
  result
end

def tap({:error, _reason} = err, _fun), do: err
def tap(:ok, _fun), do: :ok
```

- `@spec` и `@doc` обеих функций не меняются — правка приводит рантайм к уже написанной спеке.
- Порядок клоз внутри функции значения для домена не имеет; выбран так, чтобы диффа было минимум.
- Тесты misuse подают чужой терм **через хелпер**, а не литералом: литерал теперь даёт type warning
  в самом тесте. Образец уже в файле — `unit_ok/0` (`test/core/result_test.exs:12`), прячущий тип за
  `Process.get/1` → `dynamic()`; завести рядом такой же `alien/0` (или `dyn/1`) и звать его.
- Тест `tap/2` дополняется случаем `:ok`: `assert Result.tap(:ok, &send(parent, {:seen, &1})) == :ok`
  плюс `refute_received` — сейчас unit-вход у `tap/2` не покрыт вовсе.

**Acceptance criteria:**

- [ ] `map_error/2` и `tap/2` — по три клозы, хвостовых catch-all в модуле не осталось
- [ ] тест: `map_error/2` и `tap/2` на чужом терме → `assert_raise FunctionClauseError`, аргумент
      подан через dynamic-хелпер (в тесте нет type warning)
- [ ] тест `tap/2` покрывает `:ok`: возврат `:ok`, колбэк не вызван
- [ ] существующие тесты `map_error/2` (три формы) и `tap/2` (`{:ok, _}`, `{:error, _}`) зелёные без правок
- [ ] CHANGELOG: заведён раздел «Не выпущено» (база сравнения — `## 0.3.4`), в нём
      «Ломающие изменения контракта» — что изменилось (домен сужен до трёх форм), почему
      (`20-agreements.md`, «Домен функции и инференс типов»; рантайм расходился со спекой) и как
      правится код потребителя: `grep -rn "Result.map_error(\|Result.tap("` и привести вход к
      `{:ok, _}` / `:ok` / `{:error, _}`
- [ ] `mix test test/core/result_test.exs` и `make` зелёные

**Out of scope:**

  работе разводить по времени, зависимости по смыслу нет)
- `expect!/2` (03), таблица unit/valued в `@moduledoc` (04), объём интерфейса (05), остальные пробелы
  покрытия (06), `Enumerable` в `traverse*` (07), язык сообщений (08)

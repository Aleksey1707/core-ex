Модуль публичен для потребителя, поэтому ноль вызовов внутри библиотеки сам по себе не приговор —
но ни свод, ни `fixtures/consumer`, ни `CHANGELOG.md` эти двенадцать функций тоже не называют.
История модуля: `cc413d6 core` (заведение), `bd4cef3 rus messages`, `d49614f traverse all` — набор
комбинаторов не менялся с заведения.

**Поправка триажа 05 (21.09.2026): срез неполон — считаны только `lib/` и `fixtures/`.** Grep по трём
живым приложениям на `Core.*` (`quality-control-back`, `gar-back`, `messages-back`) даёт другую
картину: `and_then/2` — 105 вызовов, `traverse/2` — 69, `or_else/2` — 39, `map/2` — 23, `unwrap!/1` — 7.
Без вызовов не двенадцать функций, а одиннадцать: `map/2` и `or_else/2` из списка выбывают.
`Result.t(` у потребителей — это `Pagination.Result.t`, не `Core.Result`.

## Чего аудит не трогает

- `Result.unwrap!/1` в генерируемых функциях (`Core.Repo.Pg`, `Repo.Pg.Schema`, `Core.View`, …):
  это `DEBT.md`, «Генерируемые функции вне границы типов», ведётся тикетами `.scratch/es-type-safety/` (09–11).
- `Core.Option` — правится только там, где расходится с `Core.Result` (тикет 08).
- `Core.Pagination.Result` — другой модуль, конфликт имён разведён по своду (`alias Core.Result`
  + `alias Core.Pagination` → `Pagination.Result`), нарушений нет.

## Что чисто

- `make layout-check` — нарушений нет (в модуле нет приватных функций, разделители не требуются).
- `@moduledoc`, `@doc` и `@spec` — у всех публичных функций; пустая строка после спеки — везде.
- Порядок шапки (`@moduledoc` → `alias`), алфавит алиасов, правило понижения (`map/2` зовёт `ok/1`
  ниже по файлу) — соблюдены.
- `traverse_all/2` отдаёт голый список и документирует заворачивание в `Error.many/1,2` на call site —
  ровно как требует `12-errors.md`.

# 03: Перевод на схему — event sourcing

**What to build:** функции event sourcing, которые сами читают свои опции, отклоняют неизвестный
ключ и значение не того типа `ArgumentError` по схеме, а их `@doc` описывает опции из схемы. Вызов
без опций на горячем пути команды не платит за проверку.

Спека — «Объём перевода», волна 1.

## Comments

- `Es.Transact.run/2` и `run_counted/2` — свои ключи, схема у обеих (общий атрибут `@retries_schema`).
  `run/2` зовёт не `run_counted/2`, а приватный `retrying/2` с уже прочитанным `retries`: иначе
  непустые проверенные опции прошли бы NimbleOptions второй раз, а отказ назвал бы чужую функцию.
  Вызов без опций проверку не проходит (умолчание вычислено при сборке).
- `Es.Store.append/5` — свой ключ `continuous?:`, читает сам: схема над головой без тела.
  Клауза пустой пачки опции тоже проверяет (раньше — `:ok` без проверки; отмечено в CHANGELOG).
- `Es.Personal.KeyStore.Pg.rewrap/1` — свои ключи `batch_size:` / `on_batch:`, читает сам: схема.
  Умолчание `on_batch:` — `&Function.identity/1`: анонимная функция в схему не встраивается
  (`Macro.escape`), а результат колбэка не читается. Guard `batch_size > 0` /
  `is_function(on_batch, 1)` у приватного `rewrap_batches/4` снят: он дублировал схему.
- Горячий путь с опциями: `Store.Write.append` всегда передаёт `continuous?:`, процесс агрегата —
  `retries:`; проверка такого вызова — ~1,8 мкс, против запросов к базе той же команды не
  заметна, поэтому вызовы не правились.

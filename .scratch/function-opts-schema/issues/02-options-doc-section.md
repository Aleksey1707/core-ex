# 02: Раздел «Опции» в `@doc` и описание для `@moduledoc`

**What to build:** документация функции со схемой опций получает в конце раздел «Опции» — ключ,
тип, умолчание и описание каждого, собранные из той же схемы, — и не расходится с проверкой. У
функции с `@doc false` раздел не появляется. Для OTP-процессов, где `init/1` скрыт, описание опций
вставляется в `@moduledoc` явным вызовом публичной функции `Core.Options`.

Спека — `.scratch/function-opts-schema/spec.md`, «Модуль `Core.Options`», «Testing Decisions».

## Comments

- Функция описания — `Core.Options.docs/1`: принимает сырую keyword-схему (`NimbleOptions.new!`,
  некорректная или с ключом без `doc:` — `ArgumentError`), возвращает текст `NimbleOptions.docs/1`
  без заголовка. Заголовок
  в `@moduledoc` пишет автор:
  `@init_opts_schema [...]` выше `@moduledoc`, в нём `#{Core.Options.docs(@init_opts_schema)}`, над
  `init/1` — `@opts_schema @init_opts_schema`.
- Раздел в `@doc` — `## Опции` + тот же текст. Текст автора обрезается справа и отделяется пустой
  строкой. `@doc` дописывается через `Module.put_attribute(module, :doc, {line, text})` в момент
  объявления схемы: маркер тела раскрывается раньше, чем `Kernel.def` читает `@doc`.
- Скрытость по правилу Elixir: `@impl` без `@doc` даёт `:hidden`, и раздел у такой функции тоже не
  появляется — иначе `init/1` с `@impl true` стал бы документированным.
- Голова без тела (`def f(a, opts \\ [])`) забирает `@doc` до первой клаузы, а второй `@doc` у
  функции заменяет первый целиком. Поэтому схема над головой объявляется на самой голове:
  `Core.Options.def/1` в модуле с `use Core.Options` ставит перед `Kernel.def` вызов
  `Core.Options.__head__/3`, который в теле модуля читает `@opts_schema` и `@doc`. Атрибут между
  головой и первой клаузой — новый `CompileError` «@opts_schema ставится перед головой функции»:
  раздел дописать было бы уже некуда. Голова, имя которой не атом (`def unquote(name)(…)`), уходит
  в `Kernel.def` без `__head__`.
- `@doc nil` с `@opts_schema` считается отсутствием `@doc`: функция получает `@doc` из раздела.
- Сообщения NimbleOptions в разделе английские («The default value is», «Required.») — как и
  тексты отказа (ADR-0086).

# 01: Схема опций над `def` — проверка в теле

**What to build:** автор модуля подключает `use Core.Options`, ставит `@opts_schema` над обычным
`def` — и вызов с ключом вне схемы или значением не того типа падает `ArgumentError` с префиксом
`Mod.fun/n:` до входа в тело, а тело получает проверенные опции с умолчаниями. Голова функции
остаётся авторской: неверный по домену вызов по-прежнему даёт предупреждение компилятора, в том
числе в сборке потребителя. Первая переведённая функция — `Es.Projection.run_once`.

Спека — `.scratch/function-opts-schema/spec.md`, «Модуль `Core.Options`», «Правило свода»;
`CONTEXT.md` — «Опции функции», «Схема опций»; ADR-0014, ADR-0085.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] `nimble_options ~> 1.1` — прямая обязательная зависимость.
- [ ] `use Core.Options` подменяет `def/1,2`; без `@opts_schema` клауза уходит в `Kernel.def` без
      изменений, со схемой — первой строкой тела вставляется проверка последнего аргумента.
- [ ] Схема действует на функцию (имя и арность): все клаузы; голова без тела с `opts \\ []`
      работает; атрибут сбрасывается после функции.
- [ ] Схема проверяется при раскрытии и хранится скомпилированной; вызов с `[]` не идёт через
      NimbleOptions и получает умолчания, вычисленные при сборке.
- [ ] Ошибка вызова — `ArgumentError "<Mod.fun/n>: <сообщение NimbleOptions>"`.
- [ ] `CompileError` (через `Core.Helper.Opts.reject!/2`): некорректная схема; ключ без `doc:`;
      `@opts_schema` над `defp` / `defmacro` / `defmacrop`; висячий атрибут; паттерн или guard
      кроме `is_list/1` на опциях.
- [ ] Пользовательский атрибут `@opts` в модуле с `use Core.Options` не задевается.
- [ ] `Es.Projection.run_once` переведён: ручной `Keyword.validate!` убран, неизвестный ключ —
      `ArgumentError`; существующие тесты проекций зелёные.
- [ ] Тест-модуль `Core.Options`: успешный путь, умолчания, `[]`, ошибки вызова, функция без схемы
      рядом, несколько клауз, каждая ошибка объявления через `Code.compile_quoted`.
- [ ] Сценарий фикстуры-потребителя: функция со схемой и неверный по домену вызов с маркером
      `# expect:`; `make consumer-check` зелёный.
- [ ] ADR `0086-function-opts-schema`: NimbleOptions против своего валидатора; подмена `def`
      против обёртки через `defoverridable` (потеря головы и домена, ADR-0014); опции насквозь без
      схемы; граница с ADR-0085; OTP — схема над `init/1`.
- [ ] `20-agreements.md`: раздел о схеме опций — MUST в `lib/` библиотеки, SHOULD у потребителя;
      опции насквозь без схемы; `opts` в голове — переменная; `@spec` с `keyword()`. Ссылка на
      Credo-проверку добавляется в тикете 11. `make rules-check` зелёный.
- [ ] CHANGELOG, «Новое»: `use Core.Options` и `@opts_schema`, как подключить у потребителя.
      «Ломающие изменения контракта»: пункт о функциях, которые теперь отклоняют неизвестный ключ,
      со списком из `Es.Projection.run_once` (дополняется тикетами перевода).
- [ ] `make` зелёный.

# 01: Схема опций над `def` — проверка в теле

**What to build:** автор модуля подключает `use Core.Options`, ставит `@opts_schema` над обычным
`def` — и вызов с ключом вне схемы или значением не того типа падает `ArgumentError` с префиксом
`Mod.fun/n:` до входа в тело, а тело получает проверенные опции с умолчаниями. Голова функции
остаётся авторской: неверный по домену вызов по-прежнему даёт предупреждение компилятора, в том
числе в сборке потребителя. Первая переведённая функция — `Es.Projection.run_once`.

Спека — `.scratch/function-opts-schema/spec.md`, «Модуль `Core.Options`», «Правило свода»;
`CONTEXT.md` — «Опции функции», «Схема опций»; ADR-0014, ADR-0085.

**Blocked by:** None (can start immediately)

## Comments

- Устройство подмены: тело модуля раскрывается целиком до вычисления, поэтому `@opts_schema` при
  раскрытии `def` ещё не виден. `def/2` оборачивает тело маркером `Core.Options.__body__/3`
  (`@doc false` макрос); маркер раскрывается, когда `Kernel.def` сохраняет клаузу, — атрибут уже
  вычислен, `__CALLER__.function` даёт имя и арность. На первой клаузе маркер забирает атрибут
  (`Module.delete_attribute`), собирает `NimbleOptions.new!`, кладёт `%{schema:, defaults:}` в
  `@core_options_schemas` по `{name, arity}`; следующие клаузы берут оттуда.
- `@opts_schema` над `defp` / `defmacro*` / `defdelegate` ловит `@on_definition`, висячий —
  `@before_compile`. «Перед второй клаузой» — по `Module.get_definition/2` с непустыми клаузами:
  голова без тела `def f(a, opts \\ [])` определение заводит, но клауз не несёт.
- `def` из `quote` модуля с `use Core.Options` раскрывается по импорту места `quote`, то есть
  `Core.Options.def/2` и в чужом модуле (так `def await` у `Es.Projection`). Поэтому `def/2`
  в модуле без импорта `Core.Options` (`Macro.Env.lookup_import/2`) — `Kernel.def` как есть.
- По той же причине тесты ошибок объявления собирают модуль `Code.compile_string`, а не
  `Code.compile_quoted`: `def` из `quote` теста раскрылся бы `Kernel.def` по импорту теста.
- Перепривязка опций помечена `generated: true`: нет «unused variable» при опциях, которые тело не
  читает, и предупреждения о чтении `_opts`.
- `doc:` обязателен строкой (`doc: false` тоже отказ) рекурсивно по `keys:`.
- Схема без обязательных ключей проверяет умолчания при сборке (`NimbleOptions.validate([], …)`):
  неверное умолчание — `CompileError`; custom-тип схемы должен жить в модуле, собранном раньше.
- Неявный `try` клаузы (`rescue` у `def`) уходит внутрь маркера: проверка снаружи, отказ вызова
  `rescue` функции не ловит.
- Для тикета 02: `@doc` клаузы ещё не прочитан, когда раскрывается маркер (виден через
  `Module.get_attribute(module, :doc)`), — раздел «Опции» дописывается в `declare!/5` по
  `entry.schema` (`NimbleOptions.docs/1`).
- Guard на опциях проверяется по конъюнктам `and`: допустим ровно `is_list(opts)`, любой другой
  конъюнкт с опциями (`not is_list(opts)`, `length(opts) > 0`, `or`) — `CompileError`.
- Известное ограничение: `def` из `quote` модуля с `use Core.Options`, раскрытый в модуле
  потребителя, который тоже `use Core.Options`, проходит через маркер. Висячий `@opts_schema`
  потребителя перед `use` такого builder'а достанется сгенерированной функции, а не упадёт
  «висячим». Отличить сгенерированный `def` по AST надёжно нечем; случай — ошибка автора.
- Последний аргумент `_` отклоняется как паттерн: клауза, не читающая опции, пишет `_opts`.
- Отступление до конца перевода записано в `docs/rules/DEBT.md`, «Опции функций `lib/` мимо
  схемы», снимается тикетом 11.

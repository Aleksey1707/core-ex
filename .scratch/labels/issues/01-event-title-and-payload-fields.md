# 01: Название события и подписи полей нагрузки — tracer bullet

**Status:** resolved

**Blocked by:** None (can start immediately).

**What to build:** автор приложения объявляет у модуля события название (`use Core.Labels.Event, title:`), у
нагрузки-Prim — ещё подпись нагрузки (`payload:`), а у struct'а нагрузки `Core.Es.Event.Payload` — решение по
каждому полю (`use Core.Labels.Fields, labels:`: подпись или `:hidden`). `Core.Labels.Details.build/1` отдаёт из
события название и сведения видов `text`, `number`, `date`, `datetime`; вид поля берётся из спеки нагрузки. Сборка
не проходит, пока решения нет по каждому полю. Спека — `../spec.md`, «Модули домена»; ADR-0063; термины —
`CONTEXT.md`, «Подписи».

- [x] `use Core.Labels.Event`: обязательная `title:`, `payload:` — только у нагрузки-Prim и у неё обязательна;
      хост — модуль `use Core.Es.Event`, иначе `CompileError`; пустое или не строковое название — `CompileError`.
- [x] `use Core.Labels.Fields, labels:` у `Core.Es.Event.Payload`: поле без решения, подпись вне struct'а, повтор,
      пустая подпись — `CompileError` (полнота — на `@after_compile`).
- [x] `Details.build/1`: сведение — `%{label, kind, value}` из Prim-значений, без дампа; поля в порядке спеки
      нагрузки; `:hidden` в сведения не попадает; поле без значения — `value: nil` со своим видом; нагрузка
      `nil` — пустые сведения; нагрузка-Prim — одно сведение с подписью `payload:`.
- [x] Виды `type:` сопоставляются со списком типов проверки полей библиотеки, а не с отдельным перечнем;
      `boolean` — «Да» / «Нет».
- [x] Опции — через `Core.Helper.Opts.validate!`; проверка текста подписи и keyword-списка без повторов — один
      helper подсистемы, которым пользуются и следующие тикеты.
- [x] Тесты: фикстуры событий и нагрузок в `test/support`; выход `Details.build/1` по каждому виду; отказ сборки —
      `assert_raise CompileError` на каждый отказ (образец — тесты плагина по полям).
- [x] Фикстура-потребитель объявляет событие и нагрузку с подписями; `make consumer-check` зелёный.
- [x] Свод: `docs/rules/11-domain.md` — раздел «Подписи» (механизм `Event`, `Fields`, `Details`);
      `docs/rules/app/11-domain.md` — раздел о подписях с условием «приложение, отдающее сведения событий, MUST …»:
      где объявляется, название без подстановок, `:hidden` — только служебное. `make rules-check` зелёный.
- [x] `CONTEXT.md`, группа «Подписи», — адрес нормы.
- [x] `CHANGELOG.md`, «Новое»: подсистема подписей — что даёт и как подключается; правка `app/**` — тем же пунктом.
- [x] moduledoc и примеры — `MyApp.*`, без терминов предметной области потребителей.
- [x] `make` зелёный.

# 11: ратчет проверяет автора события

**Status:** resolved

**Blocked by:** —

**What to build:** `Core.Web.Event` с `user_ref:` (его требует `labels: true`) ставит имя автора из словаря
ссылок и падает `ArgumentError`, если автора там нет (`event.ex`, `name!/2`). Словарь находит автора, только если
тип `by` — Prim-идентификатор с резолвером, а `Core.Labels.CompletenessCase` на `by` не смотрит. Приложение с
ратчетом — приложение с подписями, значит с `user_ref:`: проверка безусловна.

- [x] Новый генерируемый тест и `check_*`: тип автора каждого события (`__es_by__/0`) — Prim с
      `use Core.Labels.ID, kind: :user` и `resolver:`; пробел — `{событие, :by, модуль автора}` под своим ключом.
- [x] Moduledoc `CompletenessCase`: фраза «автор события (`by`) … не проверяется» переписана, тест в списке
      «Генерируемые тесты».
- [x] `docs/rules/11-domain.md`, раздел ратчета: «автор события в сведения не выходит и не проверяется» →
      требование вида `:user` с резолвером у автора.
- [x] Тесты: автор без `Core.Labels.ID`, с `kind: :ref`, с `:user` без резолвера — провал; с `:user` и
      резолвером — `:ok`.
- [x] `CHANGELOG.md` — дополняется пункт «Подписи событий» в «Новое» (ратчет проверяет автора).
- [x] `make` зелёный.

# 09: OpenAPI-схема сведений

**Status:** resolved

**Blocked by:** 08; опциональная зависимость `open_api_spex` и норма о ней из фичи схемы обёртки ответа. Если её
к началу тикета нет — тикет заводит зависимость (`optional: true`) и норму в `docs/rules/10-architecture.md` сам.

**What to build:** у приложения с `open_api_spex` тот же `use Core.Web.Labels` делает модуль схемой семейства
сведений (`oneOf` по видам, дискриминатор `kind`) и порождает вложенные модули схем видов — под именами от модуля
приложения, в его пространстве. Схема вида `user` ссылается на схему ссылки на учётную запись приложения
(`user_ref: [schema:]`). Без `open_api_spex` модуль остаётся только дампом. Спека — `../spec.md`, «Wire», user
stories 52–54; ADR-0064.

- [x] Наличие `open_api_spex` проверяется при раскрытии макроса; модули библиотеки на `OpenApiSpex` безусловно не
      ссылаются; `make compile-no-optional` зелёный.
- [x] При `open_api_spex` `user_ref: [schema:]` обязательна, иначе `CompileError`; без него — не требуется.
- [x] Названия схем — от последнего сегмента имени модуля приложения (`<Имя>`, `<Имя>Text`, …); описания —

- [x] Тест: дамп `to_wire/2` каждого вида, группы, списка и изменения сверяется со схемой, порождённой тем же
      `use` (`OpenApiSpex`) — требование ADR-0064.

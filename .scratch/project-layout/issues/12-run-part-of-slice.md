# 12: прогон, общий для компонента и оператора

**Status:** needs-triage

**Найдено:** аудит раскладки, итерация 2 (2026-09-28).

## Факты

- У потребителя C модуль импорта (около 650 строк) и журнал прогонов зовут и компонент
  планового обновления, и задача оператора в `Release`.
- Это не usecase и не компонент: вида модуля в срезе для него нет. Его возврат-статистика по CQS не
  описан. Ключ конфигурации делят корень компонента (тумблер) и прогоны оператора (рабочий каталог,
  размер пачки), а `app/17` требует брать опции через корень.

## Предложение

Часть среза «прогон» — `<BC>.<Actor>.<Run>` вне `Usecases`, со своим ключом конфигурации; у ключа
компонента — только тумблер и расписание. Возврат прогона — результат собственного выполнения
(статистика), как у `Repo.Pg.insert_many/4`.

Решать при адаптации потребителя C.

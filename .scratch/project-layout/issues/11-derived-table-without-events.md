# 11: read-модель над state-stored агрегатами без событий

**Status:** needs-triage

**Найдено:** аудит раскладки, итерация 2 (2026-09-28).

## Факты

- У потребителя C таблица поиска пересобирается прогоном среза индексатора через `insert_all`, а
  читает её другой срез. У агрегатов контекста событий нет (это записано в `DEBT.md` потребителя).
- Карта устаревших форм (`docs/rules/app/00-index.md`, «Версия библиотеки») безусловно говорит:
  «read-модель пишет usecase или репозиторий → её пишет проекция». `Core.Es.Projection` читает только
  `es_events`, поэтому для агрегатов без событий единственная возможная форма объявлена устаревшей.

## Предложение

- Ограничить строку карты event-sourced агрегатами.
- Добавить форму «производная таблица, пересобираемая прогоном»: `common/<read_model>/` с `view`,
  `read_repo` и `repo{,/pg}` записи; usecase пересборки — в срезе инициатора.
- Правило чтения чужих таблиц (`app/13`, «Read-модель») распространить на соседний срез явно.

Решать при адаптации потребителя C, на его коде.

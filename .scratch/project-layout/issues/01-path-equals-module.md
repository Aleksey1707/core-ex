# 01: Раскладка: путь файла = имя модуля

**What to build:** у свода потребителя появляется раздел «Раскладка» с модальностью, а
`boundary_lint --consumer` ловит файл, чей модуль не совпадает с путём, и умеет гасить
сознательное отступление маркером со ссылкой на `DEBT.md`. Проверки линтера покрыты тестами,
которые вызывают скрипт как чёрный ящик.

**Blocked by:** None (can start immediately)

**Status:** done

**Spec:** [Раскладка потребителя](../spec.md) — «Свод потребителя», «Линтер `boundary_lint --consumer`»

- [x] `app/10`, раздел «Раскладка»: `MUST` «путь файла от `lib/` = имя модуля в snake_case»,
      конвенция Mix для mix-тасок, строка «Проверяется: `boundary_lint --consumer`», форма
      маркера-исключения и запись отступления в `DEBT.md`.
- [x] `app/10`, таблица top-level namespaces дополнена `StreamID`, `MetricsServer`, `Release`,
      `Mix.Tasks.*`; явная строка «один Mix-проект, один `otp_app`, один `DAO`, umbrella не
      поддерживается».
- [x] Линтер (только `lib/`): верхнеуровневый `defmodule` сверяется с путём через
      `Macro.underscore` имени модуля (аббревиатура `AppA` в `lib/app_a/` — без нарушения); два
      верхнеуровневых модуля в файле — нарушение; вложенные модули следуют за родителем;
      `Mix.Tasks.Foo.Bar` ожидается в `mix/tasks/foo.bar.ex`.
- [x] Маркер у `defmodule` называет правило и строку `DEBT.md`, гасит нарушения только своего
      правила в своём модуле; маркер без ссылки на `DEBT.md` не гасит ничего.
- [x] Сообщение нарушения — `путь:строка: текст`, в конце прогона — путь к норме свода, как у
      существующих проверок; существующая проверка DI не меняет поведения.
- [x] ExUnit-тест пишет пробы во временный каталог-потребитель и вызывает скрипт через
      `System.cmd`: путь ≠ имя, два модуля в файле, аббревиатура, mix-таска, маркер гасит своё и
      не гасит чужое, DI-нарушение по-прежнему ловится, чистое дерево — код 0.
- [x] `app/20`, таблица пайплайна: шаг `boundary-check` называет новую проверку.
- [x] CHANGELOG, «Ломающие изменения контракта»: что проверяется, форма маркера, как чинить.
- [x] `make` зелёный.

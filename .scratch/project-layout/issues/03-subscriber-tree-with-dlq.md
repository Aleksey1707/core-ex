# 03: Дерево подписчика с DLQ в `Core.PubSub`

**What to build:** библиотека даёт готовый супервизор подписчика брокера: свой DLQ-writer, затем
на каждый топик читатель и `MqSubscriberReliable`, стратегия `:rest_for_one`. Обязательный порядок
детей из свода держится построением, а не копированием супервизора в каждом компоненте.

**Blocked by:** None (can start immediately)

**Status:** done

**Spec:** [Раскладка потребителя](../spec.md) — «Дерево подписчика с DLQ в `Core.PubSub`»

- [x] Дети строго в порядке: DLQ-writer (если задан) → на каждый топик читатель → его подписчик;
      подписчик стартует с `subscribe: true`.
- [x] Тумблер `enabled:`: выключенное дерево отдаёт `:ignore` и пишет причину на `info`, как
      `Core.Es.Projection.Supervisor`.
- [x] `watch_list/1` по тем же опциям, что и старт: имена процессов не повторяются литералами.
- [x] Библиотека не читает конфигурацию потребителя: всё приходит опциями.
- [x] Тест поверх `MqFake`: порядок детей, отравленное сообщение уходит в DLQ, выключенное дерево —
      `:ignore`, `watch_list/1` совпадает с именами запущенных процессов.
- [x] `@moduledoc` / `@doc` / `@spec`, разметка разделителями.
- [x] Свод библиотеки, раздел о подписчиках, называет дерево.
- [x] CHANGELOG, «Новое».
- [x] `make` и `make compile-no-optional` зелёные.

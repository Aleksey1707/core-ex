## Comments

> *This was generated by AI during triage.*

**Category:** enhancement. **State:** ready-for-human.

Сверено с кодом на 2026-10-23. Опции `use` разбираются тремя способами:

- **При раскрытии** (`Macro.expand_literals` + `Core.Helper.Opts.validate!/4`): `Es.Aggregate`, `Es.Cmd`,
  `Es.Aggregate.Repo`, `Es.Aggregate.Process`, `Es.KeyReservation`, `Repo.Pg.StateStored`, `Core.View`,
  case-модули (`Labels.CompletenessCase` и др.).
- **В теле модуля** (`quote bind_quoted`): `Codec`, `Codec.Facade`, `Codec.Plugin`, `Enum`, `Prim.*`,
  `Repo`, `Repo.Pg`, `Labels.*`, `Web.Event`, `Es.Event`, `Es.Event.Payload`, `Es.ValueChanged`,
  `Context.Accessor`. Для `bind_quoted` 16 модулей держат публичные `@doc false`
  `required_keys/0` / `optional_keys/0` — проходные, только чтобы тело увидело списки.
- **Смешанный**: публичные `@doc false` валидаторы в атрибутах — `Es.Event.Codec`
  (`type!` / `tags!` / `mods!` / `upcasts!` / `derive!`), `Es.Projection.declaration!/4`. Причина —
  опции со ссылкой на атрибут модуля (`tags: @tag_by_mod`), которые при раскрытии ещё не вычислены.

Сопутствующие повторы: `where/1` — в пяти модулях `Labels.*` и `View.Opts`; `reject!` / `fail!` — в
трёх `Labels.*`. `StateStored` проверяет ключи, затем `use Core.Repo.Pg` проверяет их ещё раз.

Уже в работе: 14 переводит `Es.Event` на разбор при раскрытии; 07 меняет набор опций агрегатных
builder'ов; длинный `quote` `Repo.Pg` записан в `docs/rules/DEBT.md`.

**Почему не агенту:**
- Канонический режим — архитектурное решение для ~25 builder'ов: оно ложится в ADR и в
  `20-agreements.md` («Параметры `__using__`… проверка на этапе компиляции»).
- Ограничение `tags: @attr` (опция ссылается на атрибут) разбор при раскрытии не снимает. Нужно
  решить: смешанный режим законен как исключение или опции через атрибут уходят из контракта —
  второе ломает потребителей.
- Порядок перевода зависит от исхода 07 / 08.

**Что решить:**
1. Канонический режим и критерий исключения.
2. Судьба `required_keys/0` / `optional_keys/0`: уходят вместе с переводом или заменяются общим
   механизмом.
3. Общие `where` / `reject!` для сообщений `CompileError` — в `Core.Helper.Opts` или нет.
4. Двойная проверка `StateStored` → `Repo.Pg`: кто владеет ключами.

После решения — нарезать тикеты по builder'ам (`ready-for-agent`).

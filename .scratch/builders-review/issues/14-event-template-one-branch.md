## Agent Brief

**Category:** enhancement
**Summary:** `use Core.Es.Event` разбирает опции при раскрытии макроса и генерирует событие одной веткой `quote`
вместо двух почти одинаковых веток «с нагрузкой» / «без нагрузки».

**Current behavior:**
- `Core.Es.Event.__using__/1` — `quote bind_quoted`: `Helper.Opts.validate!`, проверка `:payload` и
  `check_subject!/2` выполняются в теле модуля события через публичные `@doc false`
  `required_keys/0` / `optional_keys/0`.
- Дальше `if is_nil(payload_mod)` с двумя ветками примерно по 55 строк. Они отличаются только аргументом
  нагрузки:
  - `@type t` — `payload: nil` против `payload: Payload.t()`;
  - `draft/0` → `__MODULE__` против `draft/1` → `{__MODULE__, payload}` с головой `%Payload{}`;
  - `new/4,5` против `new/5,6`: лишний первый аргумент `%Payload{} = payload` в голове и `@spec`, поле
    `payload:` в struct.
- `Core.Es.Aggregate` и `Core.Es.Cmd` разбирают опции при раскрытии: `Macro.expand_literals(opts, __CALLER__)`
  + `Helper.Opts.validate!` по атрибутам модуля.

**Desired behavior:**
- Опции `use Core.Es.Event` разбираются и проверяются при раскрытии макроса, как у `Aggregate` / `Cmd`: те же
  ключи, те же тексты `CompileError`, проверка `subject: :aggregate_id` нагрузки (ADR-0073) — тоже при
  раскрытии.
- Шаблон события — одна ветка `quote`. Разница «с нагрузкой» / «без» собирается вне `quote` (список
  аргументов / пар через `unquote_splicing`, как в `Core.View` и `Core.Es.ValueChanged`).
- Сгенерированный модуль события неотличим от текущего:
  - те же функции и арности: `new/4,5` (без нагрузки) или `new/5,6` (с нагрузкой) — `id \\ nil` последним,
    `draft/0` или `draft/1`, `__es_payload__/0`, `__es_aggregate_id__/0`, `__es_by__/0`;
  - литеральные головы `%AggID{}`, `%By{}`, `%Payload{}`, `%Version{}`, `%At{}` и guard `is_opt(id, ID)`
    сохраняются (ADR-0014);
  - тот же `@type t`, те же `@spec` и `@doc`;
  - тот же `defstruct` и `@enforce_keys`.
- Pass-through `required_keys/0` / `optional_keys/0` уходят, если после правки их никто не читает. Вне
  `quote` сейчас их не вызывает никто.

**Key interfaces:**
- `Core.Es.Event.__using__/1` — единственная точка правки; публичный контракт `use Core.Es.Event,
  aggregate_id:, by:, payload:` не меняется.
- `Core.Es.Event.check_subject!/2` вызывается при раскрытии. Порядок ожидания компиляции нагрузки при этом
  не должен измениться: раскрытие и тело модуля — обе фазы сборки модуля события. Проверить сборкой фикстуры,
  а не рассуждением.

**Acceptance criteria:**

      идут до `quote`.

- [ ] `make consumer-check` проходит с прежними маркерами `# expect:` в `fixtures/consumer/scenarios/**`:
      неверный тип в `draft` / `new` по-прежнему даёт предупреждение компилятора у вызывающего.

- [ ] `CHANGELOG.md` не меняется: контракт `use` и сгенерированные функции прежние.

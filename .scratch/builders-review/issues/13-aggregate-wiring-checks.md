## Agent Brief

**Category:** bug
**Summary:** `use Core.Es.Aggregate.Repo` сверяет `id:` с Prim агрегата кодека, а `use Core.Es.Aggregate.Repo.Pg`
сверяет свои `aggregate:` / `id:` с behaviour.

**Current behavior:**
- `use Core.Es.Aggregate.Repo` проверяет только, что `aggregate:` экспортирует `__es_event_codec__/0`.
  - Кодек он уже загружает (`evolve_checks/2` → `Es.Store.Opts.event_codec!/2`), но `id:` с
    `event_codec.__es_aggregate_id__()` не сверяет.
  - `use Core.Es.Aggregate.Process` берёт тип головы `execute` из `behaviour.__es_aggregate_repo__().id`,
    поэтому неверный `id:` behaviour'а даёт процесс с чужой головой.
- `use Core.Es.Aggregate.Repo.Pg` сверяет свой `id:` с кодеком, но `behaviour!/1` проверяет у behaviour
  только набор колбэков.
  - `aggregate:` и `id:` реализации могут не совпадать с `aggregate:` / `id:` behaviour'а, и сборка
    проходит.

**Desired behavior:**
- `use Core.Es.Aggregate.Repo`: `id:` не равен `__es_aggregate_id__/0` кодека агрегата → `CompileError` с тем же
  текстом, что у `Repo.Pg` (`Es.Store.Opts.ensure_aggregate_id!/3`, метка `Es.Aggregate.Repo`).
- `use Core.Es.Aggregate.Repo.Pg`:
  - `behaviour:` должен экспортировать `__es_aggregate_repo__/0`. По `docs/rules/13-repos.md` behaviour —
    это `use Core.Es.Aggregate.Repo`.
  - Свои `aggregate:` / `id:` реализация сверяет с `behaviour.__es_aggregate_repo__()`. Расхождение →
    `CompileError` с именами обоих модулей.
- Новых рёбер компиляции нет: оба `use` уже загружают кодек и behaviour при раскрытии.

**Key interfaces:**
- `Es.Store.Opts.ensure_aggregate_id!/3` переиспользуется, а не копируется.
- Тексты существующих отказов не меняются.

**Acceptance criteria:**
- [ ] Тест: `use Core.Es.Aggregate.Repo` с `id:` чужого Prim — `CompileError`. До правки красный.
- [ ] Тест: `use Core.Es.Aggregate.Repo.Pg` с behaviour другого агрегата / другим `id:`, чем у
      behaviour, — `CompileError`. До правки красный.
- [ ] Тест: `behaviour:` без `__es_aggregate_repo__/0` — `CompileError` (если существующие тесты
      собирают behaviour руками, перевести их на `use Core.Es.Aggregate.Repo`).
- [ ] `docs/rules/13-repos.md`, «Write event-sourced агрегата», строка «Проверяется»: добавлены
      обе сверки.
- [ ] `CHANGELOG.md`, «Не выпущено» → «Изменения контракта макросов»:
      - что: рассогласованные `id:` / `aggregate:` у behaviour и реализации — `CompileError`;
      - почему: процесс агрегата брал голову `execute` из несверенного `id:`;
      - как править: привести опции к Prim и агрегату кодека.
- [ ] `make` зелёный, включая `consumer-check`.

**Out of scope:**
- Снятие дублирующих опций и любые изменения набора опций `use` (тикеты 07 / 08).
- `KeyReservation`, `Outbox`, `Projection`.

# 04: Prim-обёртки — общий протокол в одном месте

**Status:** resolved

**Blocked by:** None (can start immediately)

**Сила:** Strong.

**Файлы:** `lib/core/prim/{string,integer,decimal,uuid,date,date_time,compose}.ex`, `lib/core/prim/wrapper.ex` (44 строки), `lib/core/prim.ex` (~45).

**Проблема.**
- Каждая из семи обёрток вручную пробрасывает в базу одни и те же 6–7 опций: `custom_mutate: Keyword.get(opts, :mutate)`, `custom_validate:`, `name:`, `sensitive:`, `personal:` (например, `string.ex` ~45–52, `date.ex` ~32–37, `uuid.ex` ~62–67).
- Каждая повторяет `Prim.Opts.boolean!(opts, ~w(... sensitive personal)a)` в `validate_opts!`.
- Каждая вписывает общие ключи `kind mutate validate sensitive personal` в свой `optional:`.
- `Wrapper` — это четыре геттера атрибутов: по deletion test модуль shallow.
- Базовый `use Core.Prim` проверяет только required-ключи, поэтому опечатку на уровне базы он не ловит. Ключи при этом ещё и переименовываются (`mutate` → `custom_mutate`).

**Что изменилось бы.** Обёртка объявляет только свои опции. Общие ключи, их проверку и проброс в базу берёт на себя `Wrapper` / `Prim.Opts`.

**Выигрыш.** Leverage: новая общая опция (как недавний `personal:`) добавляется в одном месте вместо 21. Обёртки перестают расходиться. Опечатка ключа ловится на базе.

**ADR:** конфликта нет.

## Agent Brief

**Category:** enhancement
**Summary:** Общий протокол Prim-обёрток (общие ключи, проверка их значений и передача в базу) живёт в
`Core.Prim.Wrapper`; базовый `use Core.Prim` отклоняет неизвестные ключи.

**Current behavior:**
- Каждая из семи обёрток (`Prim.String` / `Integer` / `Decimal` / `UUID` / `Date` / `DateTime` /
  `Compose`) сама:
  - вписывает общие ключи `kind mutate validate sensitive personal` в `optional:` у `use Core.Prim.Wrapper`;
  - проверяет `Prim.Opts.boolean!(opts, ~w(… sensitive personal)a, label())` в `validate_opts!/1`;
  - передаёт в `use Prim` одни и те же `custom_mutate: Keyword.get(opts, :mutate)`,
    `custom_validate: Keyword.get(opts, :validate)`, `name:`, `kind:`, `sensitive:`, `personal:`.
- `Core.Prim.Wrapper` — только четыре геттера метаданных (`label/0`, `native_kind/0`,
  `required_keys/0`, `optional_keys/0`).
- Базовый `use Core.Prim` проверяет одни обязательные ключи (`Helper.Opts.require!`). Воспроизведено:
  `use Core.Prim, cast: …, name: "X", kind: :x, sensitve: true` собирается,
  `__domain_sensitive__() == false`, а `inspect/1` печатает значение. Та же опечатка в обёртке даёт
  `CompileError` «неизвестные опции».

**Desired behavior:**
- Обёртка объявляет в `use Core.Prim.Wrapper` только свои ключи. Общие ключи (`name` обязателен;
  `kind mutate validate sensitive personal` необязательны) `Wrapper` добавляет сам, и
  `required_keys/0` / `optional_keys/0` отдают полный набор.
- Boolean-проверку `sensitive` / `personal` делает `Prim.Opts.prepare!/2` (или `Wrapper`) один раз на
  все обёртки. В `validate_opts!/1` обёртки остаются только её собственные значения (у `Prim.String`
  в `boolean!` остаётся `trim`, у `UUID` — `check_version`).
- Опции общих ключей для базы собирает одна функция `Wrapper`: она переводит `mutate` →
  `custom_mutate` и `validate` → `custom_validate`, задаёт `name`, `kind`, `sensitive`, `personal`.
  Обёртка добавляет к ним свои (`cast`, `mutate`, `validate`, `type_opts`, `pipeline_opts`,
  `value_type`) и может переопределить общие: `Compose` подставляет унаследованные флаги
  (`Compose.sensitive?/2` / `personal?/2`).
- Базовый `use Core.Prim` проверяет набор ключей через `Helper.Opts.validate!/4`. Разрешены: `cast name
  kind` (обязательные), `mutate validate custom_mutate custom_validate type_opts pipeline_opts sensitive
  personal` (необязательные). `value_type:` снимается `Keyword.pop` до `quote` и в проверку не попадает.
- Имена ключей базы не меняются: `mutate` / `validate` у обёртки и `custom_*` у базы остаются,
  переименование делается в одном месте, в `Wrapper`.

**Key interfaces:**
- `use Core.Prim.Wrapper`: `required:` / `optional:` — только ключи обёртки; функция сборки опций базы — новая.
- `Core.Prim.Opts.prepare!/2`: порядок прежний (набор ключей → `kind:` → значения), плюс проверка
  общих флагов.
- `use Core.Prim`: неизвестный ключ — `CompileError` «Prim: неизвестные опции: […]».
- Публичный контракт обёрток (их опции и генерируемые функции) не меняется.

**Acceptance criteria:**
- [ ] Общие ключи `kind mutate validate sensitive personal` и `name` не перечисляются ни в одной обёртке.
- [ ] `sensitive` / `personal` не проверяются в `validate_opts!/1` ни одной обёртки.
- [ ] Ни одна обёртка не содержит `custom_mutate:` / `custom_validate:` / `sensitive:` / `personal:` при
      вызове `use Prim` (у `Compose` — только переопределение флагов наследованием).
- [ ] Тест: `use Core.Prim` с неизвестным ключом (`sensitve: true`) — `CompileError`. До правки красный.
- [ ] Тест: обёртка с не-boolean `sensitive:` / `personal:` по-прежнему `CompileError` (если такого
      теста нет — завести на одну обёртку).
- [ ] Существующие тесты `test/core/prim/**` зелёные без правок ожиданий.
- [ ] `docs/rules/11-domain.md`, «Типизированные обёртки»: общие ключи и их передача в базу —
      у `Core.Prim.Wrapper`; у базового `use Core.Prim` неизвестный ключ — `CompileError`.
- [ ] `CHANGELOG.md`, «Не выпущено» → «Изменения контракта макросов»: базовый `use Core.Prim` отклоняет
      неизвестные ключи. Почему: опечатка во флаге (`sensitve:`) молча снимала редакцию значения. Как
      править: убрать или исправить лишний ключ.
- [ ] `make` зелёный.

**Out of scope:**
- Переименование ключей базы (`custom_mutate` / `custom_validate`).
- Leaf и kind композита (тикет 01) и прочие изменения `Prim.Compose`, кроме передачи опций.
- Генерируемые функции обёрток (`today/0`, `now/0`, `from/1`, `new/0` у UUID).

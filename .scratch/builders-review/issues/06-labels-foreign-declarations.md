# 06: Labels — явный interface чтения чужих объявлений

**Status:** ready-for-agent

**Blocked by:** 03 — Чтение подписей (реализация: тот же `fields.ex`)

**Сила:** Worth exploring.

**Файлы:**
- `lib/core/labels/{text,values,fields,id,event}.ex`;
- `lib/core/labels/check.ex` — `prim!`;
- `lib/core/web/event.ex` (~180–185);
- `test/core/labels/fields_test.exs` — около 80 проверок `CompileError`.

**Проблема.**
- Labels читают приватные атрибуты чужих макросов: `:enum_values` (`values.ex` ~94), `:es_payload_fields` (`fields.ex` ~197) и `:es_value_changed` (`fields.ex` ~236). Если переименовать `@enum_values`, ошибка молча превращается в «не Enum».
- `Check.prim!` проверяет `__domain_kind__/0`, `__label_id__/0` и `__label_text__/0` через `Module.defines?`.
- Шесть модулей повторяют один шаблон: `quote bind_quoted`, `Helper.Opts.validate!(opts, X.required_keys(), X.optional_keys(), …)`, публичные pass-through `required_keys/0` и `optional_keys/0` (12 функций), копии `where/1` и `reject!` / `fail!`.
- View и CompletenessCase проверяют опции при раскрытии макроса (`Macro.expand_literals`) — это вторая стратегия той же задачи.
- `declare!` нельзя вызвать вне собираемого модуля, поэтому тесты компилируют модули целиком.

**Что изменилось бы.** Enum, Payload и ValueChanged получают явный interface для чтения при компиляции. Labels берут оттуда готовые данные и становятся чистыми функциями от них.

**Выигрыш.** Тесты на уровне функций. Seam к Enum и Payload становится явным. Шаблонный код уходит из шести модулей.

**ADR:** конфликта нет.

**Связь с `.scratch/codec-field/`.** Если `:es_payload_fields` станет списком `%Core.Codec.Field{}`, часть утечки уйдёт сама. Это нужно перепроверить перед проработкой.

## Agent Brief

**Category:** enhancement
**Summary:** Labels не знают имён чужих атрибутов и функций-маркеров. Объявление спрашивают у
владельца через его compile-time читатель, а разбор опций `Labels.Values` / `Labels.Fields` — чистые
функции от прочитанных данных, которые тестируются без сборки модуля.

**Current behavior:**
- При сборке Labels читают чужие атрибуты:
  - `Core.Labels.Values` — `Module.get_attribute(module, :enum_values)`;
  - `Core.Labels.Fields` — `:es_payload_fields` (поля нагрузки) и `:es_value_changed` (вид значения
    изменения).
- Существование чужих объявлений Labels проверяют по функциям-маркерам через `Module.defines?`:
  - `Core.Labels.Check.prim!/3` — Prim (`__domain_kind__/0`), уже объявленные `Labels.ID` / `Labels.Text`
    (`__label_id__/0`, `__label_text__/0`);
  - `Core.Labels.Event.declaration!/2` — событие (`__es_payload__/0`);
  - `Core.Labels.Fields.__after_compile__/2` — нагрузка (`__es_payload_fields__/0`).
- `Values.labels!/2` и `Fields.declare!/2` принимают собираемый модуль и сами читают из него. Вызвать
  их можно только при сборке модуля, поэтому каждый отказ тестируется компиляцией целого модуля
  (`test/core/labels/fields_test.exs` — 80 проверок `CompileError`).

**Desired behavior:**
- Владелец объявления даёт compile-time читатель для модуля, который ещё собирается (`@doc false`,
  `@spec`; имена на выбор):
  - `Core.Enum` — значения Enum или `nil`;
  - `Core.Es.Event.Payload` — поля спеки `[%Core.Codec.Field{}]` или `nil`;
  - `Core.Es.ValueChanged` — `[type:, nilable:]` или `nil`;
  - `Core.Prim` — объявлен ли Prim;
  - `Core.Labels.ID` / `Core.Labels.Text` — есть ли своё объявление (они тоже владельцы маркеров);
  - `Core.Es.Event` — объявлено ли событие;
  - проверка «это нагрузка» в `@after_compile` `Labels.Fields` — через тот же читатель `Payload` или
    парную функцию для собранного модуля.
- Вне модуля-владельца в `lib/core/labels/**` нет `Module.get_attribute` чужого атрибута и
  `Module.defines?` чужой функции-маркера. `Module.defines?(module, {:__struct__, 0})` (это struct
  Elixir, а не чужой макрос) MAY остаться.
- Разбор разделяется на тонкое чтение и чистую функцию:
  - `use` читает объявление через читатели владельцев и передаёт его в чистую функцию;
  - чистая функция получает данные (значения Enum; поля нагрузки | изменение | ничего; опции;
    `where`) и возвращает разобранное объявление или поднимает `CompileError`, как сейчас.
  - Это делается для `Labels.Values` и `Labels.Fields`. `Labels.ID`, `Labels.Text`, `Labels.Event`
    переходят на читатели, а их разбор MAY остаться в прежней форме: он уже не зависит от чужих
    атрибутов.
- Тексты отказов и всё, что порождают `use Core.Labels.*`, не меняются.
- `@moduledoc` владельцев: у `Core.Enum` появляется строка о занятом `@enum_values` (как у `Payload` /
  `ValueChanged`). Фразы «по нему `use Core.Labels.Fields` берёт…» ссылаются на читатель, а не на
  атрибут.

**Key interfaces:**
- Читатели в `Core.Enum`, `Core.Es.Event.Payload`, `Core.Es.ValueChanged`, `Core.Prim`,
  `Core.Labels.ID`, `Core.Labels.Text`, `Core.Es.Event` — `@doc false`, вызываются только при сборке.
- Чистые функции разбора `Labels.Values` / `Labels.Fields` — `@doc false`, вход — данные и `where`,
  а не модуль.
- `Core.Labels.Check.prim!/3` получает готовые признаки (или вызывает читатели), а не
  `Module.defines?` по чужим именам.

**Acceptance criteria:**
- [ ] `grep` по `lib/core/labels/`: нет `:enum_values`, `:es_payload_fields`, `:es_value_changed`,
      `__domain_kind__`, `__es_payload__`, `__es_payload_fields__` в `Module.get_attribute` /
      `Module.defines?`.
- [ ] Новые тесты чистых функций `Labels.Values` и `Labels.Fields` без `Code.compile_*` и `defmodule`.
      `Values`: значение без подписи, подпись вне Enum, «не Enum».
      `Fields`: `labels:` у нагрузки, `fields:` у struct'а, спека и у нагрузки, и в `fields:`, `change:` у
      `ValueChanged`, ручной struct изменения с `value:` и без, `value:` без `change:`, обе опции,
      ни одной.
- [ ] Тесты читателей: модуль с объявлением и без (там, где проверку можно сделать без собираемого
      модуля, — на уровне функции).
- [ ] Существующие тесты `test/core/labels/**`, `test/core/enum*`, `test/core/es/**` зелёные без правок
      ожиданий. Модульные тесты `CompileError` остаются.
- [ ] `make` зелёный.

  (`Macro.expand_literals`) во View и CompletenessCase. Это тикет 12, «Три режима разбора опций».
- Перевод 80 модульных тестов `CompileError` на функции.

- Семантика объявлений подписей (ADR-0063), тексты отказов.
- CHANGELOG: читатели и чистые функции внутренние (`@doc false`), контракт потребителя не меняется.

# 05: Web.Event — схема функциями, поля одним списком

**Status:** ready-for-agent

**Blocked by:** None (can start immediately)

**Сила:** Strong для схемы.

**Файлы:** `lib/core/web/event.ex` (571 строка, `quote`-блоки ~238–520), `lib/core/web/event/details.ex`.

**Проблема.**
- OpenAPI-схема собирается AST'ом внутри `quote`, около 190 строк (~333–520). `Core.Web.Response.Schema` по ADR-0065 решает ту же задачу условным модулем библиотеки с обычными функциями.
- Поля ответа (`id … by`) перечислены около девяти раз: переименование по ADR-0069 задело строки ~94, 105, 274, 284, 305, 317, 364, 390, 534.
- `plain/0` и `labelled/0` — два почти одинаковых блока сужения (~264–328).
- Поиск в словаре ссылок `name!/2` продублирован в `event.ex` (~560) и `event/details.ex`.

**Что изменилось бы.** Схему строят функции условного модуля библиотеки. В `quote` остаются только оболочки модулей и `def schema`. Сужение генерируется из одного списка полей.

**Выигрыш.** Схему можно тестировать без компиляции модуля потребителя. Переименование поля правится в одном месте.

**ADR:** по линии ADR-0064 / ADR-0065, конфликта нет. Само сужение требуют ADR-0014 и «Генерируемые функции» (`20-agreements.md`), поэтому меняется только источник списка полей.

## Agent Brief

**Category:** enhancement
**Summary:** Тела OpenAPI-схем `use Core.Web.Event` собирают функции условного модуля библиотеки
`Core.Web.Event.Schema`. Сужение результата `to_wire/2` порождается из одного списка полей, а поиск
в словаре ссылок написан один раз.

**Current behavior:**
- `lib/core/web/event.ex` собирает схему AST'ом прямо в `quote`: `schemas/1`, `detail/0`, `variant/1`,
  `properties/1`, `required/1` (около 190 строк). Проверить схему можно только через модуль
  потребителя (`test/core/web/event_test.exs`, describe «схема»).
- `__using__` порождает схему при `Code.ensure_loaded?(OpenApiSpex)` в сборке потребителя.
- Поля `id aggregateId aggregateVersion type payload at by` перечислены 9 раз: в `@type t` и
  `@type labelled`, по два раза в `plain/0` и `labelled/0`, в `properties` и `required` схемы, в
  `to_wire/5`.
- `plain/0` и `labelled/0` — два почти одинаковых блока сужения. Разница только в полях `title` /
  `details` и guard'ах (`by: %{}`, `is_binary(title)`, `is_list(details)`).
- `name!/2` написана дважды: в `event.ex` (автор события) и `event/details.ex` (id сведения), тексты
  ошибок у них разные.

**Desired behavior:**
- Новый модуль `Core.Web.Event.Schema` (`@moduledoc false`) лежит под
  `if Code.ensure_loaded?(OpenApiSpex)`, по образцу `Core.Web.Response.Schema` (ADR-0064, ADR-0065).
  Его функции возвращают `%OpenApiSpex.Schema{}` события, сведения (`oneOf` + дискриминатор) и
  каждого вида сведения. Параметры передаются аргументами: название (последний сегмент модуля),
  схема `user_ref:` или `nil`, `labels?`, модули видов / ref на `<Имя>Detail`.
- В `quote` остаются оболочки модулей потребителя (сам модуль, `Detail` и модули видов в его
  пространстве — ADR-0064), `@behaviour OpenApiSpex.Schema`, атрибут с результатом вызова функции
  библиотеки и `def schema`. Как и сейчас, не `OpenApiSpex.schema/2`.
- Если у потребителя есть `OpenApiSpex`, а `Core.Web.Event.Schema` нет (`core` собран без
  `open_api_spex`), `use Core.Web.Event` даёт `CompileError` с подсказкой
  `mix deps.compile core --force`. Схема молча не пропадает.
- Сужение `to_wire/2` для `plain` и `labelled` порождается из одного атрибута полей (поле → guard).
  `labels: true` добавляет к нему `title` / `details`. Требования ADR-0014 и «Генерируемые функции»
  (`20-agreements.md`) сохраняются: `quote generated: true`, map собирается заново, а не
  возвращается переменной.
- `required` схемы события выводится из ключей `properties`.
- `@type t` / `@type labelled` и сборка map'ы в `to_wire/5` остаются вручную.
- Поиск в словаре ссылок — одна функция (например, `Details.name!/3` с описанием, что ищется). Тексты
  обоих отказов по смыслу сохраняются.
- Схема на wire не меняется: названия, `properties`, `required`, `oneOf`, `discriminator`, описания.

**Key interfaces:**
- `use Core.Web.Event`: опции и порождаемые `to_wire/2`, `schema/0`, `Detail` с модулями видов не
  меняются.
- `Core.Web.Event.Schema` — внутренний (`@doc false`), под `Code.ensure_loaded?(OpenApiSpex)`.
- Имя модуля вида не вычисляется в `lib/` через `Module.concat` без `# credo:disable-…` с причиной
  (`20-agreements.md`, «Атомы из внешних данных»). Проще передавать модули видов из `quote`.

**Acceptance criteria:**
- [ ] В `event.ex` нет литералов `%OpenApiSpex.Schema{}` / `OpenApiSpex.build_schema` внутри `quote`.
      Их строят функции `Core.Web.Event.Schema`.
- [ ] Новый тест вызывает функции `Core.Web.Event.Schema` напрямую, без `use Core.Web.Event`: событие
      без и с `user_ref:`, при `labels: true`, `Detail`, хотя бы один вид (`change`, `destroyed`).
- [ ] Список полей конверта в `event.ex` для сужения — один. `plain/0` и `labelled/0` не дублируют
      паттерн и сборку map'ы.
- [ ] Существующие тесты `test/core/web/event_test.exs` и `test/core/web/event/details_test.exs`
      зелёные без правок ожиданий.
- [ ] Тест (или ручная проверка, описанная в коммите): при `OpenApiSpex` без
      `Core.Web.Event.Schema` — `CompileError` с подсказкой о пересборке `core`.
- [ ] `name!` словаря ссылок определена один раз.
- [ ] `@moduledoc` `Core.Web.Event`, раздел «Схема» и «Сборку ломают»: добавлен отказ при `core`,
      собранном без `open_api_spex`.
- [ ] `CHANGELOG.md`, «Не выпущено» → «Изменения контракта макросов»: `use Core.Web.Event` у
      приложения с `open_api_spex` при `core`, собранном без него, — `CompileError`, а не схема.
      Почему: схема теперь живёт в условном модуле библиотеки (как у `Core.Web.Response.Schema`).
      Как править: `mix deps.compile core --force`.
- [ ] `make` зелёный, включая `compile-no-optional` и `consumer-check`.

**Out of scope:**
- Описания и типы полей схемы в общем списке полей: `properties` пишутся вручную.
- Порождение `@type t` / `labelled` из списка.
- Форма wire и схемы, имена опций `use`, дамп сведений (`Details.to_wire/4`), кроме `name!`.
- Новый ADR: решение укладывается в ADR-0064 / ADR-0065.

# Заметки тикета 01 для 02 и 03

## Где лежит признак уничтожаемости

- `%Core.Codec.Field{}` получил ключ `destroyable :: [Field.place()]` (в `@enforce_keys`): список мест внутри
  значения поля, где объявлено `destroyable: true`. Место — путь шагов: `[]` — само поле, `:list` — шаг в
  элемент `list:`, `:value` — шаг в значение `map:`. Пример: `matrix: [list: [list: [prim: N, destroyable: true],
  destroyable: true]]` → `destroyable: [[:list], [:list, :list]]`. Пусто — поле не уничтожаемо.
- Спека значения (`Field.spec`) не меняется: `destroyable:` снимается со спеки до её разбора
  (`pop_destroyable!/3` в `field!/4`), поэтому все обходчики спеки (`children/1`, `values/1`, плагин, подписи, View) его
  не видят.
- Во всех режимах, кроме `:struct`, ключ `destroyable` на любой глубине спеки даёт `CompileError` с префиксом
  поля (текст по режиму — `mode_text/1`);
  у `Core.View` — свой парсер (`Core.View.Opts.field!/4`), там отдельный отказ «destroyable: у View нет».
  Значит, у нормализованного поля плагина, нагрузки, подписей `destroyable` всегда `[]`.

## Как прочесть (02, `Core.Es.Cmd`)

- Поле команды уничтожаемо, если `field.destroyable != []`. Отдельной функции-предиката не заводил — проверка
  одна, у `Core.Es.Cmd`; если понадобится в двух местах, MAY завести `Field.destroyable?/1`.
- Обход вложенных сущностей: у поля `spec` вида `{:entity, mod}` (в том числе внутри `{:list, _}`,
  `{:set, _}`, `{:map, _, value}` — обходить через `Field.values/1`) → `Field.struct_fields(mod)` (nil — ручной
  struct, не проверяется) → рекурсивно по его полям. `{:union, _}` не обходится (спека, Out of Scope).
  Защита от цикла сущностей не нужна: `entity:` требует уже собранный модуль (`struct_module!`), поэтому
  сущность не может вложить себя ни прямо, ни через другую.

## Для 03 (`events:`)

- `Core.Struct.__using__` разбирает опции через `Helper.Opts.expand!` → `validate!` → `literal!`;
  `@optional_keys` сейчас `~w()a` — туда ляжет `events`.
- Плагин исключает ключ `events` из сверки по имени: `@skipped_keys ~w(__struct__ events)a` в
  `Core.Codec.Field` (`check_struct!/4`) — по спеке так и остаётся.
- `Field.typespec/1` теперь строит объединение справа (`union_type/1`: `A | (B | nil)`), чтобы
  `Macro.to_string` печатал тип плоско: `T | Destroyed.t() | nil`. Новое поле `events` в `@type t` добавляется в `Core.Struct` рядом с
  `typespec(@core_struct_fields)`, не через `Field`.

## Отступление от тикета

- В `docs/rules/23-personal-data.md` не написано «сборка этого не проверяет»: стандарт свода
  (`docs/rules/00-index.md`, «Оформление» — «отсутствие проверки не проговаривается») и `make rules-check`
  (`@unchecked` в `scripts/rules_lint.exs`) такую фразу запрещают. Вместо неё — ссылка «Почему разметку
  ставит автор, а не вывод по потоку значения, — ADR-0092, «Цена»», и у нормы нет строки `Проверяется:`.

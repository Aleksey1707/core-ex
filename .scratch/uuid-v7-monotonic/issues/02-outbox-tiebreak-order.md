# 02: Outbox: tiebreaker — порядок вставки

**What to build:** при равном `created_at` очередь отдаёт записи в порядке вставки, а не в
случайном порядке битов UUID. Контракт проверяется на шве репозитория: пачка записей с одним
`created_at` возвращается из `fetch_and_reserve` ровно в порядке добавления. Норма
`14-events-outbox` закрепляет MUST: генератор v7-id, которым пользуется `Outbox.ID`, строго
возрастает в пределах ноды, поэтому tiebreaker по `id` действителен; там же фиксируется
остаточный риск `created_at` (wall clock) и межнодовая граница. ADR-0003 и `@moduledoc`
миграции outbox называют гарантию явно. Схема, индексы, `order_by` и `es_events` не меняются.

**Blocked by:** 01

**Status:** resolved

- [x] Существующий тест «равный `created_at`» усилен: 100 записей с одним и тем же
      `created_at` добавляются в известном порядке, `fetch_and_reserve` возвращает id ровно в
      порядке вставки (не только «отсортированы»); на старой зависимости тест падает, на новой
      проходит.
- [x] Свод `14-events-outbox` содержит MUST: v7-генератор очереди строго возрастает в пределах
      ноды — каждый следующий вызов больше предыдущего, в том числе внутри одной миллисекунды и
      после отката системных часов; tiebreaker по `id` действителен только при этом условии.
- [x] Там же зафиксирован остаточный риск: `created_at` остаётся первичным ключом сортировки,
      откат NTP между вставками с разными отметками может инвертировать порядок, межнодовой
      монотонности нет.
- [x] ADR-0003 в «Последствиях» называет `id` UUIDv7 от монотонного в пределах ноды генератора;
      `@moduledoc` миграции outbox говорит «монотонен в пределах ноды». DDL не меняется.
- [x] Порядок `es_events`, схема `outbox`, состав индексов и `order_by` не менялись.
- [x] `make` зелёный целиком.

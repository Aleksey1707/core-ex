# 01: Верхняя граница потока в загрузке write-репозитория

**What to build:** внутренний путь загрузки write-репозитория event-sourced агрегата (`Core.Es.Aggregate.Repo.Pg`)
принимает необязательную верхнюю версию на поток: в свёртку идут события с версией не выше неё, снапшот
берётся только с версией не выше неё, иначе — свёртка с начала потока. Отдельным признаком загрузка
не пишет снапшоты. Без границы и признака путь ведёт себя ровно как сейчас. Подготовка к чтению состояния
на версии (спека `.scratch/state-at-version/spec.md`, ADR-0094); публичный API и поведение не меняются.

**Blocked by:** None (can start immediately).

**Status:** claimed

- [ ] Загрузка принимает верхнюю версию на каждый поток запроса; без неё читается до головы потока.
- [ ] С границей: события выше неё не читаются ни в запросе без снапшотов, ни в запросе со снапшотами, ни при перечитывании потоков отвергнутых снапшотов.
- [ ] С границей: снапшот новее границы не используется (поток — с начала), снапшот не выше — используется.
- [ ] Признак «не писать снапшоты» подавляет запись снапшотов после загрузки.
- [ ] `get`, `get_decision`, `get_many`, `refresh` границу и признак не передают; `Core.EsAggregateRepoContract` и тесты снапшотов проходят без правок.
- [ ] Публичных функций, колбэков и опций не добавлено; CHANGELOG не меняется.
- [ ] `make` зелёный.

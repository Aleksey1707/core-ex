# Codec-плагин по полям: `dump` / `load` из спеки полей

Type: spec
Status: ready-for-agent

Решение и отвергнутые варианты — ADR-0056 (`docs/adr/0056-codec-plugin-by-fields.md`); термин — `CONTEXT.md`,
«Codec-плагин по полям».

## Problem Statement

Автор приложения на `Core.*` на каждую сущность, агрегат и нагрузку события пишет Codec-плагин руками: `dump/2` —
map из полей через `codec.dump`, `load/3` — `with` по каждому полю через `codec.load(Prim, field(wire, :x))`, `cast`
для enum, сборка struct. У события с нагрузкой — ещё пара `dump_payload/2` / `load_payload/3` в `Event.Codec` и
модуль `Payload` с тривиальным `new`.

Замер на 2026-10-10 по потребителям A–F: 48 ручных плагинов на 89 типов (≈3000 строк кода) и 89 нагрузок событий
(≈930 строк клауз); из 178 типов и нагрузок 146 (82 %) повторяют поля один к одному — без переименований и без
пропусков полей. Этот код:

- **объёмен и однообразен** — читается и ревьюится как шаблон, ошибки в нём не видны глазом;
- **молча рассинхронизируется** — поле, добавленное в struct и забытое в плагине, не попадает в wire, и сборка
  этого не замечает;
- **дублируется** — у потребителя A десять событий копируют поля плагина value object в `dump_payload` вручную;
  потребитель C завёл собственный макрос-шаблон плагинов.

## Solution

Тип, чья wire-форма повторяет поля, объявляется спекой полей, а `dump` / `load` генерирует библиотека:

- сущность и агрегат — опция `fields:` у `use Core.Codec.Plugin`, по типу; struct остаётся ручным, сборка сверяет
  ключи спеки с его полями;
- нагрузка события — `use Core.Es.Event.Payload, fields: [...]` порождает struct, `new`, `@type t` и спеку;
  `Event.Codec` сам выводит клаузы нагрузки для нагрузки по полям, нагрузки-Prim и `Es.ValueChanged`;
- всё, что расходится с полями сильнее переименования ключа, остаётся ручным — в том же плагине для отдельных типов.

Для кода с ручными плагинами ничего не меняется: новые опции аддитивны.

## User Stories

1. As an автор агрегата, I want объявить кодек агрегата списком полей с их Prim, so that не писать `dump/2` и
   `load/3` руками.
2. As an автор агрегата, I want получать `CompileError`, если в struct есть поле, которого нет в спеке, so that
   добавленное поле не терялось в wire молча.
3. As an автор агрегата, I want получать `CompileError`, если в спеке есть поле, которого нет в struct, so that
   опечатка в имени поля ловилась при сборке.
4. As an автор агрегата, I want, чтобы поле `events` в сверке не участвовало, so that события шли только через
   `Event.Codec`, как сейчас.
5. As an автор агрегата, I want объявить `version` обычным полем `prim: Core.Version`, so that версия state-stored
   агрегата шла в wire так же, как сейчас.
6. As an автор плагина с несколькими типами, I want объявить по полям только часть типов, а остальные написать
   руками в том же плагине, so that не делить плагин агрегата на два ради одного нетривиального типа.
7. As an автор плагина, I want получать `CompileError`, если тип из `types:` не покрыт ни спекой, ни ручной
   клаузой, so that непокрытый тип не падал при исполнении.
8. As an автор плагина, I want получать `CompileError`, если ключ `fields:` не входит в `types:`, so that `types:`
   оставался единственным списком обслуживаемых типов.
9. As an автор плагина, I want объявить поле видом `prim:`, so that значение дампилось профилем фасада и
   загружалось своим Prim.
10. As an автор плагина, I want объявить поле видом `enum:`, so that при дампе уходил атом, а при загрузке
    значение проверялось `cast` enum-модуля.
11. As an автор плагина, I want объявить поле видом `entity:`, so that вложенная сущность дампилась и загружалась
    через фасад, а не через соседний плагин.
12. As an автор плагина, I want объявить поле видом `list:` с вложенной спекой, so that списки Prim, enum и
    сущностей шли поэлементно.
13. As an автор плагина, I want объявить поле видом `type:` (скаляр или `:map`), so that сырое значение без Prim
    проходило как есть.
14. As an автор плагина, I want пометить поле `optional: true`, so that `nil` проходил в обе стороны, а
    отсутствующий ключ давал `nil`.
15. As an автор плагина, I want задать `wire: "title"` у поля, so that переименование поля в коде не меняло
    записанный wire.
16. As an автор плагина, I want задать `default:` у поля, so that строки jsonb, записанные до появления поля,
    продолжали загружаться.
17. As an автор плагина, I want объявить по полям поле с sensitive Prim, so that хранимый хеш или токен шёл через
    тот же плагин, что и остальные поля.
18. As an автор плагина, I want получать `CompileError` на модуль в `prim:`, который не Prim, на модуль в `enum:`,
    который не `Core.Enum`, и на неизвестный вид поля, so that ошибка спеки называла поле и причину.
19. As an автор плагина, I want получать предупреждение сборки или `FunctionClauseError`, если значение поля не
    того Prim, что объявлен в спеке, so that ошибка спеки ловилась при первом dump, а не при чтении.
20. As an автор usecase, I want, чтобы `InCodec.load(Agg, wire)` плагина по полям был сужен до `{:ok, %Agg{}}`
    или `{:error, _}`, so that опечатка в поле загруженного значения ловилась при сборке (ADR-0014).
21. As an автор Schema, I want получать при загрузке первую ошибку поля, как от ручного `with`, so that разбор
    ошибок на call site не менялся.
22. As an автор Schema, I want, чтобы лишние ключи wire при загрузке игнорировались, so that строка, записанная
    более новым кодом, читалась старым.
23. As an автор агрегата, I want, чтобы загрузка собирала struct литералом, а не через `new`, so that
    восстановление записанного состояния не зависело от арности и проверок доменного конструктора.
24. As an автор плагина с `loadable: false`, I want объявить тип по полям, so that генерировался только `dump/2`.
25. As an автор события, I want объявить нагрузку `use Core.Es.Event.Payload, fields: [...]`, so that struct,
    `new`, `@type t` и кодек нагрузки брались из одной декларации.
26. As an автор агрегата, I want, чтобы `new` нагрузки по полям был позиционным в порядке объявления, so that
    вызовы `Event.X.draft(Event.X.Payload.new(...))` при переводе не менялись.
27. As an автор агрегата, I want, чтобы голова `new` нагрузки проверяла вид каждого поля, so that нагрузка не того
    типа ловилась при сборке вызывающего.
28. As an автор кодека событий, I want не писать `dump_payload` / `load_payload` для события с нагрузкой по полям,
    so that кодек содержал только нетривиальные клаузы.
29. As an автор кодека событий, I want не писать клаузы для события, чья нагрузка — Prim, so that такая нагрузка
    шла через фасад без кода.
30. As an автор кодека событий, I want не писать клаузы для нагрузки `use Core.Es.ValueChanged`, so that спека
    `old_value` / `new_value` выводилась из её `type:`.
31. As an автор кодека событий, I want получать предупреждение «clause will never match», если написал ручную
    клаузу для события, чья нагрузка выводится сама, so that два источника wire не уживались молча.
32. As an автор кодека событий, I want получать `CompileError` на `default:` в спеке нагрузки, so that развитие
    события шло новым тегом и апкастом (ADR-0010, ADR-0020), а не дефолтом.
33. As an автор кодека событий, I want, чтобы нагрузка по полям не регистрировалась в фасаде, so that реестр
    `codec_plugins/0` не рос на каждое событие.
34. As an автор кодека событий, I want, чтобы событие с нагрузкой value object (своим плагином) по-прежнему писалось
    руками одной строкой через фасад, so that поведение явного кода не менялось.
35. As an автор события, I want, чтобы конверт события с нагрузкой по полям совпадал по форме с ручным, so that
    перевод не менял wire в event store, outbox и брокере.
36. As an автор теста, I want, чтобы golden-фикстура события с нагрузкой по полям проверялась
    `Core.Es.EventCompatCase` как прежде, so that переименование поля нагрузки ловилось тестом.
37. As an автор теста, I want писать round-trip для плагина по полям так же, как для ручного, so that проверялось
    моё объявление, а не генератор.
38. As an ревьюер приложения, I want норму SHOULD «тип, совпадающий с wire один к одному, объявляется по полям», so
    that ручной плагин для такого типа был замечанием ревью.
39. As an мейнтейнер библиотеки, I want, чтобы регресс вывода типов в сгенерированном коде ловился
    `make consumer-check`, so that сужение результата не терялось незаметно.
40. As an мейнтейнер библиотеки, I want, чтобы спека плагина и спека `Core.View` делили только элементарные
    проверки, so that различия семантики не превращали общий модуль в развилку по режиму.
41. As an потребитель с собственным макросом-шаблоном плагинов, I want заменить его опцией `fields:`, so that не
    сопровождать свой генератор.

## Implementation Decisions

### Спека полей плагина

- Новый модуль спеки полей плагина рядом с `Core.Codec.Plugin`. Ключи — те же имена, что у `Core.View`: `prim:`,
  `enum:`, `list:`, `type:`, `optional:`; плюс `entity:`, `wire:`, `default:`. Форм (`form:`) и `jsonb:` нет.
- Общие с `Core.View.Opts` элементарные проверки (`ensure_compiled`, «модуль — Prim», «модуль — `Core.Enum`»)
  выносятся в общий хелпер; сам `Core.View.Opts` поведения не меняет.
- `prim:` — любой Prim, включая composite и кастомный kind; sensitive разрешён. Значение — Prim-структура (не голое,
  как у View): дамп `codec.dump/1`, загрузка `codec.load(Prim, raw)`.
- `enum:` — модуль `Core.Enum`; дамп — атом как есть; загрузка — `cast` (`cast_optional` при `optional:`).
- `entity:` — модуль struct, обслуживаемый фасадом; дамп `codec.dump/1`, загрузка `codec.load(Mod, raw)`. Что модуль
  зарегистрирован в фасаде, сборка плагина не проверяет — это делает фасад.
- `list:` — вложенная спека элемента; `optional:` задаётся у самого поля, не у элемента (как у View).
- `type:` — скаляры `Core.View` плюс `:map`; значение проходит как есть в обе стороны.
- `wire:` — строка; по умолчанию `Atom.to_string(field)`. Загрузка читает ключ через `Core.Helper.Map.field/2` — и
  строковый, и атомарный.
- `default:` — литерал, подставляется при загрузке, если ключа нет или он `nil`; поле с `default:` в обратную сторону
  дампится как обычно. Сочетание `default:` с `optional: true` — `CompileError` (два ответа на один `nil`).
- Ошибка спеки — `CompileError` с именем плагина, типа и поля.

### `use Core.Codec.Plugin, fields:`

- `fields:` — необязательная опция: список пар `{Type, spec}`; ключи — подмножество `types:`, повтор типа или ключ вне
  `types:` — `CompileError`.
- Сверка ключей спеки с полями struct типа (без `__struct__` и `events`) — после сборки модуля типа; расхождение в
  любую сторону — `CompileError` со списком лишних и недостающих.
- Типы вне `fields:` требуют ручных клауз `dump/2` (и `load/3` при `loadable: true`); тип без клаузы ни там, ни там —
  `CompileError` (расширение существующей проверки «требуется dump/2»). Если все типы плагина объявлены по полям,
  ручные `dump/2` / `load/3` не нужны.
- Сгенерированные клаузы и ручные — одна функция: сгенерированные встают так, чтобы ручная клауза на тип из
  `fields:` давала предупреждение «never match», а не молча побеждала. Механика (порядок, `@before_compile`) — на
  усмотрение реализации, критерий — отсутствие предупреждения о негруппированных клаузах у потребителя.
- Голова сгенерированного `dump/2` закрывает struct и каждое поле: `%Prim{}` / `%Mod{}` для `prim:` / `entity:`,
  `is_atom` для `enum:`, допуск `nil` при `optional:`, `is_list` для `list:`. Код — в `quote generated: true`
  (`docs/rules/20-agreements.md`, «Генерируемые функции»).
- Сгенерированный `load/3` собирает struct литералом `%Type{...}` после успешной загрузки всех полей; возвращает
  первую ошибку; лишние ключи игнорирует. Результат сужен паттерном `{:ok, %Type{}} | {:error, _}` — фасад уже
  сужает `load/2` по типам плагина, плагин по полям должен давать ту же форму.
- `loadable: false` — генерируется только `dump/2`; `default:` в таком плагине — `CompileError` (не применяется).
- `union:` с `fields:` совместим: варианты объявляются по полям, клауза `load(Family, ...)` пишется руками.

### `use Core.Es.Event.Payload`

- Новый билдер нагрузки события: `fields:` — та же спека полей, без `default:` (`CompileError`).
- Порождает `@enforce_keys` (все поля, кроме `optional:`), `defstruct`, `@type t` по видам полей, позиционный
  `new/N` в порядке объявления с головой по видам (как у `dump/2`), маркер со спекой для `Event.Codec`.
- Нагрузка по полям в фасаде не регистрируется: её кодирует `Event.Codec` события, которому она принадлежит.

### `Core.Es.Event.Codec`

- Для события, чья нагрузка (`__es_payload__/0`) — нагрузка по полям, Prim или `use Core.Es.ValueChanged`, кодек сам
  генерирует клаузы `dump_payload/2` / `load_payload/3`:
  - по полям — по её спеке, тем же генератором, что у плагина;
  - Prim — `codec.dump(payload)` / `codec.load(Prim, wire)`;
  - `Es.ValueChanged` — спека `old_value` / `new_value` из её `type:` (Prim → `prim:`, `Core.Enum` → `enum:`, иначе
    `entity:`), с `optional:` при `nilable: true`; для этого `Es.ValueChanged` отдаёт свой `type:` и `nilable:`
    интроспекцией.
- Сгенерированные клаузы встают перед ручными; ручная клауза для такого события — предупреждение «never match».
- Проверки полноты (`Core.Es.Check`) для событий с выведенными клаузами остаются и проходят без ручного кода.
- Остальные нагрузки — ручные клаузы, как сейчас.
- Конверт не меняется: нагрузка по полям даёт ту же map со строковыми ключами, что ручной `dump_payload`.

### Нормы и документация

- `docs/rules/11-domain.md`, «Codec (Prim и Entity)»: опция `fields:`, виды полей, сверка со struct, `default:`
  только в плагине, загрузка литералом, `Core.Es.Event.Payload` и выводимые клаузы `Event.Codec`.
- `docs/rules/app/11-domain.md`: SHOULD — тип, совпадающий с wire один к одному, объявляется по полям; ручной
  плагин — для расхождения сильнее переименования ключа. Правка `app/**` — тем же коммитом в `CHANGELOG.md`.
- `docs/rules/19-testing.md`, «Codec: round-trip»: round-trip обязателен и для плагина по полям; golden-фикстуры
  событий с нагрузкой по полям — как для ручных.
- `@moduledoc` `Core.Codec.Plugin`, `Core.Es.Event.Codec`, `Core.Es.ValueChanged`, нового `Core.Es.Event.Payload`.
- `CHANGELOG.md`, «Не выпущено»: «Новое» — плагин по полям и нагрузка по полям; «Изменения контракта макросов» —
  опция `fields:` у `use Core.Codec.Plugin`, выводимые клаузы `Event.Codec`. Ломающих изменений нет.

## Testing Decisions

Хороший тест проверяет внешнее поведение через фасад и сообщения сборки, а не устройство сгенерированного AST: какая
wire-map получилась, что вернул `load`, какой `CompileError` и какое предупреждение получил автор.

- **Фасад (основной шов).** Тестовый фасад с зарегистрированным плагином по полям: `dump/1` даёт ожидаемую wire-map;
  `load/2` — struct, равный исходному (round-trip), первую ошибку поля, `nil` по `optional:`, значение `default:`,
  чтение по `wire:`, `cast` enum и его отказ, `list:` и `entity:` через фасад, игнор лишних ключей; смешанный плагин
  (тип по полям и ручной тип). События — через тот же фасад: `dump(event)` / `load(Agg.Event, конверт)` с нагрузкой
  по полям, нагрузкой-Prim и `Es.ValueChanged`; конверт совпадает с конвертом ручного кодека той же нагрузки.
  Образец — `Core.Codec.FacadeTest`, фикстуры кодеков из `test/support`.
- **Ошибки сборки.** `Code.eval_quoted` → `CompileError`: поле struct без спеки и поле спеки без struct, ключ `fields:`
  вне `types:`, тип без спеки и без клаузы, не Prim в `prim:`, не enum в `enum:`, неизвестный вид, `default:` с
  `optional:`, `default:` при `loadable: false`, `default:` в нагрузке события. Образец — `Core.Codec.PluginTest`
  («плагин без dump/2»).
- **Вывод типов у потребителя.** `fixtures/consumer` с маркерами `# expect:` (`make consumer-check`): опечатка в поле
  результата `InCodec.load` плагина по полям, поле не того Prim в `dump`, нагрузка не того вида в `new` у `draft`,
  ручная клауза для события с выводимой нагрузкой — «never match»; плагин по полям без предупреждений в чистом коде
  фикстуры. Образец — существующие сценарии кодека событий фикстуры.
- **Golden-фикстуры.** Событие фикстуры с нагрузкой по полям проходит `Core.Es.EventCompatCase` — тот же шов фасада с
  сохранённым конвертом.

## Out of Scope

- Struct и кодек сущности или агрегата из одной декларации (вариант D) — отклонён в ADR-0056; пересмотр — по нужде в
  точном `@type t` агрегата.
- Декларативный разбор тега union (`tags:` у плагина) — ручная клауза `load(Family, ...)`.
- Словари `enum → Prim` / `Prim → Prim` (`map: {k, v}`) — ручные клаузы.
- Хелпер дампа без спеки.
- Ручное перекладывание колонок в wire-map в Schema (`to_entity` / `to_model`) — отдельная ветка после плагина по
  полям.
- `default:` у нагрузки события и любой иной обход тега и апкаста.
- Перевод кода потребителей: библиотека даёт опции и норму, переводят сами потребители.

## Further Notes

- Порядок работ: общая спека полей → плагин по полям → нагрузки событий. Нагрузки зависят от генератора клауз
  плагина.
- Нетривиальные типы замера (полиморфный логин, шифрование секретов `Core.Security.Secret`, сплющенные value
  object, вариантные struct) — сознательно ручные; спека не должна расти опциями ради них.

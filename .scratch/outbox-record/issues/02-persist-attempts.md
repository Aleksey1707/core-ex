# 02: `attempts` пишет запись, а не SQL

**What to build:** попытка инкрементится один раз — структурой записи; репозиторий сохраняет посчитанные
поля, а не повторяет арифметику инкрементом. Резервация по-прежнему увеличивает `attempts` в строке в
момент захвата, поэтому падение процесса до сохранения результата попытку учитывает. Батчевая запись
по группам одинаковых значений сохраняется, неразобранная строка остаётся SQL-инкрементом, схема и
кастомный репозиторий не меняются. Спека — `.scratch/outbox-record/spec.md`.

**Blocked by:** B1 (`01-record-requeue`).

**Status:** resolved

- [ ] Резервация пишет `attempts` из записи; второго инкремента той же попытки в репозитории нет.
- [ ] Сохранение результатов пишет lifecycle-поля из записи, без жёсткого обнуления токена и без пересчёта счётчика.
- [ ] Падение между резервацией и сохранением результата оставляет попытку учтённой (регрессионный тест).
- [ ] Fail-stop по-прежнему пишет три группы одним `UPDATE` каждая: опубликованный префикс, проваленная запись, возвращённый хвост.
- [ ] Неразобранная строка помечается `:failed` прежним SQL-инкрементом; поведение и лог не меняются.
- [ ] `requeue_failed` сбрасывает счётчики как документировано; схема и behaviour `Outbox.Repo` не меняются.
- [ ] Тесты машины переходов без базы и round-trip через `Repo.Pg` зелёные; `make` зелёный.

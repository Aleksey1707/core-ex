# 01: `requeue/2` и два смысла снятия аренды

**What to build:** возврат записи outbox в очередь после обработки назван отдельно от снятия резервации:
`Record.requeue/2` возвращает запись в `:new` и сохраняет токен аренды, потому что строка ещё будет
записана под прежней арендой; `Repo.release/2` снимает резервацию с фехтованием по токену и обнуляет
его. Разница зафиксирована в документации и тесте, чтобы следующий рефакторинг не «унифицировал» её
обратно. Старое имя остаётся помеченным `@deprecated`, публичный behaviour репозитория и схема не
меняются. Спека — `.scratch/outbox-record/spec.md`.

**Blocked by:** None (can start immediately).

**Status:** resolved

- [ ] `Record.requeue/2` — возврат в очередь: `status: :new`, `locked_until: nil`, токен аренды сохранён.
- [ ] `Record.release/2` — `@deprecated`-делегат на `requeue/2`; внутренние вызовы переведены, предупреждений сборки нет.
- [ ] `Repo.release/2` по-прежнему фехтует по токену и обнуляет `lease_id`; behaviour `Outbox.Repo` не меняется.
- [ ] Табличный тест переходов: `requeue` сохраняет токен, `Repo.release` его снимает; инвариант описан в документации обеих функций.

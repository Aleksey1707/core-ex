# Снапшот и процесс агрегата после уничтожения ключа

Type: grilling
Status: resolved
Blocked by: 06, 08
Map: [Crypto-shredding персональных данных в событиях :core](../map.md)

## Question

Как состояние агрегата, свёрнутое до уничтожения ключа, перестаёт хранить ПДн:

- снапшот — `term_to_binary` состояния с открытыми Prim, мимо кодека: шифровать, не писать снапшот агрегата с
  ПДн, удалять снапшоты затронутых потоков при уничтожении (нужна связь субъект → потоки);
- процесс агрегата держит состояние в памяти до `idle_timeout`, на нескольких нодах, API выгнать нет: остановка,
  перечитывание, проверка ключа на каждой команде;
- маркер снапшота и инвалидация: меняется ли что-то в `snapshot: [every:, version:]`;
- свёртка после уничтожения даёт состояние с уничтоженными значениями
  ([Уничтоженное ПДн-значение](06-grilling-destroyed-value.md)) — перечитанное состояние уже без ПДн.

## Answer

Решено в grilling 2026-10-18; нового ADR нет — снапшот и возраст кеша откатываются дёшево; дополнен
[ADR-0076](../../../docs/adr/0076-subject-key-destruction-final.md): процессам и снапшотам сигнал уничтожения не нужен.

- **Снапшот агрегата с ПДн в событиях** (поле с `subject:` хоть у одного события кодека):
  - допустим, только если у всех ПДн-полей событий `subject: :aggregate_id` — тогда состояние держит ПДн одного
    субъекта; снапшот целиком — одно ПДн-значение этого субъекта, шифрует и расшифровывает порт хранилища ключей,
    AAD — тип, id, версия и маркер; субъект в поле нагрузки — `snapshot:` запрещён, проверяет сборка;
  - `snapshot: [every:, version:]` и маркер не меняются; признак открытого и зашифрованного снапшота — в спеке;
  - отвергнуты: доли ключа снапшота под каждым субъектом состояния (готовых решений нет, нужен учёт субъектов);
    удаление снапшотов по индексу «субъект → потоки» (открытый текст остаётся в WAL и копиях); полный запрет
    (агрегат-лицо с длинным потоком — основной случай снапшотов, так же шифрует Akka).
- **Чтение снапшота** — одной пачкой с хвостом событий:
  - ключ уничтожен — `:rejected` на `debug`, полная свёртка, она даёт уничтоженные значения;
  - ключ неизвестен, тег не сошёлся, версия схемы неизвестна — `:rejected`, `Logger.warning`, полная свёртка:
    снапшот — кеш, `Core.Exc` нет;
  - хранилище не ответило — `{:error, %Error{kind: :app}}` вызывающему.
- **Запись снапшота** — шифруется всегда. Ключа у субъекта нет — порт создаёт его своим запросом после commit, вне
  транзакции `append`. Ключ уничтожен — отказ порта, снапшот не пишется, лог на `debug`; если чтение уже видело
  уничтоженный снапшот или значение, запись не пытается. Новый снапшот после уничтожения не появляется — поток
  сворачивается целиком (не проверено на нагрузке). Отвергнут открытый снапшот субъекта без ключа: признак «свёртка
  не видела ПДн» пришлось бы протащить через кеш процесса, гонка с первой записью ПДн открыла бы текст.
- **Процесс агрегата с ПДн в событиях** — предельный возраст кеша: состояние старше T выбрасывается, следующая
  команда идёт полным `get_decision`, а не `refresh`. T — опция процесса, по умолчанию 5 минут, `:infinity` для
  такого агрегата нельзя; возраст считается от последнего полного чтения, `refresh` его не обновляет;
  `idle_timeout` не меняется. Агрегат без ПДн — как раньше. Работает на всех нодах без извещения. Отказ записи ПДн
  из устаревшего состояния (`:subject_destroyed`) остаётся. Отвергнуты: без кеша (T = 0) — дороже без выигрыша в
  сроках; выгон по id с рассылкой — ПДн бывают в чужих потоках, нода за разрывом рассылку не получит.
- **Перечитанное состояние** — свёртка после уничтожения даёт уничтоженные значения, ПДн в нём нет.
- **Освобождённая память** — копии состояния до сборки мусора и незанулённые страницы — не форма, которую хранит
  `:core`, как swap и дамп памяти; не зануляется, GC не форсируется.

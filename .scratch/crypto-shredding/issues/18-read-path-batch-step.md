# 18: Пути чтения событий — через общий пакетный шаг

**What to build:** подготовительный рефакторинг без изменения поведения.
- Сейчас четыре пути чтения разбирают записанные строки по одной: свёртку и хвост со снапшотом, `page_stream`, пачку
  проекции и `Core.Es.Store.Test.events!/2`.
- После тикета их ведёт один пакетный шаг `Core.Es.Store`: «строки → wire-конверты → события (апкаст + `load`)», с
  политикой ошибок своего пути — safe или bang.
- Тикет 23 встраивает расшифровку `$pd` до апкаста и замену исключения апкастера в одно место, а не в четыре.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Spec:** [Crypto-shredding: ПДн в событиях под ключом субъекта](../spec.md) — «Чтение: пакетная расшифровка в
`Core.Es.Store`», Further Notes («Предлагаемый порядок срезов»)

- [ ] Шаг принимает пачку строк целиком, а не по одной: на его входе потом встанет один запрос в хранилище ключей на
      пачку.
- [ ] Через шаг идут свёртка и хвост со снапшотом в `Core.Es.Aggregate.Repo.Pg` — включая полную свёртку после
      отвергнутого снапшота, — а также `page_stream`, пачка проекции и `Core.Es.Store.Test.events!/2`.
- [ ] Политика ошибок прежняя:
      - свёртка и `events!` — `Core.Exc`;
      - `page_stream` — первая ошибка `load` на всю страницу;
      - проекция — пропуск необъявленного тега без `load`, ошибка ведёт в retry.
- [ ] Публичный API, telemetry и логи не меняются. `CHANGELOG.md` не трогается: изменение внутреннее.
- [ ] Нынешние тесты хранилища, репозиториев обоих видов, снапшотов и проекций зелёные без правок.
- [ ] `make` зелёный.

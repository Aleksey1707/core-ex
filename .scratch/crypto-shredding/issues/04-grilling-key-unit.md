# Единица ключа и субъект данных

Type: grilling
Status: resolved
Blocked by: 02
Map: [Crypto-shredding персональных данных в событиях :core](../map.md)

## Question

Чьи данные стираются одним уничтожением ключа:

- единица ключа — субъект данных (физическое лицо, чьи ПДн встречаются в потоках нескольких агрегатов), поток
  агрегата или поле; что теряется при каждом выборе (ПДн одного лица в чужом потоке, частичное уничтожение);
- откуда берётся идентификатор субъекта: id агрегата, поле нагрузки, отдельное значение; может ли одно событие
  нести ПДн нескольких субъектов;
- термины в `CONTEXT.md`: субъект данных, ключ субъекта, уничтожение — и их отличие от `sensitive:` и
  `Core.Security.Secret`.

Решение — кандидат в ADR.

## Answer

Решено в grilling 2026-10-18; ADR — [ADR-0072](../../../docs/adr/0072-key-per-data-subject.md), термины —
`CONTEXT.md`, «Персональные данные».

- **Единица ключа — субъект данных**, физлицо: один ключ закрывает его ПДн в любом потоке. Поток — частный
  случай (субъект = `aggregate_id`), поле — отвергнуто (сводится к субъекту плюс индекс).
- **Один ключ на субъекта**, уничтожение только целиком. Ключи по целям обработки (частичное уничтожение по
  ст. 21 ч. 4) — вне карты; путь к ним оставляет требование «шифротекст называет свой ключ».
- **Операция — «уничтожение ключа субъекта»**; «удаление», «стирание», «забвение», «shred» — не употребляются.
- **Идентификатор субъекта** — значение `Prim.UUID` или `Prim.Compose` над ним (проверка сборкой); субъекта
  различает UUID, а не тип Prim. Берётся из самого события: `aggregate_id` или явно объявленное поле
  нагрузки — не `%Context{}`, не метаданные, не `by`. Лежит открыто, сам не ПДн. Два несвязанных
  идентификатора одного лица — два субъекта.
- **Привязка — на событие**, не на поток: смена владельца не перешифровывает историю.
- **Несколько субъектов в событии** допускаются, у каждого ПДн-значения ровно один; смешанное значение
  (свободный текст) не делится — субъекта выбирает автор события.
- **ПДн-значение без субъекта** (`nil` в поле-субъекте) не пишется — ошибка программиста.
- **Отличие от соседних терминов:** чувствительный Prim (`sensitive:`) скрывает значение в логах и ошибках,
  `Core.Security.Secret` — конфиденциальность одним общим ключом; ни то, ни другое данные не уничтожает.

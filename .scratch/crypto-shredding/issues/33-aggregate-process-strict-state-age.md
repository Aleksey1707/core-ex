# 33: Процесс агрегата с ПДн: строгая граница памяти и граница `format_status/1`

**What to build:** процесс агрегата с ПДн, у которого нет команд, уходит, как только его состояние устарело, — память
ноды держит ПДн уничтоженного субъекта не дольше `state_max_age:`, а не `state_max_age + idle_timeout`. Своды честно
говорят, что `format_status/1` скрывает состояние и последнее сообщение, а `reason` и стек с аргументами кадра идут
как есть.

**Blocked by:**
- [25: Процесс агрегата с ПДн: предельный возраст кеша](25-aggregate-process-state-max-age.md)

**Status:** resolved

**Spec:** [Crypto-shredding: ПДн в событиях под ключом субъекта](../spec.md) — «Процесс агрегата», «Наблюдаемость»
(«Граница гарантии»); ADR-0076

- [x] Таймаут процесса на id — меньшее из `idle_timeout` и остатка до устаревания состояния; без состояния или при
      `state_max_age: :infinity` — `idle_timeout`, поведение прежнее.
- [x] По таймауту с устаревшим состоянием процесс уходит `{:stop, :normal}` той же веткой, что уход по простою, с
      `debug` «состояние устарело»; уход по простою — прежний лог. Нового сообщения и таймера нет.
- [x] Остаток до устаревания — чистая функция рядом с `stale?/3` (от времени полного чтения, текущего времени и
      предела), тест — таблицей исходов без процесса.
- [x] Тест процесса: `:sys.replace_state` сдвигает отметку полного чтения — процесс без команд уходит раньше
      `idle_timeout`; `refresh` отметку не обновляет и уход не откладывает.
- [x] Сброс устаревшего состояния перед командой остаётся: под нагрузкой таймаут не наступает.
- [x] Граница `format_status/1` — в moduledoc `Core.Es.Aggregate.Process`, `13-repos.md` «Процесс агрегата»,
      `21-observability.md` «Персональные данные в выводе», `23-personal-data.md` «Состояние в памяти»:
      - скрыты состояние и последнее сообщение;
      - `reason` и стек — как есть: аргументы верхнего кадра печатают отчёт процесса, отчёт супервизора и exit
        вызывающего; ПДн в них скрывает `Inspect` Prim с `personal: true`;
      - в «Состоянии в памяти» — память держит ПДн не дольше `state_max_age:`, без оговорки про `idle_timeout:`.
- [x] app/23 «Персональные данные в выводе»:
      - факт: отчёт о падении любого процесса (процесс агрегата, usecase в Plug, Task, подписчик) печатает аргументы
        кадра стека; Prim в них скрыт, извлечённое значение — открыто;
      - SHOULD: приватные helper'ы `decide` / `evolve` / `project` принимают ПДн Prim'ом, а не извлечённым значением;
        значение извлекается в выражении, где оно нужно.
- [x] `CHANGELOG.md` — дополнить существующий абзац о процессе агрегата в сквозном пункте «Новое», нового пункта
      не заводить.
- [x] `make` зелёный.

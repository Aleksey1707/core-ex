# 25: Процесс агрегата с ПДн: предельный возраст кеша

**What to build:** процесс агрегата с ПДн в событиях выбрасывает закешированное состояние старше `state_max_age:` (по
умолчанию 5 минут) и следующую команду начинает полным чтением. Поэтому память ноды держит ПДн уничтоженного субъекта
не дольше этого срока, и процессы извещать не нужно. Отчёт о падении такого процесса не печатает его состояние.

**Blocked by:**
- [21: ПДн-поле нагрузки: `subject:`, маркер и уничтоженное значение в кодеке](21-payload-subject-marker.md)

**Status:** resolved

**Spec:** [Crypto-shredding: ПДн в событиях под ключом субъекта](../spec.md) — «Процесс агрегата»; ADR-0076

- [x] Опция старта `state_max_age:` в мс, как `idle_timeout:`:
      - у агрегата с ПДн (по `__es_subjects__/0` кодека) — 300 000 по умолчанию; `:infinity` — `ArgumentError` на
        старте;
      - у агрегата без ПДн — `:infinity`, поведение прежнее.
- [x] Возраст считается от последнего полного `get_decision`, `refresh` его не обновляет. Состояние старше предела
      выбрасывается, и команда идёт полным `get_decision`.
- [x] «Состояние устарело» — чистая функция от времени полного чтения, текущего времени и предела; тест — таблицей
      исходов без процесса.
- [x] Тест процесса: `:sys.replace_state` сдвигает отметку полного чтения, затем проверяется, что идёт полный
      `get_decision` и что `refresh` отметку не обновляет.
- [x] `format_status/1` процесса агрегата с ПДн: вместо состояния — тип, `aggregate_id` и версия, вместо последнего
      сообщения — модуль команды, `reason` как есть. Остальные агрегаты — как сейчас. Есть тест.
- [x] Режим `enabled: false` не меняется.

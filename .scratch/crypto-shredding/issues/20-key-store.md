# 20: Хранилище ключей: порт и встроенная реализация

**What to build:** библиотека даёт порт `Core.Es.Personal.KeyStore` и его рабочую встроенную реализацию по умолчанию —
`Core.Es.Personal.KeyStore.Pg`.

- **Порт** работает пачками: шифрует, расшифровывает, считает индекс и уничтожает ключ субъекта. Ключ субъекта порт
  не покидает.
- **Встроенная реализация:**
  - таблица в базе событий;
  - ключ субъекта под KEK из конфигурации;
  - AES-256-GCM из `:crypto`;
  - без кеша.

Проверка — `Core.Es.Personal.KeyStoreCase` на встроенной реализации и golden схемы `1`. Записи событий порт пока не
касается — её подключает тикет 23.

**Blocked by:** [19: Персональный Prim: `personal: true`](19-personal-prim.md)

**Status:** resolved

**Spec:** [Crypto-shredding: ПДн в событиях под ключом субъекта](../spec.md) — «Порт хранилища ключей», «Встроенная
реализация», «Наблюдаемость» (telemetry), «Тестовая поддержка в `lib/`»; ADR-0075, ADR-0077 (индекс)

- [x] Behaviour из четырёх операций — `seal`, `open`, `index`, `destroy`; формы — спека, «Порт хранилища ключей».
      Общие правила:
      - ответ идёт в порядке пачки;
      - сбой хранилища — `{:error, %Error{kind: :app}}` на всю пачку.

      Исходы операций:
      - `open` — `{:ok, _} | :destroyed | :unreadable` на элемент;
      - уничтоженный субъект в `seal` — `%Error{kind: :domain, ns: :key_store, code: :subject_destroyed}`:
        константный текст, в `detail` — субъект, без идентификатора ключа.
- [x] `Core.Config.key_store/0` резолвит реализацию в рантайме по конвенции `<Behaviour>.Pg`. Подмена —
      `config :core, Core.Es.Personal.KeyStore, MyImpl`. `Core.Config.validate!/0` проверяет экспорт колбэков.
- [x] Внутренний фасад `Core.Es.Personal` над портом эмитит telemetry на каждый вызов:
      - `[:es, :personal, :call]` — измерение `duration`, метаданные `op` и `result` (`ok | refused | error`);
      - `[:es, :personal, :open]` — `count` по `outcome` (`opened | destroyed | unreadable`).

      Меток с идентификаторами субъекта, ключа и агрегата нет.
- [x] `Core.Es.Personal.KeyStore.Migration` (`up/0` / `down/0`) создаёт `es_subject_keys`:
      - идентификатор ключа (PK);
      - субъект (полный уникальный индекс);
      - обёрнутый ключ (`NULL` у следа);
      - версия KEK;
      - время создания и время уничтожения.

      Тестовые миграции библиотеки вызывают эту миграцию.
- [x] Шифр схемы `1`:
      - ключ субъекта — 32 случайных байта;
      - значение — AES-256-GCM: nonce 12 байт, тег 16 байт, длина тега проверяется при расшифровке;
      - раскладка `версия ‖ идентификатор ключа ‖ nonce ‖ ct ‖ tag`, AAD — заголовок и адрес;
      - обёртка ключа — AES-256-GCM под KEK, AAD — идентификатор ключа и версия KEK.
- [x] `seal`:
      - строки ключей пачки читаются `FOR SHARE`;
      - недостающие ключи создаются вставкой пачки в порядке сортировки субъектов с `on_conflict: :nothing`, затем
        перечитывание и один повтор; не помогло — `:key_unresolved` (`:app`);
      - всё идёт в транзакции вызывающего, и откат убирает ключ.
- [x] `open`:
      - один запрос на пачку;
      - строка-след → `:destroyed` при любой версии KEK;
      - неизвестный ключ, несошедшийся тег, неизвестная версия схемы → `:unreadable`;
      - версии KEK нет в конфигурации → `:kek_unknown` (`:app`) на всю пачку.
- [x] `destroy` — `INSERT … ON CONFLICT (subject) DO UPDATE`:
      - обёрнутый ключ стирается, первая дата уничтожения сохраняется;
      - субъект без ключа получает строку-след;
      - повтор — `:ok`.
- [x] `index` — HMAC-SHA256 секретом индекса над областью и частями в однозначной кодировке, результат в hex.
- [x] Запросы с обёрнутым ключом идут с `log: false`; кеша ключей нет.
- [x] Конфигурация — `keks:` (набор версий по 32 байта), `current_kek:`, `index_secret:` (32 байта). Сборка её не
      требует. `ensure_configured!/0` проверяет только форму: `current_kek` в наборе, длины, уникальность версий,
      наличие секрета; к базе не обращается. Если конфигурация не задана — `raise` на первой операции.
- [x] `use Core.Es.Personal.KeyStoreCase, impl: …` лежит в `lib/`; библиотека гоняет его на `KeyStore.Pg`. Case
      проверяет:
      - пачку туда-обратно;
      - `:destroyed` после `destroy`;
      - `:unreadable` на чужом ключе и изменённом AAD (`event_id`, wire-ключ);
      - `:subject_destroyed` в `seal` после уничтожения;
      - след у субъекта без ключа;
      - `:ok` на повтор;
      - детерминизм `index` и различение области и частей.
- [x] Тесты встроенной реализации:
      - «хранилище не ответило»;
      - `:kek_unknown`;
      - откат ключа вместе с транзакцией;
      - `ensure_configured!/0`.

      Гонки — `ExUnit.Case, async: false`, `unboxed_run` с настоящими commit:
      - создание ключа одного субъекта двумя транзакциями;
      - `seal` против `destroy` одного субъекта: зашифрованное до commit уничтожения читается как `:destroyed`,
        после — отказ `:subject_destroyed`.
- [x] Golden:
      - строка ключа и `$pd` схемы `1` под KEK-литералом фикстуры расшифровываются в известный текст;
      - индекс фиксированных области и частей — фиксированный hex.
- [x] Тестовая конфигурация — литералы `config/test.exs`: набор KEK с `current_kek` и секрет индекса.

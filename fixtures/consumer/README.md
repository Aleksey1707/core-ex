# Фикстура-потребитель

Приложение на `Core`, которое видит библиотеку зависимостью (`{:core, path: "../.."}`), — так же, как
её видит настоящий потребитель. Держит храповик вывода типов (ADR-0014): предупреждения компилятора
фикстуры сверяются с маркерами в её исходниках. Шаг `make consumer-check` падает, если ожидаемое
предупреждение пропало или появилось лишнее.

Зачем отдельный проект: внутри самой библиотеки её модули для компилятора — «тот же проект», и
сигнатуры `Core.*` в выводе не участвуют. Картину потребителя даёт только зависимость.

## Состав

- `lib/consumer/**` — корректный потребитель: агрегаты `Account` (кодек с `upcasts:`), `Order`,
  `Ping` (кодек только из событий без нагрузки), `Grants` (два события делят модуль нагрузки),
  `NeverFails` и `AlwaysFails` (`decide` никогда не ошибается / только ошибается), события `Parcel`
  без агрегата (кодек, чей `load_payload/3` никогда не ошибается), репозитории, процесс, проекция на
  события двух агрегатов, фасад Codec с dump-only плагином и `Usecase` с типовыми вызовами.
  Собирается без единого предупреждения — это страховка от ложных срабатываний.
  «Корректный» здесь — по типам: `@doc` и `@spec` не пишутся, на вывод типов они не влияют, а Credo и
  линтеры библиотеки фикстуру не проверяют.
- `lib/scenarios/**` — сценарии: функция или модуль на одну ошибку, над ошибочной строкой маркер.
  Коды сценариев (A3, E4b, …) — из `.scratch/es-type-safety/research/02-core-es-blind-spots.md`;
  буква после номера — вариант сценария карты (`B1p` — B1 с нагрузкой другого агрегата литералом).
- `check.exs` — сверка, `selftest.sh` — её самопроверка.

Версии зависимостей берутся из `mix.lock` библиотеки (`lockfile:`), сборка — в своём `_build`
(окружение `dev`): `_build` и lock библиотеки шаг не трогает.

## Запуск

```bash
make consumer-check                                   # из корня библиотеки

cd fixtures/consumer
mix deps.get                                          # первый раз; без сети — HEX_OFFLINE=1 из кеша hex
mix run --no-start --no-compile check.exs             # сверка
mix run --no-start --no-compile check.exs --dump      # все предупреждения: file:line: заголовок [функция]
bash selftest.sh                                      # самопроверка сверки
```

Сверка пересобирает изменённый core сама. Dialyzer на фикстуре не запускается.

`selftest.sh` проверяет четыре исхода и откатывает свои правки: исходное состояние — `ok`; маркер над
строкой без предупреждения — провал; предупреждение без маркера — провал; сдвиг строк на семь — `ok`.

## Маркер

```elixir
# A3 — состояние другого агрегата
def a3_foreign_state(%Order{} = state, %Account.Cmd.Open{} = command),
  # expect: incompatible types given to Consumer.Account.execute/2
  do: Account.execute(state, command)
```

- Маркер — отдельная строка `# expect: <начало заголовка>` над строкой, на которую указывает
  предупреждение; комментарии и пустые строки между ними допустимы, несколько маркеров подряд
  относятся к одной строке.
- Сверяется начало первой строки сообщения, а не текст целиком: сообщения компилятора — не контракт.
- Строку предупреждения показывает `--dump`: у многострочного вызова это строка самого вызова или
  clause, а не строка `def`.

## Как добавить сценарий

1. Одна ошибка — одна функция или модуль в `lib/scenarios/`, комментарий с кодом сценария.
2. `mix run --no-start --no-compile check.exs` — новое предупреждение придёт как «лишнее» с файлом,
   строкой и заголовком.
3. Поставить маркер над этой строкой и прогнать сверку ещё раз.

Сценарий, который компилятор пропускает, в фикстуру не добавляется: храповик держит только ожидаемые
предупреждения. Правка библиотеки, которая делает такую ошибку видимой, добавляет сценарий вместе с
маркером. При подъёме версии Elixir `make consumer-check` — первый шаг, который надо прогнать.

# Персональные данные приложения

- **Область.** `lib/my_app/**`: код, который извлекает ПДн-значение из Prim (`Prim.value/1`,
  `raw/1`, сопоставление `%Mod{value: v}`) и выводит его.
- **Читать перед.** Логом, исключением или атрибутом span'а рядом с ПДн; новым Prim с ПДн;
  usecase уничтожения ключа субъекта.
- **Словарь.** Плейсхолдеры и модальность — `deps/core/docs/rules/00-index.md`; термины —
  `deps/core/CONTEXT.md`, «Персональные данные».

Разметку `personal: true` и то, что библиотека скрывает сама, нормирует
`deps/core/docs/rules/23-personal-data.md`. Здесь — то, что остаётся на приложении.

## Usecase уничтожения

Ключ субъекта уничтожает usecase приложения одним вызовом
`Core.Es.Personal.destroy_key(subject_id, by, context)`; операция, её исходы и событие уничтожения
ключа — `deps/core/docs/rules/23-personal-data.md`, «Уничтожение ключа субъекта».

- Права на уничтожение usecase MUST проверять сам, до транзакции: библиотека прав не знает.
- `by` MUST браться из `CurrentUser.get(context)` до транзакции — как `by` команды
  (`10-architecture.md`, «Usecases»): `%Context{}` библиотека не читает.
- Уничтожение ключа и всё, что приложение делает с данными субъекта, MUST идти одной транзакцией
  `Transact.run(DAO, …)`:
  - событие-акт своего агрегата — причина, автор, категории ПДн для акта: событие библиотеки их не
    несёт, а журнала уничтожений у библиотеки нет;
  - снятие резервов ключа из ПДн — событием потребителя;
  - чистка строк state-stored агрегатов и таблиц, которые не принадлежат проекциям, — обычным
    `update` / `delete`.

  Таблицы read-модели usecase не трогает: их чистит проекция по событию уничтожения ключа.
- Отказ `:subject_destroyed` (`ns: :key_store`, `:domain`) на записи ПДн уничтоженного субъекта
  usecase записи MUST отображать сам — доменным ответом клиенту; повторять команду по нему MUST
  NOT: отказ окончательный.
- Повторное согласие лица MUST получать новый идентификатор субъекта — новый агрегат или новое
  поле-субъект: ПДн прежнего субъекта после уничтожения не пишутся.

```elixir
# плохо — уничтожение отдельной транзакцией: акт и чистка строк не атомарны с ключом
def forget(%<Aggregate>.ID{} = id, %Context{} = context) do
  with {:ok, by} <- CurrentUser.get(context),
       :ok <- Personal.destroy_key(id, by, context),
       do: write_act(id, by, context)
end

# хорошо
def forget(%<Aggregate>.ID{} = id, %Context{} = context) do
  with :ok <- check_user(~w(forget)a, context),
       {:ok, by} <- CurrentUser.get(context) do
    Transact.run(DAO, fn ->
      with :ok <- Personal.destroy_key(id, by, context),
           do: write_act(id, by, context)
    end)
  end
end
```

## Вывод

Библиотека скрывает ПДн-значение, пока оно в своей форме — Prim с `personal: true`. Извлечённое
значение — строка, число, дата — уже не Prim, и `Inspect` его не скрывает.

- Извлечённое ПДн-значение MUST NOT попадать в текст `raise`, в `Logger.*` и в атрибут span'а.
- Вместо значения выводится идентификатор агрегата или субъекта, длина или признак наличия.
- Prim с ПДн целиком в `Logger.*` и в `inspect/1` MAY: значение скрывает его `Inspect`.
- Отчёт о падении любого процесса — процесса агрегата, usecase в Plug, `Task`, подписчика —
  печатает аргументы верхнего кадра стека: Prim в них скрыт, извлечённое значение — открыто.
  Приватные helper'ы `decide` / `evolve` / `project` SHOULD принимать ПДн Prim'ом, а не
  извлечённым значением: значение извлекается в выражении, где оно нужно.

```elixir
# плохо — телефон уходит в лог и в службу учёта ошибок открытым
Logger.warning("контакт не принят: phone=#{Phone.value(phone)}")
raise ArgumentError, "неверный телефон #{Phone.value(phone)}"

# хорошо
Logger.warning("контакт не принят: client_id=#{InCodec.dump(client.id)}")
raise ArgumentError, "неверный телефон: client_id=#{InCodec.dump(client.id)}"

# плохо — FunctionClauseError helper'а evolve печатает извлечённый телефон аргументом кадра
defp put_phone(state, phone) when byte_size(phone) == 12, do: %{state | phone: phone}
put_phone(state, Phone.value(payload.phone))

# хорошо — аргумент кадра — Prim, значение скрывает его Inspect
defp put_phone(state, %Phone{} = phone), do: %{state | phone: phone}
put_phone(state, payload.phone)
```

## Эксплуатация

Встроенное хранилище ключей (`Core.Es.Personal.KeyStore.Pg`) шифрует AES-256-GCM из `:crypto` —
это не СКЗИ (ADR-0075). Оператор MUST оценить его достаточность по своей модели угроз до первой
записи ПДн; требование сертифицированного средства закрывает своя реализация порта
(`deps/core/docs/rules/23-personal-data.md`, «Своя реализация порта»).

KEK и секрет индекса MUST храниться вне базы событий и её копий — в хранилище секретов
приложения, и копироваться отдельно от базы.

### Ротация KEK

Новый KEK вводится двумя выкладками и перевёрткой (`deps/core/docs/rules/23-personal-data.md`,
«Перевёртка и статус»). Порядок MUST:

1. новый KEK — версией в `keks:` на все ноды, `current_kek:` прежний;
2. `current_kek:` — на новую версию, на все ноды;
3. перевёртка — `mix es.personal.rewrap` из корня приложения, в релизе — `rewrap/1` и `status/0`
   из задачи релиза через `bin/my_app eval`; прерванный прогон продолжается повторным запуском,
   а `:kek_unknown` не пройдёт, пока версия строки не вернётся в `keks:`;
4. когда под старой версией ноль, старый KEK удаляется из `keks:` и хранилища секретов — не
   раньше, чем истекут копии базы, нужные для восстановления.

```text
# плохо — current раньше выкладки KEK: отставшие ноды не разворачивают новые ключи (:kek_unknown)
keks + current_kek одной выкладкой → rewrap

# плохо — KEK удалён при живых копиях старше перевёртки: их восстановление теряет все ключи
rewrap → status: 0 → удалить KEK

# хорошо
keks на все ноды → current_kek на все ноды → rewrap → status: 0 → копии истекли → удалить KEK
```

Задача релиза поднимает репозиторий сама: Mix в релизе нет, ответ оператору — `IO.puts`.

```elixir
alias Core.Es.Personal.KeyStore.Pg

def rewrap_keks do
  Application.load(:my_app)

  {:ok, result, _apps} =
    Ecto.Migrator.with_repo(MyApp.Infra.DAO, fn _dao ->
      with {:ok, count} <- Pg.rewrap(on_batch: &IO.puts("перевёрнуто: #{&1}")),
           {:ok, status} <- Pg.status(),
           do: {:ok, count, status}
    end)

  IO.puts(inspect(result))
end
```

Удаление старого KEK — дополнительная мера против следов уничтоженных ключей в копиях, WAL-архиве
и мёртвых кортежах; основная — повтор уничтожения по актам («Восстановление копии»). Период
ротации библиотека не задаёт.

### Секрет индекса

Секрет индекса не ротируется: версии и функции пересчёта резервов нет, и живёт он, пока живут
области ключа с `personal: true` (ADR-0077). Хранится и копируется он наравне с KEK (выше): его
утрата ломает поиск и уникальность прежних резервов.

При компрометации секрета приложение MUST перевести резервы ключей из ПДн на новую область ключа
(ADR-0077): смена секрета поверх прежних резервов ломает их поиск и уникальность. Перевод области —
перевод приложения.

```text
# плохо — новый секрет поверх прежних резервов: find/2 их больше не находит, уникальность потеряна
index_secret: новый

# хорошо
компрометация → новая область ключа с personal: true → перевод резервов
```

### Восстановление копии

Копия базы, WAL-архив и реплика держат обёрнутые ключи, уничтоженные после точки копии: пока жив
KEK их версии, восстановление воскрешает ПДн. После восстановления базы событий из копии оператор
MUST повторить уничтожение ключей всех субъектов из актов, составленных позже точки копии:

1. восстановить базу (`es_events` и `es_subject_keys` — вместе);
2. до приёма трафика выгрузить из журнала актов субъектов, уничтоженных после точки копии;
3. для каждого — usecase уничтожения ключа субъекта; повтор идемпотентен и первой даты не меняет;
4. только после этого открыть приложение на запись.

```text
# плохо — приложение открыто сразу: ПДн субъектов из поздних актов снова читаются
restore → start

# хорошо
restore → повтор уничтожения по актам после точки копии → start
```

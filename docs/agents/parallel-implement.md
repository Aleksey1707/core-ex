# Параллельная реализация тикетов

Skill `implement` (mattpocock-skills) помечен `disable-model-invocation: true`: агент вызвать его не может.
Его инструкции — несколько строк, поэтому параллельная реализация идёт субагентами в worktree, а текст
`implement` передаётся им в промпте.

## Порядок

1. **Фронт.** Берутся тикеты `.scratch/<feature>/issues/*.md` со `Status: ready-for-agent`, у которых все
   `Blocked by` — `resolved`.
2. **Группы по пересечению файлов.** Тикеты, которые правят один и тот же файл (модуль `lib/`, свод
   `docs/rules/*.md`, `CHANGELOG.md`), отдаются одному агенту последовательно. Остальные — по агенту на тикет.
3. **Инфраструктура.** `make infra-up` до запуска; Postgres / RabbitMQ / Kafka общие для всех worktree.
4. **Запуск.** Все агенты одним сообщением: `Agent` с `isolation: "worktree"`. Промпт агента содержит:
   - абсолютный путь к тикету в основном дереве — неотслеживаемых тикетов в worktree нет;
   - первым шагом `git reset --hard <текущая ветка основного дерева>`: worktree создаётся от `master`, а не от
     ветки, на которой идёт работа;
   - копирование `deploy/infra/.env` из основного дерева в worktree до первого `make`: файл не в git, а без
     него `make infra-up` поднимает второй стек на портах по умолчанию, занятых инфраструктурой потребителя;
   - `make DOCKER=true`: `infra-up` из worktree пересоздаёт контейнеры `core-infra` (compose-файл по другому
     пути) и роняет тесты соседних агентов, а `DOCKER=true` делает его no-op;
   - коммит с `SKIP=mix-test` после зелёного `make`: хук pre-commit гоняет `mix test`, а параллельные прогоны
     упираются в `too_many_connections` общего Postgres; падения `econnrefused` / `too_many_connections` /
     `admin_shutdown` перепроверяются `mix test --failed`;
   - `MIX_TEST_PARTITION=<N>`, уникальный на агента (`1`, `2`, …): тестовая база —
     `core_test#{MIX_TEST_PARTITION}` (`config/test.exs`), иначе параллельные `mix test` делят одну БД;
   - инструкции `implement`: skill `mattpocock-skills:tdd` на швах тикета, `mix compile` и отдельные
     тест-файлы по ходу, `make` целиком в конце, затем skill `mattpocock-skills:code-review` и исправление
     найденного;
   - коммит в ветку своего worktree вместе с тикетом (`Status: resolved`), без слияния; в отчёте — ветка,
     что сделано, что не сделано и почему.
5. **Основное дерево не трогается**, пока агенты работают.
6. **Слияние.** Ветки по очереди сливаются в текущую ветку, конфликты разрешаются при слиянии; после
   последней — `make` в основном дереве.

## Цена

В каждом worktree свой `_build` и свой PLT dialyzer: первый `make` в каждом — полная сборка.

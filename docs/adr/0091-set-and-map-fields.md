# Поле-множество и поле-словарь: виды `set:` и `map:` в спеке полей

Спека полей (`Core.Codec.Field`) получает два вида значения: `set: <спека элемента>` и
`map: [key: <спека ключа>, value: <спека значения>]`. Виды действуют во всех режимах языка —
плагин по полям, нагрузка события, View, подписи, структура по полям — и у каждого одна
каноническая wire-форма: множество — список, отсортированный по wire элемента; словарь — объект,
ключ которого — вид с wire-строкой.

## Контекст

Значение «набор без повторов» и «соответствие ключа значению» в домене обычное: у потребителя A
множество идентификаторов лежит в состоянии двух агрегатов, словарь «идентификатор → количество» —
в команде и событии. Спека полей знает только `list:` и сырой `type: :map`, поэтому такие модули
остаются на ручном `defstruct` с ручным кодеком, а `type: :map` в подписях теряет вид ключа и
значения.

Язык спеки полей один для всех режимов (`CONTEXT.md`, «Спека полей»): вид, который есть только в
структуре, развёл бы команду, состояние и событие одного агрегата по способу объявления. Значит,
у вида должен быть wire. Wire уходит в хранилище событий и по нему читается история, поэтому
форма выбирается один раз.

## Рассмотренные варианты

### Нужен ли вид

- **Перевести потребителя на `list:`** (множество — список без повторов, словарь — список
  сущностей-пар). Отвергнут: домен держит семантику множества и словаря (идемпотентное
  добавление, поиск по ключу), и библиотека заставила бы потребителя её воспроизводить руками.
- **Вид только в режиме `:struct`, без wire.** Отвергнут: нагрузка события того же агрегата поле
  не объявит.
- **Виды `set:` и `map:` во всех режимах (принято).**

### Wire множества

- **Список в порядке `MapSet`.** Отвергнут: порядок обхода `MapSet` зависит от числа элементов и
  не совпадает с порядком их wire; одно значение давало бы разный список, и golden-фикстура,
  сравнивающая разобранный JSON, расходилась бы на равных множествах.
- **Отсортированный по wire элемента список (принято).** Одно значение — один wire. Для элемента
  с персональными данными порядок берётся по wire до шифрования.
- **Повтор в wire при `load` — отказ.** Отвергнут: повтор не меняет значения множества, а отказ
  сломал бы чтение истории из-за формы. Повторы схлопываются.

### Wire словаря

- **Список пар `[{"key": …, "value": …}]`.** Отвергнут: годится для любого ключа, но это не
  естественный JSON — проекция и индекс `jsonb` его не читают как объект.
- **Опция формы wire у вида** (объект или пары на выбор). Отвергнут: опция формы превращает вид в
  конфигуратор; у вида одна форма.
- **Объект `{"<wire ключа>": <wire значения>}` (принято).** Ключ — только вид с wire-строкой:
  Prim со строковой базой, `enum:`, `type: :string`. Ключ с wire-числом пришлось бы превращать в
  строку и разбирать обратно — та же неоднозначность, что у опции формы. Порядок ключей не
  гарантируется: объект JSON неупорядочен, `jsonb` и сравнение разобранного JSON его не видят.
- **Персональный ключ.** Запрещён: ключ объекта лежит в wire открыто и виден в индексе `jsonb`,
  зашифровать его по одному нельзя. Значение словаря и элемент множества с персональными данными
  обрабатываются как элемент `list:`.

### Имя

- **`dict:`.** Отвергнут: снимает пересечение с `type: :map`, но в Elixir тип зовётся map, и
  автор ищет `map:`. Различие объясняет `@moduledoc`: `type: :map` — значение без спеки, `map:` —
  словарь со спекой ключа и значения. Внутренняя форма Redump `{:map, %{поле => спека}}` (запись
  с полями) остаётся, словарь получает в Redump своё имя формы.

### За рамками

- **`type: :atom`.** Атомы из внешних данных запрещены сводом (`20-agreements.md`, «Атомы из
  внешних данных»); закрытое множество — `enum:`.
- **Объединение по соседнему полю** (вариант значения выбирает другое поле). Дискриминатор вне
  значения один вид поля не описывает — остаётся ручной кодек.

## Решение

- `set: <спека>`: элемент — любой вид спеки полей. Тип — `MapSet.t(<тип элемента>)`. Wire —
  список, отсортированный по wire элемента; `load` собирает `MapSet`, повторы схлопываются.
- `map: [key: <спека>, value: <спека>]`: значение — любой вид; ключ — вид с wire-строкой, иначе
  `CompileError`; персональный ключ — `CompileError`. Тип — `%{optional(<ключ>) => <значение>}`.
  Wire — объект без гарантии порядка ключей.
- Режимы: плагин по полям (`dump` / `load`, сверка со структурой), нагрузка события (шифрование
  ПДн как у `list:`), View и Redump (read-путь в той же форме, что wire), подписи (`Core.Labels.Details`
  отдаёт вид `:set` со списком элементов в каноническом порядке и вид `:map` со списком пар),
  структура по полям (`default:` — выражение, проверяется по видам элемента, ключа и значения).
  У плагина `default:` — wire-литерал (`[]`, `%{}`).
- Фикстура-потребитель объявляет оба вида в нагрузке события, структуре и плагине: храповик вывода
  типов (`make consumer-check`, ADR-0014) держит сгенерированный код.

## Цена

- **Сортировка на каждом `dump` множества** — `O(n log n)` по wire элементов.
- **Ключ словаря ограничен строкой wire.** Словарь с числовым или составным ключом остаётся ручным
  кодеком либо списком сущностей-пар.
- **Переход потребителя с ручного кодека** с другой формой wire (список пар) — новый тег события с
  апкастом (`14-events-outbox.md`); работа потребителя.
- **Два смысла `map` в языке**: `type: :map` и `map:`.

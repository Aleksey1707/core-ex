# Структура по полям: `Core.Struct` на языке спеки полей, обязательный ключ — из `default:`

Доменный struct (команда, состояние агрегата, вложенная сущность, вариант семейства) MAY
объявляться `use Core.Struct, fields: [...]` на языке спеки полей (`Core.Codec.Field`). Из одной
декларации порождаются `defstruct`, `@enforce_keys` и `@type t`. Кодека и конструктора `new` нет.
Ручной `defstruct` остаётся допустимым.

## Контекст

Struct из Prim пишется руками тремя частями: `@enforce_keys`, `defstruct`, `@type t`. Части
расходятся: у агрегата фикстуры-потребителя тип `%__MODULE__{}` полей не описывает вовсе.
Генерацию struct по спеке полей уже делают `Core.Es.Event.Payload` и `Core.View`, но каждый
вместе с кодеком: wire, `subject:`, dump.

У вложенного struct сведений и варианта семейства вид полей объявляется второй раз в `fields:`
у `use Core.Labels.Fields`, иначе подписям не из чего взять вид.

В `Payload` и `View` `optional: true` значит сразу две вещи: тип допускает `nil`, ключ можно не
указывать. Это разные оси. Поле, которое указывается обязательно, но может быть `nil`, так не
объявить.

Репозиторий event-sourced агрегата собирает исходное состояние `struct(Agg, id: id)` — мимо
`@enforce_keys`. До события создания поля, кроме `id`, равны `nil` или значению из `defstruct`.

## Рассмотренные варианты

### Язык полей

- **Свой синтаксис в духе typed_struct** (`field :name, Name`). Отвергнут: второй язык полей рядом
  со спекой полей, которую уже говорят плагин, нагрузка, `ValueChanged` и подписи.
- **Спека полей, новый режим нормализации (принято).** `wire:` и `subject:` в нём — `CompileError`:
  без кодека они ничего не значат.

### Обязательный ключ

- **`optional: true` снимает и `nil`, и обязательность**, как в `Payload` и `View`. Отвергнут:
  пропадает поле «указать обязательно, можно `nil`», которое роняет сборку каждого `%S{}` при
  добавлении нового необязательного поля.
- **Отдельный ключ `enforce:`.** Отвергнут: `enforce: false` без значения по умолчанию — ровно
  `default: nil`, а клетку «не `optional`, не `enforce`» (значение по умолчанию `nil` противоречит
  типу) пришлось бы запрещать особо.
- **Обязательность выводится из `default:` (принято).** Ключ можно не указывать тогда и только
  тогда, когда у поля есть значение по умолчанию. `optional:` отвечает только за `| nil` в типе.
  Клетка «тип врёт» невозможна: `default: nil` без `optional: true` — `CompileError`.

### Значение по умолчанию

- **Без `default:`.** Отвергнут: обязательность не из чего выводить.
- **Литерал для `type:` / `enum:`, для `prim:` — только `nil`.** Отвергнут: поле со значением по
  умолчанию толкает автора от Prim к голому `type:`.
- **Сырой литерал для `prim:` с неявным `Mod.new!`.** Отвергнут: годится только для `new`, а Prim
  строится и другими чистыми функциями (`from_key`, `from_number!`).
- **Выражение — значение поля (принято).** `default:` вычисляется в теле модуля при сборке, вид
  результата проверяет валидатор: Prim этого модуля, значение Enum, значение `type:`, `nil` при
  `optional: true`. Prim с `personal: true` или `sensitive:` в `default:` — `CompileError`: значение
  ушло бы в исходник и байткод.

### Что порождать

- **Конструктор `new/N` с проверкой вида в голове**, как у `Payload`. Отвергнут: позиционный `new`
  на десятке полей путается, keyword-голову с паттерном по каждому полю не написать. Состав ключей
  проверяет `@enforce_keys`, вид — Dialyzer по `@type t`.
- **Кодек вместе со struct.** Отвергнут: это третий `Payload` / `View`. Wire даёт Codec-плагин по
  полям с независимой декларацией.
- **Подписи `label:` в спеке структуры.** Отвергнуты: ADR-0063 уже отказался от подписей опциями
  существующих макросов, подписи нужны меньшинству потребителей и подключаются по желанию.

## Решение

- `use Core.Struct, fields: [...]`: виды полей спеки (`prim:` / `enum:` / `entity:` / `union:` /
  `list:` / `type:`), `optional:`, `default:`. Набор `type:` — общий (`FieldCheck.type_values/0`).
- Порождаются `defstruct` со значениями по умолчанию, `@enforce_keys` (поля без `default:`),
  `@type t` и внутренняя `__struct_fields__/0` (`@doc false`).
- `default:` — опция-выражение внутри литерального `fields:`: `Core.Struct` снимает её AST со спеки
  до нормализатора и ставит вычисление с проверкой в тело модуля. В режиме плагина `default:`
  остаётся wire-литералом.
- `Payload` и `View` не меняются: их struct собирает конструктор, обязательность там по-прежнему
  `not optional`.
- Проверки по ролям остаются у ролей и срабатывают только при `__struct_fields__/0`:
  - `Core.Es.Aggregate` — поле состояния, кроме `id`, без `optional: true` и без `default:` —
    `CompileError`;
  - плагин по полям сверяет со структурой не только ключи, но и виды;
  - `Core.Labels.Fields` берёт вид полей из спеки структуры, `fields:` рядом с ней — `CompileError`.
- Норма — MAY в `docs/rules/11-domain.md`. Фикстура-потребитель переводит команду и состояние
  агрегата, `make consumer-check` держит храповик вывода типов.

## Цена

- **Два смысла `default:` в одном языке.** У плагина — wire-литерал для `load`, у структуры —
  значение поля. У строк, чисел и UUID совпадают, у datetime и decimal — нет.
- **Значение по умолчанию вычисляется один раз.** `default: CreatedAt.now!()` или
  `default: ID.generate()` собираются и дают одно значение на все struct — момент сборки модуля.
  Сборка этого не ловит, остаются `@moduledoc` и ревью.
- **Выражение внутри литеральной опции.** `Core.Helper.Opts` учится держать AST во вложенном
  ключе, а `Core.Struct` — снимать его со спеки до нормализатора; раньше выражением бывала только
  опция верхнего уровня.
- **`optional:` значит разное по режимам.** В структуре — только `| nil`, в `Payload` и `View` — ещё
  и необязательный ключ.

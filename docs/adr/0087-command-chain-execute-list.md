# Цепочка команд: клауза `execute/2` над списком

Генерируемый `execute/2` event-sourced агрегата (`use Core.Es.Aggregate`) принимает вторым
аргументом и список команд — цепочку (`CONTEXT.md`, «Цепочка команд»): каждая следующая решает от
состояния после предыдущей, первый отказ обрывает цепочку, итог — события всех команд и состояние
после них. Отдельной функции нет. Процесс агрегата по-прежнему исполняет одну команду.

## Контекст

Цепочку библиотека признавала штатной: колбэк `get_decision` выбран вместо команды потому, что
«цепочка команд и чтения соседних агрегатов в неё не укладываются» (ADR-0016), а
`13-repos.md` допускает следующей команде идти от состояния из `execute/2` без повторного чтения.
Формы для неё не было, и потребитель A свернул команды своей функцией над модулем-переменной:
`execute_all(aggregate, state, commands)` зовёт `aggregate.execute(acc, command)`. Вызов через
модуль-переменную вывод типов видит как `dynamic()` (ADR-0014): состояние чужого агрегата
(`execute_all(Account, %Order{}, commands)`) сборка пропускает, ошибка — `FunctionClauseError` в
рантайме. Закрыть дыру может только функция с головой `%__MODULE__{}`, то есть сгенерированная у
каждого агрегата; рукой — копия свёртки на каждый агрегат.

## Рассмотренные варианты

- **Функция `Core` над модулем-переменной** (перенос как есть). Отвергнута: закрепляет `dynamic()`
  в API всех потребителей.
- **Генерируемая `execute_all/2`.** Отвергнута: занимает ещё одно имя в модуле агрегата у каждого
  потребителя, а честного имени нет — `_many` (`get_many`, `insert_many`) в словаре библиотеки
  значит независимые элементы, `_all` (`traverse_all`) — сбор всех ошибок; цепочка ни то ни другое.
- **Составная команда в домене** (`Cmd.Update` с несколькими полями). Не решение библиотеки:
  «одна правка — одна команда» — выбор модели потребителя, и те же команды переиспользуются в
  других цепочках.
- **Список и в `Agg.Process.execute/6`.** Отложено: процессом с цепочкой никто не пользуется, а
  атрибут span'а `command` пришлось бы сделать списком. Расширить позже — не ломающее изменение,
  сузить — ломающее.
- **Клауза `execute/2` над списком (принято).** Глагол один: цепочка — тоже исполнение, итог той
  же формы `{events, state}`. Головы различаются guard'ом (`is_struct/1` против `is_list/1`), обе —
  допустимый ввод (`20-agreements.md`, «Домен функции»).

## Решение

- `execute(%Agg{} = state, commands) when is_list(commands)` → `Result.t({[Es.Event.t()], %Agg{}})`.
- Пустой список — `{:ok, {[], state}}`: пустое решение штатно и у одиночной команды
  (`decide/2` → `{:ok, []}`), а `append` пустой пачки — `:ok`.
- Отказ — `{:error, %Error{}}` оборвавшей команды как есть, без обёртки и номера: обёртка сменила
  бы `code` наверху и маппинг ошибок на HTTP у потребителя.
- Элемент списка — команда, не вложенный список.
- Цепочка исполняется через `get_decision` репозитория (`&Agg.execute(&1, commands)`); процесс
  агрегата берёт одну команду.

## Цена

- **Команда чужого агрегата в цепочке сборкой не ловится.** Голова клаузы закрывает состояние
  (`%__MODULE__{}`), а элементы списка — `struct()`: `Account.execute(state, [%Order.Cmd.Place{}])`
  молчит, в рантайме — `FunctionClauseError` в `decide/2`. Одиночная команда того же агрегата
  ловится. Сценарии A3c и A1c — `fixtures/consumer/scenarios/execute.ex`.

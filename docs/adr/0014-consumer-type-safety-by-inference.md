# Типобезопасность потребителя — вывод типов Elixir через генерируемые функции

Ошибки потребителя в вызовах `Core.Es` ловит вывод типов Elixir 1.20 при `--warnings-as-errors`. Каждая функция, которую
генерирует `Core` у потребителя, служит границей типов: голова закрывает struct, результат из библиотеки сужается
паттерном. Полноту `evolve/2`, `project/1` и `dump_payload/2` / `load_payload/3` проверяют генерируемые функции-проверки
с литеральным вызовом на каждое событие. Элемент результата `decide/2` строит само событие:
`Event.X.draft(payload)` / `Event.X.draft()`. `@spec` и `@callback` источником проверки не служат, тестовые модули
остаются страховкой для того, что компилятор не видит. Регресс ловит фикстура-потребитель в `make`.

## Контекст

Исследования и прототип лежат в `.scratch/es-type-safety/` (Elixir 1.20.3):

- `@spec` и типы `@callback` компилятор не читает. Сигнатуру функции он выводит из clauses и guards, а предупреждение
  выдаёт только при гарантированном провале.
- Вызов через модуль-переменную (`aggregate.decide`, `mod.new`, `projection.project`, `codec.load`) не проверяется, и
  его результат — `dynamic()`. Вся связь библиотеки с кодом потребителя устроена именно так.
- `is_struct/2` в голове даёт открытую map. Обёртка над модулем того же проекта при выводе получает
  `(term() -> dynamic())`. Сигнатуры зависимости участвуют в выводе, поэтому у потребителя функции, которые генерирует
  `Core`, наследуют форму результата библиотеки, но не состояние агрегата и не события.

По карте слепых зон потребителя молчали:

- команда чужого агрегата в `execute`;
- любой неверный результат `decide` (событие не из кодека, чужая нагрузка, голый модуль события с нагрузкой);
- полнота `evolve`, `project/1`, `dump_payload` / `load_payload`;
- опечатки в полях состояния из `execute` и `get`, в полях событий из `InCodec.load`;
- ID из `new/0` и `new!/1`;
- `await/4` и `page_stream/5` с чужим агрегатом.

Всё это падало только в runtime. Полноту `evolve` и `project/1` проверяли лишь `EventCompatCase` и `ProjectionCase`,
если потребитель их подключил.

## Рассмотренные варианты

### Механизм

- **Dialyzer через `@spec` / `@callback`.** Отвергнут как основной: отдельный медленный шаг, ошибки по контракту
  behaviour не связаны с местом вызова. `@spec` остаются документацией.
- **Тестовые модули** (`EventCompatCase`, `ProjectionCase`). Отвергнуты как основной механизм: ошибка всплывает только
  при прогоне и только у того, кто модуль подключил.
- **Вывод типов при компиляции (принято).** Работает уже сегодня, отдельного инструмента не требует, у всех
  потребителей сборка идёт с `--warnings-as-errors`.

### Граница типов

- **Только головы генерируемых функций.** Отвергнут: чужой аргумент ловится, но результат остаётся `{term(), term()}`,
  и опечатка в поле состояния молчит.
- **Головы плюс сужение результата (принято).** Паттерн `{:ok, {events, %__MODULE__{} = state}}` стоит один match на
  вызов. Сужение в `case` даёт ложное «clause will never match» у агрегата, чей `decide` никогда не ошибается,
  поэтому код генерируется в `quote generated: true`. Недостижимая clause не должна возвращать голую переменную
  (`{:error, _} = e -> e`), иначе результат схлопывается в `dynamic()`: пишется `{:error, reason} -> {:error, reason}`.
- **`execute/2` зовёт `decide(command, state)` локально**, а не через `aggregate.decide` в библиотеке: домен локального
  вызова переходит в домен `execute`, и команда чужого агрегата ловится без объявления списка команд.

### Полнота

- **Проверка в самом агрегате.** Отвергнута. В начале тела агрегата кодек не загрузить: кодек ждёт события, события
  ждут `Agg.ID`, а вложенного `Agg.ID` ещё нет — сборка падает `CompileError` взаимного ожидания. В `@before_compile`
  агрегата `Agg.ID` уже определён, и загрузка проходит (прототип `draft` в агрегате, «Результат `decide`»). Но тогда
  агрегат ждёт кодек при сборке и держится лишь на том, что ни кодек, ни события не ждут сам модуль агрегата, а
  функции-проверки занимают имена в модуле автора.
- **Функции-проверки в модулях, которые и так зависят от событий на компиляции (принято).** Полнота `evolve` проверяется
  в `use Core.Es.Aggregate.Repo`, `project/1` — в `__before_compile__` проекции по `events:`, нагрузка — в
  `__before_compile__` кодека по `tags:`. Новых рёбер компиляции нет. Цена: агрегат без репозитория не проверяется.
- **Имя функции-проверки — нарушенное утверждение**: `"evolve/2 принимает <Event>"`. Компилятор печатает его в месте
  предупреждения, а место указывает на строку `use`. Служебное `__es_*_covers__` отвергнуто: суть нарушения из него не
  видна.

### Результат `decide`

- **Кортеж `{Event.X, payload}` без проверки.** Отвергнут: B1–B3 остаются ошибками runtime, хотя сигнатура `decide`
  знает результат точно.
- **`draft(%Payload{})`, событие определяется модулем нагрузки.** Отвергнут: в законных кодеках события делят модуль
  нагрузки (`RoleGranted` / `RoleRevoked` с `Role.ID`). Смешанная форма, где `draft/2` генерируется только для общих
  нагрузок, отвергнута тоже: добавление соседнего события ломало бы уже написанные вызовы.
- **`draft` на семействе `<Aggregate>.Event`.** Отвергнут: семейство и кодек ждут компиляции друг друга.
- **`%Core.Es.Draft{}` вместо кортежа.** Отвергнут: компилятору он ничего не добавляет, а тесты с кортежами ломает.
- **`<Aggregate>.Event.Codec.draft(Event.X, payload)` / `draft(Event.X)`.** Clause на каждую пару «событие — модуль
  нагрузки» и на каждое событие без нагрузки; ловит и событие не из кодека. Был принят, затем отвергнут: кодек отвечает
  за wire, а черновик из wire не использует ничего — ни значения тегов, ни конверт, ни `upcasts:`, и чистый `decide`
  называл модуль сериализации. Довод графа компиляции, ради которого место выбиралось, оказался уже: цикл
  «агрегат → кодек → семейство → агрегат» у потребителя есть и без `draft` — его рёбра дают алиасы в опциях `use`.
  Запрещено только взаимное ожидание компиляции (deadlock семейства из варианта выше).
- **`draft/1,2` в агрегате: `defp`, генерирует `use Core.Es.Aggregate` в `@before_compile` по кодеку.** Отвергнут.
  Прототип на копии фикстуры-потребителя собирается без deadlock и ловит все ошибки, включая событие чужого агрегата,
  но агрегат начинает ждать компиляции кодека, а макрос занимает имя в модуле автора.
- **`<Aggregate>.Event.<Name>.draft(payload)` / `draft()` (принято).** Генерирует `use Core.Es.Event`: у события с
  нагрузкой — `draft/1` с `%Payload{}` в голове, без нагрузки — `draft/0`. Нагрузку другого события и не-struct
  ловит вывод типов, неверную арность — предупреждение о неопределённой функции. Рёбер компиляции нет: голова `new`
  уже содержит `%Payload{}`. Возвращает прежний кортеж, так что `events/5` и `Aggregate.Test.given/3` не меняются.
  Событие чужого агрегата сборка не ловит — `FunctionClauseError` при исполнении команды. Ошибка дешёвая: чужое
  пространство имён пишется явно, а провал даёт первый же тест команды через `given/3`. Собрать кортеж вручную
  по-прежнему можно: запрет записан в своде, но не проверяется.

### Храповик

- **ExUnit с `Code.with_diagnostics`.** Отвергнут: вне Mix сигнатуры `Core` не участвуют в выводе, и картина расходится
  с тем, что видит потребитель.
- **Фикстура-потребитель (принято).** Mix-проект с path-зависимостью вне `config|lib|test` и с отдельным `_build`.
  Диагностики берутся через Mix API, ожидание записано маркером `# expect: <заголовок>` над ошибочной строкой. Шаг
  стоит в `make` по умолчанию. Эталон `file:line` отвергнут: при сдвиге строк на семь он разошёлся в 16 местах из 30.

## Решение

- Функции, которые `Core` генерирует у потребителя, закрывают struct в голове и сужают результат библиотеки паттерном,
  код сужения помечен `generated: true`. Это `Agg.execute`, `fold`, `Repo.Pg.get` / `get_many` / `refresh` / `append`,
  `Agg.Process.execute`, Prim `new/0`, `new!/1`, `now!/0`, `Version.new/0`. Bang-конструкторы вызывают `raise` сами, а
  не через `Result.unwrap!/1`.
- `Agg.execute/2` вызывает `decide/2` локально.
- Функции-проверки полноты генерируются в `Agg.Repo`, в проекции и в кодеке. Проверка полноты `evolve` из
  `EventCompatCase` и clauses `project/1` из `ProjectionCase` удаляется.
- Элемент результата `decide` строится самим событием: `<Aggregate>.Event.<Name>.draft/0,1`.
- API с модулем-параметром, у которого на месте вызова всегда литерал, заменяются генерируемыми функциями:
  `Core.Es.Projection.await/4` → `Projection.await(Agg, %Agg.ID{}, timeout)`,
  `Core.Es.Store.page_stream/5` → `page_stream/4` у репозитория агрегата.
- `load/2` фасада Codec сужает результат по типам плагинов, фолбэк `dump/1` сужен guard'ом `is_prim/1`.
- Отложены: команда чужого агрегата в `Agg.Process.execute` (нужен список команд агрегата) и типы полей команды (ждём
  typed structs). Оба пункта записываются в `docs/rules/DEBT.md` с условием возврата. Пределы компилятора, которые
  закрываются тестом, перечисляются в своде потребителя.
- Приём, который станет лишним с typed structs, не принимается, если ошибка не дорогая.

## Цена

- **Ломающие изменения контракта**: `draft` в `decide`, новые формы `await` и `page_stream`, удалённые проверки
  `EventCompatCase` / `ProjectionCase`. Потребители переводятся при подъёме версии по «было → стало» в `CHANGELOG.md`.
- **Генерируемый код растёт**: функция-проверка на каждое событие в трёх модулях, `draft` у каждого события.
- **Событие чужого агрегата в `decide`** — ошибка исполнения команды, а не сборки.
- **Странные имена в `__info__(:functions)`**: атомы с пробелами и кириллицей. Атом ограничен 255 символами, при
  глубоком пространстве имён модуль в имени укорачивается.
- **Намеренно сломанные фикстуры core-ex** (`BrokenProjection` и подобные) теперь ловятся при компиляции и
  перестраиваются под проверки, которые остаются в тестовых модулях.
- **Хрупкость вывода**: catch-all clause или обёртка внутри `Core` молча вернёт `dynamic()`. От этого защищает только
  храповик, и эталон предупреждений нужно сопровождать.

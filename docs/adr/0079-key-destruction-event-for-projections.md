# Уничтожение ключа пишет событие для проекций

Уничтожение ключа субъекта в той же транзакции дописывает в `es_events` событие уничтожения ключа — в поток
субъекта зарезервированного типа библиотеки. Read-модель, которая держит ПДн, объявляет это событие в `events:`
своей проекции и по нему перестаёт держать данные субъекта; read-модель без ПДн объявляет `personal: false`. Выбор
проверяют сборка и `Core.Es.ProjectionCase`. Пункт ADR-0076 «операция никого не извещает» сужен: процессы,
снапшоты и третьих лиц она по-прежнему не извещает. Уничтоженное значение — ADR-0074, хранилище ключей — ADR-0075;
термин — `CONTEXT.md`, «Событие уничтожения ключа».

## Контекст

Факты на 2026-10-18:

- read-модель держит ПДн-значения открытыми; её таблицы пишет только её проекция, в `project/1` и `clear/0`;
- `project/1` получает только struct события; события, записанные до уничтожения, после него грузятся с
  уничтоженным значением (ADR-0074), но строку, сохранённую раньше, проекция сама не перечитывает;
- уничтожение меняет только строку ключа; связи «субъект → потоки» нет (ADR-0076);
- ПДн субъекта лежат в потоках любых агрегатов и контекстов, проекция читает события чужого контекста как
  копии полей (ADR-0038); у части субъектов своего агрегата нет;
- первичный ключ `es_events` — `(aggregate_type, aggregate_id, aggregate_version)`;
- своя реализация порта хранилища ключей может жить вне базы: после восстановления копии базы её ключ уже
  уничтожен, а база об этом не знает (ADR-0075);
- кеш ReadRepo сбрасывается по id из заголовка события брокера, TTL — страховка.

## Рассмотренные варианты

- **Событие потребителя, только норма** — проекция объявляет событие, которое usecase уничтожения кладёт в той же
  транзакции. Отвергнут: сигнал у каждого потребителя свой; проекция с ПДн из поля чужого агрегата должна знать
  событие владельца субъекта; субъекту без своего агрегата нужен агрегат ради события; библиотека ничего не
  проверяет; повтор по актам обязан повторить и событие.
- **`NOTIFY`.** Отвергнут: не сохраняется, пересборка его не видит.
- **Колбэк проекции по субъекту** из операции уничтожения. Отвергнут: пишет таблицу мимо `project/1`, операции
  нужен список проекций приложения.
- **Шифрованная колонка read-модели** с расшифровкой в ReadRepo. Отвергнут: поиск и сортировка по ПДн-колонке
  невозможны, каждое чтение идёт в хранилище ключей.
- **Событие только при переходе ключа в «уничтожен»** по ответу порта. Отвергнут: повтор по актам после
  восстановления копии базы не дал бы события, если ключ своей реализации вне базы уже уничтожен.
- **Чистка таблиц read-модели в usecase уничтожения.** Отвергнут: таблицу пишет одна проекция, и пересборка
  разошлась бы с ней.
- **Без проверки сборкой.** Отвергнут: проекция, которую забыли подписать на событие, держит ПДн открытыми
  бессрочно, и этого не видно ни в тестах, ни в эксплуатации.

## Решение

- операция уничтожения после строки ключа дописывает событие уничтожения ключа: `aggregate_type` зарезервирован
  библиотекой, `aggregate_id` — идентификатор субъекта, версия `1`, нагрузка пуста, `by` — аргумент операции
  (ADR-0076), `at` — часы библиотеки в момент вызова, как время уничтожения в строке ключа; кодек потребителя с
  тем же `type:` — `CompileError`;
- событие пишется, если его нет в потоке субъекта, независимо от ответа порта; повтор при записанном — `:ok`
  без записи;
- в outbox событие не идёт; потока нет в странице потока и странице событий;
- проекция, у события из `events:` которой есть поле с `subject:`, MUST объявить событие уничтожения ключа в
  `events:` или указать `personal: false`; ни того, ни другого или оба — `CompileError`;
- по событию в read-модели MUST NOT оставаться открытого ПДн-значения субъекта: удалить строку или занулить
  колонки — решает потребитель; таблица с ПДн хранит рядом идентификатор субъекта; на уничтоженном значении
  пишется не ПДн;
- `Core.Es.ProjectionCase` на каждой открытой фикстуре с полями `subject:` прогоняет `project/1`, затем событие
  уничтожения ключа каждого её субъекта, которое строит сам, и ищет открытые строковые wire-значения ПДн-полей в
  затронутых таблицах; у `personal: false` — сразу после фикстуры;
- usecase уничтожения таблиц read-модели не трогает и проекцию не ждёт; кеш ReadRepo с ПДн без TTL — MUST NOT.

## Цена

- **Библиотека пишет в историю потребителя.** Строки потока субъекта остаются в `es_events` навсегда, тип
  зарезервирован и называется в `CHANGELOG.md` контрактом хранения.
- **Два события на одно уничтожение** у потребителя, который пишет акт или снимает резерв ключа из ПДн событием:
  своё и библиотеки.
- **Read-модель отстаёт от уничтожения** на отставание проекции; застрявшую пачку ловит алерт проекции. Кеш
  ReadRepo отстаёт до TTL.
- **Поиск в `ProjectionCase` эвристический**: видит только строки и только неизменённое значение — нижний регистр
  или склейку перед записью он пропустит.
- **Событие называет субъекта и время уничтожения.** Это след рядом со строкой хранилища ключей, но не журнал:
  причину и автора акта по-прежнему пишет потребитель.

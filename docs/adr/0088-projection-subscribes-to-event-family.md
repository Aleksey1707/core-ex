# Проекция подписывается на семейство событий

Элементом `events:` у `use Core.Es.Projection` может быть, кроме модуля события, семейство событий
агрегата (`use Core.Es.Event.Family`): при раскрытии `use` оно становится всеми модулями событий
своего кодека. Семейство стоит в списке вперемешку с модулями и другими семействами. Отдельной опции
нет.

## Контекст

`events:` принимал только модули событий, семейство отвергалось `CompileError`, а норма
`22-projections.md` показывала его примером «плохо» рядом с catch-all. Тег, известный кодеку, но не
объявленный в `events:`, пачка пропускает: подписка — выбранное подмножество, и это штатно.

У проекции, которой нужно каждое событие агрегата, у того же правила обратная сторона: событие,
добавленное в семейство позже, проекция молча пропускает. Перечень модулей не говорит, полон ли он
по замыслу или по забывчивости, а ошибиться можно уже после ревью проекции — правкой агрегата.

## Рассмотренные варианты

- **Отдельная опция `family:` рядом с `events:`.** Отвергнута: проекция с ПДн объявляет ещё
  `Core.Es.Personal.Event.KeyDestroyed`, проекция над несколькими агрегатами — модули другого
  семейства, и тогда нужны обе опции с правилом их сложения.
- **Маркер полноты (`{:all, Account.Event}`).** Отвергнут: новый синтаксис ради различия, которое
  элемент списка уже несёт сам — модуль события или семейство.
- **Семейство кроме перечисленных (`except:`).** Отвергнуто: снова подмножество, только через
  отрицание; места вызова для него нет.
- **Свой `CompileError` «у события нет clause».** Отвергнут: полноту clauses уже проверяет вызов
  `project/1` на каждый модуль `events:` (ADR-0014), предупреждение типизатора у потребителя валит
  сборку через `--warnings-as-errors`.
- **Семейство — элемент `events:` (принято).** Раскрытие — первый шаг разбора `events:`, всё ниже
  (кодек, ПДн, потоки, проверка полноты) видит плоский список модулей.

## Решение

- Семейство раскрывается в отсортированные модули событий своего кодека; `codec:` семейства, не
  кодек событий этого семейства, — `CompileError`.
- Событие вместе со своим семейством — `CompileError` с именем семейства, а не молчаливый дубль:
  запись выглядела бы так, будто событие выделено особо.
- Семейство — для проекции, которой нужно каждое событие агрегата. Проекция с частью событий
  перечисляет модули: пустые clauses `:ok` ради краткости — тот же catch-all по одному на событие.

## Цена

- **Рост семейства подписывает проекцию сам.** Новое событие кодека попадает в `events:` без правки
  проекции — для этого форма и заведена; без clause `project/1` сборка предупреждает. `version:`
  поднимать не нужно: у нового тега нет истории. Удалённый тип, оставленный в `tags:` ради
  истории, тоже входит в семейство и требует clause.

# Запрос для других контекстов — `Query` без декларации доступа

Чтение, которое контекст отдаёт другому контексту для шага его проверки или решения, лежит в
модуле `Query` — `<Aggregate>.Query` или `<ReadModel>.Query` — и декларации `use MyApp.Authz` не
несёт: доступ уже проверил usecase вызывающего контекста. Точки входа (`MyAppWeb`, `MyAppIngest`, корень `MyAppApp`,
mix-таски) на `Query` не ссылаются — это ловит `boundary_lint --consumer`. Заменяет пункт ADR-0046
«общее чтение без проверки отвергнуто» для чтения другими контекстами и пункт ADR-0047 «read-модель
без таблицы — со своим `<ReadModel>.Usecases`». Норма — `docs/rules/app/10-architecture.md`,
«Состав контекста», «Boundary», «Проверка доступа», «Usecases»; `docs/rules/app/13-repos.md`,
«Read-модель»; `docs/rules/22-projections.md`, «Read-after-write».

## Контекст

Факты на 2026-10-03 (адаптация потребителя A к rc после 0.10.0):

- ADR-0047 отдаёт другим контекстам состояние учётной записи без отставания проекции — read-модель
  без таблицы с запросом `<ReadModel>.Usecases`; ADR-0046 требует декларацию на каждом модуле
  usecases и отвергает чтение без проверки: web зовёт usecase напрямую;
- реализация порта проверки доступа у потребителя A читает тип учётной записи и её блокировку у
  контекста учётных записей этим запросом. Запрос со своей декларацией зовёт `check_user`, тот —
  порт, порт — ту же реализацию: рекурсия без выхода;
- usecase назначения у потребителя A проверяет этим же запросом, что назначаемая учётная запись
  действует. Запрос проверяет право на пространство учётных записей, которого у назначающего нет:
  отказ, хотя назначение ему разрешено;
- `app/10` уже держит `<Aggregate>.Query` — хелпер чтения usecases агрегата без своей проверки:
  доступ проверил usecase, который его зовёт;
- `boundary` не умеет экспорт для одних границ и не для других: модуль в `exports` видят все, кто
  держит контекст в `deps`, включая web.

## Рассмотренные варианты

- **Реализация порта читает write-репозиторий учётных записей.** Отвергнут: репозиторий записи
  пришлось бы экспортировать, а ADR-0047 этот экспорт уже отверг — он открыл бы запись всем.
- **Системный контекст для чтения в реализации порта.** Отвергнут: рекурсию не снимает — запрос
  проверяет и системного актора через тот же порт; чужое право в usecase назначения не решает.
- **Пространство учётных записей в декларации usecase назначения.** Отвергнут: ADR-0046 запрещает
  ключ другого контекста в декларации, и назначающему пришлось бы выдавать право на чтение всех
  учётных записей ради проверки одной.
- **Запрос без декларации в модуле `<ReadModel>.Usecases`.** Отвергнут: имя `Usecases` значит «точка
  входа с проверкой», и чтение без проверки под ним выглядело бы забытой декларацией.
- **Архитектурный тест в каждом приложении.** Отвергнут: у всех потребителей один и тот же тест, а
  раскладку потребителя уже проверяет общий линтер библиотеки.

## Решение

- чтение для другого контекста, чей usecase уже решил доступ, — функции модуля `Query`
  (`<Aggregate>.Query`, `<ReadModel>.Query`), отдают View; декларации и `check_user` в нём нет;
- чтение по праву пользователя на данные контекста — по-прежнему его экспортированный usecase с
  декларацией (ADR-0046);
- `Query` входит в `exports` контекста, когда его читает другой контекст; хелпер чтения своих
  usecases — тот же модуль без экспорта;
- точка входа на `Query` MUST NOT ссылаться — правило `entry-query` линтера;
- запрос с `wait:` для реакции другого контекста (ADR-0047) — функция `Query`;
- `:projected` команды по-прежнему читает представление запросом актора с проверкой: его отдают
  точке входа.

## Цена

- **Доверие внутри домена:** контекст, который держит `Query` в `deps`, читает без проверки всё, что
  тот отдаёт; граница доступа — usecase вызывающего, и забытая в нём проверка `Query` не страхует.
- **Ссылку линтер видит только литералом:** модуль, собранный в рантайме или переданный из
  контекста значением, правило не ловит; держит ревью.
- **Два модуля чтения у read-модели:** `<ReadModel>.Usecases` для точек входа и `<ReadModel>.Query`
  для контекстов, и одно чтение для обоих — две функции.

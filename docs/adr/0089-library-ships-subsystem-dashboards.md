# Дашборды подсистем библиотеки поставляет core

Дашборды Grafana на метриках плагинов `Core.*.PromEx` лежат в библиотеке шаблонами EEx
(`priv/dashboards/*.json.eex`). Приложение рендерит их mix-задачей core через
`PromEx.DashboardRenderer` в свой каталог дашбордов и коммитит выгрузку. Provisioning файлами
остаётся. Доменные дашборды по-прежнему пишет приложение.

## Контекст

Свод потребителя относил дашборды к локальному своду приложения (`app/00-index.md`). У потребителя A
дашборды outbox, брокеров, event sourcing, кеша, процессов и внешних вызовов повторяют плагины
библиотеки один в один. У другого потребителя они отличались бы только префиксом метрик, `title`,
`uid` и datasource. Имена метрик меняются в библиотеке, а копии дашбордов лежат у каждого
потребителя, и переименование метрики молча гасит панель в проде.

Штатная задача `mix prom_ex.dashboard.export` рендерит только шаблоны `:prom_ex`. Рендер из `priv`
другого приложения PromEx делает только при выгрузке через API Grafana, а свод требует provisioning
файлами.

## Рассмотренные варианты

- **Норма без кода.** Отвергнута: каждый потребитель пишет свой JSON, копии расходятся, сверять
  имена метрик не с чем.
- **Образцы JSON в `docs/`.** Отвергнуты: та же копия, только без тестов.
- **Статический JSON со скрытой переменной Grafana для префикса.** Отвергнут: `uid`, `title` и
  datasource всё равно правятся руками, а выгрузку уже нельзя сверить с источником.
- **Выгрузка через API Grafana (`grafana:` у PromEx).** Отвергнута: противоречит provisioning
  файлами — дашборд, существующий только в Grafana, теряется при пересоздании стека.
- **Шаблоны EEx в core и своя задача экспорта (принято).** Процедура та же, что у штатных дашбордов
  PromEx: выгрузка без ручных правок. Параметры шаблона — из `dashboard_assigns/0` модуля PromEx
  приложения.

## Решение

- Один шаблон на плагин. Kafka отдельно от RabbitMQ Stream: приложение экспортирует дашборды только
  тех подсистем, которые у него есть (по умолчанию — по `plugins/0`).
- Пороги панелей — параметры шаблона с умолчаниями библиотеки, переопределяются в
  `dashboard_assigns/0`. Повторный экспорт их не теряет.
- Выгрузку руками не правят. Точки расширения нет: доменная панель живёт в доменном дашборде.
- Библиотека проверяет свои шаблоны тестом: имена метрик объявлены плагинами `Core.*.PromEx`, панели
  соответствуют норме формы. Приложению библиотека даёт публичную проверку каталога дашбордов: форма
  панелей и совпадение выгрузки с текущим рендером.

## Цена

- **Публичная зависимость от `PromEx.DashboardRenderer`.** Модуль документирован, но смена его API
  в PromEx ломает задачу экспорта core.
- **Переэкспорт после обновления core.** Устаревшую выгрузку ловит проверка приложения, а не
  пустая панель; цена — шаг в обновлении зависимости.
- **Граница ярусов сдвинута.** Дашборды подсистем библиотеки и штатные — выгрузки с нормами в ярусе
  потребителя, доменные дашборды и пороги — в локальном своде.

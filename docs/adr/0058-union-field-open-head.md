# Поле с семейством в спеке полей: голова открыта до `is_struct`, тип — `struct()`

Дополняет ADR-0056 (`0056-codec-plugin-by-fields.md`) и ADR-0057 (`0057-union-variants-by-address.md`).
Значение поля, которое хранит вариант семейства, объявляется в спеке полей видом `union: Family`:
дамп — `codec.dump/1`, загрузка — `codec.load(Family, raw)`. Голова сгенерированных `dump/2` и `new/N`
проверяет такое поле только `is_struct`, а тип поля — `struct()`. Это отступление от нормы «голова
закрывает struct и Prim каждого поля»: варианты семейства знает его плагин, а не плагин родителя.
Норма — `docs/rules/11-domain.md`, «Плагин по полям (`fields:`)»; `docs/rules/app/11-domain.md`,
«Кодек: по полям или ручной».

## Контекст

Замер на 2026-10-11 по потребителям A–F (только `lib/`):

- у A одна вложенная сущность и четыре нагрузки событий хранят в поле вариант семейства. Поле
  необязательное и грузится ручной обёрткой над `codec.load(Family, raw)`, остальные поля повторяют
  wire один к одному. Без вида поля в спеке эти типы остаются ручными целиком;
- у F вложенная сущность агрегата хранит тег и поля варианта в разных ключах родителя — вне объёма
  (ADR-0057, «Цена»);
- семейства A, F и фикстуры-потребителя — определённые модули без struct. `@type t` есть только у
  семейства F, где он обязателен по норме (`event.ex` / `cmd.ex`, `docs/rules/app/13-repos.md`). A
  пишет тип такого поля как `struct() | nil`;
- после ADR-0057 `codec.load(Family, raw)` принимает любой term, а фасад сужает результат до
  объединения вариантов;
- какой плагин обслуживает семейство, знает только фасад: он собирается после плагинов и читает их
  при сборке;
- `Es.ValueChanged` с семейством в `type:` нет ни у кого.

## Рассмотренные варианты

- **Закрыть голову через плагин семейства.** Спека называет плагин (`union: {Shape, Shape.Codec}`),
  и сборка родителя читает его `__codec_variants__/0`. Отвергнут по трём причинам: имя плагина
  попадает в доменную спеку вопреки норме «плагин вызывается только через фасад»; появляется ребро
  компиляции от родителя (и от нагрузки события) к плагину семейства; ручной `union:` без `variants:`
  закрыть всё равно нечем.
- **Перечислить варианты в поле** (`union: [Shape.Circle, Shape.Rect]`). Отвергнут: каждый вариант
  назван дважды, и расхождение с плагином семейства никто не сверяет.
- **Тип поля `Family.t()`.** Отвергнут: обязанность семейства объявлять `@type t` сборка не
  проверит, отсутствие типа заметит только Dialyzer.
- **Проверять у `Family` только атом.** Отвергнут: `union: Shape.Circle` (нужен `entity:`) работал
  бы на одном варианте — с ADR-0057 `load(Variant, wire)` принимает форму адреса — и молча ломался
  на остальных; `union: Status` (нужен `enum:`) упал бы только при исполнении.
- **Сверять значение с семейством при дампе.** Отвергнут: понадобилась бы третья функция фасада
  «варианты семейства», а фасад отдаёт только `dump/1`, `load/2`, `load!/2`.
- **Выводить `union:` в `Es.ValueChanged` из «модуль без struct».** Отвергнут: опечатка в имени
  модуля выглядит так же, а нужды в таком выводе нет.

## Решение

- `union: Family` — вид значения поля в спеке полей: в `fields:` и `variants:` плагина, в
  `Core.Es.Event.Payload` и как элемент `list:`;
- дамп — `codec.dump/1`, загрузка — `codec.load(Family, raw)`; при `optional:` — `nil` в обе
  стороны;
- голова `dump/2` и `new/N` — `is_struct(v)`, при `optional:` — `is_nil(v) or is_struct(v)`. Struct
  родителя по-прежнему закрыт паттерном;
- тип поля — `struct()`, при `optional:` — `struct() | nil`;
- при сборке `Family` обязан быть собранным модулем, не struct и не `Core.Enum`. Иначе —
  `CompileError` с подсказкой вида `entity:` или `enum:`. Регистрацию семейства в фасаде сборка не
  проверяет — так же, как у `entity:`;
- `default:` — как у `entity:`: wire-литерал, который сборка не грузит;
- `Es.ValueChanged` вид `union:` из `type:` не выводит.

## Цена

- **Не тот struct при записи ловит только чтение.** Struct другого плагина фасада дампится без
  ошибки, а `load(Family, …)` отвечает `:unknown_tag`. Struct без плагина падает уже при записи —
  на фолбэке фасада. Ловит такую ошибку round-trip-тест поля.
- **Вывод типов не знает, какой вариант лежит в поле.** Опечатка в поле варианта, взятого из
  загруженного родителя, молчит; сужение есть только у прямого `codec.load(Family, …)`.
- **Семейство, на которое ссылается поле, обязано быть модулем.** Имени в опции `union:` плагина для
  этого мало.

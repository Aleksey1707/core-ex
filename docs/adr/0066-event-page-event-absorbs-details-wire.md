# Событие страницы событий — `Core.Web.Event`, wire сведений внутри него

Дамп события страницы событий и его OpenAPI-схему даёт `use Core.Web.Event` в модуле приложения:
одно объявление `codec:` и `user_ref:` на всё событие, подписи — опцией `labels: true`. Wire
сведений перестаёт быть публичным модулем `Core.Web.Labels` и становится внутренней частью
`Core.Web.Event`. Это частично заменяет ADR-0063: домен подписей (`Core.Labels.*`) остаётся
публичным, меняется только место wire.

## Контекст

Факты на 2026-10-14:

- страницу событий отдают три потребителя из шести (A, B, F), каждый своим презентером и своей
  схемой. Поля у всех одни — `id`, `aggregateId`, `type`, `payload`, `at`, `by`; нагрузка — дамп
  кодека с camelize, схема нагрузки — свободная nullable; различается форма `by`: ссылка на учётную
  запись с обязательным именем (A), с необязательным (B), строка id (F);
- подписи (`title`, `details`) есть только у A; у него же — подмена строк-id учётных записей в
  машинной нагрузке и обнуление нагрузки у одного события;
- `Core.Web.Labels` (ADR-0063) не выпущен; ему нужны те же `codec:` и форма ссылки на учётную
  запись, что и дампу `by`;
- у A скоро понадобится описание формы для клиента, собранное из кода, а не из данных: ему нужны
  подписи по типу, без значения, — их уже дают `Core.Labels.Fields.paths/1`, `specs/1` и
  `labels/0` Enum, а не wire сведений.

## Рассмотренные варианты

- **Композиция: `Core.Web.Labels` публичный, `Core.Web.Event` получает `labels: <модуль>`.**
  Отвергнут: `codec:` и `user_ref:` объявляются дважды, и сборке пришлось бы сверять их
  совпадение, иначе `by` и ссылка на учётную запись в сведениях выйдут разной формой. Публичный
  wire сведений без события нужен только приложению, у которого сведения есть, а страницы событий
  нет, — такого нет.
- **`Core.Web.Event` без `Core.Web.Labels`, `by:` задаётся независимо.** Отвергнут по той же причине
  без проверки совпадения.
- **Слияние: один `use Core.Web.Event, codec:, user_ref:, labels:`.** Принят.

## Решение

- `to_wire/2` всегда — событие и словарь ссылок; без `user_ref:` и `labels:` словарь просто пуст;
- `by` — строка-дамп id без `user_ref:`, результат `dump:` с ним; `labels: true` без `user_ref:`
  ломает сборку;
- в событие страницы событий входит `version`; нагрузка — дамп кодека с camelize, без подмены id;
  точечные правки приложение делает над результатом `to_wire/2`, опции для них нет;
- схема — модуль приложения (название — последний сегмент имени), схема сведений — вложенный модуль;
  все поля обязательны, объект открытый, `type` — строка без перечисления;
- wire формы, когда понадобится, — отдельная фича поверх `Core.Labels.*`: повторять wire сведений
  он не обязан, а общее (словарь видов, дамп значения) выносится из `Core.Web.Event` в публичный
  модуль, когда у него появится второй пользователь.

## Цена

- **Сведения на wire без события страницы событий библиотека не отдаёт.** Публичный модуль позже
  добавить дёшево, а убрать выпущенный — ломающее изменение: поэтому сначала внутренний.
- **У A на wire меняется `payload`**: строки-id учётных записей остаются строками, имена — в
  `details`. Меняются и названия схем видов сведений в OpenAPI-документе (`KindText` →
  `EventDetailText`); JSON ответа — нет.

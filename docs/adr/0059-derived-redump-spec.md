# Спека пере-дампа выводится из спеки полей, ссылку на тип разрешает фасад

Дополняет ADR-0056 (`0056-codec-plugin-by-fields.md`) и ADR-0057 (`0057-union-variants-by-address.md`).
Спеку `Core.Codec.Redump` для типа из `fields:` или `variants:` и для семейства генерирует плагин,
ручной плагин объявляет её колбэком `redump_spec/1`. Ссылка на тип другого плагина записывается узлом
`{:codec, M}` и разрешается через фасад при исполнении, поэтому контракт фасада получает служебную
`__codec_redump__/1`. `Core.View` ссылается на спеку по типу (`jsonb: Type`). Норма —
`docs/rules/13-repos.md`, «jsonb-нагрузка на read-пути»; `docs/rules/11-domain.md`, «Плагин по полям
(`fields:`)» и «Варианты семейства (`variants:`)»; `docs/rules/19-testing.md`, «jsonb на read-пути:
контракт wire»; `docs/rules/app/11-domain.md`, «Кодек: по полям или ручной».

## Контекст

Замер на 2026-10-11 по потребителям A, B, E, F (только `lib/`):

- ручных спек `Core.Codec.Redump` 15 (A — 5, B — 6, E — 3, F — 1), ссылок на них из `Core.View` — 20;
- спеку типа на `fields:` повторяет одна (у A); семь описывают типы с ручным плагином; одна — словарь
  из спек других плагинов; шесть — пустые `{:map, %{}}`, заведённые только ради View, — их снимает
  `type: :map` во View (`.scratch/codec-plugin-by-fields/issues/12-view-map-field.md`);
- на спеку другого плагина ссылаются вызовом его функции: у A кодек состояния — на спеки вариантов
  семейства, у B словарь — на спеки двух ручных плагинов;
- у A спеку семейства из 13 тегов собирает собственный DSL из 6 объявлений `wire_prims:` (10 полей,
  все — голые Prim); вне redump опция не используется. Сверок read-wire с агрегатным путём у A — 16,
  у B — 4, у E и F — нет;
- общий тег у A — один, на два варианта с дискриминатором; одноимённых полей с разной спекой у них
  нет, форматируемых Prim — тоже;
- sensitive-Prim нет ни в одной jsonb-форме; секрет у B маскирует read-схема до View;
- фасад отдаёт только `dump/1`, `load/2`, `load!/2`; какой плагин обслуживает тип, знает только он;
- `jsonb: {Mod, :fun}` вызывается при исполнении — ребра компиляции от View к кодеку нет.

## Рассмотренные варианты

- **Свёртка ссылок при сборке фасада.** Фасад разворачивает все ссылки в плоскую спеку. Отвергнут:
  рекурсивный тип не развернуть, а ошибка спеки ломала бы сборку фасада, которому redump не нужен.
- **Вывод только внутри одного плагина.** Отвергнут: на спеку другого плагина ссылаются и A, и B.
- **Узлы дискриминатора в `Redump`** (`{:by, ключ, %{значение => спека}}` под тегом, `{:inline, …}`).
  Отложен: конфликта одноимённых полей у вариантов одного тега нет ни у кого. Узел добавляется, когда
  конфликт появится, — форма спеки от этого не ломается.
- **Sensitive-поле — мимо спеки, как в ручных.** Отвергнут: выведенная спека сама проводила бы
  чувствительное значение наружу. `CompileError` — тоже отвергнут: вывод идёт при сборке плагина, а
  спека полей sensitive разрешает — это write-путь.
- **Тип без спеки проходит как есть.** Отвергнут: значение молча остаётся в формате внутреннего
  профиля — то самое расхождение, ради которого спеку выводят.
- **Без колбэка у ручного плагина** (ручные типы — только через `{Mod, :fun}`). Отвергнут: спека
  остаётся функцией вдали от плагина, который пишет форму, и View не может сослаться на тип.
- **Опускать plain-kind Prim, как A.** Отвергнут: профиль может переопределить `dump/1` и для
  `:string` / `:integer`; `Core.View` и `dump_raw/3` их не опускают.
- **Сверка read-wire обязательна для всех форм.** Отвергнут: у выведенной формы она проверяет
  генератор, а это тест библиотеки.

## Решение

- плагин генерирует спеку для каждого типа из `fields:`, варианта из `variants:` и семейства с
  `variants:`. Тип по полям даёт `{:map, %{wire-ключ => спека}}`: приводимый Prim, включая plain-kind,
  — `{:prim, P}`, `entity:` / `union:` — `{:codec, M}`, `list:` — `{:list, спека}`, sensitive —
  `:sensitive`. Prim с кастомным kind, `enum:` и `type:` в спеку не входят;
- спека варианта — форма его дампа: тегированный — `{:tagged, %{тег => {:map, поля}}}`, без
  обёртки — `{:map, поля}`. Иначе `{:codec, Variant}` у поля `entity: Variant` молча не совпал бы с
  обёрнутым значением, которое пишет `codec.dump/1`; спеку только полей объявляет лишь колбэк
  ручного варианта, обёртку добавляет плагин;
- спеки вариантов одного тега сливаются в одну, форма без обёртки — в одну `{:map, …}` на семейство;
  одноимённый ключ с разной спекой — `CompileError` при сборке плагина;
- ручной плагин объявляет спеку ручного типа, ручного варианта и семейства без `variants:`
  колбэком `redump_spec/1`;
- `{:codec, M}` разрешает фасад, переданный в `Redump.run/3`: его `__codec_redump__/1` берёт спеку
  у плагина типа. Тип без спеки и модуль без плагина — `ArgumentError`, где названы тип и плагин;
  бросает его фасад: плагин генерирует `__codec_redump__/1` только на типы со спекой, а типы без неё
  отдаёт `__codec_redump_missing__/0`. Клауза плагина, которая только бросает, давала функции
  success typing `none()` против `@spec` — Dialyzer у потребителя: `invalid_contract` у плагина и
  «will not succeed» у фасада;
- `:sensitive` удаляет ключ из результата;
- View ссылается на спеку по типу (`jsonb: Type`); `jsonb: {Mod, :fun}` остаётся для форм без типа —
  словарей, варианта, который выбирает родитель, тега вне jsonb;
- сверка read-wire обязательна только для формы с ручной частью — колбэком или `{Mod, :fun}`.

## Цена

- **У фасада появилась четвёртая функция.** Контракт «`dump/1`, `load/2`, `load!/2` — и больше
  ничего» расширен служебной `__codec_redump__/1`.
- **Тип без спеки находится при исполнении.** Ссылку `{:codec, M}` и `jsonb: Type` сборка не
  проверяет: какой плагин обслуживает тип, известно только фасаду. Ловит тест read-пути, иначе —
  `ArgumentError` на первом запросе.
- **Слитые варианты делят спеку ключа.** Пока нет узла дискриминатора, одноимённые поля с разной
  спекой под одним тегом не объявить.
- **Форма наружу отличается от записанной.** Ключ с sensitive-значением на read-пути исчезает.

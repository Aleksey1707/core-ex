# Golden-фикстура события с ПДн-значением — открытая форма и уничтоженный вариант

Golden-фикстура события с ПДн-значением хранит конверт после расшифровки — то, что видит апкастер при живом ключе, —
а не записанную форму с шифротекстом. Уничтоженный вариант лежит отдельной фикстурой `destroyed/<тег>.json`:
`Core.Es.EventCompatCase` требует её и сверяет со схемой, пока тег текущий, а когда тег становится источником
`upcasts:`, она проверяет апкаст на `{"$pd": null}`. `subject:` с поля не снимается, субъект поля на прежнем теге
не меняется. Эволюция событий — ADR-0010, слой шифрования — ADR-0073, уничтоженное значение — ADR-0074.

## Контекст

Факты на 2026-10-18:

- `Core.Es.EventCompatCase` — `ExUnit.Case` без БД: грузит фикстуры `Jason.decode` + `codec.load` по семейству,
  `dump` с фикстурой не сверяет; `Core.Es.ProjectionCase` гоняет `project/1` на фикстурах текущих тегов, глотает
  его отказы и проверяет только `clear/0`;
- фикстуры не перегенерируются (ADR-0010) и живут в репозиториях потребителей;
- расшифровка идёт до апкаста: на месте `{"$pd": …}` встаёт JSON wire-значение поля, при уничтоженном ключе —
  `{"$pd": null}`; шифротекст несёт случайный nonce, его открывает только записавшая реализация хранилища ключей
  (ADR-0073, ADR-0075);
- у источника `upcasts:` схемы нет — только функции апкаста: какие поля старого тега были ПДн, после смены тега
  не знает никто;
- маркер уничтоженного значения принимает только поле с `subject:` (ADR-0074);
- `Jason.encode!(InCodec.dump(event))` на маркере ПДн-значения падает (ADR-0073); генератора фикстур нет.

## Рассмотренные варианты

### Форма фикстуры

- **Записанная форма под тестовым ключом.** Отвергнута: case получает хранилище ключей с засеянным обёрнутым
  ключом — у встроенной реализации это БД и потеря `async`; шифротекст непрозрачен на ревью; фикстура привязана к
  реализации порта, и у потребителя со своим портом case перестаёт работать.
- **Разметка ПДн-полей в открытой фикстуре** (`{"$pd": <открытое значение>}`). Отвергнута: третья форма, которой
  нет ни в хранилище, ни у апкастера; `$pd` в ней значил бы не то же, что в `es_events`.

### Уничтоженный вариант

- **Выводить case'ом по схеме полей текущего тега.** Отвергнуто: источник `upcasts:` схемы не имеет, и проверка
  апкаста на маркере пропала бы ровно тогда, когда она нужна.
- **Требовать уничтоженное значение в результате апкаста.** Отвергнуто: апкаст, удаляющий поле, дал бы ложный
  провал.
- **Вариант на каждое сочетание субъектов.** Отвергнуто: апкастер разбирает каждое поле по отдельности.

### Снятие `subject:`

- **Новый тег с апкастом.** Отвергнуто: маркер в поле без `subject:` — `:invalid_value`, апкастеру остаётся
  подмена, которую отверг ADR-0074.

## Решение

- `<тег>.json` — конверт после расшифровки, на месте ПДн-значения открытое wire-значение; одна фикстура покрывает
  и строки тега, записанные открытыми до разметки поля, и зашифрованные; шифротекст в фикстуре даёт ошибку
  «нерасшифрованное ПДн-значение»;
- `destroyed/<тег>.json` — та же фикстура с `{"$pd": null}` на месте каждого ПДн-значения; MUST у текущего тега,
  в нагрузке которого есть поле с `subject:`; `EventCompatCase` проверяет тег в `type`, загрузку и `%Destroyed{}` в
  каждом поле с `subject:`, у источника `upcasts:` — загрузку апкастом; фикстура тега, которого нет в кодеке, или
  текущего тега без `subject:` — провал; вариант один на тег, уничтожены все ПДн-значения;
- `EventCompatCase` проверяет, что персональный Prim в загруженной фикстуре текущего тега лежит только в поле
  верхнего уровня с `subject:` — вложенную сущность сборка не проверяет;
- `ProjectionCase` прогоняет `project/1` на уничтоженном варианте в откатываемом savepoint перед открытым: открытый
  прошёл, уничтоженный — нет, провал;
- тела обеих фикстур отдаёт функция библиотеки по событию, дамп — через фасад; файлы пишет автор;
- `subject:` на существующем поле — тег прежний; снятие `subject:` — MUST NOT; смена субъекта поля — новый тег;
- шифрование писателями и формат шифротекста проверяют тесты библиотеки: golden-шифротекст схемы `1` и обёрнутый
  ключ под тестовым KEK.

## Цена

- **Фикстура — не записанная строка.** «То, что лежит в проде» читается как «после расшифровки»; формат
  шифротекста держит тест библиотеки, у своего порта — тест потребителя.
- **Два файла на тег с ПДн.** Разметка существующего поля добавляет уничтоженный вариант новым файлом.
- **ПДн-поле — навсегда.** Ошибочно размеченное поле остаётся ПДн-полем, как тег остаётся в кодеке.
- **Проверка персонального Prim видит только заполненное.** Необязательная вложенная сущность `nil` и варианты
  union вне фикстуры её проходят.
- **Не проверяются case'ом:** подмена маркера апкастером, смешанный случай двух субъектов, смена субъекта поля на
  прежнем теге, `evolve/2` и `decide/2` на уничтоженном значении.

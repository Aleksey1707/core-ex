# Уничтожаемое поле и события в структуре по полям: `destroyable:` и `events:`

Язык полей `Core.Struct` (ADR-0090) получает две опции. `destroyable: true` у поля добавляет к типу
`| Core.Es.Personal.Destroyed.t()`: поле состояния, куда свёртка кладёт ПДн-значение, после уничтожения ключа
субъекта держит уничтоженное ПДн-значение (ADR-0074). `events: Family` на уровне `use` порождает служебное
поле `events` state-stored агрегата с типом `Core.Es.Events.t(Family.t())` и значением по умолчанию
`Es.Events.new()`. Термин — `CONTEXT.md`, «Уничтожаемое поле».

## Контекст

Факты на 2026-10-27:

- состояние event-sourced агрегата фикстуры-потребителя объявлено `use Core.Struct` с полем
  `holder: [prim: Holder, optional: true]`, тип — `Holder.t() | nil`; `evolve/2` кладёт в него значение поля
  нагрузки с `subject:`, которое после уничтожения ключа — `%Destroyed{}`: тип состояния врёт;
- в нагрузке `| Destroyed.t()` получает поле с `subject:`, а не поле с `personal: true`: `subject:` MAY у поля
  с Prim без `personal:` и у `entity:` / `type: :map` (`23-personal-data.md`);
- уничтоженное значение стоит только на месте поля нагрузки верхнего уровня, но состояние собирает `evolve/2`, и
  значение попадает куда угодно: в поле вложенной сущности, в элемент списка, в значение словаря — например,
  у агрегата с получателями-субъектами, ключ каждого из которых уничтожается отдельно;
- экземпляры `%Destroyed{}` равны: в `MapSet` и в ключе словаря два уничтоженных значения неотличимы;
- `Core.Struct` при раскрытии роль модуля не знает; роли (`Core.Es.Aggregate`, `Core.Es.Cmd`, плагин по
  полям) проверяют поля сами по `__struct_fields__/0`;
- поле `events` state-stored агрегата объявлялось только ручным `defstruct`: в языке полей нет вида для
  `Es.Events.t()`; `Repo.Pg.StateStored` читает его буквально (`entity.events`), плагин по полям исключает ключ
  `events` из сверки по имени; у семейства событий `@type t` обязателен.

## Рассмотренные варианты

### Как объявить уничтожаемое поле

- **Вывод из флага Prim** (`personal: true` в виде поля → `| Destroyed`). Отвергнут: пропускает поле с
  `subject:` без `personal:`, а в команде и сущности ответа даёт лишний вариант типа.
- **Своя опция типа** (произвольный typespec поля). Отвергнута: лазейка из языка полей, уничтоженное значение в
  ней не видно.
- **`personal: true` у поля.** Отвергнут: говорит о природе данных, а не о том, что окажется на их месте; поле
  команды с ПДн не уничтожаемо, уничтожаемое поле не обязано держать ПДн-Prim; у `personal:` уже три смысла
  (редакция Prim, индекс резерва ключа, проекция без ПДн).
- **`subject:` по образцу нагрузки.** Отвергнут: в состоянии значению некуда применяться — снапшот запечатан
  целиком (ADR-0090 отверг `subject:` в структуре по этой причине).
- **`destroyable: true` (принято).** Прилагательное о значении поля, расширяющее тип, как `optional: true`;
  корень — словарь подсистемы (`Destroyed`, `destroy_key/3`).

### Где допустимо

- **Только поле верхнего уровня, только состояние агрегата.** Отвергнуто: состояние с данными нескольких
  субъектов держит уничтоженное значение внутри сущности, списка или словаря.
- **Любая `Core.Struct`, кроме команды; элемент `list:` и значение `map:` (принято).** Элемент `set:` и ключ
  `map:` — отказ: равные экземпляры не идентифицируют запись. Вложенная сущность годится и для состояния, и для
  ответа — решает автор; сборка запрещает только тип записи.

### Как выразить `events`

- **Вид поля `events: [events: Family]`.** Отвергнут: имя поля выбирает автор, а репозиторий читает только
  `events`.
- **`type: :events`.** Отвергнут: тип без семейства.
- **Опция `events: Family` на уровне `use` (принято).** Имя фиксировано, тип точный, служебное поле не
  смешивается с доменными и не входит в `__struct_fields__/0`.

## Решение

- `destroyable: true` — у поля верхнего уровня, у элемента `list:` и у значения `map:`, любого вида; тип —
  `T | Core.Es.Personal.Destroyed.t()`, с `optional: true` ещё `| nil`. У элемента `set:` и ключа `map:` —
  `CompileError`.
- `Core.Es.Cmd` отказывает `CompileError` на `destroyable:` у своего поля и у поля сущности `entity:` на любой
  глубине; варианты `union:` не проверяются.
- В режимах плагина по полям, `Payload` и `View` `destroyable:` — `CompileError`; плагин при сверке со
  структурой его не сравнивает.
- `use Core.Struct, events: Family` порождает поле `events: Core.Es.Events.t(Family.t())` со значением
  по умолчанию `Es.Events.new()`. `CompileError`: `Repo.Pg.StateStored` с `entity:`, собранным `Core.Struct`
  без `events:`; семейство `events:` не совпадает с семейством `event_codec:`; `events:` у `Core.Es.Aggregate`
  и `Core.Es.Cmd`; поле `events` в `fields:` рядом с `events:`.
- Норма MUST в `23-personal-data.md`: место состояния, куда `evolve/2` кладёт значение поля с `subject:`,
  объявляется `destroyable: true`.

## Цена

- **Сборка не проверяет, что уничтожаемое поле размечено.** Поток значения через `evolve/2` не прослеживается:
  забытая `destroyable:` снова даёт тип без `Destroyed`, ловит только ревью.
- **Тип вложенной сущности шире у всех её пользователей.** Сущность с уничтожаемым полем, взятая в ответ или
  View, несёт `| Destroyed` и там, где его не бывает.
- **Варианты `union:` в команде не проверяются.** Вариант с уничтожаемым полем проходит сборку команды.
- **`events` — поле вне спеки.** Плагин по-прежнему исключает его по имени, а не по объявлению; подписи —
  по опции `events:`.

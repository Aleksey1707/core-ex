# Резерв ключа из ПДн: индекс через хранилище ключей, снятие событием потребителя

Резерв ключа, значение которого — ПДн (email, телефон), хранит не `to_key/1`, а индекс ключа: HMAC с секретом,
который считает хранилище ключей. Модуль такого ключа объявляется `personal: true`. Резерв снимает событие
потребителя в транзакции уничтожения ключа субъекта, после чего ключ свободен. Идентификатор из ключа из ПДн не
вычисляется. Резерв ключа — ADR-0018, хранилище ключей — ADR-0075, уничтожение — ADR-0076; термины — `CONTEXT.md`,
«Резерв ключа», «Идентификатор из ключа».

## Контекст

Факты на 2026-10-18:

- `es_key_reservations.key` — ровно то, что вернул `to_key/1`, `text[]` в открытом виде, PK `(scope, key)`;
  `find/2` ищет точным совпадением; таблица выпущена (ADR-0018);
- в копии базы без KEK остальное нечитаемо: события — шифротекст (ADR-0073), ключи субъектов обёрнуты KEK
  (ADR-0075); открытым остаётся только резерв ключа;
- уничтожение ключа субъекта меняет только строку ключа и никого не извещает; связи «субъект → потоки» нет
  (ADR-0076);
- владелец резерва — `aggregate_id`, субъект в строке резерва не записан;
- идентификатор из ключа — UUIDv5 от namespace, области и частей ключа (ADR-0017); namespace и область лежат в
  коде, секрета в схеме нет; `aggregate_id` открыт в `es_events`, outbox, логах и read-модели;
- уничтожение по 152-ФЗ — невосстановимость содержания ПДн в ИСПДн, копии включительно; телефонов около 10^10;
- готовые решения в event sourcing уникальность по ПДн не описывают; `Cloak.Ecto.HMAC` держит HMAC с секретом в
  отдельной колонке, равенство значений по нему видно.

## Рассмотренные варианты

### Резерв после уничтожения

- **Занят навсегда.** Отвергнут: строка — ПДн субъекта, связанное с `aggregate_id`; индекс телефона с секретом
  перебирается, то есть содержание восстановимо. Тот же человек по новому согласию не получил бы свой email.

### Форма ключа в строке

- **Открытое значение, защита только снятием.** Отвергнут: снятие закрывает живую таблицу, а открытый email
  остаётся в копиях, WAL-архиве и мёртвых кортежах, и зачистить его нечем — ротация KEK этих следов не касается.
- **HMAC в `to_key/1` потребителя.** Отвергнут: секрет добывает каждый потребитель сам, а забытый HMAC в одном
  модуле ключа не виден.
- **Индекс у всех модулей ключа.** Отвергнут: ломает выпущенный контракт и требует секрет у каждого потребителя с
  резервами, а ключу без ПДн (название роли) он не нужен.
- **Признак из Prim значения в рантайме.** Отвергнут как объявление: значение-struct с вложенным Prim не видно.
  Оставлен проверкой: `personal: true` Prim на модуле без `personal: true` — `ArgumentError` на `append`.

### Кто считает индекс

- **Библиотека сама, `:crypto.mac/4` и отдельный ключ конфигурации.** Отвергнут: криптография ПДн мимо
  подменяемого порта; оператор, которому модель угроз требует СКЗИ, остался бы с несертифицированным HMAC.
- **Секрет из KEK.** Отвергнут: KEK ротируется, а индекс без открытых значений не пересчитать.

### Состав индекса

- **Каждая часть ключа отдельно.** Отвергнут: у составного `[tenant, email]` один email в двух арендаторах дал бы
  равную часть, и связь лица между арендаторами видна.
- **Без области.** Отвергнут: один email в двух областях сопоставим.

### Кто снимает резерв

- **`destroy_key` удаляет резервы субъекта.** Отвергнут: строке резерва нужен субъект — новая колонка в выпущенной
  таблице и миграция у каждого потребителя, — `reservation/1` должен его называть, а операция перестаёт менять
  только строку ключа (ADR-0076).

### Идентификатор из ключа из ПДн

- **Секретный namespace из конфигурации.** Отвергнут: смена конфигурации переименовывает потоки (ADR-0017), а
  `aggregate_id` не снимается, как резерв, — индекс с секретом остаётся в каждом событии навсегда.

### Резервы, записанные открытыми

- **Функция перевода строк области в индекс.** Отвергнута: публичный API под сценарий, которого нет; история такой
  области и так открыта и не переписывается (ADR-0010).

### Ротация секрета индекса

- **Функция пересчёта резервов свёрткой агрегатов-владельцев.** Отвергнута: связи «модуль ключа → типы агрегатов»
  библиотека не держит, машинерии пересвёртки нет.
- **Версия секрета в строке индекса и двойной поиск в `find/2`.** Отвергнута: без пересчёта старые строки держат
  старый секрет навсегда, и он не уходит.

## Решение

- `use Core.Es.KeyReservation, …, personal: true` — модуль ключа из ПДн; библиотека считает индекс поверх
  `to_key/1` одинаково на записи и в `find/2`; в `key` — `text[]` из одной строки индекса;
- на `append` значение `{:reserve, value}` — Prim с `personal: true` у модуля без `personal: true` —
  `ArgumentError`; вложенный Prim проверка не видит;
- индекс считает порт хранилища ключей: пачка `(область, части)` → индексы, отказ — `{:error, %Error{kind: :app}}`
  на всю пачку; встроенная реализация — HMAC-SHA256 секретом из конфигурации, отдельным от KEK и без версии;
  индекс равен для равных пар и различен для разных областей, части кодируются однозначно;
- секрет индекса не ротируется: живёт, пока живут области с `personal: true`, хранится и копируется наравне с KEK;
  компрометация закрывается переводом потребителя на новую область; `ensure_configured!/0` проверяет его наличие
  и длину;
- `append` считает индексы всех шагов `{:reserve, value}` пачки одним вызовом до записи; отказ откатывает
  транзакцию, `Es.Transact` не повторяет; `find/2` сохраняет `Agg.ID.t() | nil` и при отказе поднимает `Core.Exc`
  — как его SQL при сбое базы;
- usecase уничтожения ключа субъекта MUST в своей транзакции снять резервы ключей из ПДн этого субъекта —
  событием в агрегате-владельце, на которое `reservation/1` отвечает `:release`; clause на это событие требует
  сборка;
- `personal: true` ставится только на область без записанных резервов; перевод существующей области — перевод
  потребителя;
- идентификатор из ключа из ПДн MUST NOT: неизменяемый ключ-ПДн получает случайный идентификатор и резерв ключа с
  `personal: true`; проверки сборкой нет — `from_key/1` видит строки.

## Цена

- **Снятие держит норма.** Забытое событие оставляет строку индекса навсегда, а `find/2` находит агрегат
  уничтоженного субъекта.
- **Секрет индекса не ротируется** без открытых значений ключей; его утрата ломает `find/2` и уникальность прежних
  ключей; копия базы с секретом раскрывает перебором индексы телефонов.
- **Следы после снятия.** Мёртвый кортеж, WAL-архив и реплики держат индекс снятого ключа; без секрета он
  непрозрачен.
- **Равенство видно.** Два одинаковых ключа в области дают одинаковый индекс — на этом стоит уникальность.
- **Индекс воспроизводит только посчитавшая его реализация.** Смена реализации порта — пересчёт резервов из открытых
  значений.
- **`find/2` у внешней реализации порта** ходит в неё на каждый вызов.
- **Запрет идентификатора из ключа держит норма.**

# Уничтожение ключа субъекта — одним шагом и окончательно

Уничтожение ключа субъекта — один синхронный шаг в транзакции вызывающего: ключ уничтожен в момент её commit,
отложенной фазы нет. Уничтожение окончательно: ПДн-значение субъекта после него не пишется, запись получает
доменный отказ, а повторное согласие требует нового идентификатора субъекта. Акт об уничтожении пишет потребитель,
библиотека своего журнала не ведёт. Единица ключа — ADR-0072, хранилище ключей — ADR-0075; термин — `CONTEXT.md`,
«Уничтожение ключа субъекта».

## Контекст

Факты на 2026-10-18:

- 152-ФЗ даёт на уничтожение от 7 рабочих дней (ст. 20 ч. 3); подтверждение — акт и выгрузка из журнала с
  субъектом, причиной и датой (приказ РКН № 179), реквизиты оператора, лиц и подписи — у оператора;
- готовые решения уничтожают ключ сразу (Axon) или сначала пишут событие удаления, а ключ удаляют с задержкой,
  пока read-side чистит копии (akka-gdpr, сотрудник Kurrent, Verraes); запись после уничтожения не описывает никто;
- хранилище ключей держит строку на субъекта с уникальным индексом по субъекту, создаёт ключ в транзакции
  `append` и уничтожает его `UPDATE` (ADR-0075); кеша ключей на нодах нет;
- связи «субъект → потоки» нет; категорий ПДн у полей нет — `personal: true` только признак;
- процесс агрегата перед командой дочитывает только хвост потока, а `idle_timeout` сбрасывает каждая команда:
  под нагрузкой процесс держит расшифрованное состояние бессрочно, на каждой ноде своё; снапшот —
  `term_to_binary` состояния мимо кодека, пишется после commit любого чтения;
- в транзакции `Transact.run` допустимы запросы через `DAO`; ключ, созданный порт-реализацией мимо транзакции,
  после отката остаётся сиротой (ADR-0075).

## Рассмотренные варианты

### Порядок

- **Два шага: событие или заявка, затем ключ с задержкой.** Отвергнут: ПДн читаемы весь срок задержки, нужен
  воркер, дата в акте расходится с вызовом. Когда уничтожать, решает потребитель: задержку он ставит своей
  очередью задач.

### Транзакция

- **Всегда своя транзакция, внутри `Transact.run` — `ArgumentError`.** Отвергнут: потребитель не запишет своё
  событие об уничтожении и чистку своих таблиц атомарно с ключом.

### Запись после уничтожения

- **Новый ключ** — уникальный индекс только по живым ключам, повторное согласие на том же субъекте. Отвергнут:
  поздняя команда, отправленная до уничтожения, ретрай подписчика или процесс агрегата с устаревшим состоянием
  молча пишут ПДн снова.
- **Без блокировки строки ключа.** Отвергнут: событие, зашифрованное ключом, который конкурент уничтожил до его
  commit, записывается успешно и уничтожено с рождения — отказ обойдён.

### Ошибка отказа

- **Код из каталога агрегата `errors:`.** Отвергнут: `Store.append` общий для обоих видов агрегатов и каталога не
  знает, а новый обязательный код сломал бы каталоги потребителей.

### Процессы агрегатов и снапшоты

- **Выгон процесса по id** с рассылкой по кластеру из usecase уничтожения. Отвергнут: ПДн субъекта лежат и в
  чужих потоках, а нода за разрывом сети рассылку не получит.
- **Процесс без кеша у агрегата с ПДн** — полная свёртка на каждую команду. Отвергнут: граница в минуты
  укладывается в сроки 152-ФЗ дешевле.
- **Удаление снапшотов при уничтожении** по индексу «субъект → потоки». Отвергнут: открытое состояние остаётся в
  WAL и копиях.
- **Снапшот с долями ключа под каждым субъектом состояния.** Отвергнут: готовых решений нет, нужен учёт
  субъектов состояния; снапшот под одним субъектом-агрегатом покрывает агрегат-лицо.

### Подтверждение

- **Журнал уничтожений библиотеки** — причина аргументом, автор из `%Context{}`. Отвергнут: дублирует акт
  потребителя; дату и субъекта и так держит строка хранилища ключей.
- **Чтение «уничтожен ли ключ субъекта».** Не заведено: запись защищает отказ, команду потребитель отвергает по
  своему состоянию, повтор по актам идемпотентен.

## Решение

- операция — функция фасада хранилища ключей `(subject_id, by, context)`: `subject_id` — UUID-Prim субъекта, `by` —
  UUID-Prim актора, которого usecase берёт своим `CurrentUser` до транзакции, как `by` команды; библиотека актора
  из `%Context{}` не читает — ключа и типа аксессора потребителя она не знает; изменяющая, возврат
  `Result.unit()`, хранилище не ответило — `{:error, %Error{kind: :app}}`; права проверяет usecase;
- реализация резолвится через `Core.Config`; в транзакции вызывающего операция участвует, вне её — открывает
  свою; библиотека в ней меняет строку ключа и пишет событие уничтожения ключа (ADR-0079); реализация мимо
  транзакции уничтожает ключ необратимо, и контракт порта это называет;
- уникальный индекс по субъекту — полный: строка-след держит субъекта навсегда; субъект без ключа получает
  строку-след без ключа; повтор — `:ok`, первая дата уничтожения не перезаписывается;
- запись непустого ПДн-значения уничтоженного субъекта — `%Error{kind: :domain}` с фиксированным кодом и `ns`
  хранилища ключей, в `detail` — идентификатор субъекта; `Es.Transact` её не повторяет;
- встроенная реализация читает строку ключа при шифровании под блокировкой, которую ждёт уничтожение: событие
  либо записано раньше и уничтожено, либо получает отказ; от своей реализации порта требуется только одно —
  после уничтожения ни одно ПДн-значение субъекта не читается;
- процессы агрегатов и снапшоты операция не извещает — они решают своё сами; проекциям она пишет событие
  уничтожения ключа (ADR-0079); третьих лиц извещает потребитель;
- процесс агрегата с ПДн в событиях выбрасывает состояние старше предельного возраста (по умолчанию 5 минут,
  `:infinity` нельзя) и следующую команду начинает полным чтением; возраст считается от полного чтения; без команд
  процесс уходит, как только состояние устарело;
- снапшот агрегата с ПДн допустим, только если субъект всех ПДн-полей его событий — `:aggregate_id`: снапшот
  целиком — одно ПДн-значение этого субъекта; снапшот уничтоженного ключа отвергается, поток сворачивается
  полностью, новый снапшот после уничтожения не пишется;
- для акта библиотека даёт строку-след и описание способа встроенной реализации в своде; причину, автора,
  категории и ИСПДн потребитель пишет в свой акт, например событием в той же транзакции.

## Цена

- **Повторное согласие — новый субъект.** У субъекта `:aggregate_id` агрегат больше не пишет событий с
  ПДн-значением; новые данные лица — под новым идентификатором субъекта, новым агрегатом или отдельным полем.
- **Отказ приходит из глубины `append`.** Команда, собранная до уничтожения, узнаёт о нём только на записи;
  usecase потребителя отображает отказ сам.
- **Взаимная блокировка** при уничтожении нескольких субъектов одной транзакцией в произвольном порядке против
  `append` с сортировкой: Postgres обрывает одну из транзакций.
- **Своя реализация порта мимо транзакции**: откат транзакции вызывающего ключ не вернёт, а событие уничтожения
  потребителя может не записаться — повтор операции идемпотентен.
- **Акт целиком на потребителе.** Библиотека не помнит причину и автора уничтожения.
- **Память отстаёт от уничтожения** на предельный возраст кеша процесса; освобождённую память до сборки мусора
  библиотека не зануляет.
- **Поток уничтоженного субъекта-агрегата без снапшота**: каждое чтение сворачивает его целиком, а у агрегата с
  субъектом в поле нагрузки снапшотов нет вовсе; не проверено на нагрузке.

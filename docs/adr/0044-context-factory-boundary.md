# Фабрика контекста — своя граница над границей аксессора

Фабрика контекста `MyApp.ContextFactory` — подсистема приложения, своя граница; её `deps` —
владельцы ключей контекста, сейчас только граница аксессора текущего пользователя: контекст
учётной записи или подсистема `MyApp.Auth`. Фабрику держат в `deps` контексты, web, граница входа
и корень; граница аксессора от неё не зависит и контекст для своих воркеров и подписчиков собирает
сама. Место фабрики задаёт направление зависимостей, а не то, о чём она. Пересматривает решение
Q18 для потребителя A («фабрика — экспорт контекста учётной записи»).
Норма — `docs/rules/app/11-domain.md`, «Context»; `docs/rules/app/10-architecture.md`,
«Top-level namespaces», «Boundary».

## Контекст

Факты на 2026-10-03 (решения — `.scratch/consumer-architecture/decisions.md`, Q18; разбор
потребителя A — `.scratch/consumer-architecture/research/02-consumer-a-structure.md`; разбор
фабрик — `.scratch/consumer-architecture/issues/09-context-factory-place.md`):

- после ADR-0037 `MyApp` границей не является, и фабрика модулем верхнего уровня
  `lib/my_app/context_factory.ex` осталась вне границ — у потребителя это ошибка сборки;
- фабрики есть у потребителей A, B, C, D, F. Ключей контекста у всех два — эталонные копии
  (`Repo.Sc`) и текущий пользователь. Знание приложения у фабрики — только учётная запись:
  аксессор, тип ID, ID системной и анонимной учётных записей; `empty/0` и `sc/0` — обёртки над
  `Core`. У B, C, F аксессор и ID учётных записей лежат в разных местах;
- фабрику зовут воркеры, подписчики и обработчики контекстов, outbox, mix-таски и задачи релиза,
  репозитории и кеш read-модели (A, C, F) и плаг контекста web — у всех пяти;
- изнутри границы аксессора фабрику не зовёт ни один потребитель; у A контекст учётной записи ни
  от кого не зависит, остальные контексты зависят от него;
- `boundary` ищет циклы по объявленным `deps` (`Boundary.Checker`), а ссылку на границу без неё в
  `deps` репортит как запрещённую.

## Рассмотренные варианты

- **Экспорт контекста учётной записи (Q18), у приложения без агрегата учётной записи — модуль
  `MyApp.Auth`.** Отвергнут: фабрика собирает контекст единицы работы, а не учётную запись, и
  контекст учётной записи держал бы обвязку всего приложения — от плага web до задач релиза. Ключ
  контекста другого владельца привязал бы контекст учётной записи к этому владельцу.
- **Сток `MyApp.Infra`.** Отвергнут: стоку не виден тип ID учётной записи — он не зависит от
  домена.
- **Макрос фабрики в `Core`.** Отвергнут: состав фабрики прикладной — откуда берутся системная и
  анонимная учётные записи, решает приложение, а обёртки над `Core` библиотеке не нужны.
- **Своя граница без исключения для границы аксессора.** Отвергнут: воркер контекста учётной
  записи, который по общей норме берёт контекст у фабрики, замкнул бы цикл границ, и `dirty_xrefs`
  на нём стал бы постоянным отступлением.

## Решение

- фабрика — граница `MyApp.ContextFactory` в `lib/my_app/context_factory.ex`, модуль и путь
  прежние; `deps` — владельцы ключей контекста, сейчас только граница аксессора текущего
  пользователя;
- фабрику держат в `deps` контексты, `MyAppWeb`, `MyAppIngest` и корень; плаг контекста web
  собирает контекст фабрикой, как воркеры и подписчики;
- граница аксессора не зависит от фабрики ни прямо, ни через границу из своих `deps`: контекст
  для своих воркеров и подписчиков она собирает `Core.Context.new/0`, `Core.Repo.Sc.init/1` и
  своим аксессором;
- ключ контекста другого владельца входит в фабрику строкой её `deps`; его владелец лежит ниже
  всех, кто зовёт фабрику.

## Цена

- **Исключение из «контекст — только через фабрику»:** граница аксессора повторяет сборку
  контекста, которую делает фабрика. Нарушение ловит сборка — цикл или запрещённая ссылка
  `boundary`.
- **Фабрика — ещё одна строка `deps`** у каждой границы, которая собирает контекст.
- **Ключ контекста вне нижнего слоя невозможен:** ключ, чей владелец зависит от контекста,
  который зовёт фабрику, замкнул бы цикл. Это следствие направления вызовов, а не места фабрики.
- **Переезд потребителей:** у A, B, C, D, F — `use Boundary` в фабрике и фабрика в `deps`
  вызывающих границ; решение Q18 у A к переезду не применяется.

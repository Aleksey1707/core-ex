# Codec-плагин по полям: спека полей в плагине, нагрузка события — struct из декларации

Тип, чья wire-форма повторяет поля один к одному, объявляется спекой полей, и `dump` / `load`
генерирует библиотека: у сущности и агрегата — опцией `fields:` у `use Core.Codec.Plugin` (struct
остаётся ручным), у нагрузки события — `use Core.Es.Event.Payload, fields:`, который порождает и
struct, и спеку. Ручной плагин остаётся для всего, что расходится с полями сильнее переименования
ключа. Норма — `docs/rules/11-domain.md` и `docs/rules/app/11-domain.md`, «Codec (Prim и Entity)».

## Контекст

Замер на 2026-10-10 по потребителям A–F (только `lib/`):

- ручных Codec-плагинов 48 на 89 типов, кодеков событий 23 на 89 нагрузок; один к одному с wire —
  146 из 178 (82 %), почти вся нетривиальность — у потребителя B;
- переименований wire-ключа и типов «часть полей вне wire» — ни одного;
- enum при загрузке везде идёт через `cast` / `cast_optional`;
- нагрузки событий: 40 голых struct с тривиальным `new`, 13 `Es.ValueChanged`, 19 нагрузок-Prim,
  у 14 нагрузка — value object со своим плагином;
- у потребителя C — собственный макрос-шаблон плагинов; у A многотиповые плагины смешивают типы
  1:1 и нетривиальные (так же у C и F);
- снапшоты кодек не используют (`term_to_binary`).

Дамп выводится и без декларации — значения полей сами Prim или сущности фасада. Загрузку нет:
у `defstruct` типов полей нет, и Prim каждого поля должен быть где-то объявлен.

## Рассмотренные варианты

- **Struct и кодек сущности из одной декларации (как `Core.View`).** Отвергнут для сущностей и
  агрегатов: их struct несёт поля, которые ведёт библиотека (`id` / `version` у
  `Core.Es.Aggregate`), `events`, дефолты и доменные конструкторы — макрос вырос бы в язык схем,
  а перевод переписал бы каждый файл сущности. Риск «добавил поле — забыл кодек» закрывает сверка
  ключей спеки со struct. Пересмотр — если потребителю понадобится точный `@type t` агрегата для
  вывода типов. Для нагрузки события принят: она — чистые данные, как View.
- **Общая спека с `Core.View`.** Отвергнут: у View значения голые, kind только приводимые,
  sensitive запрещён, есть `form:` / `jsonb:`; у плагина значения — Prim, kind любой, sensitive
  обязан проходить, нужен `entity:`. Общие — имена ключей и элементарные проверки.
- **`@derive` / протокол.** Отвергнут: вторая ось диспетчеризации мимо фасада, а загрузке
  протокол не подходит — значения для выбора реализации ещё нет.
- **Вывод полей из `@type t`.** Отвергнут: typespec доступен только из `.beam`, не при сборке
  того же модуля.
- **Генератор `mix`-таской.** Отвергнут: снимает набор кода, но не сопровождение и не рассинхрон.
- **Хелпер дампа без спеки.** Отвергнут: типов «dump 1:1, load нет» в замере ноль.

## Решение

- спека плагина задаётся по типу (`fields: [{Type, spec}]`), ключи — подмножество `types:`;
  остальные типы плагина — ручными клаузами, непокрытый тип — `CompileError`;
- ключи спеки строго равны полям struct без `events` — иначе `CompileError`;
- голова `dump/2` закрывает struct и каждое поле по виду (ADR-0014); wire-ключ — имя поля строкой
  или `wire:`;
- `load` собирает struct литералом, а не через `new`: загрузка восстанавливает записанное, поле
  проверяет его Prim, межполевые инварианты проверены записью; первая ошибка — итог, неизвестные
  ключи игнорируются;
- `default:` при загрузке — только в плагине: строка jsonb state-stored агрегата развивается
  добавлением поля; у нагрузки события `default:` запрещён — её развитие идёт новым тегом и
  апкастом (ADR-0010, ADR-0020);
- значение `default:` — wire-литерал, а не значение поля: он подставляется вместо отсутствующего
  ключа или `nil` и грузится как записанный (Prim, `cast` enum, фасад). Значение поля — Prim или
  сущность — литералом в опциях `use` не записать, а wire-литерал проходит ту же проверку, что
  строка из БД; сборка проверяет его только у `enum:` (`cast` — чистая функция модуля), прочие
  виды без фасада не грузятся;
- `Event.Codec` выводит клаузы нагрузки сам для нагрузки-Prim, нагрузки по полям и
  `Es.ValueChanged`; нагрузка по полям в фасаде не регистрируется;
- union-типы и словари — ручные клаузы; декларативный `tags:` — когда разбор тега начнёт
  повторяться.

## Цена

- **Переименование поля нагрузки молча меняет wire события.** Ловят только golden-фикстуры
  (`Core.Es.EventCompatCase`), поэтому они остаются обязательными; round-trip у потребителя —
  тоже: он проверяет объявление автора, а не генератор.
- **Struct и спека сущности — в двух файлах.** Расхождение ловит сборка, но `@type t` агрегата
  остаётся таким, каким его написал автор.
- **Межполевые инварианты `new` при загрузке не выполняются.** Сущность, которой они нужны на
  чтении, остаётся с ручным плагином.

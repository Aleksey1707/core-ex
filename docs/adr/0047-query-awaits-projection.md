# Запрос ждёт проекцию по `wait:`, исходы команд без представления

Частично заменён ADR-0053 (`0053-query-for-other-contexts-without-declaration.md`): запрос для
другого контекста — и с `wait:`, и read-модели без таблицы — функция `Query` без декларации
доступа, а не `<ReadModel>.Usecases`. Ниже — решение в редакции 2026-10-03.

Экспортированный запрос, который зовёт другой контекст, MAY принимать `wait:` и ждать проекцию до
чтения; не дождался — ошибка ожидания. Состояние агрегата без отставания другой контекст читает
запросом read-модели без таблицы над write-репозиторием. `:projected` команды читает представление
запросом актора, а не ReadRepo, и отказ чтения после commit — исход `:accepted`. Удаление и
upsert отдают исход создания `{id, version}`, команда агрегата без read-модели —
`{:accepted, id, version}`. Дополняет ADR-0039 (ждёт usecase) и ADR-0038 (данные другого
контекста — через его `exports`). Норма — `docs/rules/22-projections.md`, «Read-after-write»;
`docs/rules/app/10-architecture.md`, «Usecases»; `docs/rules/app/13-repos.md`, «Read-модель»;
`docs/rules/app/14-events-outbox.md`, «Подписчики».

## Контекст

Факты на 2026-10-03 (адаптация потребителя A к rc после 0.10.0):

- `app/14` требует от правила, читающего read-модель, дождаться проекции агрегата, чью модель оно
  читает (MUST); проекция и ReadRepo не входят в `exports` контекста, а `wait:` был только у команд
  (ADR-0039): реакция на событие агрегата другого контекста исполнить норму не могла;
- у потребителя A правила уведомлений ждут проекции двух агрегатов другого контекста и читают их
  ReadRepo; своих проекций у контекста уведомлений нет — он state-stored, и копия полей своей
  проекцией (ADR-0038) потребовала бы завести её ради двух полей;
- четыре контекста потребителя A читают учётную запись свёрткой потока, а не проекцией — решение
  приложения ради отсутствия отставания в проверках; через `exports` отдаётся только View;
- `app/13` уже допускает read-модель без таблицы над write-репозиториями, но только если своей
  проекции у неё нет;
- ветка `:projected` по образцу свода читала `@read_repo` напрямую: право на чтение у вызывающего
  не проверялось, а у удаления чтение после commit давало `:not_found` после успешной записи;
- upsert справочника — создание или команда в зависимости от состояния; таблица возвратов знала
  только команду и создание.

## Рассмотренные варианты

- **Экспорт проекции другого контекста ради `await/3`.** Отвергнут: проекция — внутреннее
  устройство контекста, и экспорт ради ожидания открыл бы её и для чтения мимо usecase.
- **Реакция копирует поля своей проекцией (ADR-0038).** Остаётся для join и read-модели читателя;
  для чтения двух полей в правиле state-stored контекста — несоразмерно.
- **Запрос с `wait:` отдаёт устаревшее представление по таймауту.** Отвергнут: вызывающий просил
  свежее, и устаревшее без признака неотличимо от свежего; ошибка ожидания ведёт реакцию в
  повтор.
- **Экспорт репозитория записи для чтения без отставания.** Отвергнут: репозиторий — запись
  контекста, и экспорт открыл бы её всем.
- **Исход `:projected` с `nil` у удаления.** Отвергнут: тип представления стал бы опциональным у
  всех команд ради одной.
- **Проверка права чтения до записи, когда `wait:` не `:none`.** Отвергнут: команда без права
  чтения отказывала бы только при ожидании — исход записи зависел бы от заголовка клиента.

## Решение

- экспортированный запрос MAY принимать `wait: :none | pos_integer()` и ждать проекцию до чтения
  литеральным `await/3`; не дождался — `{:error, %Error{}}` с кодом ожидания;
- реакция читает read-модель другого контекста этим запросом, ошибка ожидания — повтор
  сообщения;
- состояние агрегата без отставания — read-модель без таблицы рядом с проецируемой, каталогом по
  назначению, со своими View и `<ReadModel>.Usecases`;
- `:projected` читает представление запросом актора; отказ чтения после commit — `:accepted`;
- удаление и upsert — `{:ok, {:projected | :accepted, id, version}}`; команда агрегата без
  read-модели — `{:ok, {:accepted, id, version}}`.

## Цена

- **Ожидание в запросе держит вызывающего** до `wait:` мс; таймаут — повтор сообщения целиком.
- **Две read-модели одного агрегата:** проецируемая и без таблицы, с двумя View; свёртка потока
  на каждом чтении — нагрузка на хранилище событий, кеш — по `16-caching.md`.
- **`:projected` команды проверяет доступ второй раз** — проверкой запроса.
- **Пакетная команда, которая ничего не записала** (пустой список выдач), формы исхода пока не
  имеет.

# Event sourcing — своя реализация на `Repo.Pg`, без EventStore и Commanded

Event-sourced агрегат `:core` строится на собственном хранилище событий поверх `Repo.Pg` и `DAO`:
глобальная позиция, подписки, чекпоинты и снапшоты пишутся в библиотеке. Готовые ES-библиотеки не
подключаются даже optional-зависимостью: ни одна не пишет события в транзакции `DAO` без глобальной
сериализации записи, опоры на приватный API или собственного процесса агрегата.

## Контекст

Путь команды — usecase → repo внутри `Transact.run`, без router; события пишутся в транзакции `DAO`
вместе с outbox и Oban-джобами usecase. Хранилище событий обязано это уметь. Исходное предпочтение —
взять готовую библиотеку и написать к ней адаптеры под принципы `:core`, а не писать event sourcing
с нуля.

Кандидаты с PostgreSQL на 2026-09-13: `eventstore` 1.4.8, `commanded` 1.4.11, `maestro` 1.0.0,
`ariadne_flow` 0.10.1. EventStore дополнительно проверен спайком на Elixir 1.20.3 / OTP 29 и
PostgreSQL 18.4: собирается и работает, append через `conn:` коммитится и откатывается вместе с
транзакцией Ecto.

## Рассмотренные варианты

- **Commanded + EventStore.** Отвергнут: команда исполняется только через `Commanded.Application` →
  router → процесс агрегата, append идёт в процессе агрегата вне транзакции вызывающего;
  `compile_config` снимает app env при компиляции, TypeProvider (wire-имя) глобален на VM.

- **Maestro.** Отвергнут: GenServer на агрегат, `repo` и storage adapter глобальны на VM, в
  `event_log` нет колонки метаданных.

- **Ariadne Flow.** Отвергнут: единственный кандидат, который пишет в транзакции repo потребителя и не
  требует процессов, но модель DCB не знает версии агрегата, append сериализуется advisory lock на
  context; на hex один релиз, PR не принимаются.

- **EventStore + адаптеры `:core`** (хранилище, подписки и снапшоты — из библиотеки; decide / evolve и
  репозиторий — в `:core`). Отвергнут:
  - строка `$all` под row lock до commit: append в любой поток store ждёт commit самой длинной
    транзакции с append (2003 мс при удержании 2000 мс), а длину транзакции задаёт usecase
    потребителя; отключить блокировку нельзя;
  - в транзакцию Ecto встаёт только через `conn:` из `Process.get({Ecto.Adapters.SQL, pool})` — ключ
    приватный в ecto_sql; вне транзакции `conn: nil`, и append молча пишет мимо неё;
  - supervisor store (пул на 10 соединений, advisory-соединение, notifications) обязателен даже для
    append через `conn:`;
  - конфликт версии при гонке переводит транзакцию в aborted, гонка создания потока отдаёт
    `%Postgrex.Error{}`, от 1000 событий рвётся соединение пула Ecto;
  - экономия мала: чекпоинт в одной транзакции с read-моделью подписки EventStore не дают (`ack`
    отдельно, at-least-once), telemetry нет — это пишется в `:core` в любом случае.

- **Скопировать внутренний `EventStore.Streams.Stream`** (пишет в транзакции без супервизора).
  Отвергнут: это своя реализация чужим SQL, чужой схемой таблиц и без публичного контракта.

## Решение

Хранилище событий, глобальный порядок, подписки с чекпоинтом и снапшоты — код `:core` поверх
`Repo.Pg` и `DAO`, без новых зависимостей. Commanded, EventStore, Marten, Emmett и Message DB —
образцы устройства, а не зависимости.

Из отвергнутого следуют два ограничения:

- глобальный порядок не заставляет запись в разные потоки ждать commit чужой транзакции:
  строка-счётчик под row lock и advisory lock на категорию исключены, задержку несёт читатель
  (`xid8 < pg_snapshot_xmin`, high-water mark); на нагрузке не проверено;
- конфликт ожидаемой версии возвращает доменную ошибку `:version_mismatch` и не переводит транзакцию
  usecase в aborted — как `Es.Event.Repo.Pg.append/2` (`insert_all` с `on_conflict: :nothing` и
  сверка числа строк); запись не опирается на приватные API Ecto и ecto_sql.

## Цена

- **То, что EventStore даёт готовым, пишется и сопровождается в `:core`**: глобальная позиция,
  доставка новых событий подпискам, чекпоинты, снапшоты, DDL — вместе с тестами на конкурентную
  запись.

- **Экосистемы нет**: `commanded_ecto_projections`, `opentelemetry_commanded` и подобные пакеты не
  подключаются; проекции, трассировка и тестовая поддержка агрегата — свои.

- **Чтение по глобальной позиции ждёт долгие транзакции** — плата за запись без глобальной
  блокировки.

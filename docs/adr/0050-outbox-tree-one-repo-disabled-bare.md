# Дерево outbox: репозиторий — `Core.Config.outbox_repo/0`, выключенному дереву хватает `enabled:`

У `Core.Outbox.Supervisor` нет опции `repo:`: поллеры и cleaner берут репозиторий очереди из
`Core.Config.outbox_repo/0`, тем же ключом пишут записи. Выключенное дерево требует только
`enabled: false`; прочие опции обязательны при `enabled: true`. Заменяет пункты ADR-0045 «`repo:`
— обязательная опция» и «опции проверяются при любом `enabled:`». Норма —
`docs/rules/app/14-events-outbox.md`, «Конфигурация»; moduledoc `Core.Outbox.Supervisor`.

## Контекст

Факты на 2026-10-03 (адаптация потребителя A к rc после 0.10.0):

- запись в очередь (`Repo.Pg.StateStored`, `Es.Aggregate.Repo.Pg`), `Core.Outbox.PromEx` и
  `mix outbox.requeue` берут репозиторий из `Core.Config.outbox_repo/0`, а поллеры и cleaner —
  из опции `repo:` дерева; расхождение двух источников ничто не ловит: запись идёт в одну
  реализацию, опрос — в другую;
- `Core.Config.validate!/0` уже проверяет `outbox_repo/0` на старте приложения;
- тестовый overlay потребителя был обязан нести все tunables выключенного дерева, а
  `cluster_query:` у потребителя A задан только в prod-блоке `runtime.exs`;
- выключенное дерево отвечает `:ignore`; `watch_list/1` при `enabled: false` пуст и tunables не
  читает, отметка wake пуста.

## Рассмотренные варианты

- **`repo:` у дерева со сверкой с `outbox_repo/0` в `init`.** Отвергнут: два источника одного
  значения, и опция, которая может быть только одной, — шум в конфигурации.
- **Репозиторий из отметки дерева для всех читателей.** Отвергнут: запись в очередь идёт и на
  ноде с выключенным деревом (тесты, ноды без поллера), а отметки там нет.
- **Проверять все опции и у выключенного дерева (ADR-0045).** Отвергнут: tunables выключенного
  дерева никто не читает, а требовать их — заставлять overlay копировать prod-значения ради
  проверки, которая на этой ноде ничего не защищает.
- **Дефолт `cluster_query: nil`.** Отвергнут: забытый ключ в prod молча снял бы проверку
  единственности; база `nil` пишется явно.

## Решение

- опции `repo:` у дерева нет — неизвестная опция; поллеры и cleaner получают
  `Core.Config.outbox_repo/0`;
- при `enabled: false` обязательна только `enabled:`; неизвестная опция — `ArgumentError` при
  любом `enabled:`, переданные `pollers:` проверяются (их имена уходят в лог);
- `cluster_query:` остаётся обязательной без дефолта при `enabled: true`; норма приложения
  задаёт базу `nil` и значение в prod-блоке.

## Цена

- **Ошибку в tunables ноды с выключенной очередью видит только нода, где очередь включена.**
- **Подменить репозиторий очереди для одного дерева нельзя:** только ключом
  `config :core, Core.Outbox.Repo` на всё приложение.

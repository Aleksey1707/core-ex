# Версия агрегата на странице событий — `aggregateVersion`

Поле события страницы событий `version` переименовывается в `aggregateVersion`, на wire и в
OpenAPI-схеме `Core.Web.Event`. Значение прежнее — версия агрегата после события. Это меняет
пункты ADR-0066 о поле `version`; остальное в нём в силе.

## Контекст

Факты на 2026-10-14:

- ADR-0066 ввёл поле `version` (выпущено в 0.14.0); значение — `aggregate_version` конверта;
- у события две «версии» разного рода: версия агрегата — позиция события в потоке, растёт с каждым
  событием; версия схемы события — его тег (`delivery.registered.v2`, `14-events-outbox.md`), на
  wire — `type`. Своего номера у события нет;
- поля страницы событий об агрегате несут префикс — `aggregateId`, кроме `version`; рядом с `type`,
  где живёт версия схемы, голое `version` читается как версия события;
- ответ записи `MyAppWeb.Schemas.Written` (`id`, `version`) префикса не требует: его `id` — id
  агрегата, и `version` однозначна.

## Рассмотренные варианты

- **Оставить `version`, уточнить описание в схеме.** Отвергнут: имя на wire читает клиент, описание
  схемы — не всегда; асимметрия с `aggregateId` остаётся.
- **`aggregateVersion`, как `aggregate_version` конверта.** Принят.

## Решение

- поле события страницы событий — `aggregateVersion`, целое от 1, обязательное;
- `Written` не меняется: его `version` — версия ресурса-агрегата.

## Цена

- **Ломает wire клиента страницы событий.** Поле `version` пропадает, клиент читает
  `aggregateVersion`; в OpenAPI-документе меняется свойство схемы события.

# Схема обёртки ответа — функции условного модуля

OpenAPI-схему обёртки ответа (ADR-0062) даёт условный модуль библиотеки
`Core.Web.Response.Schema` (под `if Code.ensure_loaded?(OpenApiSpex)`, ADR-0064): схема данных
эндпоинта — аргумент функции (`Response.Schema.success(Item)`, `page(Item)`), а не опция `use` в
модуле потребителя. Это уточняет ADR-0064: `use` в пространстве потребителя — для параметра
приложения, заданного один раз и общего у схемы и дампа; схема данных места вызова — аргумент.

## Контекст

Факты на 2026-10-13:

- схему обёртки описывают руками все шесть потребителей, и все шесть — в форме до ADR-0062
  (`{code, messages, data}`, страница `{count, items}`): новая форма ещё не выпущена;
- `data` параметризуют четырьмя способами: хелпер, отдающий анонимную `%Schema{}` (потребители A,
  B, F — копия одного файла), хелпер с названием (E), хелпер плюс модуль ответа на каждую операцию
  (C), `allOf` над общим компонентом обёртки и модулем на ответ (D);
- общий компонент ошибки есть у C, D, E, у A, B, F ошибки почти не описаны; реальный ответ
  сверяет со схемой только D;
- дамп обёртки (`Core.Web.Response.success/1`) от схемы данных не зависит: параметр есть только у
  схемы, и у каждого эндпоинта свой.

## Рассмотренные варианты

- **`use` с `data:` в модуле ответа потребителя** — по букве ADR-0064 («схемы с параметром
  потребителя порождаются в его пространстве»). Отвергнут: модуль на каждый ответ, а параметр не
  общий со схемой дампа — порождать нечего, кроме самой схемы.
- **Компонент обёртки и `allOf` в модуле ответа потребителя.** Отвергнут: тот же модуль на ответ,
  и форму `data` библиотека не видит.
- **Функции, отдающие `%Schema{}` по месту вызова.** Принят: вызов в `operation/2` читается как
  вызов `Response.*` в экшене, а самый массовый способ потребителей переходит переименованием.

## Решение

- `Response.Schema.success(data)`, `success()`, `page(item)` — анонимные схемы, без названия и без
  опции `title:`; `error()` — модуль `Core.Web.Response.Schema.Error` с названием `ErrorResponse`,
  одна схема на все статусы ошибки;
- `status` — перечисление из одного значения, `code` — строка без перечисления, объекты
  открытые; пример — только у `ErrorResponse`;
- схема не описывает то, чего `Core.Web.Response` не пишет: 202 `{id, version}`, `{id}` создания,
  курсорная страница остаются у приложения;
- тест библиотеки сверяет со схемами `Response.*` и каждую строку `Core.Web.ErrorMapper.map/2`.

## Цена

- **Переписка вызовов у всех шести потребителей**, механическая: десятки вызовов хелпера на
  приложение.
- **Названия ответов пропадают из components** у потребителя, который их давал: генератор клиента
  называет тип ответа сам.
- **Модуль есть только при сборке `core` вместе с `open_api_spex`**: добавленный позже
  `open_api_spex` требует пересборки `core`, как клиент брокера.

# Нагрузку события кодирует плагин её типа

Дополняет ADR-0056 (`0056-codec-plugin-by-fields.md`): кодек событий выводит клаузы нагрузки для любого
события с нагрузкой, а колбэки `dump_payload/2` / `load_payload/3` уходят из контракта
`Core.Es.Event.Codec`. Нагрузка, которая не по полям, не `Es.ValueChanged` и не Prim, передаётся фасаду
целиком, её wire-форму задаёт плагин её типа. Норма — `docs/rules/11-domain.md`, «Нагрузка-сущность»;
`docs/rules/14-events-outbox.md`, «Domain events»; `docs/rules/app/11-domain.md`, «Кодек: по полям или
ручной».

## Контекст

Замер на 2026-10-11 у потребителя A (на неопубликованном core-ex, прочие нагрузки уже по полям):

- 7 кодеков событий из 15 держат ручные клаузы, которые только передают нагрузку фасаду:
  `codec.dump(payload)` / `codec.load(Payload, wire)` — 12 событий, 24 клаузы. Тот же код для
  нагрузки-Prim кодек уже выводил сам; для struct — нет;
- ещё 7 событий в 4 кодеках закодированы руками по-настоящему: 3 выводятся текущими средствами, 4 — нет
  (загрузка поля зависит от соседнего поля; открытое множество атомов с терпимой загрузкой; map,
  записанный отсортированным списком записей);
- норма потребителя показывала ручную передачу фасаду образцом.

У формы нагрузки было два места — плагин её типа и клаузы кодека событий, и автор выбирал между ними
каждый раз заново. При сборке кодека событий фасада ещё нет: узнать, обслуживает ли тип какой-то
плагин, можно только при сборке фасада.

## Рассмотренные варианты

- **Явный список событий в `use`** (`facade: [Event.Registered, Event.Updated]`). Отвергнут: строка
  объявления на событие — тот же шаблон, только короче, и два способа сделать одно и то же.
- **Объявление в событии** (`use Es.Event, payload: {:codec, M}`). Отвергнут: меняет DSL события ради
  сведения, которое выводится из самого типа нагрузки.
- **Вывод по умолчанию, ручные колбэки остаются для нестандартной формы.** Отвергнут: выведенная
  клауза стоит перед ручной, и у формы снова два места.
- **Переходный период: предупреждение сейчас, `CompileError` в следующем выпуске.** Отвергнут:
  ломающие изменения идут в каждом выпуске, перевод механический — клаузы передачи удаляются, ручная
  форма переезжает в плагин без изменения wire.
- **Колбэки удаляются молча, ручные клаузы остаются мёртвыми функциями.** Отвергнут: у потребителя на
  старом контракте пропавшая форма всплыла бы ошибкой сборки фасада, по которой не видно, при чём тут
  фасад.

## Решение

- кодек событий выводит клаузы нагрузки для каждого события с нагрузкой: по полям и `Es.ValueChanged`
  — по их спеке, Prim и любая другая struct — передачей фасаду целиком;
- `dump_payload/2` и `load_payload/3` удалены из behaviour; выведенные клаузы — приватные функции
  кодека. Определение `dump_payload/2` или `load_payload/3` в модуле `use Core.Es.Event.Codec` —
  `CompileError`, который велит перенести форму в плагин типа нагрузки;
- нестандартная wire-форма нагрузки — ручной плагин её типа; у потребителя — плагин агрегата
  `<Aggregate>.Codec`;
- сборка фасада проверяет, что тип нагрузки-сущности каждого события его кодеков событий есть в
  `__codec_types__` какого-то плагина того же фасада, иначе — `CompileError` с типом нагрузки и
  кодеком событий. Prim, нагрузка по полям и `Es.ValueChanged` в проверку не входят;
- проверки ручных клауз при сборке кодека (`Core.Es.Check`: событие с нагрузкой без клаузы, клауза с
  нагрузкой другого события) сняты — им нечего проверять. Сужение результата загрузки события по
  struct нагрузки остаётся у фасада.

## Цена

- **Ручная нагрузка переезжает, а не исчезает.** Форма, которую не вывести из полей, уходит из
  кодека событий в ручной плагин её типа — новый файл у агрегата, у которого плагина не было.
- **Ошибка забытого плагина — в фасаде.** Сборка кодека событий тип нагрузки не проверяет; кодек вне
  фасада (без `plugins:`) не проверяется вовсе, и его нагрузка без плагина ломается при исполнении.
- **Ломающее изменение контракта.** Потребитель на старом контракте получает `CompileError` на каждый
  кодек с ручными клаузами нагрузки.

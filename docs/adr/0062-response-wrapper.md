# Обёртка ответа: `status` и строковый `code` из `%Error{}`

Обёртка ответа меняется с `{code, messages, data}` на `{status, data}` у успеха и
`{status, data, code, message}` у ошибки — форму, которую уже читает фронт проекта-образца.
`code` ошибки — строка, взятая из `%Error{}`, а не число из словаря кодов ответа; словарь,
опция `use Core.Web.Response, codes:` и резерв `0..9` удаляются. HTTP-статусы не меняются.
Норма — `docs/rules/10-architecture.md`, граница HTTP; `docs/rules/app/15-web-api.md`.

## Контекст

Факты на 2026-10-13:

- обёртка библиотеки — `{"code": <int>, "messages": [...], "data": …}`: признак успеха — `code: 0`,
  ошибка — целое из `Core.Web.Response.Code` (`0..9` за библиотекой) или из `Core.Enum`
  потребителя, проверка целых — на компиляции; текст — всегда список, и в успехе тоже;
- проект-образец (не потребитель `:core`) отдаёт `{"status": "ok", "data": …}` и
  `{"status": "error", "data": {}, "code": <string | null>, "message": "…"}`, ошибки валидации —
  `data.fields` по путям полей; фронт, общий с ним, ждёт эту форму от всех потребителей;
- `%Error{}` уже несёт стабильный машинный код — `code` из каталога `<Aggregate>.Errors`;
  числовой код ответа дублирует его в грубой классификации (`:domain_error`, `:diff_version`);
- исследование форм обеих сторон — `.scratch/http-response-envelope/research.md`.

## Рассмотренные варианты

- **Опция формата в `Core.Config`, старая обёртка по умолчанию.** Отвергнут: два формата —
  двойной `ErrorMapper`, тесты и свод `15-web-api.md`, а новая форма нужна всем потребителям.
- **Сменить обёртку, `code` оставить числом.** Отвергнут: фронт образца ветвится по строковому
  коду, а число переводит в класс то, что `%Error{}` знает точно.
- **Строковый код через словарь `Response.Code` (атом → строка) с `codes:` у потребителя.**
  Отвергнут: второй источник кода рядом с каталогом ошибок агрегата, который нужно сверять.
- **Статусы образца (404 на «не найдено», 409 на конфликт, 424 на сбой внешней системы).**
  Отвергнут в этой задаче: статус — отдельный контракт (`10-architecture.md`), задача — тело.
- **`Error.many` одной строкой в `message` (склейка или первый элемент).** Отвергнут: фронт
  теряет коды элементов; состав — `data.errors`.
- **Ошибки по полям (`data.fields`) сразу.** Отложен: в `%Error{}` нет пути поля, это решение о
  модели ошибки (`12-errors.md`); форма `data.fields` зарезервирована под него
  (`.scratch/http-response-envelope/issues/01-error-fields.md`).

## Решение

- успех — `{"status": "ok", "data": …}`, пустой успех — `data: {}`; 204 остаётся без тела, 202
  (`{id, version}`) — в обёртке;
- ошибка — `{"status": "error", "data": {}, "code": "…", "message": "…"}`;
- `code` доменной ошибки — `to_string(error.code)`; прикладной и не-`%Error{}` (500) —
  `"internal_error"`; 401 (`auth_codes:`) — `"not_authorized"`: настоящий код, как и текст,
  наружу не уходит;
- `Error.many` с доменным исходом — код и текст контейнера, состав —
  `data.errors: [{"code", "message"}]`; иначе состав не отдаётся, как раньше;
- `messages` в успехе (`success/2`) удаляется;
- пагинация — `data: {items, total}` вместо `{count, items}`;
- HTTP-статусы, русские тексты маппера, регистр ключей и форматы дат — без изменений.

## Цена

- **Ломающая замена у всех потребителей:** тесты контроллеров, `Core.Enum` кодов ответа и
  фронты переходят разом, переходной версии нет.
- **Код ошибки стал публичным контрактом:** переименование `code` в `<Aggregate>.Errors` теперь
  ломает клиента, а не только сверку `errors:` на сборке.
- **`status` дублирует HTTP-статус:** поле избыточно, держится ради совместимости с фронтом
  образца.

# Варианты union объявляются адресом и спекой, разбор тега генерирует плагин

Дополняет ADR-0056 (`0056-codec-plugin-by-fields.md`) в трёх пунктах. «Union-типы и словари —
ручные клаузы» и «декларативный `tags:` — когда разбор тега начнёт повторяться» заменены: вариант
семейства объявляется в `variants:` адресом и спекой полей, а дамп в форме адреса, симметричная
загрузка варианта, загрузка по семейству и ошибки разбора генерируются. «Ключи спеки —
подмножество `types:`» заменён: `types:` перечисляет только ручные типы, типы плагина выводятся из
спек. Словари остаются ручными; остальное решение ADR-0056 в силе. Норма — `docs/rules/11-domain.md`,
«Плагин по полям (`fields:`)»; `docs/rules/app/11-domain.md`, «Кодек: по полям или ручной».

## Контекст

Замер на 2026-10-11 по потребителям A–F (только `lib/`):

- `union:` объявлен у двух плагинов — у A и F; оба пишут тегированную форму
  `%{"type" => тег, "fields" => поля}` (13 тегов на 14 модулей у A, 6 у F) и разбирают её руками:
  таблица тег ↔ модуль, `type/1` / `types/0`, загрузка по семейству, свои коды ошибок;
- у A один тег делят два модуля: вариант выбирается по полю-дискриминатору внутри `fields`, а
  значение по умолчанию этого поля в struct равно тегу варианта — это сверяет собственный DSL A;
- тег внутри данных без обёртки — пример `Shape` в своде и приватное значение у B;
- поля всех вариантов F и всех, кроме дискриминатора, у A повторяют wire один к одному;
- контракт варианта у A и F несимметричен: `dump(variant)` отдаёт тегированную форму,
  `load(Variant, wire)` ждёт голые поля;
- `Core.Es.Event.Codec` уже даёт эту модель для событий: `tags:`, `type/1`, `types/0`, симметричный
  `load(mod, конверт)`, загрузка по семейству, ошибки библиотеки;
- спеки `Core.Codec.Redump` пишутся руками — 15 у четырёх потребителей — и повторяют Prim полей,
  известные спеке кодека; `{:tagged, _}` вывести нельзя, пока выбор варианта живёт в ручном коде;
- `fields:` на 2026-10-11 не выпущен.

## Рассмотренные варианты

- **Генерация только полей (`fields_only:`), форма и выбор варианта — руками.** Отвергнут: разбор
  тега остаётся у каждого автора, а знание «адрес → модуль» — в коде, из которого redump-спеку не
  вывести.
- **`tags: %{Mod => адрес}` рядом с `fields:`, как у `Core.Es.Event.Codec`.** Отвергнут: тип
  варианта назван дважды. У события спеки полей в кодеке нет, поэтому там повтора нет.
- **Варианты внутри `union:` (`union: [family: Shape, variants: […]]`).** Отвергнут: у опции стало
  бы две формы — модуль ручного семейства и keyword декларативного; связь `variants:` с `union:`
  держит проверка сборки.
- **Переименовать `fields:`, чтобы развести с ключом `"fields"` тегированной формы.** Отвергнут:
  имя спеки полей общее с `Core.View` и `Core.Es.Event.Payload`, а ключ wire — данные, не API.
- **Адрес ключом внутри спеки полей.** Отвергнут: адрес занял бы имя поля и смешался со спекой.
- **Только тегированная форма, без дискриминатора.** Отвергнут: вариант с общим тегом остаётся
  ручным целиком, а дискриминатор и тег внутри данных — один механизм.
- **Хук ошибок на каталог потребителя.** Отвергнут: ошибки разбора видны только на пути загрузки,
  как `:invalid_envelope` / `:unknown_event_type` у событий.

## Решение

- `variants: [{Mod, адрес, spec} | {Mod, адрес}]` требует `union:`; `union:` без `variants:` — как
  прежде, загрузка по семейству ручная;
- типы плагина — `types:` ∪ ключи `fields:` ∪ модули `variants:`; тип в двух опциях —
  `CompileError`, `types:` MAY отсутствовать;
- адрес — `"tag"` (тегированная форма), `{"tag", key: value}` (тег и дискриминатор внутри `fields`)
  или `[key: value]` (дискриминатор среди полей, без обёртки); две формы в одном плагине, повтор
  адреса, общий тег без дискриминатора и разные ключи дискриминатора у одного тега — `CompileError`;
- поле struct с именем дискриминатора в спеку не входит: дамп пишет значение как объявлено (атом —
  атомом, как `enum:`), загрузка сравнивает по строке; значение поля по умолчанию обязано равняться
  `value`, wire-ключ поля спеки не совпадает с ключом дискриминатора — иначе `CompileError`;
- `{Mod, адрес}` без спеки — поля пишет автор колбэками `dump_variant/2` / `load_variant/3`
  (optional `@callback` плагина); адрес, обёртку и выбор пишет библиотека;
- генерируются `dump/2` варианта в форме адреса, `load(Variant, wire)`, сверяющий адрес,
  `load(Family, wire)` на любой term, `type/1`, `types/0` и `__codec_variants__/0`; ручная клауза
  `dump/2` / `load/3` на вариант или семейство — `CompileError` «never match»;
- ошибки — `ns: :codec`: повреждённая форма — `:invalid_value`, адрес вне семейства или не этого
  варианта — `:unknown_tag`.

## Цена

- **Адрес варианта не переименовать.** Он записан в jsonb и в событиях, развития тегов
  (как `upcasts:` у событий) у плагина нет; переименование ловят только golden-фикстуры.
- **Потребитель теряет свои коды ошибок разбора.** Различия тоньше «повреждённая форма» и «адрес
  вне семейства» (например, «тег известен, но нагрузки за ним нет») не остаётся.
- **Раскладка формы по ключам родителя не поддержана.** Родитель, хранящий тег и поля в разных
  ключах, собирает форму сам перед загрузкой по семейству.
- **Полнота регистрации уходит из `types:`.** Плагин, чьи варианты вычисляются из своей таблицы,
  сверяет полноту сам — по `__codec_variants__/0`.

# Состояние на версии — только через read-репозиторий и View

Потребитель хранит адрес версии `{id, N}` вместо копии event-sourced агрегата и получает состояние
на версии `N` только представлением: макрос `use Core.Es.Aggregate.ReadRepo` (`repo:`, `view:`) и
реализация `use Core.Es.Aggregate.ReadRepo.Pg` (`behaviour:`, `to_view:`) генерируют `get_at/3,4`
и `get_many_at/2,3`, результат сужен до `%View{}`. Свёртка до версии — внутренняя функция
библиотеки (`@doc false`); behaviour write-репозитория не меняется, и `%Agg{}` на версии `N` код
потребителя видит только аргументом `to_view`. Норма — `docs/rules/13-repos.md`, «Состояние на
версии».

## Контекст

Факты на 2026-11-06:

- потребители держат копию агрегата (или его полей) на момент события, чтобы показать «как было»;
  копия расходится с потоком событий и дублирует хранение;
- в 0.17.1 состояния на версии нет: `get(id, %Version{}, context)` сворачивает поток до головы и
  сверяет её с версией, `:version_mismatch` при расхождении; префикс собирается только руками —
  `page_stream` и `Agg.fold/2`;
- исполнение команды от состояния на версии ловит только хранилище: версия `N+1` занята, отказ
  `source: :storage`, и `Es.Transact` повторяет обречённую команду до `retries:`; `append` получает
  события, а не состояние, и пометить их происхождение нечем;
- снапшот хранится один на агрегат и перезаписывается (`es_snapshots`, upsert);
- read-модель без таблицы уже читает write-репозитории (`app/13-repos.md`, «Read-модель»), а
  `ReadRepo` переводит строку в View опцией `to_view:`.

## Рассмотренные варианты

- **`get_at` на write-репозитории с нормой MUST NOT на решение от результата.** Отвергнут:
  нарушение сборка не ловит, а хранилище ловит его лишь повторами `Es.Transact` с отказом
  `:storage`, который вызывающий примет за гонку.
- **Обёртка результата (`{:at, %Agg{}}` или своя структура), которую не примет `execute/2`.**
  Отвергнута: в коде потребителя остаётся доменное состояние, а развернуть обёртку можно одной
  строкой.
- **Опция `view:` у `use Core.Es.Aggregate.Repo.Pg`.** Отвергнута: смешивает write-путь и read-путь
  в одном модуле и behaviour.
- **Вывод View по совпадающим полям агрегата.** Отвергнут: wire-форма повторяла бы агрегат поле в
  поле, и переименование поля агрегата ломало бы API.
- **История снапшотов для быстрой свёртки до старой версии.** Отвергнута: снапшот — оптимизация,
  а не источник истины; цену далёкой версии решать по метрике отдельно.

## Решение

- только event-sourced агрегат: `repo:` не event-sourced агрегата — `CompileError`; граница —
  только `%Version{}`, `:current` — `FunctionClauseError`;
- адрес за головой потока или пустой поток — `:version_mismatch` каталога `errors:`
  write-репозитория с `source: :address`; `Es.Transact` его не повторяет;
- `get_many_at`: уникальна пара `{id, N}`, а не id; поток каждого id читается один раз до
  наибольшей `N`; все расхождения — одна ошибка со списком detail в порядке пар;
- снапшот с версией ≤ `N` — начало свёртки, новее — свёртка с начала потока; снапшот не пишется;
- ПДн — как у `get`: уничтоженное значение не восстанавливается; кешировать состояние на версии
  MUST NOT ни библиотеке, ни потребителю;
- доступ и существование не проверяются, как у `page_stream`: права по `Context` — читающий usecase
  до чтения;
- вне `Transact.run`, `opts` — только опции запроса; telemetry — `[:es, :aggregate, :load]` и
  `[:es, :aggregate, :fold]` с `op: :get_at | :get_many_at`.

## Цена

- **Далёкая версия длинного потока сворачивается с начала:** снапшот на голове ей не помогает,
  длина свёртки видна в `es_aggregate_fold_events`.
- **На каждую read-модель по версии — пара модулей и View:** потребитель пишет `to_view` даже там,
  где View почти повторяет агрегат.
- **State-stored агрегат копию оставляет:** его источник истины — строка, свёртки нет.
- **Адрес версии держит потребитель:** библиотека не проверяет, что сохранённая версия существовала
  на момент записи адреса.

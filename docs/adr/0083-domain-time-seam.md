# Шов доменного времени: `Core.Clock` для Prim, реальное время для инфраструктуры

«Сейчас» значений даты и времени (`now/0` и `now!/0` у `use Core.Prim.DateTime` и
`use Core.Prim.Date`) и `Core.Clock.now/0` идут через `Core.Clock`. Реализацию выбирает ключ `clock:`
в `Core.Config` в рантайме. `Core.Clock.Test` на `nimble_ownership` останавливает и сдвигает время
процесса-владельца, видимое через `$callers`, `allow/2` или глобальный режим. Инфраструктура
библиотеки берёт реальное время явно. Нормы — `docs/rules/11-domain.md` и `docs/rules/19-testing.md`;
термин — `CONTEXT.md`, «Доменное время».

## Контекст

Факты на 2026-10-19 (проектирование потребителя F):

- истории потребителя F с истечением срока проверяются HTTP-тестами: код входа, срок оплаты, срок
  сеанса, сутки чека коррекции, уборка просроченного;
- `now/0` у Prim даты и времени генерируется вызовом `DateTime.now(tz)`, шва нет;
- инфраструктура библиотеки берёт время сама: аренды и время записей outbox, поллер, cleaner,
  хранилище ключей субъектов, читатель проекции, метрики;
- тесты потребителей идут `async: true`, sandbox Ecto находит владельца по `$callers`;
- компиляция библиотеки не может требовать конфигурацию потребителя.

## Рассмотренные варианты

- **Явное `at` в каждом usecase.** Отвергнут потребителем: истории с истечением срока через API
  тогда не закрыть.
- **Шов и для инфраструктуры.** Отвергнут: остановленное время ломает аренды, уборку и чекпоинты
  в тестах, а проверять их через подмену времени никому не нужно.
- **Глобальная подмена через Application env.** Отвергнут: несовместима с `async: true`, тесты видели
  бы время друг друга.
- **Выбор реализации на компиляции.** Отвергнут: это требование к конфигурации потребителя при сборке
  библиотеки.
- **Своё владение на ETS.** Отвергнут: повторяет `$callers`, разрешения, глобальный режим и уборку
  при выходе процесса, которые `nimble_ownership` уже отладил под Mox.
- **Смещение при текущем ходе времени.** Отвергнут: тесту нужен детерминированный момент, а
  `freeze` + `advance` его дают.

## Решение

- **`Core.Clock`.** Behaviour `now/0` → UTC `DateTime` с микросекундами. Реализации — системная (по
  умолчанию) и `Core.Clock.Test`. Ключ `clock:` в `Core.Config` читается на каждый вызов.
- **Prim.** Генерируемые `now/0` и `now!/0` берут время у `Core.Clock` и приводят его к поясу и
  точности Prim.
- **Инфраструктура** берёт реальное время явно, в том числе через `new` у Prim outbox. Время события
  уничтожения ключа субъекта — доменное.
- **`Core.Clock.Test`:**
  - `start/0` в `test_helper.exs`, `freeze/1`, `advance/1`, `allow/2`, глобальный режим;
  - поиск: `self()` → `$callers` → разрешения, иначе реальное время;
  - `advance/1` без `freeze` — ошибка программиста.

## Цена

- **Чтение конфигурации на каждый `now`** в prod — одно обращение к env.
- **`nimble_ownership` — новая обязательная зависимость,** хотя нужна только тестам потребителя.
- **Два времени в одном тесте.** Записи outbox и метрики живут по реальному времени, домен — по
  остановленному; сравнивать их в тесте нельзя.
- **Зависимости вне `:core` шва не видят.** Время Oban и прочих зависимостей остаётся реальным, и
  `scheduled_at` задания сравнивается с остановленным «сейчас» на стороне потребителя.

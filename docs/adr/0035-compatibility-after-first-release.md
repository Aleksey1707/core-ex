# Нормы совместимости действуют с первого релиза приложения

Нормы совместимости яруса потребителя — wire событий, expand / contract, версия API, заполнение
резервов ключа, история миграций — защищают накатанные базы и внешних клиентов. До первого релиза
приложения их нет, и нормы не действуют: правка идёт на месте, базы после pull пересоздаются,
пооперационного учёта нет. Первый релиз — один момент на приложение, его состояние записано
обязательной строкой локального свода. Норма — `docs/rules/app/00-index.md`.

## Контекст

Факты на 2026-10-01:

- исключение «до первого выката» в ярусе неровное: история миграций — MAY (`app/18`, «История
  миграций»); wire событий — MAY только до выката контракта наружу и с записью каждого случая в
  `DEBT.md` (`app/14`, «Совместимость»); expand / contract (`app/18`), новая версия API
  (`app/15`, «Поверхности и версии») и заполнение резервов ключа (`app/13`, «Уникальность без
  индекса состояния») исключения не имеют;
- потребитель A до первого релиза завёл собственную норму «до первого релиза» в трёх файлах
  локального свода, а пооперационный учёт занял около 280 из 700 строк его `DEBT.md`: 14
  несовместимых правок wire, expand / contract в одном релизе, API v1 без новой версии, резерв
  ключа без заполняющей миграции;
- объём `DEBT.md` агент и человек читают как меру несогласия со сводом; записи, у которых нет
  нарушенной нормы, делают эту меру ложной.

## Рассмотренные варианты

- **Совместимость с первого коммита.** Отвергнут: защищает несуществующие данные и клиентов, цена —
  апкасты и версии API, которые никогда не встретят старого читателя.
- **MAY в каждой норме по отдельности.** Отвергнут: четыре формулировки одного условия разойдутся,
  и следующая норма совместимости снова придёт без исключения.
- **Момент на каждый контракт** (как в `app/14`: «до выката контракта наружу»). Отвергнут: требует
  учёта момента для каждого топика, поверхности и таблицы — того самого учёта, от которого норма
  избавляет.
- **Строка только после релиза, её отсутствие — «до релиза».** Отвергнут: выкаченное приложение,
  забывшее строку, считало бы себя дорелизным; отсутствие — небезопасное умолчание.
- **Один момент на приложение, строка в обоих состояниях (принято).**

## Решение

- Первый релиз — первое из двух: появилась база, которую нельзя пересоздать; у любого контракта
  приложения (API, топик, wire событий) появился потребитель вне команды.
- Локальный свод приложения (`docs/rules/00-index.md`) MUST нести строку «Первый релиз: не
  состоялся» либо «Первый релиз: <дата>, <версия>».
- До первого релиза нормы совместимости не действуют и в `DEBT.md` не записываются; частные
  исключения в `app/14`, `app/18` ссылаются на общую норму.
- После первого релиза нормы действуют полностью, без переходного периода.

## Цена

- **Граница грубая:** после релиза новый, ещё не выкаченный контракт подчиняется нормам наравне с
  выкаченными. Правка, не дошедшая ни до одной базы и ни до одного клиента, несовместимостью не
  является и так.
- **Строка держится дисциплиной:** линтера на неё нет, переход в «состоялся» — ответственность
  того, кто выкатывает.
